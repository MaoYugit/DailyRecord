# [53. 最大子数组和](https://leetcode.cn/problems/maximum-subarray/)

中等 **不会看的答案**

给你一个整数数组 `nums` ，请你找出一个具有最大和的连续子数组（子数组最少包含一个元素），返回其最大和。

**子数组**是数组中的一个连续部分。

**示例 1：**

```
输入：nums = [-2,1,-3,4,-1,2,1,-5,4]
输出：6
解释：连续子数组 [4,-1,2,1] 的和最大，为 6 。
```

**示例 2：**

```
输入：nums = [1]
输出：1
```

**示例 3：**

```
输入：nums = [5,4,-1,7,8]
输出：23
```

**提示：**

- `1 <= nums.length <= 105`
- `-104 <= nums[i] <= 104`

**进阶：**如果你已经实现复杂度为 `O(n)` 的解法，尝试使用更为精妙的 **分治法** 求解。



这道题是面试高频题（动态规划/贪心），标准解法叫 **Kadane 算法**。别被名字吓到，代码非常短。

**核心思想**：
走到当前数字时，是**接着前面的子数组继续加**划算？还是**甩掉前面的包袱，自己重新开始**划算？

```python
class Solution:
    def maxSubArray(self, nums: List[int]) -> int:
        # 这里的 pre 代表“以此前一个位置结尾的最大子数组和”
        pre = 0 
        max_ans = nums[0]
        
        for x in nums:
            # 核心逻辑：
            # 如果 pre + x 还不如 x 本身大（说明 pre 是负累赘），那就扔掉 pre，从 x 重新开始
            # 否则就带着 pre 继续加
            pre = max(pre + x, x)
            
            # 记录历史出现过的最大值
            max_ans = max(max_ans, pre)
            
        return max_ans
```

为了让你彻底弄懂，我用一个**“负债与人生”**的比喻来讲解。

### 一、 核心思想讲解：丢掉包袱，重新做人

假设你在玩一个闯关游戏，你的目标是**让手里的金币数量曾经达到的最大值尽可能高**。
数组里的数字，就是你在每一关赚到（正数）或赔掉（负数）的金币。

`nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4]`

#### 规则：
你要么**带着之前的资产进入下一关**，要么**扔掉之前的资产（如果是负债），这一关从 0 开始算起**。

#### 咱们一关一关地走：

1.  **第一关 `[-2]`**：
    *   你没得选，只能拿 `-2`。
    *   **当前手里的钱**：`-2`。
    *   **历史最高纪录**：`-2`。

2.  **第二关 `[1]`**：
    *   如果你带着之前的 `-2` 过来，加上现在的 `1`，你手里是 `-1`。
    *   如果你扔掉之前的包袱，只拿现在的 `1`，你手里是 `1`。
    *   **决策**：肯定扔掉之前的负债啊！我自己单干都比带着你强。
    *   **当前手里的钱**：`1`。
    *   **历史最高纪录**：更新为 `1`。

3.  **第三关 `[-3]`**：
    *   你带着之前的 `1` 过来，加上 `-3`，变成 `-2`。
    *   如果你自己单干，只有 `-3`。
    *   **决策**：虽然变成了负数，但带着之前的 `1` 总比光秃秃的 `-3` 要好一点点（-2 > -3）。所以我们忍痛带着“负资产”继续走，期待后面有大钱翻盘。
    *   **当前手里的钱**：`-2`。
    *   **历史最高纪录**：保持 `1`。

4.  **第四关 `[4]`**：
    *   **关键时刻来了！**
    *   带着之前的 `-2` 过来，加上 `4`，变成 `2`。
    *   如果你自己单干，直接拿 `4`，就是 `4`。
    *   **决策**：之前的那些累赘（-2），不仅没帮我，还拖累了我（让 4 变成了 2）。**果断切断过去，从这一关开始重新计算！**
    *   **当前手里的钱**：`4`。
    *   **历史最高纪录**：更新为 `4`。

5.  **第五关 `[-1]`**：
    *   带着之前的 `4`，加上 `-1`，变成 `3`。
    *   自己单干是 `-1`。
    *   **决策**：带着 `4` 显然更划算。
    *   **当前手里的钱**：`3`。
    *   **历史最高纪录**：保持 `4`。

6.  **第六关 `[2]`**：
    *   带着之前的 `3`，加上 `2`，变成 `5`。
    *   自己单干是 `2`。
    *   **决策**：肯定带着，越加越多。
    *   **当前手里的钱**：`5`。
    *   **历史最高纪录**：哇！更新为 `5`。

7.  **第七关 `[1]`**：
    *   带着 `5`，加上 `1`，变成 `6`。
    *   **决策**：带着。
    *   **当前手里的钱**：`6`。
    *   **历史最高纪录**：更新为 `6`。**（这就是最终答案）**

#### 总结成一句话公式
在任何一个位置 `i`，你只需要问自己一个问题：
> **“我是继承前面的资产（`pre + nums[i]`）划算，还是另起炉灶（`nums[i]`）划算？”**

写成代码就是：
`pre = max(pre + x, x)`

---

### 二、 这个算法思想叫什么？什么时候用？

这个思想的专业术语叫 **“动态规划”（Dynamic Programming，简称 DP）** 的一种简化形式。

#### 什么时候会用到这种“Kadane 思想”？

面试中，只要看到题目里出现以下 **3 个关键词的组合**，你就要条件反射想到这个算法：

1.  **“连续”** (Contiguous)：
    *   必须是连在一起的子数组，不能跳着选。
2.  **“子数组” / “子区间”** (Subarray)：
    *   不仅仅是找两个数，而是一段数。
3.  **“最大和” / “最大积”** (Maximum Sum / Product)：
    *   求极值。

#### 常见变体题目（面试高频）：

1.  **最大子数组和（就是这道题）**：
    *   累加过程中，如果前面的和是负的，直接扔掉。
2.  **乘积最大子数组**（LeetCode 152）：
    *   逻辑类似，但因为“负负得正”，所以要同时记录“最大值”和“最小值”。
3.  **买卖股票的最佳时机**（LeetCode 121）：
    *   虽然解法很多，但本质上也是在找一段差值最大的区间，思想有相通之处（找最低点买入）。

### 给你一段“人话版”代码注释，面试可以直接背：

```python
class Solution:
    def maxSubArray(self, nums: List[int]) -> int:
        # pre 代表“手里目前的资产”（以前一个元素结尾的最大和）
        # max_ans 代表“历史上曾经最富有的时刻”
        pre = 0 
        max_ans = nums[0] 
        
        for x in nums:
            # 灵魂拷问：
            # 选项 A：pre + x (带着过去的积蓄加上现在的钱)
            # 选项 B：x (过去的积蓄是负债，不如直接扔了，只拿现在的钱)
            # 选 A 还是 B？谁大选谁！
            pre = max(pre + x, x)
            
            # 每次手里资产变动后，都要看看是不是打破了历史纪录
            max_ans = max(max_ans, pre)
            
        return max_ans
```

这样解释，是不是感觉这不仅是个算法，更像是一种人生哲学？（**过去的如果是包袱，就果断放下；如果是积累，就好好利用。**）





**为什么它一定不会漏掉那个真正的最大值？**

你的担心通常是这样的：
> “如果我现在的累加和变成了负数，我就把它丢掉了。万一后面有个超级大的正数，需要前面这一段（虽然暂时是负的）作为桥梁连过来怎么办？”

我用两个逻辑来打破你的疑虑，向你证明它为什么绝对正确。

---

### 逻辑一：我们要找的那个“真命天子”，一定结束在某个位置

不管最终答案（全局最大子数组）长什么样，它一定有一个**结束位置**，对吧？
它要么结束在下标 0，要么结束在下标 1，……要么结束在下标 `n-1`。

Kadane 算法的本质并不是“贪心”，而是**穷举**。
那个变量 `pre`（或者叫 `dp[i]`）的严格定义是：

> **必须以当前索引 `i` 结尾的最大子数组和。**

注意这几个词：**“必须”、“以当前 `i` 结尾”**。

我们来看看算法在做什么：
1.  算出**必须以 index 0 结尾**的最大和。
2.  算出**必须以 index 1 结尾**的最大和。
3.  ...
4.  算出**必须以 index n-1 结尾**的最大和。

既然全局最大子数组一定结束在某处，而我们把**所有结束位置的可能性**都算到了极致，然后取了其中的最大值 (`max_ans`)，我们就**绝对不可能漏掉**最优解。

---

### 逻辑二：为什么“抛弃负数”不会切断后续的连接？

你最担心的可能是这种情况：`[10, -2, 100]`。中间有个 `-2`，如果抛弃了，会不会连不上 `100`？

让我们看看 `pre = max(pre + x, x)` 这个公式到底在干什么：

#### 情况 A：中间的坑不够深（应该连起来）
数组：`[10, -2, 100]`

1.  走到 `10`：`pre` = 10。
2.  走到 `-2`：
    *   如果你连上前面的（10 + -2）= 8。
    *   如果你另起炉灶（-2）= -2。
    *   **决策**：8 > -2，所以 `pre` 变成了 8。
    *   **注意！** 这里虽然 `-2` 让总数变小了，但总数 **依然是正的（8）**。这意味着保留前面的部分，对后面是有贡献的！**所以并没有抛弃**。
3.  走到 `100`：
    *   连上前面的（8 + 100）= 108。
    *   另起炉灶（100）= 100。
    *   **决策**：`pre` = 108。
    *   **结果**：成功连起来了。

#### 情况 B：中间的坑太深了（不该连起来）
数组：`[10, -20, 100]`

1.  走到 `10`：`pre` = 10。
2.  走到 `-20`：
    *   连上前面的（10 + -20）= -10。
    *   另起炉灶（-20）= -20。
    *   **决策**：-10 > -20，虽然很难看，但 `pre` 暂时变成了 -10。
3.  走到 `100`：
    *   **关键时刻！**
    *   连上前面的（-10 + 100）= 90。
    *   另起炉灶（100）= 100。
    *   **决策**：100 > 90。
    *   **含义**：前面的 `[10, -20]` 加起来是 `-10`，这是一个**负债**。对于 `100` 来说，加上这个负债反而变小了。所以 `100` 决定：“我自己单干是 100，带上你们这帮拖油瓶只有 90，滚蛋！”

**结论：**
算法只会在 **“前面的和（pre）已经变成了负数”** 的时候才会抛弃前面。
*   只要 `pre` 还是正的（哪怕从 100 降到了 1），它对后面的数字就是**正贡献**，算法就会保留连接。
*   一旦 `pre` 变成了负数（哪怕是 -1），它对后面的数字就是**副作用**，算法就会切断连接。

这正是最理性的最优解，不多拿一分负债，不少拿一分正资产。

### 总结
你不用担心它“短视”。
1.  它计算了以**每一个位置结尾**的极限情况，覆盖了所有结束点。
2.  它只有在前面的累积结果**彻底变成累赘（负数）**时才会断开，否则会一直保留连接。

这两个逻辑保证了它的**数学完备性**。
