# [1. 两数之和](https://leetcode.cn/problems/two-sum/)

简单

给定一个整数数组 `nums` 和一个整数目标值 `target`，请你在该数组中找出 **和为目标值** *`target`* 的那 **两个** 整数，并返回它们的数组下标。

你可以假设每种输入只会对应一个答案，并且你不能使用两次相同的元素。

你可以按任意顺序返回答案。

**示例 1：**

```
输入：nums = [2,7,11,15], target = 9
输出：[0,1]
解释：因为 nums[0] + nums[1] == 9 ，返回 [0, 1] 。
```

**示例 2：**

```
输入：nums = [3,2,4], target = 6
输出：[1,2]
```

**示例 3：**

```
输入：nums = [3,3], target = 6
输出：[0,1]
```

**提示：**

- `2 <= nums.length <= 104`
- `-109 <= nums[i] <= 109`
- `-109 <= target <= 109`
- **只会存在一个有效答案**

**进阶：**你可以想出一个时间复杂度小于 `O(n2)` 的算法吗？



```python
class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        for i in range(len(nums)-1):
            for j in range(i+1,len(nums)):
                if target - nums[i] == nums[j]:
                    return [i, j]
                
        
```



### 评价你的题解

你的代码是**正确**的，使用了**暴力枚举法（Brute Force）**。

#### 优点：
1.  **逻辑清晰**：思路非常直观，就是把所有可能的两两组合都试一遍，看哪两个加起来等于目标值。
2.  **空间复杂度低**：$O(1)$，除了存储结果外，不需要额外的内存空间。
3.  **代码简洁**：没有使用复杂的数据结构。

#### 缺点（关键点）：
1.  **时间复杂度高**：使用了双重循环，时间复杂度是 **$O(N^2)$**。
    *   题目提示 $N$ 最大可达 $10^4$。$(10^4)^2 = 10^8$ 次运算。在 Python 中，这通常是超时的边缘（Time Limit Exceeded），或者运行时间非常长（几千毫秒）。
2.  **未满足进阶要求**：题目最后明确问：“你可以想出一个时间复杂度小于 $O(n^2)$ 的算法吗？”

---

### 更好的推荐：哈希表法（One-pass Hash Map）

这是解决“两数之和”最经典、最高效的解法。

#### 核心思路：
利用**空间换时间**。我们在遍历数组的时候，用一个**哈希表（在 Python 中是 `dict`）** 记录已经遍历过的数字及其下标。

对于每一个数字 `num`，我们只需要问：**“哈希表里有没有它的‘另一半’（即 `target - num`）？”**

*   如果有，直接返回这两个下标。
*   如果没有，就把当前的 `num` 和它的下标 `i` 存入哈希表，继续看下一个。

这样只需要遍历一次数组。

#### 推荐代码：

```python
class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        # 创建一个空字典，用于存储 {数值: 下标}
        hashtable = dict()
        
        # 使用 enumerate 同时获取下标 i 和数值 num
        for i, num in enumerate(nums):
            # 计算需要的另一半数值
            complement = target - num
            
            # 如果另一半已经在字典里了，说明找到了
            if complement in hashtable:
                # 返回 [另一半的下标, 当前下标]
                return [hashtable[complement], i]
            
            # 如果没找到，把当前数值和下标存入字典，供后面匹配使用
            hashtable[num] = i
            
        return []
```

#### 对比分析：

| 维度           | 你的解法 (暴力法)      | 推荐解法 (哈希表法)          |
| :------------- | :--------------------- | :--------------------------- |
| **时间复杂度** | **$O(N^2)$** (慢)      | **$O(N)$** (极快)            |
| **空间复杂度** | **$O(1)$** (省内存)    | **$O(N)$** (需额外内存)      |
| **查找原理**   | 每次都重新遍历整个数组 | 利用哈希表 $O(1)$ 的查找速度 |
| **通过情况**   | 可能勉强通过或超时     | 轻松通过 (击败 90%+)         |

#### 举例演示流程：
假设 `nums = [2, 7, 11, 15]`, `target = 9`

1.  **i=0, num=2**:
    *   需要找 `9 - 2 = 7`。
    *   字典是空的，没找到。
    *   存入字典：`{2: 0}`。
2.  **i=1, num=7**:
    *   需要找 `9 - 7 = 2`。
    *   查字典：`2` 在字典里吗？**在！** 下标是 `0`。
    *   找到答案，返回 `[0, 1]`。

**总结**：在面试或实际开发中，推荐使用**哈希表法**，因为它展示了你对数据结构（Hash Map）特性的理解以及对算法复杂度的优化能力。



```python
class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:

        dic = {}

        for i in range(len(nums)):
            if target - nums[i] in dic:
                return [dic[target-nums[i]], i]
            dic[nums[i]] = i
        return []
```



**在 Python 语言里，字典（Dictionary）就是哈希表（Hash Table）。**

这两个词的关系就像：
*   **哈希表（Hash Table）**：是**学名**（数据结构课本里的名字，指一种原理）。
*   **字典（Dictionary）**：是**小名**（Python 给这个东西起的名字）。

你在代码里写的 `dic = {}`，就是在创建一个哈希表。

### 为什么面试官喜欢叫“哈希表”？

因为面试官可能不用 Python，他可能用 Java 或 C++。
*   在 Java 里，这个东西叫 `HashMap`。
*   在 C++ 里，这个东西叫 `unordered_map`。
*   在 Python 里，它叫 `dict`。

虽然名字不同，但它们的**底层原理**都是一样的，统称为**“哈希表”**。

### 为什么它比列表（List）快？

为了让你面试更有底气，我用最通俗的例子解释一下为什么我们要用它：

**场景：你要在一本书里找“张三”这一页。**

1.  **列表（List/Array）的做法 —— $O(N)$**
    *   你从第 1 页开始翻，一页一页看，直到找到“张三”。
    *   如果书有 10000 页，“张三”在最后一页，你就得翻 10000 次。
    *   这就是你最开始那个两层 `for` 循环在这个层面的逻辑。

2.  **哈希表/字典（Hash Table/Dict）的做法 —— $O(1)$**
    *   哈希表就像书的**目录**。
    *   你心里想找 `key = "张三"`。
    *   哈希表内部有一个算法（哈希函数），直接算出“张三”在第 50 页。
    *   你直接翻到第 50 页，找到了！
    *   不管书有多厚，你只需要**算一次**就能找到位置。
