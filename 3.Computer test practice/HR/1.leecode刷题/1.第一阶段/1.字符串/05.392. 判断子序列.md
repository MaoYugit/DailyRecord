# [392. 判断子序列](https://leetcode.cn/problems/is-subsequence/)

简单

给定字符串 **s** 和 **t** ，判断 **s** 是否为 **t** 的子序列。

字符串的一个子序列是原始字符串删除一些（也可以不删除）字符而不改变剩余字符相对位置形成的新字符串。（例如，`"ace"`是`"abcde"`的一个子序列，而`"aec"`不是）。

**进阶：**

如果有大量输入的 S，称作 S1, S2, ... , Sk 其中 k >= 10亿，你需要依次检查它们是否为 T 的子序列。在这种情况下，你会怎样改变代码？

**致谢：**

特别感谢 [@pbrother ](https://leetcode.com/pbrother/)添加此问题并且创建所有测试用例。

**示例 1：**

```
输入：s = "abc", t = "ahbgdc"
输出：true
```

**示例 2：**

```
输入：s = "axc", t = "ahbgdc"
输出：false
```

**提示：**

- `0 <= s.length <= 100`
- `0 <= t.length <= 10^4`
- 两个字符串都只由小写字符组成。



```python
class Solution:
    def isSubsequence(self, s: str, t: str) -> bool:
        i = 0
        j = 0
        while i < len(s) and j < len(t):
            if s[i] == t[j]:
                i += 1
                j += 1
                continue
            j += 1
        return i == len(s) 
        
```



这个进阶问题考察的是**“海量数据下的性能优化”**，是典型的**大厂面试题**（特别是像 Google、字节跳动这种对算法性能要求高的公司）。

### 1. 为什么要优化？（瓶颈在哪里）

*   **原来的双指针法**：时间复杂度是 $O(N)$（$N$ 是长字符串 `t` 的长度）。
*   **进阶场景**：
    *   `t` 只有 1 个，但非常长（比如 50万字符）。
    *   `s` 有 **10亿** 个。
*   **计算量**：如果你用双指针法，总计算量 = $10亿 \times 50万$，这绝对会超时（Time Limit Exceeded），跑几天都跑不完。

我们需要一种方法，**不再每次都重新扫描整个 `t`**，而是利用预处理，快速跳跃。

---

### 2. 核心思路：倒排索引 + 二分查找

我们可以模仿**查字典**或者书籍的**索引**。

#### 第一步：预处理 `t`（建立索引）
既然 `t` 是固定不便的，我们先花点时间把它“解剖”了。我们要记录**每个字母出现在了哪些位置**。

假设 `t = "bahbgdabca"`：
*   `a`: `[1, 5, 9]`  (a 出现在第1、5、9位)
*   `b`: `[0, 2, 6]`
*   `c`: `[8]`
*   `d`: `[4]`
...以此类推。

我们将这个结构存入一个**哈希表（字典）**。
*   **Key**: 字符
*   **Value**: 一个有序的数组（索引列表）

#### 第二步：查找 `s`（二分查找）
假设我们要查 `s = "abc"` 是否是子序列：

1.  **找 'a'**：
    *   我们需要找第一个 'a'。
    *   去 `a` 的列表 `[1, 5, 9]` 里找。
    *   只要位置大于 `-1` (初始位置) 即可。找到第一个是 **1**。
    *   **当前位置标记为 1**。

2.  **找 'b'**：
    *   我们需要找一个 'b'，但是位置必须 **大于 1**（因为子序列必须保持顺序，不能回头）。
    *   去 `b` 的列表 `[0, 2, 6]` 里找。
    *   利用**二分查找**，在列表里找第一个大于 1 的数。
    *   找到了 **2**。
    *   **当前位置更新为 2**。

3.  **找 'c'**：
    *   我们需要找一个 'c'，位置必须 **大于 2**。
    *   去 `c` 的列表 `[8]` 里找。
    *   找到了 **8**。
    *   **当前位置更新为 8**。

全部找到，返回 `True`。

---

### 3. 代码实现

我们需要用到 Python 内置的 `bisect` 模块（专门做二分查找的库），速度非常快。

```python
import bisect
from collections import defaultdict

class Solution:
    def isSubsequence(self, s: str, t: str) -> bool:
        # 这只是为了配合 LeetCode 的函数签名
        # 如果是进阶场景，preprocess 应该在类初始化时只做一次
        # 这里模拟一下流程
        
        # --- 阶段 1: 预处理 t (建立索引) ---
        # 实际应用中，这一步只做一次，针对 10亿个 s 复用
        index_map = defaultdict(list)
        for index, char in enumerate(t):
            index_map[char].append(index)
            
        # 此时 index_map 长这样：{'a': [1, 5, 9], 'b': [0, 2, 6] ...}
        
        # --- 阶段 2: 检查 s (二分查找) ---
        current_idx = -1  # 我们的“指针”，初始在 -1
        
        for char in s:
            # 1. 如果 t 里根本没这个字，直接挂
            if char not in index_map:
                return False
            
            # 2. 取出这个字符所有的出现位置列表
            indices_list = index_map[char]
            
            # 3. 二分查找：在 indices_list 中找到第一个 大于 current_idx 的位置
            # bisect_right 的作用是寻找插入点，返回的 pos 是列表下标
            pos = bisect.bisect_right(indices_list, current_idx)
            
            # 4. 检查是否找到了
            if pos == len(indices_list):
                # 如果返回的下标等于列表长度，说明列表里所有数都比 current_idx 小
                # 也就是说：后面没有这个字符了
                return False
            
            # 5. 更新当前位置
            # indices_list[pos] 就是我们要找的那个下标
            current_idx = indices_list[pos]
            
        return True
```

### 4. 为什么这个更快？

让我们对比一下复杂度：

**假设**：
*   $N$ = `t` 的长度 (如 10,000)
*   $M$ = `s` 的长度 (如 100)
*   $K$ = `s` 的数量 (如 10亿)

**方案 A：普通双指针**
*   每次都要遍历 `t`。
*   单次耗时：$O(N)$
*   总耗时：$O(K \times N)$
*   **结果**：慢到无法接受。

**方案 B：预处理 + 二分查找（进阶版）**
*   **预处理**：扫描一遍 `t`，耗时 $O(N)$。（只做一次）
*   **查询**：对于 `s` 的每个字符，我们在有序列表里做二分查找。
    *   二分查找耗时是 $O(\log N)$。
    *   单次查询耗时：$O(M \times \log N)$。
*   **对比**：
    *   $\log N$ 非常小（即使 $N$ 是 100万，$\log N$ 也就 20 左右）。
    *   所以查询速度几乎只和短字符串 `s` 的长度有关，和长字符串 `t` 没关系了！
*   **总耗时**：$O(N) + O(K \times M \times \log N)$
*   **结果**：飞快。

### 总结
这就是**“空间换时间”**的经典案例。我们多花了一点内存（存哈希表），换取了查询速度的指数级提升。这在搜索引擎、数据库查询中是非常通用的思想。

```python
class Solution:
    def isSubsequence(self, s: str, t: str) -> bool:
        n, m = len(s), len(t)
        f = [[0] * 26 for _ in range(m)]
        f.append([m] * 26)

        for i in range(m - 1, -1, -1):
            for j in range(26):
                f[i][j] = i if ord(t[i]) == j + ord('a') else f[i + 1][j]
        
        add = 0
        for i in range(n):
            if f[add][ord(s[i]) - ord('a')] == m:
                return False
            add = f[add][ord(s[i]) - ord('a')] + 1
        
        return True

```

这是 **动态规划 (Dynamic Programming, DP)** 的方法。

具体来说，这是一种 **“预处理 + 状态机（跳转表）”** 的解法。

它的目的是为了解决那个**进阶问题**（如果有 10 亿个 `s` 怎么办）。相比于刚才讲的“二分查找”法，这个方法的查询速度更快，达到了极致的 **O(M)**（M 是短字符串 `s` 的长度），完全消除了长字符串 `t` 长度的影响。

### 1. 核心思想：制作一张“寻宝地图”

想象 `t` 是一个很长的走廊，你站在位置 `i`。你想知道：“从我现在站的地方往后看，**最近的** 字母 'a' 在哪里？最近的 'b' 在哪里？...”

*   **二分查找法**是：每次都要去翻目录，找“大于当前位置的最小位置”。
*   **这个 DP 方法**是：直接给你一张地图。
    *   地图告诉你在第 0 步：如果你想要 'a'，直接跳到第 5 格；想要 'b'，跳到第 1 格...
    *   不需要查找，**直接跳转**。

---

### 2. 代码详细拆解

#### 第一步：定义状态 `f[i][j]`
`f` 是一个二维数组（表格）：
*   **行 `i`**：代表长字符串 `t` 目前的下标位置（从 0 到 m）。
*   **列 `j`**：代表 26 个字母（0 是 'a', 1 是 'b', ... 25 是 'z'）。
*   **`f[i][j]` 的含义**：**从位置 `i` 开始（包含 i），第一次出现字符 `j` 的位置在哪里。**

#### 第二步：倒序填表（预处理）
```python
# 从后往前遍历 t
for i in range(m - 1, -1, -1):
    for j in range(26):
        # 逻辑判断：
        if ord(t[i]) == j + ord('a'):
            # 如果 t[i] 刚好就是字符 j，那位置就是 i 自己
            f[i][j] = i
        else:
            # 如果 t[i] 不是字符 j，那就要看 i+1 位置之后的记录
            # 因为是倒着推的，f[i+1][j] 肯定已经算好了
            f[i][j] = f[i + 1][j]
```

**为什么要倒着算？**
这就好比你想知道“从这里往后最近的加油站”。
*   如果你知道“从**下一站**往后最近的加油站”在哪里，
*   且**这一站**不是加油站，
*   那么“从这里往后”的答案 = “从下一站往后”的答案。

#### 第三步：极速查询
```python
add = 0  # 当前在 t 中的指针位置
for i in range(n): # 遍历短字符串 s
    # 查表：从 add 位置开始，有没有 s[i] 这个字符？
    # 如果 f[add][...] == m，说明后面没有这个字符了（m 代表越界/不存在）
    if f[add][ord(s[i]) - ord('a')] == m:
        return False
    
    # 直接跳转！
    # 下一次查找，要从找到位置的“下一个”位置开始 (+1)
    add = f[add][ord(s[i]) - ord('a')] + 1
```

### 3. 图解示例

假设 `t = "abc"`, 长度 `m=3`。
我们补一个终点 `3` 代表“没找到”。

**构建表格 f** (简化演示 'a', 'b', 'c')：

*   **i = 2 ('c')**:
    *   找 'c'? -> 是我 (2)
    *   找 'b'? -> 后面没了 (3)
    *   找 'a'? -> 后面没了 (3)
    *   `Row 2: {'a':3, 'b':3, 'c':2}`

*   **i = 1 ('b')**:
    *   找 'b'? -> 是我 (1)
    *   找 'c'? -> 看下一行 (2)
    *   找 'a'? -> 看下一行 (3)
    *   `Row 1: {'a':3, 'b':1, 'c':2}`

*   **i = 0 ('a')**:
    *   找 'a'? -> 是我 (0)
    *   找 'b'? -> 看下一行 (1)
    *   找 'c'? -> 看下一行 (2)
    *   `Row 0: {'a':0, 'b':1, 'c':2}`

**最终查询 `s = "ac"`**：
1.  初始 `add=0`。我们要找 `'a'`。
2.  查表 `Row 0`，找 `'a'` -> 结果是 `0`。
3.  更新 `add = 0 + 1 = 1`。
4.  我们要找 `'c'`。
5.  查表 `Row 1`，找 `'c'` -> 结果是 `2`。
6.  更新 `add = 2 + 1 = 3`。
7.  遍历结束，返回 `True`。

### 4. 三种方法大比拼（面试常问）

| 方法      | 名字                       | 预处理时间       | 单次查询时间       | 空间复杂度       | 适用场景                         |
| :-------- | :------------------------- | :--------------- | :----------------- | :--------------- | :------------------------------- |
| **方法1** | 双指针 (Two Pointers)      | 无               | $O(N)$ (慢)        | $O(1)$           | 单次查询，内存紧张               |
| **方法2** | 二分查找 (Binary Search)   | $O(N)$           | $O(M \log N)$ (快) | $O(N)$           | $s$ 很多，$t$ 超级长             |
| **方法3** | **DP / 状态机** (当前这个) | $O(26 \times N)$ | **$O(M)$ (最快)**  | $O(26 \times N)$ | **查询速度要求极致**，且内存足够 |

**总结：**
这个方法是 **“空间换时间”** 的极致体现。它用一个比较大的二维数组 ($26 \times 长度$)，换取了查询时完全不需要“搜索”，直接“瞬移”的能力。
