### 第一阶段：内存模型与基本操作

这是你开始写代码前必须建立的“心理模型”。

#### 1. 链表 vs 数组：你在和谁作对？

面试中常问：“链表和数组有什么区别？” 别只背概念，要从**内存**角度理解：

*   **数组 (Array)：** 像是**一排连续的储物柜**，每个人都有编号（下标）。
    *   **优点：** 找人快（查下标 $O(1)$）。
    *   **缺点：** 插入/删除慢（因为中间塞进一个人，后面所有人都得往后挪位置 $O(N)$）；长度固定，难以扩容。
*   **链表 (Linked List)：** 像是**寻宝游戏**。你手里的纸条（Node）写着宝藏信息（Value），背面写着下一张纸条藏在哪（Next Pointer）。纸条可能散落在房间的任何角落（内存不连续）。
    *   **优点：** 插入/删除快（只需要改一下纸条上的地址，不用挪动其他人 $O(1)$）。
    *   **缺点：** 找人慢（必须从第一张纸条顺藤摸瓜找下去 $O(N)$）；不支持随机访问。

#### 2. 代码中的样子 (Node Definition)

不管你用 Java, C++, Python，链表节点的定义大同小异。

```python
# Python 示例
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val   # 数据域
        self.next = next # 指针域，指向下一个节点对象
```

**面试大忌：**
永远不要想当然地认为 `head` 存在，或者 `head.next` 存在。**空指针异常 (Null Pointer Exception)** 是链表题挂掉的头号原因。

#### 3. 核心操作：增删改查的“手术刀”

链表操作就像做微创手术，顺序极其重要。

**场景一：插入节点（在 A 和 B 之间插入 X）**
假设当前是 `A -> B`，我们要变成 `A -> X -> B`。

*   **错误写法：** `A.next = X` (完了，B 的地址丢了，链表断开了！)
*   **正确写法：**
    1.  `X.next = B`  (先让 X 抓住 B)
    2.  `A.next = X`  (再让 A 抓住 X)

**场景二：删除节点（删除 B）**
假设 `A -> B -> C`。

*   **操作：** `A.next = A.next.next` (或者 `A.next = C`)
*   **注意：** 在 C++ 等非自动垃圾回收语言中，记得手动 `delete B`。

#### 核心技巧：虚拟头结点 (Dummy Node)

这是面试刷题中**最重要的技巧**，能解决 50% 的链表边界问题。

**痛点：**
通常我们要操作链表，头结点（Head）往往很特殊。比如你要删除 Head，或者在 Head 前面插入新节点，你需要写额外的 `if head is None` 或者特殊处理逻辑，代码会很丑。

**解决方案：**
人为创建一个“假”的头结点，放在真正的 Head 之前。
`Dummy -> Head -> Node2 -> ...`

**代码模版（背下来）：**
```python
def solveLinkedList(head):
    # 1. 创建 dummy 节点，指向 head
    dummy = ListNode(-1) # 值随便写，不重要
    dummy.next = head
    
    # 2. 使用 cur 指针进行遍历操作，从 dummy 开始
    cur = dummy
    while cur.next:
        # 这里进行你的插入/删除/遍历逻辑
        # ...
        cur = cur.next
        
    # 3. 最后返回 dummy.next，这才是真正的新链表头
    return dummy.next
```
**好处：** 无论原来的 head 怎么变（被删了、被换了），`dummy.next` 永远指向最新的头，你不需要特殊处理头结点了。



```
class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        pre = None
        cur = head
        while cur:
            next_node = cur.next
            cur.next = pre
            pre = cur
            cur = cur.next
        return pre
```

### **第二阶段：快慢指针与前后指针**

如果说“虚拟头结点”是防守神技（防止空指针报错），那**双指针**就是链表题中的**进攻利器**。

在数组里，我们能算下标（例如 `arr[n/2]` 直接找中点），但在链表里，你不知道链表有多长。**双指针的核心价值就在于：在不知道链表长度 `N` 的情况下，只需遍历一次（One Pass）就能找到特定的位置。**

面试中 80% 的链表**中等难度（Medium）**题目，都是用双指针解决的。

---

#### 核心技巧：快慢指针 (Fast & Slow Pointers)

想象操场上有两个人跑步：
*   **Slow（慢指针）：** 每次跑 1 步。
*   **Fast（快指针）：** 每次跑 2 步。

#### 必背模版

不管是找中点还是判断环，起手式几乎都是这样的：

```python
slow = head
fast = head

# 核心条件：因为 fast 跑得快，所以要检查 fast 和 fast.next 是否为空
while fast and fast.next:
    slow = slow.next      # 走一步
    fast = fast.next.next # 走两步
    
    # 针对不同题目，在这里加逻辑
```

#### 三大经典应用场景

##### 场景一：找中点 (Middle of the Linked List)
**题目：** [LeetCode 876]
**问题：** 给你一个链表，请返回中间那个节点。
**原理：**

*   当 Fast 到达终点（End）时，Slow 刚好走到中点（Middle）。
*   因为 $Fast = 2 \times Slow$。

**面试坑点：**
*   **奇数长度：** `1->2->3->4->5`。Fast 走到 5，Slow 走到 3。完美。
*   **偶数长度：** `1->2->3->4`。Fast 走到 None，Slow 走到 3。
    *   注意：大部分题目要求偶数时返回**第二个**中点（即 3），上述模版刚好符合。如果要求返回第一个中点（即 2），则快指针的起步需要调整（比如 `fast = head.next`）。

##### 场景二：判断链表是否有环 (Linked List Cycle)
**题目：** [LeetCode 141]
**问题：** 链表里是否有环？
**原理：**
*   如果链表是直的，Fast 最终会遇到 None（跑完比赛）。
*   如果链表有环，Fast 会进入环圈。因为 Fast 比 Slow 快，Fast 最终会在环里**追上（套圈）** Slow。
*   **结论：** 只要 `slow == fast`，就说明有环。

##### 场景三：倒数第 K 个节点 (Remove Nth Node From End)
**题目：** [LeetCode 19]
**问题：** 删除倒数第 N 个节点。
**技巧：** **“直尺法”**（也叫**前后指针**）。
这次不是一快一慢，而是**一个先走，一个后走**，但速度一样。

**操作步骤（假设找倒数第 2 个）：**

1.  **Fast 先走：** 让 Fast 指针先走 N 步（比如 2 步）。此时 Fast 和 Slow 之间的距离就是 N。
2.  **一起走：** 然后 Slow 和 Fast 同时开始移动，每次都走 1 步。
3.  **结果：** 当 Fast 走到链表末尾（None）时，Slow 刚好指在倒数第 N 个节点的位置（或者它的前一个，看具体逻辑）。

#### 进阶：双指针的顶级理解（相交链表）

这是面试中非常优雅的一道题。

**题目：** [LeetCode 160. 相交链表]
**问题：** 两个链表 A 和 B，它们在某个节点汇合了，求这个交点。

```text
A:       a1 -> a2
                 \
                  c1 -> c2 -> c3
                 /
B: b1 -> b2 -> b3
```

**暴力法：** 算长度，长的先走差值步...太麻烦了。
**浪漫解法（双指针）：**

*   指针 pA 走 A 链表，走到头了就转去走 B 链表。
*   指针 pB 走 B 链表，走到头了就转去走 A 链表。
*   **原理：** `A的长度 + B的长度 = B的长度 + A的长度`。
*   只要这样走，它们一定会走过相同的总路程，最终在 **交点 (c1)** 相遇。如果不相交，它们会同时走到 None。

```python
# 伪代码
pA, pB = headA, headB
while pA != pB:
    pA = pA.next if pA else headB # 走完A去走B
    pB = pB.next if pB else headA # 走完B去走A
return pA
```

#### 一、 递归的思维 (The Recursive Mindset)

链表天然具有递归属性：`一个链表 = 头结点 + 剩下的链表`。
很多迭代写起来很麻烦的题，递归写起来只有几行。

##### 例子：递归反转链表
还记得第一阶段的“反转链表”吗？迭代法需要三个指针倒来倒去。看看递归法怎么想：

**心法：** “相信你的函数”。
假设 `reverse(head)` 这个函数一定能把 `head` 之后的所有节点都反转好。

1.  **当前：** `head -> [2 -> 3 -> 4 -> 5]`
2.  **递归：** 调用 `new_head = reverse(head.next)`。
    *   不用管里面怎么发生的，反正函数返回后，链表变成了：
    *   `head -> 2 <- 3 <- 4 <- 5` (其中 5 是 new_head)
    *   注意：此时 `head.next` 依然指向 2。
3.  **操作：**
    *   我想让 2 指向 head：`head.next.next = head`
    *   head 变成了尾巴，指向空：`head.next = None`
4.  **返回：** `new_head`

```python
def reverseList(head):
    # 终止条件：链表为空或只有一个节点，不用反转
    if not head or not head.next:
        return head
    
    # 递归调用：先把后面的反转了
    last = reverseList(head.next)
    
    # 核心操作：把当前节点接到反转后的链表尾部
    head.next.next = head
    head.next = None
    
    return last
```
**面试提示：** 虽然迭代法空间复杂度 $O(1)$ 更好（递归是 $O(N)$ 栈空间），但理解递归对解决复杂链表题（如合并 K 个链表）至关重要。

#### 二、 链表题的“终极 Boss”：K 个一组翻转

**题目：** **LeetCode 25. K 个一组翻转链表 (Reverse Nodes in k-Group)**
*这也是字节跳动面试中出现频率最高的题目之一。*

**描述：** 给定 `1->2->3->4->5`，k=2。
**输出：** `2->1->4->3->5` （每 2 个翻转一次，最后剩 1 个不够 k 就不翻）。

**为什么难？**
它把你需要的所有技能都考了一遍：
1.  判断剩余长度（是否够 k 个）。
2.  子链表的反转（局部反转）。
3.  **断链与重连**（最容易晕的地方）：你需要把反转后的这一段，跟“上一段的尾巴”和“下一段的头”重新接上。

**解题策略：模块化（Modular Programming）**
千万不要试图在一个 `while` 循环里把所有逻辑写完，必挂无疑。你要把自己当成架构师：

1.  **写一个辅助函数 `reverse(a, b)`：** 专门负责反转从节点 `a` 到节点 `b` 之间的链表。
2.  **主循环逻辑：**
    *   找到第 k 个节点（作为终点 b）。
    *   如果找不到（不够 k 个），直接 return。
    *   如果找到了，调用辅助函数翻转 `[a, b)`。
    *   **缝合伤口：** 把翻转后的子链表接回原链表。
    *   移动指针，准备下一轮。

**代码骨架（伪代码）：**
```python
def reverseKGroup(head, k):
    dummy = ListNode(0, head)
    prev = dummy # 上一组的结尾
    
    while True:
        # 1. 检查剩余是否够 k 个
        tail = prev
        for i in range(k):
            tail = tail.next
            if not tail: return dummy.next # 不够就结束
        
        # 记录下一组的开头
        next_group_head = tail.next
        
        # 2. 截断并反转当前组 (这里需要你自己实现局部反转逻辑)
        # 输入是这一组的头和尾，返回新的头和尾
        # new_head, new_tail = my_reverse(prev.next, tail)
        
        # 3. 缝合
        prev.next = new_head
        new_tail.next = next_group_head
        
        # 4. 移动 prev 到当前组的尾巴，准备下一轮
        prev = new_tail
```

### 一、 核心解题策略：微创手术法

不要把整条链表看成一个整体。我们要像做手术一样，把链表**切**成一段一段的，处理完再**缝**回去。

**步骤分解：**
1.  **分组：** 从头开始数 `k` 个节点。
2.  **判断：** 如果数够了 `k` 个，说明这一组要翻转；如果不够，直接结束（保留原样）。
3.  **切割（Cut）：** 把这一组跟后面的链表断开（暂时切断联系）。
4.  **局部反转（Reverse）：** 调用我们最熟悉的 `reverse` 函数，把这一小段翻转。
5.  **缝合（Connect）：**
    *   把上一组的尾巴（`groupPrev`）接到这一组的新头（`newHead`）。
    *   把这一组的新尾巴（也就是原来的头 `head`）接到下一组的头（`groupNext`）。
6.  **推进：** 准备处理下一组。

---

### 二、 图解“缝合”过程

假设 `Dummy -> 1 -> 2 -> 3 -> 4 -> 5`，k=2。

**第一轮：**
1.  **找终点：** 从 Dummy 出发走 2 步，找到 `2`。
2.  **记录下一组：** 记下 `3` (groupNext)。
3.  **切割：** 把 `2.next` 设为 `None`。现在手里有一小段 `1 -> 2 -> None`。
4.  **反转：** 变成 `2 -> 1 -> None`。
5.  **缝合：**
    *   Dummy 接 `2`。
    *   `1` 接 `3`。
    *   链表变成：`Dummy -> 2 -> 1 -> 3 -> 4 -> 5`。
6.  **推进：** 上一组的尾巴变成了 `1`，从 `1` 开始找下一组。

### 三、 代码实现（模块化写法）

为了不写晕，我强烈建议写一个**辅助函数**专门负责“反转一段链表”。

```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

class Solution:
    # 辅助函数：标准的链表反转（Phase 1 讲过的）
    def reverse(self, head: ListNode) -> ListNode:
        prev = None
        curr = head
        while curr:
            next_node = curr.next
            curr.next = prev
            prev = curr
            curr = next_node
        return prev

    def reverseKGroup(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        group_prev = dummy # 上一组的结尾
        
        while True:
            # 1. 检查剩余节点是否有 k 个
            kth = group_prev
            for i in range(k):
                kth = kth.next
                if not kth: 
                    # 如果不够 k 个，直接结束，不用反转了
                    return dummy.next
            
            # 2. 记录重要的节点位置
            group_start = group_prev.next  # 这一组的开头（比如 1）
            group_next = kth.next          # 下一组的开头（比如 3）
            
            # 3. 切断链表（为了给 reverse 函数一个标准的输入）
            kth.next = None
            
            # 4. 局部反转
            # 输入 1->2->None，返回 2->1->None
            # new_group_head 就是 2
            new_group_head = self.reverse(group_start)
            
            # 5. 缝合伤口
            # 上一组的尾巴接新的头： dummy -> 2
            group_prev.next = new_group_head
            
            # 这一组原来的头（现在的尾巴）接下一组： 1 -> 3
            group_start.next = group_next
            
            # 6. 推进指针
            # 当前组的尾巴（1）变成了下一组的 group_prev
            group_prev = group_start
            
        return dummy.next
```

### 四、 重点逻辑答疑

**Q1: 为什么要 `kth.next = None`？**
**A:** 因为我们的 `reverse` 辅助函数是判定 `while curr:` (即走到 None 停止) 的。如果不切断，反转函数会把后面所有的节点全部都反转了。我们只想反转这 k 个，所以要先把它们“隔离”出来。

**Q2: 最后的 `group_start.next = group_next` 是什么意思？**
**A:**
*   反转前：`1 -> 2 -> 3`。`group_start` 是 `1`。
*   反转后：`2 -> 1`。`1` 变成了尾巴。
*   因为我们在 Step 3 把 `2` 和 `3` 断开了，所以现在 `1` 后面是 `None`。
*   我们需要手动把 `1` 和 `3` 连起来，否则链表就断了。

**Q3: 为什么这道题难？**
难在指针太多。你看我们需要维护：
*   `group_prev` (上一组尾)
*   `kth` (当前组尾)
*   `group_start` (当前组头)
*   `group_next` (下一组头)

**只要弄丢其中一个，链表就断了。**
