# [93. 复原 IP 地址](https://leetcode.cn/problems/restore-ip-addresses/)

中等

**有效 IP 地址** 正好由四个整数（每个整数位于 `0` 到 `255` 之间组成，且不能含有前导 `0`），整数之间用 `'.'` 分隔。

- 例如：`"0.1.2.201"` 和` "192.168.1.1"` 是 **有效** IP 地址，但是 `"0.011.255.245"`、`"192.168.1.312"` 和 `"192.168@1.1"` 是 **无效** IP 地址。

给定一个只包含数字的字符串 `s` ，用以表示一个 IP 地址，返回所有可能的**有效 IP 地址**，这些地址可以通过在 `s` 中插入 `'.'` 来形成。你 **不能** 重新排序或删除 `s` 中的任何数字。你可以按 **任何** 顺序返回答案。

**示例 1：**

```
输入：s = "25525511135"
输出：["255.255.11.135","255.255.111.35"]
```

**示例 2：**

```
输入：s = "0000"
输出：["0.0.0.0"]
```

**示例 3：**

```
输入：s = "101023"
输出：["1.0.10.23","1.0.102.3","10.1.0.23","10.10.2.3","101.0.2.3"]
```

**提示：**

- `1 <= s.length <= 20`
- `s` 仅由数字组成





没问题，这道题是一道非常经典的**回溯算法（Backtracking）**题目。

很多同学觉得难，是因为需要处理的边界条件（比如前导0、数字范围、段数限制）比较多。

2.  **合法性判断**（怎么避开坑？）
3.  **代码实现**（逐行解释）

---

### 1. 核心思路：切蛋糕

想象你手里有一根长长的面条（字符串 `s`），你需要切 **3 刀**，把它分成 **4 段**。每一段就是 IP 地址的一部分。

比如字符串是 `"25525511135"`：
*   我们站在起点，我们要决定第一刀切在哪里？
    *   切 1 个数字？拿到 `2`。
    *   切 2 个数字？拿到 `25`。
    *   切 3 个数字？拿到 `255`。
    *   切 4 个数字？不行，IP 的每一段最多 3 位。

这就形成了一个**决策树**。当我们切下第一段后，剩下的字符串继续重复这个过程，直到切满 4 段且字符串刚好用完。

**回溯法的逻辑：**

1.  **选择**：尝试切出一段合法的数字。
2.  **递归**：进入下一层，处理剩下的字符串。
3.  **撤销**：如果后面的路走不通（比如切完 4 段还有剩余字符，或者切出的数字不合法），就回到上一步，换一种切法。

---

### 2. 合法性判断（避坑指南）

IP 地址由 4 个整数组成（例如 `192.168.0.1`），我们切出来的每一段必须满足以下 3 个条件，缺一不可：

1.  **段数限制**：最终必须正好分成 **4 段**。
2.  **数字范围**：每一段通过字符串转换成整数后，必须在 **0 到 255** 之间。
    *   `255` 是合法的。
    *   `256` 是不合法的。
3.  **无前导 0**：这是最容易出错的地方！
    *   `"0"` 是合法的（单独一个0）。
    *   `"01"`、`"012"`、`"00"` 是**不合法**的。
    *   **规则总结**：如果这一段长度大于 1，那么第一位不能是 `'0'`。

---

### 3. 代码实现与详解

我们使用通用的回溯模板来解决。

#### 变量定义：
*   `s`: 原始字符串。
*   `startIndex`: 当前切割到字符串的哪个位置了。
*   `path`: 存放已经切好的段（比如 `['255', '255']`）。

#### Python 代码示例

```python
class Solution:
    def restoreIpAddresses(self, s: str) -> List[str]:
        result = []
        
        # 剪枝：如果字符串长度不在 4 到 12 之间，绝对构不成合法 IP
        if len(s) < 4 or len(s) > 12:
            return []

        def backtrack(startIndex, path):
            # --- 1. 终止条件 ---
            # 如果我们已经找到了 4 段
            if len(path) == 4:
                # 关键：必须正好把字符串用完才算成功
                if startIndex == len(s):
                    result.append(".".join(path))
                return

            # --- 2. 单层搜索逻辑 ---
            # 每一段最少 1 位，最多 3 位
            # 我们尝试截取长度为 1, 2, 3 的子串
            for i in range(1, 4):
                # 如果截取越界，直接结束循环
                if startIndex + i > len(s):
                    break
                
                # 截取子串
                segment = s[startIndex : startIndex + i]
                
                # --- 3. 判断合法性 ---
                # A. 前导 0 判断：长度大于1且首位是0，非法
                if len(segment) > 1 and segment.startswith("0"):
                    continue # 这一层循环不行，但不要 return，继续试别的可能没意义了其实，可以直接 break，不过 continue 逻辑更简单
                    
                # B. 数字范围判断：必须 0-255
                if int(segment) > 255:
                    continue # 既然这个已经大了，更长的肯定也大，也可以 break
                
                # --- 4. 递归与回溯 ---
                path.append(segment)  # 处理节点
                backtrack(startIndex + i, path) # 递归下一层（注意是 startIndex + i）
                path.pop()  # 回溯，撤销处理结果

        backtrack(0, [])
        return result
```

### 4. 举例模拟（帮助理解）

假设输入 `s = "255255"`（这个例子虽短，但能说明问题）。

1.  **第一层递归**：
    *   切 1 位 `"2"` -> 合法 -> 进入下一层。
    *   切 2 位 `"25"` -> 合法 -> 进入下一层。
    *   切 3 位 `"255"` -> 合法 -> 进入下一层。

2.  假设我们选了第一种，切了 `"2"`，**剩余** `"55255"`。
3.  **第二层递归**：
    *   再切 `"5"` -> 合法 -> 继续。
4.  ...以此类推。

**失败的路径示例：**
假设输入 `s = "1111"`。
1.  第一层切了 `"111"`。
2.  第二层切了 `"1"`。
3.  第三层... **哎呀，没字符串了！**
    *   此时 `startIndex == len(s)`，但是 `path` 里只有 2 段。
    *   不满足终止条件 `len(path) == 4`。
    *   触发回溯，退回到第一层，第一层把它切的 `"111"` 撤销，改切 `"11"` 试试。

### 5. 复杂度分析

这道题的复杂度其实是**常数级**的，甚至可以认为是 O(1)，这是因为 IP 地址的限制太死了。

*   **时间复杂度**：O(1)（或者确切说是 $3^4$）。
    *   因为一共只需要切 4 段。
    *   每一段最多只有 3 种长度的选择（1位、2位、3位）。
    *   整棵树的高度是 4，每层分叉最多 3 个。
    *   不管字符串多长（其实超过12就直接返回了），计算量是固定的。
*   **空间复杂度**：O(1)。递归深度最多 4 层。

### 总结

写好这道题的秘诀：
1.  **剪枝优化**：一开始就判断 `len(s)`，如果不在 [4, 12] 范围内，直接返回空。
2.  **细心校验**：写一个辅助逻辑或者专门的 `if` 块处理 "前导0" 和 ">255"。
3.  **终止条件**：一定要同时满足“找够了4段”**并且**“字符串刚好用完”。

#### 【尝试路径 A】
1.  **第一刀**：我切了 `2`。
    *   剩下的字符串是：`5525511135`。

    *   切 `55`？行。

3.  **第三刀**（在剩下的 `525511135` 里切）：
    *   ...继续切...
4.  **第四刀**：
    *   切完第四刀，如果**刚好把字符串用完了**，恭喜，找到一个答案！

*   回到**第二刀**的时候：刚才我切的是 `5`，既然这条路走不通，那我**撤销**这个决定。
*   我改切 `55` 试试？
*   这就是 `path.pop()` 的意义：**撤销刚才的选择，准备尝试下一个选择。**

### 第四部分：最通俗的代码翻译

现在再看代码，每一句都是在描述上面的过程。

```python
def restoreIpAddresses(self, s: str) -> List[str]:
    result = []
    
    # 【剪枝】如果字符串太短(不够切4段)或者太长(每段3位也就12位)，直接放弃
    if len(s) < 4 or len(s) > 12:
        return []

    # startIndex: 咱们现在切这块蛋糕，从哪里开始切？
    # path: 盘子里已经切好的蛋糕块（比如 ["255", "255"]）
    def backtrack(startIndex, path):
        
        # --- 1. 什么时候停下来？（终止条件） ---
        # 如果盘子里已经有 4 块蛋糕了
        if len(path) == 4:
            # 还要检查：是不是正好把整块大蛋糕切完了？(startIndex到了末尾)
            if startIndex == len(s):
                # 成了！把这4块拼起来做成一个IP
                result.append(".".join(path))
            return  # 无论成没成，都要停下来，不能切第5块了

        # --- 2. 咱们这一刀怎么切？（单层搜索） ---
        # IP地址每一段可能是 1位、2位、3位
        # 所以我们尝试切 1个字符、2个字符、3个字符
        for i in range(1, 4): 
            
            # 如果这一刀切下去，超过字符串长度了，就别切了
            if startIndex + i > len(s):
                break
            
            # 【截取】拿出这一段来看看
            segment = s[startIndex : startIndex + i]
            
            # --- 3. 检查这一块坏没坏？（合法性判断） ---
            
            # 规则A: 不能是 "01", "00" 这种，但 "0" 可以
            if len(segment) > 1 and segment.startswith("0"):
                continue # 这一刀切法不行，换个长度切（进入下一次循环）
            
            # 规则B: 不能超过 255
            if int(segment) > 255:
                continue # 太大了，不行
            
            # --- 4. 这一刀没问题，继续切下一刀 ---
            
            path.append(segment)        # 1. 做出选择：把这块放入盘子
            backtrack(startIndex + i, path) # 2. 递归：从切完的地方继续往下切
            path.pop()                  # 3. 撤销选择：刚才那种切法试过了，把这块从盘子里拿出来
                                        #    这样才能在下一次循环里，试另一种切法

    backtrack(0, [])
    return result
```

### 重点中的重点：为什么需要 `pop()`？

这是很多新手的死穴。

`path` 是一个**全局共享**的列表（或者说是在递归中一直传递的同一个列表）。

*   当你在 `for` 循环里，第一次选择了切 `"2"`，你把它加到了 `path` 里，`path` 变成了 `["2"]`。
*   然后你进去了下一层递归 `backtrack`。
*   等那层递归结束回来时，如果不把 `"2"` 拿出来，`path` 还是 `["2"]`。
*   接下来的循环，你想尝试切 `"25"`。如果你不 `pop`，你直接 `append`，`path` 就变成了 `["2", "25"]`。
*   **这不对！** 我们希望的是：先试 `["2"]`，试完把 `2` 拿走；再试 `["25"]`。
*   所以：**进门前穿鞋（append），出门后脱鞋（pop）。** 保证回到这一层时，环境和刚来时一样。

### 【第一层递归】
**目标**：寻找 IP 的第 1 段。
**当前状态**：`startIndex = 0`, `path = []`

进入 `for` 循环，`i` 从 1 到 3。

#### 👉 循环第 1 次：i = 1
1.  **截取**：`segment = s[0:1]` -> `"2"`。
2.  **合法性判断**：`"2"` 合法。
3.  **放入 (Append)**：`path` 变成 `["2"]`。
4.  **递归调用 (Recursion)**：`backtrack(1, ["2"])`。
    > **注意**：这里进入了第二层，我们需要进去看看。因为剩余字符串长度是 10 (`5525511135`)，而我们要切 3 段，每段最多 3 位，总共最多只能切 9 位。所以这条路注定是死胡同。但代码还是会笨笨地走下去。为了不让你晕，我们假设这次递归进去后，试了一圈发现走不通，最后**返回了**（Return）。
5.  **撤销 (Pop)**：因为刚才那条路走不通（递归函数执行完了），我们把 `"2"` 弹出来。`path` 变回 `[]`。

#### 👉 循环第 2 次：i = 2
1.  **截取**：`segment = s[0:2]` -> `"25"`。
2.  **合法性判断**：`"25"` 合法。
3.  **放入 (Append)**：`path` 变成 `["25"]`。
4.  **递归调用**：`backtrack(2, ["25"])`。
    > 这里剩余字符串是 `525511135`（9位）。我们要分 3 段，理论上 `3x3=9`，刚刚好够。这条路有可能！
    > 但是，如果我们继续走下去，会发现切分点不凑巧（比如中间切出个大于255的）。
    > 假设这次递归进去试了所有可能，最后也没找到结果，**返回了**。
5.  **撤销 (Pop)**：把 `"25"` 弹出来。`path` 变回 `[]`。

#### 👉 循环第 3 次：i = 3 （这是正确路径的开始！）
1.  **截取**：`segment = s[0:3]` -> `"255"`。
2.  **合法性判断**：`255 <= 255`，合法。
3.  **放入 (Append)**：`path` 变成 `["255"]`。
4.  **递归调用**：**`backtrack(3, ["255"])`**。
    *   我们**正式进入**这层递归的内部，不跳过了，详细看！

### 【第二层递归】
**目标**：寻找 IP 的第 2 段。
**当前状态**：`startIndex = 3`, `path = ["255"]`
**剩余字符串视角**：从索引 3 开始，是 `"25511135"`。

进入 `for` 循环，`i` 从 1 到 3。

#### 👉 循环第 1 次：i = 1
1.  **截取**：`s[3:4]` -> `"2"`。
2.  **判断**：合法。
3.  **放入**：`path` 变成 `["255", "2"]`。
4.  **递归**：`backtrack(4, ["255", "2"])`。
    > 剩余字符串 `"5511135"` (7位)。需要切 2 段。每段最多3位，2段最多6位。
    > **7 > 6**，位数不够用了！
    > 这一次递归进去后，每一层都会发现字符串太长了切不完，最终都会失败返回。
5.  **撤销**：把 `"2"` 弹出。`path` 变回 `["255"]`。

#### 👉 循环第 2 次：i = 2
1.  **截取**：`s[3:5]` -> `"25"`。
2.  **判断**：合法。
3.  **放入**：`path` 变成 `["255", "25"]`。
4.  **递归**：`backtrack(5, ["255", "25"])`。
    > 剩余字符串 `"511135"` (6位)。需要切 2 段。`2x3=6`。理论上有戏！
    > 但是，后面那个 `"511"` 大于 255，会受阻。这条路最后也会失败返回。
5.  **撤销**：把 `"25"` 弹出。`path` 变回 `["255"]`。

#### 👉 循环第 3 次：i = 3 （正确路径！）
1.  **截取**：`s[3:6]` -> `"255"`。
2.  **判断**：`255 <= 255`，合法。
3.  **放入**：`path` 变成 `["255", "255"]`。
4.  **递归**：**`backtrack(6, ["255", "255"])`**。
    *   **深入进入**这层递归！

### 【第三层递归】
**目标**：寻找 IP 的第 3 段。
**当前状态**：`startIndex = 6`, `path = ["255", "255"]`
**剩余字符串视角**：从索引 6 开始，是 `"11135"`。

进入 `for` 循环，`i` 从 1 到 3。

#### 👉 循环第 1 次：i = 1
1.  **截取**：`s[6:7]` -> `"1"`。
2.  **判断**：合法。
3.  **放入**：`path` 变成 `["255", "255", "1"]`。
4.  **递归**：`backtrack(7, ["255", "255", "1"])`。
    *   **进入第四层**（找第4段）：
        *   这里只剩最后一段了。
        *   代码会尝试切第 4 段。
        *   **如果**切 `"1"`：剩 `"135"` 没切完 -> 失败。
        *   **如果**切 `"11"`：剩 `"35"` 没切完 -> 失败。
        *   **如果**切 `"113"`：剩 `"5"` 没切完 -> 失败。
        *   **总结**：这一层全军覆没，返回。
5.  **撤销**：把 `"1"` 弹出。`path` 变回 `["255", "255"]`。

#### 👉 循环第 2 次：i = 2
1.  **截取**：`s[6:8]` -> `"11"`。
2.  **判断**：合法。
3.  **放入**：`path` 变成 `["255", "255", "11"]`。
4.  **递归**：**`backtrack(8, ["255", "255", "11"])`**。
    *   **进入第四层**（找第4段）：
        *   **状态**：`startIndex=8`, `path=["255", "255", "11"]`，剩余 `"135"`。
        *   **Loop i=1** (切"1") -> 剩 "35" -> 失败 -> 回溯。
        *   **Loop i=2** (切"13") -> 剩 "5" -> 失败 -> 回溯。
        *   **Loop i=3** (切"135") -> **合法！**
            *   `path` 变 `["255", "255", "11", "135"]`。
            *   **再递归进第五层**：
                *   检查 `len(path)==4`? 是。
                *   检查 `startIndex==len(s)`? 是！(都到末尾了)。
                *   **记录结果**：`result` 加入 `"255.255.11.135"`。
                *   return。
            *   **Pop**：拿走 "135"。
        *   第四层结束，返回。
5.  **撤销**：把 `"11"` 弹出。`path` 变回 `["255", "255"]`。

#### 👉 循环第 3 次：i = 3 （另一条正确路径！）
1.  **截取**：`s[6:9]` -> `"111"`。
2.  **判断**：合法。
3.  **放入**：`path` 变成 `["255", "255", "111"]`。
4.  **递归**：**`backtrack(9, ["255", "255", "111"])`**。
    *   **进入第四层**（找第4段）：我们要详细看这个！

### 【第四层递归】
**目标**：寻找 IP 的第 4 段。
**当前状态**：`startIndex = 9`, `path = ["255", "255", "111"]`
**剩余字符串视角**：从索引 9 开始，是 `"35"`。

进入 `for` 循环，`i` 从 1 到 3。

#### 👉 循环第 1 次：i = 1
1.  **截取**：`s[9:10]` -> `"3"`。
2.  **判断**：合法。
3.  **放入**：`path` 变成 `["255", "255", "111", "3"]`。
4.  **递归**：`backtrack(10, ["255", "255", "111", "3"])`。
    *   **进入第五层（检查层）**：
        *   `if len(path) == 4`: **是**（有4段了）。
        *   `if startIndex == len(s)`: `startIndex` 是 10，`len(s)` 是 11。**不相等！**
        *   这意味着：虽然你要了4段，但字符串还没切完（还剩个 "5"）。
        *   **直接 Return**。
5.  **撤销**：从 `path` 里弹出 `"3"`。`path` 变回 `["255", "255", "111"]`。

#### 👉 循环第 2 次：i = 2
1.  **截取**：`s[9:11]` -> `"35"`。
2.  **判断**：合法。
3.  **放入**：`path` 变成 `["255", "255", "111", "35"]`。
4.  **递归**：`backtrack(11, ["255", "255", "111", "35"])`。
    *   **进入第五层（检查层）**：
        *   `if len(path) == 4`: **是**。
        *   `if startIndex == len(s)`: `startIndex` 是 11，`len(s)` 是 11。**相等！**
        *   **成功！**
        *   `result.append("255.255.111.35")`。
        *   **Return**。
5.  **撤销**：从 `path` 里弹出 `"35"`。`path` 变回 `["255", "255", "111"]`。

#### 👉 循环第 3 次：i = 3
1.  **判断越界**：`startIndex + i` = 9 + 3 = 12。
2.  字符串总长只有 11。`12 > 11`。
3.  **Break**：直接跳出循环。

### 【回溯撤退过程】

到这里，**第四层**的所有循环（i=1, 2, 3）都跑完了。
函数执行完毕，自动**返回到第三层**。

**回到第三层**：
*   刚才我们停在 `i=3` 的递归调用上。
*   现在递归回来了。
*   **Code C (Pop)**：把 `"111"` 弹出。`path` 变回 `["255", "255"]`。
*   第三层的循环（i=1, 2, 3）也都跑完了。
*   第三层结束，**返回到第二层**。

**回到第二层**：
*   刚才停在 `i=3` 的递归上。
*   **Code C (Pop)**：把 `"255"` 弹出。`path` 变回 `["255"]`。
*   第二层的循环也跑完了。
*   第二层结束，**返回到第一层**。

**回到第一层**：
*   刚才停在 `i=3` 的递归上。
*   **Code C (Pop)**：把 `"255"` 弹出。`path` 变回 `[]`。
*   第一层循环结束。

**主函数结束**。
返回 `result`，里面装着 `["255.255.11.135", "255.255.111.35"]`。

---

### 这里的核心细节：
1.  **为什么 `pop` 这么重要？**
    如果不 `pop`，在第四层尝试完 `"3"` 失败后，列表里还有 `"3"`。紧接着尝试 `"35"` 时，列表就会变成 `["...111", "3", "35"]`，变成了 5 段，逻辑彻底崩坏。`pop` 保证了每次尝试都是在一个干净的基础上进行的。
2.  **为什么 i=1 失败了还要继续试 i=2？**
    因为这棵树是**宽度**为 3 的树。这一层切 1 个字符不行，不代表切 2 个字符不行。只有当所有宽度（1, 2, 3）都试完了，才说明这层彻底没戏，才回溯到上一层。
