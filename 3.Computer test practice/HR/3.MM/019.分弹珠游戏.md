Alice最近迷上分弹珠游戏，每次从箱子里拿出随机数量的弹珠，第一次将弹珠分为尽可能相等的两份，(偶数平分，奇数则其中一份比另外一份多一颗)，第二次将这两份弹珠各自再尽可能分为相等的两份，直到每份弹珠不超过2颗。如果第一次取出弹珠就已经少于三颗，则不用分，你能在Alice取出弹珠后就知道它要分多少次，最终会分成多少份吗? 

**输入描述**
一个整数N，表示Alice拿到的弹珠数。范围:0<N<131072

**输出描述**
输出分拆需要的次数，分拆完成后的分数，使用空格分割。
示例1
输入

1
输出
0 1
示例2
输入
11
输出
6 7
说明：
11 第一次拆分为5和6，第二次5拆分为2和3，第三次6拆分为两个3，每个3再拆分1次，共拆分6次，分为7份。

这个问题可以理解为一个**二叉树递归拆分**的过程。

### 1. 题目逻辑拆解

*   **拆分条件**：只要手中的弹珠数量 $N > 2$，就必须进行拆分。
*   **拆分方式**：
    *   如果是偶数 $N$，拆分为 $N/2$ 和 $N/2$。
    *   如果是奇数 $N$，拆分为 $(N-1)/2$ 和 $(N+1)/2$（即一个比另一个多1）。
*   **终止条件**：当每一份弹珠的数量 $\le 2$ 时，停止拆分。
*   **核心关系**：在分弹珠的过程中，每进行一次拆分动作，原来的 1 份就会变成 2 份。这意味着：**最终的份数 = 总拆分次数 + 1**。

### 2. 知识点总结
*   **递归（Recursion）**：处理这种“不断重复相同规则直到满足某个条件”的问题，递归是最直观的方法。
*   **分治思想**：将大问题（N）分解为小问题（两个子部分）。

### 3. 示例模拟：$N=11$
1.  **第一次拆分**：11 拆分为 **5** 和 **6**。（次数+1）
2.  **处理 5**：5 拆分为 **2** 和 **3**。（次数+1）
3.  **处理 6**：6 拆分为 **3** 和 **3**。（次数+1）
4.  **处理 3**（从5来的那个）：3 拆分为 **1** 和 **2**。（次数+1）
5.  **处理第一个 3**（从6来的）：3 拆分为 **1** 和 **2**。（次数+1）
6.  **处理第二个 3**（从6来的）：3 拆分为 **1** 和 **2**。（次数+1）
7.  **检查所有结果**：[2, 1, 2, 1, 2, 1, 2]，全部 $\le 2$，停止。
*   **总次数**：1 + 1 + 1 + 1 + 1 + 1 = **6次**。
*   **总份数**：6 + 1 = **7份**。

### 4. 代码实现

由于 $N < 131072$，递归的深度大约只有 $\log_2(131072) \approx 17$ 层，直接递归不会有性能问题。

```python
import sys

# 使用递归函数计算拆分次数
def count_splits(n):
    # 如果弹珠数不超过2，不需要拆分
    if n <= 2:
        return 0
    
    # 计算两个子部分的数量
    # // 是整除
    part1 = n // 2
    part2 = (n + 1) // 2
    
    # 总次数 = 当前拆分1次 + 左边拆分次数 + 右边拆分次数
    return 1 + count_splits(part1) + count_splits(part2)

def solve():
    line = sys.stdin.readline().strip()
    if not line:
        return
    
    n = int(line)
    
    # 得到总拆分次数
    splits = count_splits(n)
    
    # 最终份数 = 拆分次数 + 1
    parts = splits + 1
    
    print(f"{splits} {parts}")

if __name__ == "__main__":
    solve()
```

### 5. 关键点提示
1.  **整除与进位**：
    *   在 Python 中，`n // 2` 得到较小的半数，`(n + 1) // 2` 得到较大的半数。
    *   例如 $N=11$：`11 // 2 = 5`，`(11 + 1) // 2 = 6`。
    *   例如 $N=10$：`10 // 2 = 5`，`(10 + 1) // 2 = 5`。
2.  **递归基（Base Case）**：`if n <= 2: return 0` 是程序停止的钥匙，非常重要。
3.  **大数处理**：虽然 $N$ 有 13 万，但每次是折半减少，递归次数非常少，不需要担心超时。

通过这个递归模型，你可以清晰地看到每一次“动作”是如何发生的，并最终推导出份数。
