给定一组朋友关系，统计一下该朋友关系网中的朋友圈个数。

**朋友圈的定义:**一个朋友圈至少由3个朋友组成，且要求同一个朋友圈中的任意两个人都具有直接的朋友关系。

**输入描述**

输入一个朋友关系列表，如 Fiends =[A,B],[A,C],[B,D]，其中的每一个元素 Friendsi表示 Friends[i][0)和 Friends [i][1] 是朋友关系 

先输入一个数字 N 代表关系的总数，后面每条关系一行，两个成员以逗号分隔

**输出描述**

输出一个整数，表示整个关系网中朋友圈的个数
补充
1：Friends.length>=1，Friends.length<= 10^3
2：输入的总朋友个数<= 100
3：输入保证 Friend[i][0]和 Friend[i][1]一定不一样，且同一关系不会反向输入，即不会同时输入[A,B] 和 [B,A]。

4：不考虑子朋友圈，即当发现 [A,B,C,D]组成一个朋友圈时，[A,B,C]、[A,B,D]等子朋友圈不单独计数

示例1：

输入：

3
A,B
A,C
B,D

输出：

0

示例2：

输入：

7
A,B
A,C
B,C
A,D
D,E
B,D
A,E


输出：

3

示例3：

输入：

6
A,B
A,C
B,C
A,D
B,D
D,C

输出：

1





这道题考察的是图论中的一个经典概念：**极大团（Maximal Clique）**。

### 1. 核心知识点：最大团与极大团

*   **团（Clique）**：在一个无向图中，如果一个顶点子集中的任意两个顶点之间都存在一条边，则称这个子集为一个“团”。这对应题目中“任意两个人都具有直接的朋友关系”。
*   **极大团（Maximal Clique）**：如果一个团不能被其他任何团包含，它就是极大团。这对应题目中“不考虑子朋友圈，如发现 [A,B,C,D]，其子集不单独计数”。
*   **求解算法**：对于这种寻找图中所有极大团的问题，最著名的算法是 **Bron-Kerbosch 算法**。

### 2. 为什么不用简单的遍历？
如果只是寻找大小为 3 的团，我们可以用三重循环。但题目要求“不考虑子朋友圈”，意味着如果存在一个 5 人的朋友圈，你不能把它拆成很多个 3 人的。Bron-Kerbosch 算法天生就是用来找“最大范围”的朋友圈的。

虽然题目中朋友总数只有 100（$N \le 100$），但由于朋友圈（团）的数量在极端情况下可能很多，标准的 Bron-Kerbosch 算法是最稳妥的选择。

### 3. 题解代码 (Python)

```python
import sys

def solve():
    # 1. 读取输入
    input_data = sys.stdin.read().split()
    if not input_data:
        return
    
    try:
        n = int(input_data[0])
    except ValueError:
        return
    
    # 2. 构建邻接表
    from collections import defaultdict
    adj = defaultdict(set)
    nodes = set()
    
    for i in range(1, n + 1):
        # 处理 A,B 这种逗号分隔的格式
        u, v = input_data[i].split(',')
        adj[u].add(v)
        adj[v].add(u)
        nodes.add(u)
        nodes.add(v)
    
    # 结果计数
    maximal_cliques = []

    # 3. Bron-Kerbosch 算法
    # R: 当前团中的节点
    # P: 待处理的候选节点
    # X: 已经处理完的节点（用于排除重复的极大团）
    def bron_kerbosch(r, p, x):
        if not p and not x:
            # 找到一个极大团
            if len(r) >= 3:
                maximal_cliques.append(r)
            return
        
        # 为了优化效率，通常会引入 pivot（枢轴）
        # 这里使用基础版，对于 100 个点的规模已经足够
        p_list = list(p)
        for v in p_list:
            # 递归寻找包含 v 的极大团
            bron_kerbosch(
                r | {v}, 
                p & adj[v], 
                x & adj[v]
            )
            # 处理完 v 后，将其从候选集移到已处理集
            p.remove(v)
            x.add(v)

    # 执行算法
    bron_kerbosch(set(), nodes, set())

    # 4. 输出极大团的数量
    print(len(maximal_cliques))

if __name__ == "__main__":
    solve()
```

### 4. 代码深度解析

1.  **数据结构**：
    *   `adj`: 字典套集合（`defaultdict(set)`），存储每个人的好友名单。
    *   `nodes`: 存储所有出现过的人名。

2.  **Bron-Kerbosch 逻辑**：
    *   它是通过回溯搜索（DFS）来工作的。
    *   **R (Result)**：记录当前正在构建的朋友圈。
    *   **P (Possible)**：记录还有哪些人可以加入当前的圈子（这些人必须和 $R$ 里的所有人都是好友）。
    *   **X (Excluded)**：记录已经尝试过的人，防止重复计数。
    *   **终止条件**：当 `P` 和 `X` 都为空时，说明当前 $R$ 已经没法再加人了，且没有被之前找过的圈子包含，它就是一个“极大团”。

3.  **示例分析 (示例 2)**：
    *   关系：(A,B), (A,C), (B,C), (A,D), (D,E), (B,D), (A,E)。
    *   算法会找到：
        1. `{A, B, C}`：三个人两两认识。
        2. `{A, B, D}`：三个人两两认识。
        3. `{A, D, E}`：三个人两两认识。
    *   它们都是极大团（没有更大的 4 人团包含它们），所以输出 3。

4.  **示例分析 (示例 3)**：
    *   这是一个 4 人完全图（A,B,C,D 四人互相都认识）。
    *   算法只会找到一个极大团 `{A, B, C, D}`。
    *   因为 `{A, B, C}` 等子集被包含在里面，不会被计入结果。

*   **复杂度注意**：这个算法虽然在最坏情况下是指数级的，但在 100 个节点以内的社交网络问题中速度非常快。
