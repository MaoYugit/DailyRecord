某部门计划通过结队编程来进行项目开发，已知该部门有 N 名员工，每个员工有独一无二的职级，每三个员工形成一个小组进行结队编程，结队分组规则如下:
从部门中选出序号分别为 i、j、k 的3名员工，他们的职级分别为 leve[i]，level[j]，level[k],结队小组满足 level[i] < level[j] < level[k] 或者 level[i] > level[j] > level[k],其中0<i<j<k<n。
请你按上述条件计算可能组合的小组数量。同一员工可以参加多个小组.

**输入描述**
第一行输入: 员工总数 n
第二行输入: 按序号依次排列的员工的职级 level，中间用空格隔开
备注:
1≤n≤6000
1 ≤ level[i] ≤10^5

**输出描述**
可能结队的小组数量

**示例1：**
输入

4
1 2 3 4
输出

4
说明
可能结队成的组合(1,2,3)、(1,2,4)、(1,3,4)、(2,3,4)

**示例2：**
输入
3
5 4 7
输出

0
说明
根据结队条件，我们无法为该部门组建小组

这道题的核心考察点是**三元组的统计**。

### 题目分析
我们需要在数组中找到满足以下条件的 `(i, j, k)`：
1.  下标顺序：$i < j < k$
2.  职级顺序：$level[i] < level[j] < level[k]$（升序） **或者** $level[i] > level[j] > level[k]$（降序）。

### 最优解法：枚举中间元素
如果直接用三层循环遍历 $i, j, k$，时间复杂度是 $O(N^3)$。当 $N=6000$ 时，$6000^3$ 约为 2160 亿，绝对会超时。

**改进思路：**
我们可以**枚举中间的元素 $j$**。对于每一个 $j$，我们只需要知道：
*   在 $j$ 的左边，有多少个元素比 $level[j]$ 小（记为 `left_smaller`）。
*   在 $j$ 的左边，有多少个元素比 $level[j]$ 大（记为 `left_larger`）。
*   在 $j$ 的右边，有多少个元素比 $level[j]$ 小（记为 `right_smaller`）。
*   在 $j$ 的右边，有多少个元素比 $level[j]$ 大（记为 `right_larger`）。

那么，以 $j$ 为中心的小组数量就是：
*   升序组：`left_smaller * right_larger`
*   降序组：`left_larger * right_smaller`
*   总数 = 两者之和。

### 算法实现
虽然 $O(N^2)$ 的算法（双层循环统计左右数量）在 $N=6000$ 时约为 $3.6 \times 10^7$，在 Python 中可能稍显勉强，但使用 **树状数组 (Binary Indexed Tree, BIT)** 可以将复杂度降到 $O(N \log M)$，其中 $M$ 是职级的最大值（$10^5$），这是最稳妥的解法。

#### Python 代码实现（树状数组版）

```python
import sys

class FenwickTree:
    def __init__(self, size):
        self.tree = [0] * (size + 1)
        
    def add(self, i, delta):
        while i < len(self.tree):
            self.tree[i] += delta
            i += i & (-i)
            
    def query(self, i):
        s = 0
        while i > 0:
            s += self.tree[i]
            i -= i & (-i)
        return s

def solve():
    # 读取输入
    input_data = sys.stdin.read().split()
    if not input_data:
        return
    
    n = int(input_data[0])
    levels = list(map(int, input_data[1:]))
    
    if n < 3:
        print(0)
        return

    # 职级范围最大到 10^5
    MAX_LEVEL = 100000
    
    # left_smaller[j] 存储在 j 左边比 levels[j] 小的人数
    left_smaller = [0] * n
    # left_larger[j] 存储在 j 左边比 levels[j] 大的人数
    left_larger = [0] * n
    
    bit = FenwickTree(MAX_LEVEL)
    for j in range(n):
        v = levels[j]
        left_smaller[j] = bit.query(v - 1)
        left_larger[j] = j - left_smaller[j]
        bit.add(v, 1)
        
    # right_smaller[j] 存储在 j 右边比 levels[j] 小的人数
    right_smaller = [0] * n
    # right_larger[j] 存储在 j 右边比 levels[j] 大的人数
    right_larger = [0] * n
    
    bit = FenwickTree(MAX_LEVEL)
    for j in range(n - 1, -1, -1):
        v = levels[j]
        right_smaller[j] = bit.query(v - 1)
        # 右边总共有 n-1-j 个元素
        right_larger[j] = (n - 1 - j) - right_smaller[j]
        bit.add(v, 1)
        
    # 计算总和
    ans = 0
    for j in range(n):
        # 升序情形: i < j < k 且 L[i] < L[j] < L[k]
        ans += left_smaller[j] * right_larger[j]
        # 降序情形: i < j < k 且 L[i] > L[j] > L[k]
        ans += left_larger[j] * right_smaller[j]
        
    print(ans)

if __name__ == "__main__":
    solve()
```

### 关键点解释：

1.  **树状数组 (BIT)**：
    *   它的作用是高效地求出“前缀和”。
    *   当我们从左往右遍历数组并把遇到的职级 `v` 放入 BIT 中（`add(v, 1)`），那么 `query(v-1)` 就能立刻告诉我们当前已经出现了多少个比 `v` 小的数。
    *   时间复杂度为 $O(\log M)$。

2.  **左右统计**：
    *   通过两次遍历（一次正向，一次反向），我们可以预处理出每个元素左右两边比它大/小的具体人数。
    *   **正向遍历**：统计左边比自己小的。因为此时总共处理了 $j$ 个元素，所以 `j - left_smaller` 就是左边比自己大的数量。
    *   **反向遍历**：统计右边比自己小的。

3.  **组合计算**：
    *   对于下标 $j$，左边有 $A$ 个小的，右边有 $B$ 个大的，根据乘法原理，满足 $L[i] < L[j] < L[k]$ 的组合就有 $A \times B$ 种。

### 复杂度分析：
*   **时间复杂度**：$O(N \log M)$，其中 $N=6000$，$M=10^5$。计算量级在 $10^5$ 左右，Python 运行速度极快。
*   **空间复杂度**：$O(N + M)$，主要是存储 `left/right` 数组和树状数组的空间。

对于 $N=6000$ 这样的规模，$O(N^2)$ 的算法虽然在 Python 中运行时间会接近 1-2 秒（取决于具体的判题机性能），但逻辑非常直观，且不需要额外的数据结构基础。

### $O(N^2)$ 算法逻辑：
1. **枚举中间人**：遍历数组中的每一个元素，假设它是三元组中间的那个 `level[j]`。
2. **两边统计**：
   - 对于当前的 `level[j]`，向左扫描一遍，统计比它小的数（`left_smaller`）和比它大的数（`left_larger`）。
   - 向右扫描一遍，统计比它小的数（`right_smaller`）和比它大的数（`right_larger`）。
3. **组合计算**：
   - 升序三元组数量 = `left_smaller * right_larger`
   - 降序三元组数量 = `left_larger * right_smaller`
4. **累加结果**。

### Python 代码实现：

```python
import sys

def solve():
    # 1. 读取输入
    input_data = sys.stdin.read().split()
    if not input_data:
        return
    
    n = int(input_data[0])
    # 转换为整数列表
    levels = [int(x) for x in input_data[1:]]
    
    # 如果人数少于 3，无法组成小组
    if n < 3:
        print(0)
        return

    total_count = 0
    
    # 2. 枚举中间人 j
    # 中间人的下标范围是 1 到 n-2 (因为前后至少要各留一个位置)
    for j in range(1, n - 1):
        mid_val = levels[j]
        
        left_smaller = 0
        left_larger = 0
        right_smaller = 0
        right_larger = 0
        
        # 统计左边 (0 到 j-1)
        for i in range(j):
            if levels[i] < mid_val:
                left_smaller += 1
            elif levels[i] > mid_val:
                left_larger += 1
        
        # 统计右边 (j+1 到 n-1)
        for k in range(j + 1, n):
            if levels[k] < mid_val:
                right_smaller += 1
            elif levels[k] > mid_val:
                right_larger += 1
        
        # 3. 累加两种情况
        # 情况1: level[i] < level[j] < level[k] (升序)
        total_count += left_smaller * right_larger
        # 情况2: level[i] > level[j] > level[k] (降序)
        total_count += left_larger * right_smaller

    # 4. 输出最终结果
    print(total_count)

if __name__ == "__main__":
    solve()
```

### 为什么 $O(N^2)$ 能跑通？
- **理论计算量**：对于 $N=6000$，内层两个循环的总次数大约是 $6000 \times (j + (n-1-j)) = 6000 \times 6000 = 3.6 \times 10^7$。
- **Python 运行效率**：在大多数在线评测系统（OJ）中，1 秒内可以处理约 $10^7 \sim 10^8$ 次简单运算。由于我们这里的内层循环只有简单的 `if` 比较和加法，没有复杂的函数调用，因此在 $N=6000$ 的情况下有很大机会在时限内跑完。

### 优缺点：
- **优点**：代码极其简单，没有任何复杂的数据结构（如树状数组或线段树），容易调试，不容易写错。
- **缺点**：当 $N$ 增加到 $10,000$ 或更大时，时间开销会迅速增加（按平方倍数增长），而 $O(N \log M)$ 的算法则能处理更大数据量。
