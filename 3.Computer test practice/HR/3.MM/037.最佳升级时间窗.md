有一套系统需升级，为减小系统升级期间的影响，需根据系统过去一段时间内的每小时平均访问数据，来预测最佳升级时间窗。

现给长度为168（7*24）的整数数组，表示一个周期（假设从周一00:00到周日24:00）的每小时历史数据，最佳升级时间窗选择规则如下：

1：时间窗内累计用户访问量必须小于等于给定的容忍值。

2：时间窗必须是连续的x个小时，最大的x即为最佳升级时间窗，且不超过7*24.

3：时间窗允许跨周期，例如当前周期的第167小时到下一周期的第166小时，是一个长度为168的时间窗。

请计算最佳升级时间窗，并返回其开始时间和结束时间的数组下标。如果存在多个最佳升级时间窗，返回开始时间下标最小的一个。

输入

第一行为整数n，表示给定的升级影响的容忍值，取值范围：[0, 2^31]。

第二行为7*24个整数，表示一个周期（7*24）的每个小时用户访问量，每个值的范围：[0, 2^31]。

输出

两个整数，分别表示所计算出的最佳升级时间窗的开始时间下标（包含）和结束时间下标（包含），不存在时返回 -1 -1 。

输入

22 25

这是一道典型的**滑动窗口（Sliding Window）**或**双指针**问题，应用于环形数组。

### 题目逻辑分析

1.  **核心目标**：寻找一个最长的连续子数组（时间窗），使得其元素之和 **$\le$ 容忍值 $n$**。
2.  **约束条件**：
    *   长度 $x$ 最大为 168。
    *   允许跨周期（环形数组）：例如从 167 小时跨越到下一周期的 0 小时。
    *   若有多个最长窗口，取开始下标最小的一个。
3.  **算法策略**：
    *   **处理环形**：将长度为 168 的数组拼接在自己后面，形成长度为 336 的数组。这样任何跨周期的窗口都能变成一段连续的区间。
    *   **双指针（滑动窗口）**：维护一个窗口 `[left, right]`，右指针向右移动扩大窗口，当窗口内总和超过 $n$ 时，左指针向右移动缩小窗口。同时限制窗口长度不超过 168。

### Python 代码实现

```python
import sys

def solve():
    # 1. 处理输入
    # sys.stdin.read().split() 可以自动处理空格和跨行，读取所有整数
    input_data = sys.stdin.read().split()
    if not input_data:
        return
    
    # 第一个数是容忍值 n
    n = int(input_data[0])
    # 后面 168 个数是每个小时的访问量
    # 即使输入给得更多，我们也只取前 168 个作为一周期
    arr = [int(x) for x in input_data[1:169]]
    
    L = 168 # 周期长度
    # 处理环形：将数组拼接一遍，长度变为 336
    # 这样跨周期的窗口（如 167 到 166）就能以连续子数组的形式表示
    data = arr + arr
    
    max_len = 0
    best_start = -1
    best_end = -1
    
    # 2. 滑动窗口
    # right 指针在整个循环中不回退，保证 O(N) 时间复杂度
    right = 0
    current_sum = 0
    
    # 遍历每一个可能的起始点 left (0 到 167)
    for left in range(L):
        # 如果右指针落后于左指针，重置右指针和当前累加和
        if right < left:
            right = left
            current_sum = 0
        
        # 尝试向右扩展右指针
        # 条件：窗口长度不超过 168 且 累加和不超过容忍值 n
        # 注意：虽然题目写的是“大于”，但根据“减小影响”的逻辑和示例，应为“不超过”
        while right < left + L and current_sum + data[right] <= n:
            current_sum += data[right]
            right += 1
            
        # 此时窗口为 [left, right-1]，长度为 right - left
        current_len = right - left
        
        # 如果找到了更长的窗口，更新记录
        # 因为 left 是从小到大遍历的，所以当长度相等时我们不更新，
        # 这样自然就保证了返回的是“开始时间下标最小”的一个。
        if current_len > max_len:
            max_len = current_len
            best_start = left
            # 结束下标需要对 168 取模，还原到原始周期内
            best_end = (right - 1) % L
            
        # left 指针即将右移，从累加和中减去当前左边界的值
        if right > left:
            current_sum -= data[left]

    # 3. 输出结果
    if max_len == 0:
        print("-1 -1")
    else:
        print(f"{best_start} {best_end}")

if __name__ == "__main__":
    solve()
```

### 代码要点说明：

1.  **输入处理**：由于 168 个数字可能分布在多行，`sys.stdin.read().split()` 是最稳妥的读取方式。
2.  **窗口移动逻辑**：
    *   `right` 指针不需要重置。它在整个过程中只向右移动，这使得算法的时间复杂度为 $O(L)$，即 $O(168)$。
    *   `while` 条件中的 `current_sum + double_arr[right] <= n` 是核心约束。
3.  **下标取模**：当 `right` 超过 167 时，说明发生了跨周期。`(right - 1) % 168` 可以正确地将 168 映射回 0，169 映射回 1。
4.  **优先级处理**：题目要求返回开始下标最小的一个。我们在代码中使用 `if current_len > max_len`（严格大于）而非 `>=`，因此在找到同样长度的窗口时，会保留第一次发现的（即 `left` 最小的）那个。

### 示例运行（以题目为例）：
输入 $n=6$ 和那一串数字：
*   当 `left=22` 时，访问量序列为 `2, 1, 1, 2`（下标 22, 23, 24, 25）。
*   其和为 6，长度为 4。
*   此后无法找到长度为 5 且和 $\le 6$ 的窗口。
*   最终输出：`22 25`。
