**一、题目描述**
小朋友考试得第一名就可以得到零食奖励。

现在价格A、B、C、D、E、…，元商品名A1、B1、C1、D1、E1、…，小朋友的喜爱度依次为A2、B2、C2、D2、E2、…。

请返回选取x元零食可以达到的最大喜爱度。

**二、输入描述**
第一行输入为x和N，x为可使用的钱的总额，N为零食种类数。

0 ≤ x ≤ 1000
0 ≤ N ≤ 100

第二行开始为零食属性，每行有三个整型数值，分别代表零食的价格、数量和喜爱度。

零食价格(0,100)
零食个数[0,10000]
零食喜爱度[0,10000]

**三、输出描述**
最大喜爱度

**四、测试用例**
示例1：
输入:
10 2
2 4 3
3 3 4

输出:
14

说明:
可选第1种零食最多 4 个，第2种最多 3 个。最佳选择为：选 2 个第2种（花费 6 元，喜爱度 8）和 2 个第1种（花费 4 元，喜爱度 6），总计花费 10 元，总喜爱度 14。输出 14。

示例2：
输入:
6 7
3 1 8
4 1 2
3 1 1
9 1 7
4 1 1
5 1 8
4 1 4

输出:
9

说明:
6元可以购买两个3元的零食，喜爱度综合为8+1=9

这道题是一个典型的**多重背包问题 (Multiple Knapsack Problem)**。

### 题目分析
1.  **目标**：在有限的钱 $x$ 下，选择不同种类的零食，使得总“喜爱度”最大。
2.  **限制**：
    *   总预算 $x$。
    *   每种零食有自己的价格（消耗）、喜爱度（价值）以及**数量限制**（个数）。
3.  **算法选择**：
    *   如果每种零食只有一个，那是“0/1背包”。
    *   如果每种零食无限个，那是“完全背包”。
    *   **本题每种零食有具体的个数限制，属于“多重背包”**。

### 优化策略
直接使用三层循环遍历个数可能会超时（虽然本题 $x \le 1000$ 规模较小，暴力拆分也能过），但更标准高效的做法是**二进制拆分法**。
*   **二进制拆分**：将 $C$ 个数量的某种零食拆分成若干组，每组的数量分别为 $1, 2, 4, 8, \dots, 2^k$ 以及剩下的余数。这样可以将多重背包转化为 0/1 背包，大大减少计算量。

### Python 代码实现

```python
import sys

def solve():
    # 1. 读取输入
    input_data = sys.stdin.read().split()
    if not input_data:
        return
    
    # x: 总预算, n: 零食种类数
    x = int(input_data[0])
    n = int(input_data[1])
    
    items = []
    idx = 2
    for _ in range(n):
        if idx + 2 >= len(input_data):
            break
        price = int(input_data[idx])
        count = int(input_data[idx+1])
        like = int(input_data[idx+2])
        items.append((price, count, like))
        idx += 3
        
    # 2. 二进制拆分转化为 0/1 背包
    # simplified_items 存储 (价格, 喜爱度)
    simplified_items = []
    for price, count, like in items:
        # 优化：如果该零食买不起，直接跳过
        if price > x or count == 0:
            continue
        
        # 将 count 进行二进制拆分
        k = 1
        while k <= count:
            simplified_items.append((k * price, k * like))
            count -= k
            k *= 2
        if count > 0:
            simplified_items.append((count * price, count * like))
            
    # 3. 0/1 背包动态规划
    # dp[j] 表示花费 j 元能达到的最大喜爱度
    dp = [0] * (x + 1)
    
    for item_price, item_like in simplified_items:
        # 逆序遍历，确保每个拆分出来的物品只被计算一次
        for j in range(x, item_price - 1, -1):
            if dp[j - item_price] + item_like > dp[j]:
                dp[j] = dp[j - item_price] + item_like
                
    # 4. 输出结果
    print(dp[x])

if __name__ == "__main__":
    solve()
```

### 逻辑详解：

1.  **为什么需要拆分？**
    如果某种零食有 10 个，你不需要尝试“拿1个、拿2个...拿10个”。通过拆分成 1, 2, 4, 3（剩下的）这四组，你可以通过组合这四组来表示 0 到 10 之间的任意整数。这样计算次数从 10 次降到了 4 次。

2.  **DP 数组的含义**：
    `dp[j]` 存储的是当前预算为 `j` 时的最优解。
    当我们处理一个新的物品（拆分后的）时，我们更新 `dp` 数组。
    **逆序遍历** `range(x, item_price - 1, -1)` 是 0/1 背包的固定写法，目的是为了保证我们在计算 `dp[j]` 时用到的 `dp[j - item_price]` 是“上一轮”的结果，即该物品还没被放入时的结果。

3.  **示例 1 模拟**：
    *   预算 10。
    *   零食1：价格 2, 数量 4, 喜爱度 3。拆分为：(价格2,喜爱度3), (价格4,喜爱度6), (价格2,喜爱度3)。
    *   零食2：价格 3, 数量 3, 喜爱度 4。拆分为：(价格3,喜爱度4), (价格6,喜爱度8)。
    *   在 10 元预算下，最优组合是 (价格6,喜爱度8) + (价格2,喜爱度3) + (价格2,喜爱度3) = 总价 10，喜爱度 14。

### 复杂度分析：
*   **时间复杂度**：$O(N \cdot X \cdot \log(\text{max\_count}))$。在本题中最大约 $100 \times 1000 \times 14 \approx 1.4 \times 10^6$，在 Python 的执行效率范围内。
*   **空间复杂度**：$O(X)$​，即预算的大小。

如果不使用二进制拆分，最直接的方法就是使用**多重背包的原始状态转移方程**。这种方法通过三层循环来实现：第一层遍历物品，第二层遍历当前拥有的钱，第三层遍历当前物品挑选的数量。

这种写法逻辑上最直观，但在数据量极大时效率不如二进制拆分。不过对于本题的规模（钱 1000，种类 100），这种写法是可以正常运行的。

### 多重背包原始 DP 代码

```python
import sys

def solve():
    # 1. 读取输入
    input_data = sys.stdin.read().split()
    if not input_data:
        return
    
    # x: 总预算, n: 零食种类数
    x = int(input_data[0])
    n = int(input_data[1])
    
    # dp[j] 表示花费 j 元能达到的最大喜爱度
    dp = [0] * (x + 1)
    
    # 2. 三层循环处理多重背包
    # 第一层：遍历每一种零食
    idx = 2
    for _ in range(n):
        price = int(input_data[idx])    # 价格
        count = int(input_data[idx+1])  # 数量
        like = int(input_data[idx+2])   # 喜爱度
        idx += 3
        
        # 第二层：从总钱数 x 开始逆序遍历 (保证每种零食的更新基于前一种零食的结果)
        for j in range(x, -1, -1):
            # 第三层：尝试购买 k 个当前零食
            # 必须满足：购买 k 个的价格不超过当前的钱 j，且 k 不超过零食的总数 count
            for k in range(1, count + 1):
                if j >= k * price:
                    # 比较：不买这 k 个 vs 买这 k 个（剩下的钱 j - k*price 对应的最大喜爱度 + 这 k 个的喜爱度）
                    if dp[j - k * price] + k * like > dp[j]:
                        dp[j] = dp[j - k * price] + k * like
                else:
                    # 如果买 k 个已经买不起了，买 k+1 个肯定也买不起，直接结束第三层循环
                    break
                    
    # 3. 输出花费 x 元能达到的最大值
    print(dp[x])

if __name__ == "__main__":
    solve()
```

### 核心逻辑解释：

1.  **`dp[j]` 的定义**：
    它代表“当我兜里只有 `j` 元钱时，能买到的最大喜爱度总和”。

2.  **为什么 `j` 要逆序遍历（从 `x` 到 `0`）？**
    这是背包问题的经典逻辑。如果我们正序遍历，在计算买当前零食的数量时，可能会重复用到已经更新过的 `dp` 值，导致同一种物品被“无限次”购买（变成了完全背包）。逆序遍历可以确保在考虑当前零食时，我们参考的是“还没买这种零食之前”的最优状态。

3.  **第三层循环的作用**：
    它在做决策：对于当前这种零食，我是买 0 个、1 个、2 个... 还是买到上限？
    `dp[j] = max(dp[j], dp[j - k*price] + k*like)` 就是在这些选项中挑一个最大的。

### 优缺点对比：

*   **优点**：代码逻辑非常简单易懂，完全按照题目描述的“价格、数量、喜爱度”三个维度来思考，不需要额外的数学变换（二进制转换）。
*   **缺点**：计算次数较多。如果某种零食价格为 1 元且有 1000 个，那么第三层循环就要跑 1000 次。总复杂度是 $O(N \cdot X \cdot \text{count})$。

**总结**：在考试或面试中，如果数据范围不大（如本题 $X=1000$），这种写法是最稳妥、最不容易写错的。如果数据范围到了 $10^5$ 以上，就需要考虑之前提到的二进制拆分优化了。



这是一个非常经典的想法，但结论是：**这道题不能用贪心算法（性价比优先）来求最优解。**

虽然在现实生活中，我们买东西倾向于看“性价比”，但在算法竞赛的“整数背包问题”中，贪心算法往往只能得到一个“接近”的答案，而不是“绝对”的最大值。

### 为什么贪心算法不行？

贪心算法失效的根本原因在于：**物品是不可分割的整数个体（你不能买半个零食）**。

让我们看一个简单的**反例**：

假设你有 **10元**，商店里有两种零食：
*   **零食A**：价格 6 元，喜爱度 10（性价比 $10/6 \approx 1.66$）
*   **零食B**：价格 5 元，喜爱度 8 （性价比 $8/5 = 1.6$）

**如果用贪心算法：**
1.  优先选性价比最高的 **零食A**。
2.  花费 6 元，剩下 4 元。
3.  剩余的 4 元买不起任何东西了。
4.  **总喜爱度 = 10**。

**如果用动态规划（全局最优）：**
1.  放弃性价比最高的 A，选择买两个 **零食B**。
2.  花费 $5 + 5 = 10$ 元，正好花完。
3.  **总喜爱度 = $8 + 8 = 16$**。

**结论：** 16 远大于 10。贪心算法因为“太贪婪”选了单价最划算的，结果导致剩下的钱（4元）变成了无法利用的浪费，反而降低了总收益。

---

### 什么时候可以用贪心？

只有在以下两种情况，贪心（性价比优先）才是对的：
1.  **物品可以分割**：比如买散装大米、散装砂糖，你可以买 0.5 公斤，这样能保证把最后一分钱都填满。（这叫“分数背包问题”）
2.  **物品价格全部一样**：这时直接挑喜爱度最高的就行。
3.  **物品价格和喜爱度成完美正比**：这种情况极少见。

### 回到本题的测试用例 2
我们再看看示例 2 的数据：
预算 **6元**：
*   商品1：3元, 1个, 喜爱度 8 (性价比 2.66)
*   商品6：5元, 1个, 喜爱度 8 (性价比 1.6)
*   商品7：4元, 1个, 喜爱度 4 (性价比 1.0)
*   商品3：3元, 1个, 喜爱度 1 (性价比 0.33)

**贪心逻辑：**
1. 选性价比最高的“商品1”（3元，8点喜爱度）。
2. 还剩 3 元。
3. 剩下的 3 元里，性价比最高的是“商品3”（3元，1点喜爱度）。
4. 总喜爱度 = $8 + 1 = 9$。

在这个特定的例子里，贪心正好撞到了正确答案。但如果我把“商品6”的喜爱度从 8 改成 10，贪心依然会先选“商品1”，最后得 9 分；而实际最优解应该是选“商品6”加剩下的钱，或者其他组合。

### 总结
对于这种**“有限预算、整数件数、求最大价值”**的问题，必须使用**动态规划（DP）**。
*   **DP** 的本质是：穷举了所有可能的凑钱方案，并记住了每种金额下能凑出的最大价值，从而保证最后拿到的结果是全局最优的。
