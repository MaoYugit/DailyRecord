部门在进行需求开发时需要进行人力安排。当前部门需要完成 N 个需求，需求用 requirements[i] 表示，requirements[i] 表示第 i 个需求的工作量大小，单位：人月。这部分需求需要在 M 个月内完成开发，进行人力安排后每个月的人力是固定的。

目前要求每个月最多有 2 个需求开发，并且每个月需要完成的需求不能超过部门人力。请帮部门评估在满足需求开发进度的情况下，每个月需要的最小人力是多少？

**输入描述**
输入第一行为 M ，第二行为 requirements ，长度为N。

M 表示需要开发时间要求，requirements 表示每个需求工作量大小

N 为 requirements 长度。

1 ≤ N / 2 ≤ M ≤ N ≤ 10000，1 ≤ requirements[i]≤ 10^9

**输出描述**
对于每一组测试数据，输出部门需要人力需求，行末无多余的空格。

**示例1：**
输入
3
3 5 3 4
输出
6
说明

当选择人力为6时，2个需求量为3的工作可以在1个月里完成，其他2个工作各需要1个月完成。可以在3个月内完成所有需求。

当选择人力为5时，4个工作各需要1个月完成，一共需要4个月才能完成所有需求。

因此6是部门最小的人力需求。

---

这道题的核心思路是**二分查找（Binary Search）**结合**贪心算法（Greedy）**。

### 题目分析
1.  **约束条件**：
    *   总共有 $N$ 个需求，每个需求有工作量。
    *   必须在 $M$ 个月内完成。
    *   **重点**：每个月最多只能开发 **2 个** 需求。
    *   每个月的人力是固定的，设为 $H$，则每个月分配的需求总和不能超过 $H$。
2.  **目标**：寻找满足条件的**最小**人力 $H$。

### 算法设计
1.  **二分搜索范围**：
    *   **最小值（left）**：数组中的最大值（因为任何一个需求都必须能在某个月独立完成）。
    *   **最大值（right）**：数组中最大的两个值之和（因为每个月最多放两个，最极端的情况就是把最大的两个凑在一起）。
2.  **贪心校验（check 函数）**：
    给定一个人力值 $X$，能否在 $M$ 个月内完成？
    *   为了尽可能节省月份，我们希望一个月能尽可能“凑成两对”。
    *   **最优配对策略**：将需求按工作量从小到大排序。使用双指针，尝试将**当前最小的**和**当前最大的**需求配对。
    *   如果 `min + max <= X`，说明这两个需求可以放在同一个月。
    *   如果 `min + max > X`，说明这个最大的需求无法与任何其他需求配对（连最小的都带不动它），只能让它独自占用一个月。
    *   最后计算总月份，若总月份 $\le M$，则人力 $X$ 可行。

### Python 代码实现

```python
import sys

def check(limit, requirements, m):
    """
    检查在每月人力为 limit 的情况下，是否能在 m 个月内完成
    """
    count = 0
    left = 0
    right = len(requirements) - 1
    
    while left <= right:
        # 如果当前最大的和最小的能凑一对
        if left < right and requirements[left] + requirements[right] <= limit:
            left += 1
            right -= 1
        else:
            # 否则最大的只能单独占一个月
            right -= 1
        
        count += 1
        # 如果超过了规定月份，直接返回失败
        if count > m:
            return False
            
    return count <= m

def solve():
    # 读取输入
    input_data = sys.stdin.read().split()
    if not input_data:
        return
    
    m = int(input_data[0])
    # 剩余的全部是需求工作量
    requirements = sorted([int(x) for x in input_data[1:]])
    
    # 二分查找范围
    # 下界：最大的单个需求量
    # 上界：最大的两个需求量之和
    low = max(requirements)
    high = requirements[-1] + (requirements[-2] if len(requirements) > 1 else 0)
    
    ans = high
    
    while low <= high:
        mid = (low + high) // 2
        if check(mid, requirements, m):
            ans = mid
            high = mid - 1 # 尝试更小的人力
        else:
            low = mid + 1  # 人力不足，需要增加
            
    print(ans)

if __name__ == "__main__":
    solve()
```

### 复杂度分析
1.  **时间复杂度**：
    *   排序：$O(N \log N)$。
    *   二分查找：循环 $O(\log(\text{MaxCapacity}))$ 次（约 30 次）。
    *   `check` 函数：$O(N)$。
    *   总复杂度：$O(N \log N + N \cdot \log(\text{MaxCapacity}))$。对于 $N=10000$ 的规模，运行速度极快。
2.  **空间复杂度**：$O(N)$，用于存储需求数组。

### 示例校验
**输入**：
`M = 3`, `req = [3, 5, 3, 4]`
1.  排序后：`[3, 3, 4, 5]`
2.  二分测试 $H=5$：
    *   (3, 5) 不行，5 占一个月；(3, 4) 不行，4 占一个月；(3, 3) 不行，3 占一个月；剩余 3 占一个月。总共 4 个月 > 3，失败。
3.  二分测试 $H=6$：
    *   (3, 5) 不行，5 占一个月；(3, 4) 不行，4 占一个月；(3, 3) 可以，占一个月。总共 3 个月 $\le 3$，成功。
4.  最终输出 **6**。
