在产品配置中，一个配置产品是由多个产品模块(CM)构成，每个CM有自身的算法，且模块间可能存在算法依赖。例如电脑产品是由主板、CPU日、显卡等CM构成。CPU模块(CM1)算法依赖主板模块(CM2)算法，记作CM2<-CM1,算法引擎会通过算法依赖确保此前后CM执行的顺序。如果存在模块算法循环依赖的场景，那么算法引擎会报警。

**输入描述**
输入的第一行为模块列表，例如CM2，CM3，CM4;
输入的第二行为依赖情况,例如CM3<-CM2

**输出描述**
计算出循环依赖的CM数量

示例1：

输入：

CM1,CM2,CM3,CM4,CM5,CM6

CM5<-CM3,CM4<-CM5,CM6<-CM4,CM6<-CM1,CM5<-CM6

输出：

3

示例2：

输入：

CM1,CM2,CM3,CM4,CM5,CM6
CM5<-CM3,CM3<-CM6,CM6<-CM4,CM3<-CM4,CM4<-CM1

输出：

0



你的直觉非常敏锐！这道题本质上确实是**有向图的环路检测**问题。

在图论算法中，这类问题有一个标准的考点和解决方法：**拓扑排序（Topological Sort）**。

### 1. 考点分析
*   **知识点名称**：有向图的拓扑排序（Kahn 算法）。
*   **核心逻辑**：
    *   在依赖关系图中，如果不存在环，我们可以按照先后顺序把所有节点排成一排（即拓扑序列）。
    *   如果存在环，那些**在环里的节点**（以及依赖这些环的节点）永远无法被排进序列中。
*   **题目目标**：计算哪些 CM（模块）处于循环依赖中。通过拓扑排序，我们剔除掉那些可以正常排队的节点，剩下的就是无法解开依赖的节点数量。

---

### 2. 逻辑详解：如何解题？

我们以 **示例 1** 为例拆解过程：
*   **节点**：CM1, CM2, CM3, CM4, CM5, CM6
*   **依赖关系**（$A \leftarrow B$ 表示 B 依赖 A，即 A 必须先执行，边为 $A \to B$）：
    1.  $CM3 \to CM5$
    2.  $CM5 \to CM4$
    3.  $CM4 \to CM6$
    4.  $CM1 \to CM6$
    5.  $CM6 \to CM5$

#### 第一步：计算入度（In-degree）
入度是指有多少条边指向这个节点。入度为 0 的节点意味着它不依赖任何其他节点，可以最先执行。
*   CM1: 0
*   CM2: 0
*   CM3: 0
*   CM4: 1 (来自 CM5)
*   CM5: 2 (来自 CM3 和 CM6)
*   CM6: 2 (来自 CM1 和 CM4)

#### 第二步：拓扑排序（Kahn 算法过程）
1.  **找入度为 0 的节点入队**：当前队列为 `[CM1, CM2, CM3]`。
2.  **处理 CM1**：把它从图中移除。它指向 CM6，所以 CM6 的入度减 1（变成 1）。
3.  **处理 CM2**：移除。无指向。
4.  **处理 CM3**：移除。它指向 CM5，所以 CM5 的入度减 1（变成 1）。
5.  **检查队列**：现在没有新的入度为 0 的节点了，排序停止。

#### 第三步：统计结果
*   总节点数：6
*   成功被移除（正常）的节点：3 个 (CM1, CM2, CM3)
*   **无法被移除（循环依赖）的节点数**：$6 - 3 = 3$ 个。
*   剩下的节点是 CM4, CM5, CM6。它们互相拉扯（$5 \to 4 \to 6 \to 5$），入度永远减不到 0。

### 3. 代码实现

这道题处理输入字符串稍微有点麻烦，但算法核心很清晰：

```python
import sys
from collections import deque, defaultdict

def solve():
    # 1. 解析输入
    try:
        line1 = sys.stdin.readline().strip()
        if not line1: return
        all_nodes = line1.split(',')
        
        line2 = sys.stdin.readline().strip()
        # 处理可能没有依赖的情况
        dependencies = line2.split(',') if line2 else []
    except EOFError:
        return

    # 2. 构建图和入度表
    graph = defaultdict(list)
    in_degree = {node: 0 for node in all_nodes}
    
    for dep in dependencies:
        if '<-' in dep:
            # A <- B 表示 B 依赖 A，即 A -> B
            u, v = dep.split('<-')
            graph[u].append(v)
            in_degree[v] += 1

    # 3. 拓扑排序 (Kahn算法)
    queue = deque([node for node in all_nodes if in_degree[node] == 0])
    removed_count = 0
    
    while queue:
        curr = queue.popleft()
        removed_count += 1
        
        for neighbor in graph[curr]:
            in_degree[neighbor] -= 1
            if in_degree[neighbor] == 0:
                queue.append(neighbor)

    # 4. 计算结果
    # 总数 - 能正常排队的 = 循环依赖涉及的
    print(len(all_nodes) - removed_count)

if __name__ == "__main__":
    solve()
```

### 4. 为什么这类题用这个算法？

*   **直观性**：依赖关系就像穿衣服，你必须先穿内衣再穿外套。如果衣服 A 要求先穿 B，B 要求先穿 A，你就永远穿不上这两件。拓扑排序就是模拟“穿衣服”的过程。
*   **复杂度**：时间复杂度是 $O(V+E)$（节点数+边数），处理 10 万级别的依赖关系也飞快。
*   **通用性**：以后凡是看到 **“执行顺序”、“依赖关系”、“死锁检测”、“编译顺序”**，脑子里第一个反应就应该是**拓扑排序**。

### 5. 易错点提示
1.  **边方向**：一定要分清谁依赖谁。$A \leftarrow B$ 是 $A \to B$。
2.  **独立节点**：有些节点（比如示例1里的 CM2）虽然不在依赖关系里，但它也算一个正常的、无循环依赖的节点。
3.  **计算范围**：题目问的是“循环依赖的CM数量”，如果一个节点**下游**接在一个环上，通过拓扑排序它也会被剩下。严格来说，拓扑排序剩下的节点包含：**环里的节点 + 环下游的节点**。从示例 1 来看，这正是题目要求的逻辑。
