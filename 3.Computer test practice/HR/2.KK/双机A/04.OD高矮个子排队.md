### 一、 题目描述：高矮个子排队（高矮版）

**题目描述**
现在有一队小朋友，他们高矮不同，我们以正整数数组表示这一队小朋友的身高，如数组 `{5, 3, 1, 2, 3}`。
请将小朋友重新排队，要求按照 **“高”“矮”“高”“矮”** 的顺序排列。
即：索引为 0 的位置应当大于等于索引 1 的位置，索引 1 的位置应当小于等于索引 2 的位置，以此类推。

**排序规律：**
*   `h[0] >= h[1]`
*   `h[1] <= h[2]`
*   `h[2] >= h[3]`
*   ...

**移动限制：**
如果当前位置不符合要求，只能与**前一个**（或后一个，通常是相邻交换）位置交换。

**输入描述**
输入一个字符串，包含多个正整数，用空格隔开。

*   如果输入不符合格式（包含非数字字符），输出 `[]`。

**输出描述**
输出重新排列后的字符串，数字之间用空格隔开。

**示例**
*   **输入**：`4 1 3 5 2`
*   **输出**：`4 1 5 2 3`
    *   说明：
    *   `4` 和 `1`：要求 `4 >= 1`，满足，不换。
    *   `1` 和 `3`：要求 `1 <= 3`，满足，不换。
    *   `3` 和 `5`：要求 `3 >= 5`，不满足，交换 -> `4 1 5 3 2`。
    *   `3` 和 `2`：要求 `3 <= 2`，不满足，交换 -> `4 1 5 2 3`。

---

### 二、 Python 题解（已通过验证逻辑）

这段代码实现了 **“偶数位大，奇数位小”** 的逻辑，能解决你遇到的 `Wrong Answer` 问题。

```python
import sys

def solve():
    try:
        # 1. 获取输入
        # 使用 sys.stdin.readline() 读取整行，防止部分环境 input() 报错
        line = sys.stdin.readline().strip()
        
        # 如果输入为空
        if not line:
            return

        # 2. 异常处理：转换列表，如果报错说明有非法字符
        nums = list(map(int, line.split()))

    except ValueError:
        # 遇到非法字符（如 "abc"）输出 []
        print("[]")
        return

    # 3. 核心逻辑：高 - 矮 - 高 - 矮
    # 只需要遍历一次 (0 到 len-2)
    for i in range(len(nums) - 1):
        
        # ----------------------------------------------------
        # 情况 A: 偶数索引 (0, 2, 4...) -> 希望它是“高” (山峰)
        # 规则：必须 nums[i] >= nums[i+1]
        # ----------------------------------------------------
        if i % 2 == 0:
            # 如果当前比下一个“矮” ( < )，就不符合要求，交换
            if nums[i] < nums[i+1]:
                nums[i], nums[i+1] = nums[i+1], nums[i]

        # ----------------------------------------------------
        # 情况 B: 奇数索引 (1, 3, 5...) -> 希望它是“矮” (山谷)
        # 规则：必须 nums[i] <= nums[i+1]
        # ----------------------------------------------------
        else:
            # 如果当前比下一个“高” ( > )，就不符合要求，交换
            if nums[i] > nums[i+1]:
                nums[i], nums[i+1] = nums[i+1], nums[i]

    # 4. 输出结果
    print(" ".join(map(str, nums)))

if __name__ == "__main__":
    solve()
```

### 助记口诀
*   **i 是偶数**：我要当大哥（大于等于后面），不行就换。
*   **i 是奇数**：我要当小弟（小于等于后面），不行就换。

---

**交换后面的不会影响前面的吗？这样最终的结果为什么是最优解？**

这是一个非常棒的问题！这也是许多人在初次接触贪心算法（Greedy Algorithm）时的核心疑惑：**“只顾眼前（局部）的交换，为什么能保证全局是正确的？为什么不会拆东墙补西墙？”**

答案的核心在于数学上的 **不等式传递性**。

我们可以通过逻辑推理来证明：**当我们为了满足当前位置的要求进行交换时，它会让前一个位置的关系变得“更稳固”，而绝不会破坏前一个位置已经建立好的关系。**

我们以 **“高、矮、高、矮”**（偶数位大，奇数位小）为例来详细拆解。

---

### 1. 核心逻辑证明

假设我们要处理索引 `i` 和 `i+1` 的关系。在此之前，索引 `i-1` 和 `i` 的关系已经处理好了。

#### 场景一：处理奇数位（Valley/山谷）
也就是 `i` 是奇数，`i-1` 是偶数（高）。
*   **已知状态**：`h[i-1]` 已经比 `h[i]` 高了（因为前一步刚处理完）。即 `h[i-1] >= h[i]`。
*   **当前目标**：我们要让 `i` 成为“矮子”，即要求 `h[i] <= h[i+1]`。
*   **如果冲突**：假设现在 `h[i] > h[i+1]`（当前太高了，不满足矮的要求），我们需要交换 `h[i]` 和 `h[i+1]`。

**交换后的影响分析：**
交换后，新的 `h[i]` 变成了原来的 `h[i+1]`。
那么，前面的 `h[i-1]` 还能保持比新的 `h[i]` 高吗？

*   我们知道：`h[i-1] >= 旧h[i]`
*   我们发现冲突是因为：`旧h[i] > 旧h[i+1]`
*   **根据传递性**：`h[i-1] >= 旧h[i] > 旧h[i+1]` $\rightarrow$ **`h[i-1] > 旧h[i+1]`**

**结论**：交换过来的这个数（`旧h[i+1]`）比原来的 `h[i]` 还要小！既然 `h[i-1]` 比原来的那个数都大，那它**肯定比这个新换过来的更小的数还要大**。

所以，前一个“高”的位置依然是合格的“高”。

---

#### 场景二：处理偶数位（Peak/山峰）
也就是 `i` 是偶数，`i-1` 是奇数（矮）。
*   **已知状态**：`h[i-1]` 已经比 `h[i]` 矮了。即 `h[i-1] <= h[i]`。
*   **当前目标**：我们要让 `i` 成为“高个”，即要求 `h[i] >= h[i+1]`。
*   **如果冲突**：假设现在 `h[i] < h[i+1]`（当前太矮了，不满足高的要求），我们需要交换 `h[i]` 和 `h[i+1]`。

**交换后的影响分析：**
交换后，新的 `h[i]` 变成了原来的 `h[i+1]`。
那么，前面的 `h[i-1]` 还能保持比新的 `h[i]` 矮吗？

*   我们知道：`h[i-1] <= 旧h[i]`
*   我们发现冲突是因为：`旧h[i] < 旧h[i+1]`
*   **根据传递性**：`h[i-1] <= 旧h[i] < 旧h[i+1]` $\rightarrow$ **`h[i-1] < 旧h[i+1]`**

**结论**：交换过来的这个数（`旧h[i+1]`）比原来的 `h[i]` 还要大！既然 `h[i-1]` 比原来的那个数都小，那它**肯定比这个新换过来的更大的数还要小**。

所以，前一个“矮”的位置依然是合格的“矮”。

---

### 2. 图解演示

想象一下这三个数：`A, B, C`。我们要求形成 **“高、矮、高”**。

1.  先看 A 和 B。假设我们要 A > B。如果 A < B，我们交换，变成 `B, A`。现在第一个关系满足了。
2.  接着看第二个位置（现在是 A）和 C。我们要求第二个位置是“矮”，也就是要求 `A < C`。
3.  **如果出问题了**，即 `A > C`，我们需要交换 A 和 C。序列变成了 `B, C, A`。
4.  **回看前面的 B 和 C**：
    *   刚才我们要 A > B (说明 B 很小)。
    *   因为出了问题我们才换的，所以 A > C (说明 C 比 B 还要小，或者 C 介于 B 和 A 之间？不对)。
    *   等等，这里有一个**关键点**：
        *   如果是 **高(i-1) - 矮(i) - 高(i+1)** 的逻辑：
        *   i=1时，我们要求它是矮的。
        *   前面 i=0 已经是高的了 `h[0] > h[1]`。
        *   现在看 i=1 和 i=2，如果 `h[1] > h[2]` (不符合矮)，交换 `1` 和 `2`。
        *   也就是序列变成：`h[0], h[2], h[1]`。
        *   因为 `h[0] > h[1]` 且 `h[1] > h[2]`，所以 **`h[0] > h[2]`** 必然成立。
        *   **前面的高山依然比新的低谷要高。**

---

### 3. 为什么这是最优解？

这里的“最优”通常指两个方面：

1.  **时间复杂度最优**：
    这个算法只需要从头到尾扫一遍，时间复杂度是 **O(N)**。
    你不可能在不遍历所有数字的情况下完成排序，所以 O(N) 就是理论上的极限速度。

2.  **空间复杂度最优**：
    我们只在原数组上进行交换，不需要创建新的数组，空间复杂度是 **O(1)**。这是最省内存的。

3.  **交换次数**：
    虽然它不一定保证交换次数最少（那是另一个复杂的数学问题），但在工程和机考中，能在 O(N) 时间内给出一个符合条件的解，就是满分的最优解。

### 总结

一句话概括：
**因为我们总是把更极端的数值（更大的大数，或者更小的小数）换到了中间，这只会让它与前面的差距拉得更大，而绝不会缩短差距。**

*   我要当山谷，如果我比右边高，我就把右边更矮的换过来 -> 我变得更矮了 -> 左边的山峰看我更顺眼了。
*   我要当山峰，如果我比右边矮，我就把右边更高的换过来 -> 我变得更高了 -> 左边的山谷看我更顺眼了。



这是一个很好的进阶问题！

如果题目要求输出 **“最小交换次数”** 和 **“最终结果”**，其实解题思路依然是基于**贪心算法**。

因为我们之前的推导已经证明：**为了满足当前位置的波浪形状，如果必须交换，那么这个交换是不可避免的（必要的）。** 因此，我们在遍历过程中，每一次触发交换，本质上都是一次“必须的操作”。统计这些操作的次数，就是在这个贪心策略下的移动次数。

### 修改思路
1.  定义一个计数器 `count = 0`。
2.  每次发现不符合“高矮”规则，进行交换时，`count += 1`。
3.  最后输出 `count` 和 `数组字符串`。

---

### Python 代码实现（带计数功能）

这里依然沿用你刚刚通过测试的 **“高、矮、高、矮”**（即索引0是高）的逻辑。

```python
import sys

def solve_with_count():
    try:
        # 1. 获取输入
        line = sys.stdin.readline().strip()
        if not line:
            return
        
        # 转为整数列表
        nums = list(map(int, line.split()))
        
    except ValueError:
        print("[]")
        return

    # 定义交换计数器
    move_count = 0

    # 2. 核心逻辑：高 - 矮 - 高 - 矮
    # 遍历到倒数第二个元素
    for i in range(len(nums) - 1):
        
        need_swap = False
        
        # --- 偶数位 (0, 2...)：应该是“高”(山峰) ---
        if i % 2 == 0:
            if nums[i] < nums[i+1]:
                need_swap = True
        
        # --- 奇数位 (1, 3...)：应该是“矮”(山谷) ---
        else:
            if nums[i] > nums[i+1]:
                need_swap = True
        
        # --- 如果需要交换 ---
        if need_swap:
            nums[i], nums[i+1] = nums[i+1], nums[i]
            move_count += 1  # 记录移动次数

    # 3. 输出结果
    # 格式通常是：次数 结果 (具体看题目要求，有的要求分行，有的要求空格隔开)
    # 这里假设在一行输出
    result_str = " ".join(map(str, nums))
    print(f"{move_count} {result_str}")

if __name__ == "__main__":
    solve_with_count()
```

### 示例演示

假设输入：`1 2 3` （要求变为高、矮、高）

1.  **i = 0 (偶数，要是高)**：
    *   `nums[0]=1`, `nums[1]=2`。
    *   `1 < 2`，不符合“高”的要求。
    *   **交换** -> 变成 `2 1 3`。
    *   **move_count + 1** (当前为 1)。
2.  **i = 1 (奇数，要是矮)**：
    *   `nums[1]=1`, `nums[2]=3`。
    *   `1 < 3`，符合“矮”的要求。
    *   **不换**。
3.  **结束**。

**输出**：`1 2 1 3` (1次移动，结果是 2 1 3)

### 💡 进阶：如果题目没规定第一个是高还是矮？

如果题目说：*“请输出最小移动次数，你可以选择从高开始或从矮开始，取次数最少的那个。”*

这时候你需要把逻辑封装成一个函数，跑两遍：
1.  假设模式是 **“高-矮-高-矮”**，算出一个 `count1`。
2.  假设模式是 **“矮-高-矮-高”**，算出一个 `count2`。
3.  比较 `count1` 和 `count2`，输出较小的那个对应的结果。

**通常华为OD的这道题（如你之前报错的那个版本）是固定了必须从“高”开始的，所以直接用上面的代码即可。**
