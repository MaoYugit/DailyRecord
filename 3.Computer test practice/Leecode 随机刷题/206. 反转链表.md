# [206. 反转链表](https://leetcode.cn/problems/reverse-linked-list/)

**简单**

给你单链表的头节点 `head` ，请你反转链表，并返回反转后的链表。

**示例 1：**

![img](https://assets.leetcode.com/uploads/2021/02/19/rev1ex1.jpg)

```
输入：head = [1,2,3,4,5]
输出：[5,4,3,2,1]
```

**示例 2：**

![img](https://assets.leetcode.com/uploads/2021/02/19/rev1ex2.jpg)

```
输入：head = [1,2]
输出：[2,1]
```

**示例 3：**

```
输入：head = []
输出：[]
```

**提示：**

- 链表中节点的数目范围是 `[0, 5000]`
- `-5000 <= Node.val <= 5000`

**进阶：**链表可以选用迭代或递归方式完成反转。你能否用两种方法解决这道题？



---

### 题解一：迭代法

**我们的目标：** 将链表 `1 -> 2 -> 3 -> 4 -> 5` 变成 `5 -> 4 -> 3 -> 2 -> 1`。

**核心问题：**
链表是一个“单行道”，我们只能从 `1` 走到 `2`，不能从 `2` 走回 `1`。我们的任务就是把这条“单行道”的方向给调转过来。

**比喻时间：想象一下这是一列只有一节车头的火车**

*   每个**节点** (Node) 就是一节**车厢**。
*   每个车厢里的 `val` 就是车厢里装的**货物**。
*   `.next` 指针就像是车厢之间的**连接挂钩**，它总是指向下一节车厢。

`[1] -> [2] -> [3] -> None`

现在，我们要把整列火车的方向反过来。我们不能一下子把所有挂钩都反向，那样会乱套。我们必须一节一节车厢地操作。

**我们需要三个“工人”来帮忙（也就是三个指针）：**

1.  `prev` (previous, 前一个): 这个工人负责记住**已经被反转好的那部分**的最后一个车厢。一开始，还没有任何车厢被反转，所以他站在一个虚无的地方，我们称之为 `None`。
2.  `curr` (current, 当前): 这是我们的**主力工人**，他站在当前正要操作的车厢。他从第一节车厢 `head` 开始。
3.  `next_temp` (next_temporary, 临时记录员): 这是个**临时工**，他的任务非常重要！在我们断开当前车厢和下一节车厢的连接之前，他要**赶紧跑过去记住下一节车厢的位置**，不然我们就找不到后面的火车了！

---

**开始操作！一步一步走**

我们以一个简单的链表 `1 -> 2 -> 3 -> None` 为例。

**准备阶段：**

*   `prev` 站在 `None`。
*   `curr` 站在第一节车厢 `1`。

**链表状态:**
```
 prev    curr
 None     1  ->  2  ->  3  ->  None
```

---

**第一轮循环 (操作车厢 `1`):**

我们的主力工人 `curr` 在车厢 `1` 上。他要做的就是让车厢 `1` 的挂钩指向 `prev` 所站的位置 (`None`)。

1.  **临时工先上！** `curr` 对 `next_temp` 说：“喂，老兄，我马上要断开和车厢 `2` 的连接了，你快去 `2` 那里等着，不然我们等下就找不到它了！”
    *   `next_temp = curr.next`  (现在 `next_temp` 指向了车厢 `2`)

2.  **主力工人断开并反转挂钩！** `curr` 把车厢 `1` 指向车厢 `2` 的挂钩断开，然后反过来挂到 `prev` 所在的位置 (`None`)。
    
    *   `curr.next = prev`  (现在车厢 `1` 的 `next` 指向了 `None`)
    
    **此时的链表状态:**
    
    ```
            	 next_temp
             	   |
             	   v
    None <-  1     2  ->  3  ->  None   // 注意，1已经指向了None
     		 ^
     		 |
    		curr
    ```
    
    (逻辑上是 `None <- 1`, `2 -> 3 -> None`。它们暂时断开了)
    
3.  **更新位置！** 操作完成，工人们要为下一轮做准备了。
    *   `prev` 工人移动到 `curr` 现在的位置（车厢 `1`），因为 `1` 已经是“反转好”的部分了。
        *   `prev = curr`
    *   `curr` 主力工人移动到 `next_temp` 之前记好的位置（车厢 `2`），准备去操作下一节车厢。
        *   `curr = next_temp`

**第一轮循环结束后的状态:**
```
         prev    curr
None <-   1       2   ->  3  ->  None
```
(逻辑上，我们已经有了一个反转好的部分 `None <- 1`)

---

**第二轮循环 (操作车厢 `2`):**

现在 `curr` 在车厢 `2`。重复和上面完全一样的四个步骤！

1.  **临时工先行**: `next_temp` 去记住车厢 `3` 的位置。
    *   `next_temp = curr.next`
2.  **反转挂钩**: `curr` (车厢 `2`) 断开和 `3` 的连接，指向 `prev` (车厢 `1`)。
    *   `curr.next = prev`
3.  **`prev` 前进**: `prev` 移动到 `curr` 的位置 (车厢 `2`)。
    *   `prev = curr`
4.  **`curr` 前进**: `curr` 移动到 `next_temp` 的位置 (车厢 `3`)。
    *   `curr = next_temp`

**第二轮循环结束后的状态:**
```
             prev    curr
 None <- 1 <- 2       3   ->  None
```
(我们已经有了反转好的部分 `None <- 1 <- 2`)

---

**第三轮循环 (操作车厢 `3`):**

`curr` 在车厢 `3`。再次重复！

1.  **临时工先行**: `next_temp` 发现车厢 `3` 后面是 `None`，他就记住了 `None`。
    *   `next_temp = curr.next`
2.  **反转挂钩**: `curr` (车厢 `3`) 指向 `prev` (车厢 `2`)。
    *   `curr.next = prev`
3.  **`prev` 前进**: `prev` 移动到车厢 `3`。
    *   `prev = curr`
4.  **`curr` 前进**: `curr` 移动到 `next_temp` 记下的位置 `None`。
    *   `curr = next_temp`

**第三轮循环结束后的状态:**

```
                 prev    curr
 None <- 1 <- 2 <- 3     None
```

---

**循环结束：**

现在 `curr` 是 `None` 了。`while curr:` 的循环条件不满足，循环停止。

**最后一步：返回结果**

现在看看我们的工人都站在哪里？
*   `curr` 站在 `None`。
*   `prev` 站在车厢 `3`。

而车厢 `3` 正是咱们反转后链表的**新的头节点**！所以，我们只要返回 `prev` 就可以了。

最终链表: `3 -> 2 -> 1 -> None`。 任务完成！

### 代码回顾

现在再来看代码，每一行是不是就清晰多了？

```python
# Definition for singly-linked list.
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

class Solution:
    def reverseList(self, head: ListNode) -> ListNode:
        # 准备我们的两个工人：prev 和 curr
        prev = None
        curr = head

        # 只要主力工人 curr 还没走出所有车厢 (还没到 None)
        while curr:
            # 1. 临时工 next_temp 先去下一个位置等着
            next_temp = curr.next
            
            # 2. 主力工人 curr 反转挂钩，指向 prev
            curr.next = prev
            
            # 3. 两个工人都向前移动一个位置，为下一轮做准备
            prev = curr       # prev 移动到 curr 的位置
            curr = next_temp  # curr 移动到临时工记下的位置
            
        # 循环结束，curr 变成了 None, prev 停在了新链表的头部
        return prev
```

这个过程就像是你把一串珠子一颗一颗地取下来，然后从反方向重新串起来一样。`prev` 就是你手上已经串好的那部分，`curr` 是你正要取下来的那一颗。希望这个详细的解释能帮助你彻底理解迭代法！

### 题解二：递归法

如果你觉得迭代法像是“按部就班地从头干到尾”，那么递归法更像是“我先不管，让后面的人先做，等他们做完了我再处理我这部分”。这是一种非常不同的思维方式。

---

**核心思想：**
想象一下你是一个领导，你的任务是反转一个很长的链表。你觉得这个任务太大了，不想自己做。于是，你把这个任务交给了你的下属（下一次递归调用）。

你对下属说：“**你帮我把除了第一个节点之外的所有节点都反转好，然后把反转后的新头节点告诉我。**”

你完全信任你的下属能完成任务。等他完成之后，你只需要做两件小事，就可以把第一个节点也接上去了。

---

**比喻时间：排队反转**

想象一下有一队人 `1 -> 2 -> 3 -> 4` 正在排队，每个人都看着前面那个人的后脑勺。我们的目标是让整队人向后转，变成 `4 -> 3 -> 2 -> 1`。

*   **函数 `reverseList(node)` 的作用** 就是让 `node` 以及他后面的整支队伍向后转。

我们从第一个人（节点 `1`）开始调用 `reverseList(1)`。

**第一步：向下传递任务（递归的“递”）**

1.  **你 (函数 `reverseList(1)`)** 接到任务。你觉得队伍太长，于是你对**第 2 个人**说：“喂，`2`号！你带着你后面的所有人 (`2 -> 3 -> 4`) 先向后转。转好了告诉我新的排头兵是谁。”
2.  **`2`号 (函数 `reverseList(2)`)** 也觉得队伍长，于是他对**第 3 个人**说：“`3`号！你带着你后面的所有人 (`3 -> 4`) 先向后转。”
3.  **`3`号 (函数 `reverseList(3)`)** 对**第 4 个人**说：“`4`号！你带着你后面的所有人 (就你自己) 先向后转。”
4.  **`4`号 (函数 `reverseList(4)`)** 看了看身后，没人了！(`4.next` 是 `None`)。
    *   他想：“就我一个人，那我不就是已经‘反转’好了的队伍吗？我就是新的排头兵！”
    *   于是，他向他的上级（`3`号）报告：“报告！我这里搞定了，新的排头兵就是我（节点 `4`）！”
    *   这就是**递归的出口（Base Case）**。当链表只有一个节点或为空时，它本身就是反转后的结果。

---

**第二步：从后往前处理（递归的“归”）**

现在，任务从最深处开始返回结果了。

1.  **`3`号** 接到了 `4`号的报告。
    
    *   他现在知道，他后面的队伍已经反转好了，并且新的排头兵是 `4`。
    *   此时的状态是：`3`号还看着`4`号的后脑勺 (`3.next` 指向 `4`)，而 `4`号已经向后转了，不看任何人 (`4.next` 指向 `None`)。
    *   逻辑上是这样： `... -> 3 -> 4`，并且 `4` 是新排头兵。
    *   **`3`号需要做什么？** 他需要让 `4`号回头看他！
        *   怎么找到 `4`号？就是 `3.next`。
        *   所以，`3.next.next = 3`  （也就是 `4.next = 3`）。
        *   现在 `4`号回头看 `3`号了，形成了 `3 <-> 4` 的双向箭头。
    *   **还有一件事！** `3`号自己也要向后转，不再看 `4`号了。他应该看向 `None`，因为他现在是队尾了。
        *   `3.next = None`
    *   好了，`3`号的任务完成了。他向他的上级（`2`号）报告：“报告！我这里也搞定了，新的排头兵**仍然是 `4`号**！”
    
    **此时的链表状态: `4 -> 3 -> None`**
    
2.  **`2`号** 接到了 `3`号的报告。
    *   他知道了，他后面的队伍 (`3 -> 4`) 已经反转成了 `4 -> 3`，并且新排头兵是 `4`。
    *   此时的状态：`2`号还看着 `3`号 (`2.next` 指向 `3`)。
    *   **`2`号做同样的事：**
        *   让 `3`号回头看他：`2.next.next = 2` (也就是 `3.next = 2`)。
        *   自己向后转：`2.next = None`。
    *   任务完成。向他的上级（`1`号）报告：“报告！搞定了，新排头兵**还是 `4`号**！”

    **此时的链表状态: `4 -> 3 -> 2 -> None`**

3.  **`1`号** (就是我们最初的函数) 接到了 `2`号的报告。
    
    *   他知道了，他后面的队伍 (`2 -> 3 -> 4`) 已经反转成了 `4 -> 3 -> 2`，并且新排头兵是 `4`。
    *   **`1`号做最后的工作：**
        *   让 `2`号回头看他：`1.next.next = 1` (也就是 `2.next = 1`)。
        *   自己向后转，成为新的队尾：`1.next = None`。
    *   任务完成。

**最终结果：** 整个函数返回最初从最深处传回来的新排头兵——**节点 `4`**。
最终链表就是 `4 -> 3 -> 2 -> 1 -> None`。

### 代码回顾

让我们把上面的逻辑翻译成代码，你会发现惊人地简洁。

```python
# Definition for singly-linked list.
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

class Solution:
    def reverseList(self, head: ListNode) -> ListNode:
        
        # Base Case: 递归的出口
        # 如果是空队，或者队伍只有一个人，不需要反转，直接返回。
        if not head or not head.next:
            return head

        # ----------------------------------------------------
        # 递归的“递”：把任务交给下属
        # 你对下属说：“把 head 后面的队伍反转好，并告诉我新的排头兵是谁”
        new_head = self.reverseList(head.next)
        # ----------------------------------------------------

        # 递归的“归”：下属完成任务后，你来做收尾工作
        # 此时 new_head 是已经反转好的子链表的头节点
        # head.next 现在是反转后的子链表的“队尾”
        
        # 1. 让你后面那个人（head.next），回头指向你（head）
        head.next.next = head
        
        # 2. 你自己要成为新的队尾，所以你的 next 指向 None
        head.next = None
        
        # 3. 向上级报告，新的排头兵没有变，还是最初那个 new_head
        return new_head

```

**总结一下递归的精髓：**

*   **相信** `reverseList(head.next)` 这个调用一定能成功，并且会返回一个已经反转好的子链表的头节点。
*   你要做的，就是在它成功之后，把 `head` 这个节点正确地连接到这个已经反转好的子链表的末尾。

这个思维方式需要一点时间来适应，你可以试着在纸上画一下 `1 -> 2 -> 3` 的反转过程，跟踪 `head` 和 `new_head` 的变化，这会非常有帮助！

### 总结

| 特性           | 迭代法                     | 递归法                                                     |
| -------------- | -------------------------- | ---------------------------------------------------------- |
| **空间复杂度** | O(1)                       | O(n)，因为递归需要使用函数调用栈，最坏情况下栈的深度为 n。 |
| **时间复杂度** | O(n)                       | O(n)，因为需要遍历链表中的每个节点一次。                   |
| **可读性**     | 通常更容易理解，逻辑直接。 | 逻辑更抽象，需要理解递归和函数调用栈。                     |

在实际应用中，由于递归法有额外的栈空间开销，当链表非常长时，可能会导致栈溢出。因此，迭代法通常是更优的选择。
