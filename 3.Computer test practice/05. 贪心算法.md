贪心算法（Greedy Algorithm）的特点是：**代码通常很短，但思路很难想，一旦想通了就觉得“显而易见”，想不通就极其痛苦。**

贪心算法的核心思想只有一句话：**在每一步选择中，都采取当前状态下最好/最优的选择（局部最优），从而希望导致结果是全局最好/最优的。**

既然你要“超级详细”且“分阶段”的教学，我们将整个训练分为 **4个阶段**。

这是 **第一部分：贪心算法的基石与直觉培养**。

### 🟢 第一阶段：贪心初体验（直觉与简单逻辑）

在这个阶段，我们不需要复杂的证明，只需要培养一种“**只看当下，不看未来**”的思维方式。

#### 核心法则
1.  **排序（Sorting）**：90% 的贪心题目起手式都是排序。
2.  **不回头**：做了一个决定，就不再改变（不同于回溯法）。

#### 1. 题目：分发饼干 (LeetCode 455) - ⭐️ 必做入门题

**场景**：
你有一些孩子和一些饼干。
*   每个孩子 `g[i]` 有一个“胃口值”，只有饼干大小 `>= g[i]` 他才满足。
*   每个饼干 `s[j]` 有一个大小。
*   **目标**：尽可能满足更多数量的孩子。

**贪心策略**：
为了满足更多人，我们应该**把最小的饼干喂给胃口最小的孩子**。
*   如果最小的饼干连胃口最小的孩子都喂不饱，那这个饼干谁也喂不饱，直接扔掉（因为它肯定也喂不饱胃口更大的孩子）。
*   不要用大饼干喂小胃口，那是浪费。

**Python 代码详解**：

```python
class Solution:
    def findContentChildren(self, g: List[int], s: List[int]) -> int:
        # 1. 贪心第一步：排序！
        # 胃口从小到大，饼干从小到大
        g.sort()
        s.sort()
        
        child_i = 0  # 指向当前胃口最小的孩子
        cookie_j = 0 # 指向当前最小的饼干
        
        while child_i < len(g) and cookie_j < len(s):
            # 2. 贪心判断：
            # 如果当前饼干能满足当前孩子
            if s[cookie_j] >= g[child_i]:
                child_i += 1  # 孩子满足了，看下一个孩子
                cookie_j += 1 # 饼干吃掉了，拿下一块
            else:
                # 饼干太小，满足不了当前胃口最小的孩子
                # 既然连最小胃口的都满足不了，这个饼干就是废的，看下一块更大的饼干
                cookie_j += 1
                
        return child_i # 满意的孩子数量
```

**本题感悟**：
局部最优（大饼干给大胃口，或者小饼干给小胃口） $\rightarrow$ 全局最优（满足最多人）。

#### 2. 题目：柠檬水找零 (LeetCode 860) - ⭐️ 模拟生活

**场景**：
一杯柠檬水 5 美元。顾客排队购买，可能给你 5、10、20 美元。你需要找零。最开始你手头没钱。

**贪心策略**：
*   顾客给 5 元：收下，不用找。
*   顾客给 10 元：收下，找他 5 元（必须消耗一张 5 元）。
*   **关键点**：顾客给 20 元：
    *   **策略 A**：找他一张 10 元 + 一张 5 元。（优先！）
    *   **策略 B**：找他三张 5 元。
    *   **为什么优先策略 A？** 因为 5 元面值更小，**万能性更强**。5 元可以用来给 10 元找零，也可以给 20 元找零。而 10 元只能给 20 元找零。**贪心就是：保留功能更强大的零钱（5元）在手里。**

**Python 代码详解**：

```python
class Solution:
    def lemonadeChange(self, bills: List[int]) -> bool:
        five = 0
        ten = 0
        
        for bill in bills:
            if bill == 5:
                five += 1
            elif bill == 10:
                if five == 0: return False # 没5块找零，完蛋
                five -= 1
                ten += 1
            elif bill == 20:
                # 贪心核心：优先消耗 10+5，保留 5+5+5
                if ten > 0 and five > 0:
                    ten -= 1
                    five -= 1
                elif five >= 3:
                    five -= 3
                else:
                    return False # 找不开
        
        return True
```

#### 3. 题目：买卖股票的最佳时机 II (LeetCode 122) - ⭐️ 思维转换

**场景**：
给定股票价格数组 `prices`，你可以多次买卖（买之前必须卖掉手里的）。求最大利润。
例如：`[7, 1, 5, 3, 6, 4]`

**贪心策略**：
不要去想“我在最低点买，最高点卖”。
**只要明天比今天贵，我就今天买，明天卖，赚那个差价。**
即使后面还有更高的价格，我也可以理解为：明天卖了之后，立刻又买回来。
*   `1 -> 5`：涨了，赚 4 块。
*   `5 -> 3`：跌了，不操作。
*   `3 -> 6`：涨了，赚 3 块。
*   总利润：4 + 3 = 7。

**数学原理**：$profit = (p_3 - p_0)$ 等价于 $(p_1 - p_0) + (p_2 - p_1) + (p_3 - p_2)$。我们只需要收集所有**正的**差值。

**Python 代码详解**：

```python
class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        total_profit = 0
        
        for i in range(1, len(prices)):
            # 只要今天比昨天高，就有利润可图
            # 局部最优：收集每天的正利润
            if prices[i] > prices[i-1]:
                total_profit += (prices[i] - prices[i-1])
                
        return total_profit
```

#### 4. 题目：跳跃游戏 (LeetCode 55) - ⭐️ 经典中的经典

**场景**：
数组 `nums = [2, 3, 1, 1, 4]`。`nums[i]` 代表你在位置 `i` 最多能向右跳几步。判断能否到达最后一个下标。

**错误思路**：
试图计算具体怎么跳（这是回溯或DP）。

**贪心思路**：
不要纠结具体跳几步。
**关注覆盖范围**。
*   在位置 0，数值是 2。意思是我的**覆盖范围**从 `index 0` 延伸到了 `index 2`。
*   在这个覆盖范围内，我遍历每一个点，看从这些点出发，能不能把**覆盖范围**推得更远。
*   如果覆盖范围超过了最后一个下标，就成功。

**Python 代码详解**：

```python
class Solution:
    def canJump(self, nums: List[int]) -> bool:
        cover = 0 # 当前能跳到的最远位置（下标）
        
        # 只能在 cover 范围内遍历，如果 i > cover，说明这个点不可达
        for i, steps in enumerate(nums):
            if i <= cover:
                # 贪心：在当前位置 i，能跳 steps 步
                # 更新最远覆盖范围
                cover = max(cover, i + steps)
                
                # 如果覆盖范围已经包含了终点
                if cover >= len(nums) - 1:
                    return True
            else:
                # 这里的 i 已经超出了 cover，说明中间断了，跳不过去了
                return False
                
        return False
```

#### 5. 题目：摆动序列 (LeetCode 376) - ⭐️ 峰值思维

**场景**：
求最长的“摆动”子序列长度。摆动就是：大-小-大-小...
例如 `[1, 17, 5, 10, 13, 15, 10, 5, 16, 8]`
选出：`1, 17, 5, 10, 15, 10, 16, 8`。

**贪心策略**：
如果我们在一个连续上升的坡上 `1 -> 5 -> 10`，我们只需要保留**两头**（极小值和极大值），中间的过渡元素都可以忽略。
**贪心就是：只统计“峰”和“谷”的数量。**

**Python 代码详解**：

```python
class Solution:
    def wiggleMaxLength(self, nums: List[int]) -> int:
        if len(nums) < 2: return len(nums)
        
        pre_diff = 0 # 前一对差值
        cur_diff = 0 # 当前一对差值
        count = 1    # 默认最右边有一个峰值/谷值，先记为1
        
        for i in range(len(nums) - 1):
            cur_diff = nums[i+1] - nums[i]
            
            # 什么是峰/谷？
            # 峰：之前是上升(pre>=0)，现在下降(cur<0)
            # 谷：之前是下降(pre<=0)，现在上升(cur>0)
            if (cur_diff > 0 and pre_diff <= 0) or (cur_diff < 0 and pre_diff >= 0):
                count += 1
                pre_diff = cur_diff # 只有出现峰谷变化时，才更新 pre_diff
                
        return count
```

这类题目的特征很明显：给你一堆区间 `[start, end]`（比如会议时间、气球坐标），让你合并它们，或者找出重叠了多少个，或者移除最少几个才能不重叠。

**核心技巧只有两个字：排序。**
*   要么按 **左边界（Start）** 排序。

#### 1. 题目：无重叠区间 (LeetCode 435) - ⭐️ 区间问题的鼻祖

**场景**：
给你一堆区间 `intervals`，问你 **最少需要移除多少个区间**，才能让剩下的区间 **互不重叠**。
例子：`[[1,2], [2,3], [3,4], [1,3]]`
答案：移除 `[1,3]`，剩下 `[1,2], [2,3], [3,4]`。移除 1 个。

**贪心策略**：
想让“移除的数量最少”，等价于 **“保留的数量最多”**。
如果我想在一天内参加尽可能多的会议，我应该怎么选？
1.  选开始最早的？不行，如果有个会议 `[0, 24]`，选了它，别的都参加不了。
2.  选持续时间最短的？也不一定对。
3.  **正确策略：选结束时间最早的（End Time）。**
    *   因为结束得越早，留给后面的时间就越多，能容纳后续会议的概率就越大。

**代码逻辑**：
1.  按 **右边界** 从小到大排序。
2.  选第一个结束最早的区间作为 `end`。
3.  遍历后续区间：
    *   如果它的 **左边界 < 当前 end**：说明重叠了，这个区间必须丢弃（count++）。
    *   如果它的 **左边界 >= 当前 end**：说明不重叠，可以保留，更新 `end` 为这个新的一样。

**Python 代码详解**：

```python
class Solution:
    def eraseOverlapIntervals(self, intervals: List[List[int]]) -> int:
        if not intervals: return 0
        
        # 1. 按右边界排序（这是贪心的关键）
        # key=lambda x: x[1] 表示按照每个元素的第1个索引（即右边界）排序
        intervals.sort(key=lambda x: x[1])
        
        # 初始化
        end = intervals[0][1] # 当前在这个时间点结束
        count = 0             # 记录要移除的数量
        
        # 从第二个区间开始遍历
        for i in range(1, len(intervals)):
            current_start = intervals[i][0]
            current_end = intervals[i][1]
            
            if current_start < end:
                # 2. 发现重叠！
                # 因为我们要保留结束早的（也就是之前的那个 end），
                # 所以当前这个被判定为“不够好”（因为它结束得更晚或者重叠了），移除它。
                count += 1
            else:
                # 3. 没有重叠
                # 更新结束时间，准备接纳下一个
                end = current_end
                
        return count
```

#### 2. 题目：用最少数量的箭引爆气球 (LeetCode 452) - ⭐️ 换皮题

**场景**：
气球分布在 X 轴上，比如 `[10, 16], [2, 8], [1, 6], [7, 12]`。一支箭可以垂直射上去，穿透所有经过的气球。求最少要几支箭。

**贪心策略**：
这题其实和上一题（435）是 **镜像问题**。
*   435 是求“有多少个重叠必须要扔掉”。
*   452 是求“有多少组重叠可以一箭双雕”。
*   **策略**：寻找重叠区域。如果气球 A 和 气球 B 重叠，我有机会用一箭射爆它们。为了省箭，我应该尽可能让这一箭射在 **重叠区域的边缘**。

**排序选择**：按 **右边界** 排序。（其实按左边界也可以，但为了记忆统一，我们按右边界排，容易理解）。
*   排序后：`[1,6], [2,8], [7,12], [10,16]`
*   第一支箭射在第一个气球的右边缘 `6`。
*   看后面谁能被 `6` 射中？ `[2,8]` 能（因为 $2 \le 6 \le 8$）。
*   `[7,12]` 能被 `6` 射中吗？不能，因为它开始于 `7`。那就需要一支新箭。

**Python 代码详解**：

```python
class Solution:
    def findMinArrowShots(self, points: List[List[int]]) -> int:
        if not points: return 0
        
        # 1. 还是按右边界排序
        points.sort(key=lambda x: x[1])
        
        arrows = 1          # 至少需要一支箭
        end = points[0][1]  # 第一支箭射在第一个气球的右边界
        
        for i in range(1, len(points)):
            current_start = points[i][0]
            current_end = points[i][1]
            
            # 如果当前气球的左边界 > 当前箭的位置
            # 说明这支箭射不到它了（因为它开始得太晚）
            if current_start > end:
                arrows += 1      # 需要一支新箭
                end = current_end # 新箭射在这个气球的右边界
            
            # 如果 current_start <= end，说明当前箭能顺便把它带走
            # 不需要做任何操作，continue
            
        return arrows
```

#### 3. 题目：合并区间 (LeetCode 56) - ⭐️ 必考题

**场景**：
给定 `intervals = [[1,3],[2,6],[8,10],[15,18]]`。
请合并所有重叠的区间。
结果：`[[1,6],[8,10],[15,18]]`。
（解释：`[1,3]` 和 `[2,6]` 重叠，合并为 `[1,6]`）。

**贪心策略**：
这里我们不再是“选出最多的”，而是“合并”。
为了方便合并，我们应该按 **左边界（Start）** 排序。
*   这样排序后，相邻的区间才更有可能重叠。
*   `[1,3], [2,6]...`
*   如果 **下一个区间的 Start $\le$ 上一个区间的 End**，说明重叠。
*   合并后的新 End 是多少？是两个 End 中的 **最大值**。 `max(3, 6) = 6`。

**Python 代码详解**：

```python
class Solution:
    def merge(self, intervals: List[List[int]]) -> List[List[int]]:
        if not intervals: return []
        
        # 1. 按左边界排序（合并问题的通用起手式）
        intervals.sort(key=lambda x: x[0])
        
        result = [intervals[0]] # 先把第一个放入结果集
        
        for i in range(1, len(intervals)):
            current = intervals[i]
            last_merged = result[-1] # 取出结果集中最后一个区间
            
            # 2. 判断是否重叠
            # 如果 当前区间的左边界 <= 上一个区间的右边界
            if current[0] <= last_merged[1]:
                # 3. 合并操作
                # 修改 last_merged 的右边界，取两者的最大值
                last_merged[1] = max(last_merged[1], current[1])
            else:
                # 4. 不重叠，直接放入结果集
                result.append(current)
                
        return result
```

#### 4. 题目：划分字母区间 (LeetCode 763) - ⭐️ 隐形区间

**场景**：
字符串 `S = "ababcbacadefegdehijhklij"`。
要把这个字符串划分为尽可能多的片段，同一字母最多出现在一个片段中。
比如 `'a'` 只能出现在第一个片段，那么第一个片段必须包含所有的 `'a'`。

**贪心策略**：
这看起来像字符串题，其实是区间题。
1.  **找边界**：遍历字符串，记录每个字符 **最后出现的位置**。
    *   `a` 最后出现在下标 8。
    *   `b` 最后出现在下标 5。
2.  **贪心遍历**：
    *   从头遍历。遇到了 `a`，我知道这个片段 **至少** 要延伸到下标 8。
    *   在去往下标 8 的路上，我又遇到了 `b`（最后在5），5 < 8，不用延长。
    *   如果遇到了一个字符，它的最后出现位置是 12，那我的边界就要 **更新** 到 12。
    *   当我的遍历下标 `i` 走到了我当前的边界 `end` 时，说明这个片段切分完毕。

**Python 代码详解**：

```python
class Solution:
    def partitionLabels(self, s: str) -> List[int]:
        # 1. 预处理：记录每个字符最后出现的位置
        last_index = {}
        for i, char in enumerate(s):
            last_index[char] = i
            
        result = []
        start = 0 # 当前片段的起始位置
        end = 0   # 当前片段的最远结束位置
        
        for i, char in enumerate(s):
            # 2. 贪心：不断更新当前片段需要延伸到的最远位置
            end = max(end, last_index[char])
            
            # 3. 如果当前走到了边界，说明找到了一个完整的片段
            if i == end:
                result.append(end - start + 1)
                start = i + 1 # 更新下一个片段的起点
                
        return result
```

#### 1. 题目：分发糖果 (LeetCode 135) - ⭐️ Hard 难度的试金石

**场景**：
一群孩子排成一排，每人有个评分 `ratings`。
规则：
1. 每个孩子至少发 1 个糖果。
2. 评分比旁边高的孩子，糖果必须比旁边多。
   *   `ratings[i] > ratings[i-1]` $\rightarrow$ `candy[i] > candy[i-1]`
   *   `ratings[i] > ratings[i+1]` $\rightarrow$ `candy[i] > candy[i+1]`
   求最少发多少糖果。

**错误思路**：
试图遍历一次，同时看左边和右边。你会发现处理了 `i` 和 `i-1` 的关系后，`i` 和 `i+1` 的关系又乱了。

**贪心策略（分而治之）**：
把规则拆开！
*   **第一遍（从左向右遍历）**：只看 **“左规则”**。
    *   只要 `ratings[i] > ratings[i-1]`，我就让 `candy[i] = candy[i-1] + 1`。
    *   否则，我就给 1 个。
*   **第二遍（从右向左遍历）**：只看 **“右规则”**。
    *   只要 `ratings[i] > ratings[i+1]`，我就让 `candy[i]` 变大。
    *   **关键点**：变大成多少？
    *   如果我第一遍已经给了 `candy[i]` 5个糖，而根据右规则，它只需要 2 个糖，那我应该保留 5 个（满足最大需求）。
    *   所以：`candy[i] = max(candy[i], candy[i+1] + 1)`。

**Python 代码详解**：

```python
class Solution:
    def candy(self, ratings: List[int]) -> int:
        n = len(ratings)
        # 每个孩子初始至少 1 个糖
        candies = [1] * n
        
        # 1. 从左向右遍历：处理“比左边高”的情况
        for i in range(1, n):
            if ratings[i] > ratings[i-1]:
                candies[i] = candies[i-1] + 1
        
        # 2. 从右向左遍历：处理“比右边高”的情况
        # range(start, stop, step) -> 从 n-2 倒着走到 0
        for i in range(n - 2, -1, -1):
            if ratings[i] > ratings[i+1]:
                # 贪心核心：
                # 既要满足左边规则（candies[i]已有值），又要满足右边规则（candies[i+1] + 1）
                # 取最大值才能同时满足
                candies[i] = max(candies[i], candies[i+1] + 1)
                
        return sum(candies)
```

#### 2. 题目：根据身高重建队列 (LeetCode 406) - ⭐️ 两个维度的经典

**场景**：
每个人的属性是 `[h, k]`。
*   `h`：身高。
*   `k`：前面有多少个身高 $\ge h$ 的人。
你需要把打乱的队列重新排好，满足所有人的 `k` 要求。
例子：`[[7,0], [4,4], [7,1], [5,0], [6,1], [5,2]]`

**贪心策略**：
如果两个维度（身高 `h` 和前面人数 `k`）一起考虑，一定会乱。
**先确定一个维度，再确定另一个。**

*   **思考 1**：如果按 `k` 排序行吗？
    *   `k=0` 的放前面？很难判断，因为 `k` 依赖于身高。
*   **思考 2**：如果按 `h`（身高）排序行吗？
    *   高个子 **看不见** 矮个子。
    *   比如一个 `[7, 0]` 的人站在前面，后面插进来一个 `[5, 0]` 的人。对于 7 来说，5 根本不影响他的 `k` 值（因为 5 < 7）。
    *   **结论**：先排 **高个子**。
    *   **具体排序规则**：
        1.  按身高 `h` **从大到小** 排。（高的在前面）
        2.  如果身高相同，按 `k` **从小到大** 排。（`k` 小的站前面）
*   **插入过程**：
    *   排序后：`[7,0], [7,1], [6,1], [5,0], [5,2], [4,4]`
    *   拿 `[7,0]`：插入 index 0。 `[[7,0]]`
    *   拿 `[7,1]`：插入 index 1。 `[[7,0], [7,1]]`
    *   拿 `[6,1]`：它前面应该有 1 个 $\ge 6$ 的人。因为现在的队列里全是 $\ge 6$ 的（7），所以我直接把它插到 index 1 的位置！
    *   结果：`[[7,0], [6,1], [7,1]]`。
    *   **魔法**：因为 6 比 7 矮，它插到 7 前面，并不会破坏 7 的 `k` 值。

**Python 代码详解**：

```python
class Solution:
    def reconstructQueue(self, people: List[List[int]]) -> List[List[int]]:
        # 1. 排序
        # x[0] 是身高 h，-x[0] 表示按 h 降序
        # x[1] 是 k，按 k 升序
        people.sort(key=lambda x: (-x[0], x[1]))
        
        queue = []
        
        # 2. 插入
        for p in people:
            # p[1] 就是 k，意味着他前面应该有 k 个人
            # 因为我们是从高到低遍历的，所以当前 queue 里所有人都比 p 高
            # 所以 p 应该直接插入到索引 k 的位置
            queue.insert(p[1], p)
            
        return queue
```

#### 3. 题目：加油站 (LeetCode 134) - ⭐️ 全局 vs 局部

**场景**：
环形路线上有加油站。`gas[i]` 是该站的油量，`cost[i]` 是去下一站耗油量。
问从哪个站出发能跑完一圈。如果不行为 -1。

**暴力解法**：对每个点模拟跑一圈。$O(N^2)$，会超时。

**贪心策略**：
这里有两个关键推论：
1.  **全局账单**：如果 `sum(gas) < sum(cost)`，那总油量都不够总消耗，神仙也跑不完，直接返回 -1。
2.  **局部亏损**：
    *   我从 `i` 出发，跑到 `j` 时累积油量 `current_sum < 0` 了（油不够了）。
    *   这说明什么？说明从 `i` 到 `j` 之间的 **任何一个点** 出发，都无法到达 `j`（甚至更早就会断油）。
    *   **贪心操作**：既然 `i` 到 `j` 都不行，那起点肯定在 `j+1` 之后。直接把起点设为 `j+1`，并将 `current_sum` 清零重置。

**Python 代码详解**：

```python
class Solution:
    def canCompleteCircuit(self, gas: List[int], cost: List[int]) -> int:
        total_sum = 0  # 全局净油量
        current_sum = 0 # 当前累积净油量
        start = 0      # 假设的起点
        
        for i in range(len(gas)):
            net = gas[i] - cost[i]
            total_sum += net
            current_sum += net
            
            # 如果当前累积油量变成负数，说明从 start 到 i 这段路走不通
            if current_sum < 0:
                # 贪心：起点重置为下一个点 i+1
                start = i + 1
                # 累积油量归零
                current_sum = 0
        
        # 如果全局总油量不够，肯定跑不完
        if total_sum < 0:
            return -1
            
        return start
```

### 🟣 第四阶段：反悔贪心（借助优先队列/堆）

**痛点**：
前面的贪心题目中，我们做出的选择都是“不得不做”或者“做了肯定没错”。
但在某些复杂情况下，**当前的选择在当下看来是最优的，但走到后面发现刚才选错了（比如占用了太多资源），怎么办？**

**策略**：
我们需要一种机制来 **“吃后悔药”**。
1.  先不管三七二十一，选了再说（贪心）。
2.  记录下我选过的东西（通常用 **堆/优先队列**）。
3.  如果后面发现走不下去了，或者遇到了更好的选择：
    *   **检查历史记录**（堆顶）。
    *   **把那个最差的决定撤销掉（反悔）**，换成当前这个更好的。

在 Python 中，我们需要用到 `heapq` 库（最小堆）。
*   **注意**：Python 只有最小堆。如果需要“最大堆”（比如要淘汰最大的那个），我们需要存入 **负数**。

#### 1. 题目：最低加油次数 (LeetCode 871) - ⭐️ 反悔贪心的教科书

**场景**：
你要开车从起点到终点 `target`。其实始油量 `startFuel`。
路上有一系列加油站 `stations = [[位置, 油量], ...]`。
问：**最少**加几次油能跑完全程？

**直觉陷阱**：
*   “遇到加油站就加？” $\rightarrow$ 次数太多，不是最少。
*   “快没油了再加？” $\rightarrow$ 万一快没油的时候，身边没有加油站怎么办？

**反悔/堆贪心策略**：
把自己想象成一个 **“松鼠”**。
1.  我就一直开，**路过加油站我不停，但我把它记下来（装进背包/堆里）**。
2.  当我发现 **“完蛋，油不够跑到下一站了”**：
    *   这时候我开始“后悔”。
    *   我看一眼背包（堆），找出 **油量最多** 的那个加油站。
    *   假装我当时在那里停下来加了油。
    *   油量增加了，继续跑。
    *   如果背包空了还是跑不到，那就是不可能到达（-1）。

**Python 代码详解**：

```python
import heapq

class Solution:
    def minRefuelStops(self, target: int, startFuel: int, stations: List[List[int]]) -> int:
        # 我们可以把终点也看作一个加油站，位置是 target，油量是 0
        stations.append([target, 0])
        
        max_heap = [] # 记录路过的加油站油量（存负数模拟最大堆）
        cur_fuel = startFuel
        stops = 0
        prev_pos = 0 # 上一个位置
        
        for pos, fuel in stations:
            # 1. 计算跑过来消耗了多少油
            dist = pos - prev_pos
            cur_fuel -= dist
            
            # 2. 如果油变成负数了，说明半路抛锚了
            # 需要从之前的“后悔药”里拿油，直到油量 >= 0
            while cur_fuel < 0:
                if not max_heap:
                    return -1 # 没油可加了，任务失败
                
                # 贪心：选之前路过的油量最大的那个站
                # heappop 弹出的是最小值（负数绝对值最大），取反变回正数
                top_fuel = -heapq.heappop(max_heap)
                cur_fuel += top_fuel
                stops += 1
            
            # 3. 把当前这个站的油量放进堆里（以备不时之需）
            # 注意存负数
            heapq.heappush(max_heap, -fuel)
            prev_pos = pos
            
        return stops
```

#### 2. 题目：课程表 III (LeetCode 630) - ⭐️ 时间管理的艺术

**场景**：
有一堆课程，每门课有 `[duration, lastDay]`（持续时长，最晚结束时间）。
你要修尽可能多的课。
比如 `[100, 200]` 表示这门课要上 100 天，必须在第 200 天前上完。

**贪心策略**：
1.  **排序**：显然我们要优先考虑 **截止时间早（lastDay 小）** 的课。如果不先做紧急的，后面肯定来不及。
2.  **冲突**：
    *   我们按截止时间遍历课程。
    *   如果你能上（当前时间 + duration <= lastDay），那就上，放入堆中。
    *   **关键点**：如果你 **上不了**（时间不够了）怎么办？
    *   **反悔**：看看我已经选了的课（在堆里）。有没有哪一门课 **耗时超级长**？
    *   如果有，比如我之前选了一门课耗时 100 天，而当前这门课只耗时 50 天。虽然当前这门课截止时间紧一点，但显然 **把那门 100 天的课踢掉，换成这门 50 天的课，是划算的**。
    *   **收益**：修读课程数量没变（踢1换1），但在这个过程中，我 **节省了 50 天的时间**！这为后续修更多课创造了空间。

**Python 代码详解**：

```python
import heapq

class Solution:
    def scheduleCourse(self, courses: List[List[int]]) -> int:
        # 1. 按截止时间（lastDay）从小到大排序
        courses.sort(key=lambda x: x[1])
        
        max_heap = [] # 存已选课程的 duration（存负数）
        total_time = 0 # 当前已经用的总时间
        
        for duration, last_day in courses:
            if total_time + duration <= last_day:
                # 2. 能上就先上
                total_time += duration
                heapq.heappush(max_heap, -duration)
            else:
                # 3. 上不了，看看能不能反悔
                # 如果堆里有耗时比当前这门课更长的课，那就替换掉
                if max_heap and -max_heap[0] > duration:
                    # 弹出耗时最长的那个
                    longest_duration = -heapq.heappop(max_heap)
                    total_time -= longest_duration
                    
                    # 换上当前这个短的
                    total_time += duration
                    heapq.heappush(max_heap, -duration)
                    
                    # 逻辑解释：
                    # total_time 变小了，更安全了。
                    # 课程数量没变。
                    # 这就是贪心！
        
        return len(max_heap)
```

#### 3. 题目：IPO (LeetCode 502) - ⭐️ 资本积累

**场景**：
你有初始资本 `w`。
有一堆项目，每个项目有 `profit`（利润）和 `capital`（启动资金）。
你要做 `k` 个项目，每做一个，利润会加到你的资本里，下一轮可以做更大的项目。
求最大最终资本。

**贪心策略**：
1.  **分治**：项目有两个属性。
    *   只要 `capital <= 当前 w` 的项目，我都有资格做。
    *   在所有 **有资格做** 的项目中，我一定要选 **利润 profit 最大** 的那个。
2.  **实现**：
    *   按 `capital` 从小到大排序所有项目。
    *   用一个 `ptr` 指针遍历项目，把所有当前能买得起的项目（capital <= w），扔到一个 **最大堆** 里（按 profit 排序）。
    *   从堆顶拿一个利润最大的做（w += profit）。
    *   重复 `k` 次。

**Python 代码详解**：

```python
import heapq

class Solution:
    def findMaximizedCapital(self, k: int, w: int, profits: List[int], capital: List[int]) -> int:
        # 组合在一起并按启动资金排序
        projects = list(zip(capital, profits))
        projects.sort(key=lambda x: x[0])
        
        max_heap = [] # 存放当前能做项目的利润（存负数）
        ptr = 0
        n = len(projects)
        
        for _ in range(k):
            # 1. 把所有买得起的项目都解锁，扔进池子（堆）里
            while ptr < n and projects[ptr][0] <= w:
                # 注意：我们只关心利润，所以只把 profits 压入堆
                heapq.heappush(max_heap, -projects[ptr][1])
                ptr += 1
            
            # 2. 如果池子空了，说明我有钱也没项目做，提前结束
            if not max_heap:
                break
            
            # 3. 选最赚钱的做一个
            w += -heapq.heappop(max_heap)
            
        return w
```

### 🎓 贪心算法毕业总结

恭喜你，你已经了解了从基础到高阶的贪心算法体系！

**💡 终极心法回顾**：

1.  **标准贪心**：
    *   排序是灵魂（LC 455, 860）。
    *   局部最优 $\rightarrow$ 全局最优（LC 122, 55）。
2.  **区间贪心**：
    *   求最少移除/不重叠：按 **End** 排序（LC 435）。
    *   求合并：按 **Start** 排序（LC 56）。
3.  **多维/全局贪心**：
    *   两个维度冲突时，先满足一个，再满足另一个（LC 135, 406）。
    *   局部死胡同 $\rightarrow$ 全局跳过（LC 134）。
4.  **反悔贪心**：
    *   先选上，用 **堆** 记录。
    *   发现不对劲，从堆里拿最差的出来换掉（LC 871, 630）。
