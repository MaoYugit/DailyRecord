### 第一步：理解我们的目标——什么是“极大团”？

在图论里，**“团”（Clique）**就是一群人，他们**每个人和这群里的其他人都是好朋友**（全连接）。
**“极大团”（Maximal Clique）**就是：这个朋友圈已经满员了，**再加任何一个外面的人进来，都不能保证大家还是两两互为好友。**

**例子：**
假设有 4 个人：A, B, C, D。
关系是：A-B, B-C, C-A（这三个人互为好友），然后 C-D（C 和 D 也是好友）。
*   {A, B, C} 是一个极大团。
*   {C, D} 也是一个极大团。
*   虽然 {A, B} 也是好友，但它不是“极大”，因为还能把 C 加进去。

---

### 第二步：三个盒子的“朋友圈”游戏

BK 算法准备了三个盒子（集合），我们来玩个组队游戏：

1.  **R 盒 (Result)：** 已经确定进入“当前朋友圈”的人。
2.  **P 盒 (Potential)：** “待定区”。这些人目前和 R 盒里的人都是好友，有潜力加入。
3.  **X 盒 (Excluded)：** “拒绝区”。这些人虽然也是 R 的好友，但我们**以前已经处理过他们了**。加他们会导致结果重复，所以我们要排除他们。

**游戏规则（核心逻辑）：**
*   **目标：** 把 P 盒里的人，一个一个试着放进 R 盒。
*   **结束：** 如果 P 和 X 都空了，说明 R 盒里的人已经构成了一个“极大团”。

---

### 第三步：手把手模拟一个例子

假设图如下：`A-B, B-C, C-A, C-D`。我们要找所有极大团。
初始化：`R = {}`, `P = {A, B, C, D}`, `X = {}`

#### 1. 尝试 A
*   把 A 放入 R。`R = {A}`。
*   **过滤：** A 只有两个好友 B 和 C。所以 P 和 X 里不是 A 好友的都要踢掉。
    *   新 `P = {B, C}`，新 `X = {}`。
*   **下一层递归（在 A 的基础上找）：**
    *   选 B 放入 R。`R = {A, B}`。
    *   过滤：B 的好友是 A 和 C。A 已经在 R 了。新 `P = {C}`，新 `X = {}`。
    *   **再下一层：**
        *   选 C 放入 R。`R = {A, B, C}`。
        *   过滤：C 的好友是 A, B, D。新 `P = {}`（D 不是 A 和 B 的好友，被踢了），新 `X = {}`。
        *   **成功！** P 和 X 都空了，找到第一个极大团：**{A, B, C}**。
*   **回溯：** A 处理完 B 了，把 B 从 P 移到 X。此时在 A 的那一层：`P = {C}`, `X = {B}`。
    *   选 C 放入 R。`R = {A, C}`。
    *   过滤：C 的好友是 A, B, D。但由于 A 在 R 里，我们要看谁和 A, C 都是好友。只有 B。
    *   新 `P = {}`（D 不是 A 的好友），新 `X = {B}`。
    *   因为 X 不为空（B 在里面），说明这个团 {A, C} 其实可以被包含在以前找过的团里。**不记录。**

#### 2. 回到最顶层
A 彻底试完了。把 A 从 P 移到 X。
现在顶层状态：`R = {}`, `P = {B, C, D}`, `X = {A}`。
以此类推……

### 第四步：带注释的 Python 代码

在 Python 里，我们用 `set` 的位运算（`&` 是交集，`|` 是并集，`-` 是差集）会让代码非常简洁。

```python
def bron_kerbosch(R, P, X, adj, results):
    # 如果 P 和 X 都干了，说明 R 就是一个谁也加不进去的“极大团”
    if not P and not X:
        results.append(R)
        return

    # 我们要遍历 P 里的每一个人
    # 注意：list(P) 是为了防止在循环里修改 P 导致出错
    for v in list(P):
        # 1. 尝试把 v 加进当前的朋友圈 R
        new_R = R | {v}
        
        # 2. 关键：新圈子的候选人，必须既在 P 里，又是 v 的好友
        new_P = P & adj[v]
        
        # 3. 关键：新圈子的排除人，必须既在 X 里，又是 v 的好友
        new_X = X & adj[v]
        
        # 递归下去
        bron_kerbosch(new_R, new_P, new_X, adj, results)
        
        # 4. 回溯：v 试过了，从候选区 P 移除，丢进排除区 X
        P.remove(v)
        X.add(v)

# 准备工作
import collections
edges = [('A','B'), ('B','C'), ('C','A'), ('C','D')]
adj = collections.defaultdict(set)
nodes = set()
for u, v in edges:
    adj[u].add(v)
    adj[v].add(u)
    nodes.add(u); nodes.add(v)

res = []
bron_kerbosch(set(), nodes, set(), adj, res)
print("极大团有：", res)
```

### 第五步：终极优化——“找个大佬”（Pivot）

如果图很大，上面的代码会运行很多没必要的递归。我们可以选一个“大佬”（Pivot）。

**优化逻辑：**
任何一个包含“大佬” $u$ 的极大团，要么包含 $u$，要么包含 $u$ 的某个“非好友”。
所以，我们不需要遍历 P 里的所有人，**只需要遍历 P 中“不是 $u$ 的好友”的那些人即可。** 这样递归次数会瞬间减少。

**优化后的核心循环：**

```python
def bron_kerbosch_pivot(R, P, X, adj, results):
    if not P and not X:
        results.append(R)
        return
    if not P: return

    # 选一个 Pivot (u)。通常选 P 和 X 联合起来邻居最多的那个。
    # 简单点，就选 P | X 里的第一个。
    u = next(iter(P | X))
    
    # 关键：只遍历 P 中那些“不是 u 的好友”的点
    for v in list(P - adj[u]):
        bron_kerbosch_pivot(R | {v}, P & adj[v], X & adj[v], adj, results)
        P.remove(v)
        X.add(v)
```

### 避坑指南：

1.  **为什么会有 X 盒？**
    *   如果没有 X 盒，你会反复找到同一个团。比如找了 {A, B, C} 之后，可能又会找一遍 {B, A, C}。X 就是用来告诉算法：“A 我已经全部搜过了，别再拿 A 开头组团了”。
2.  **为什么 new_P = P & adj[v]？**
    *   因为 R 里新加了 v，那么接下来能进 R 的人，必须是 v 的好友才行。所以要取交集。
3.  **LeetCode 怎么考？**
    *   通常题目会问你“最大的团是多少（Maximum Clique）”。你可以运行这个 BK 算法，最后看 `len(max(results, key=len))`。

**记法：**
*   **R** 是 **R**eal（真正的团）。
*   **P** 是 **P**otential（潜力股）。
*   **X** 是 **X**-men（被开除的人）。
*   递归公式：`BK(R+v, P ∩ N(v), X ∩ N(v))`。

---

说实话，BK 算法在 LeetCode 上并没有**完全对应**的模板题（即直接让你求极大团的题目），因为它属于图论中比较高级且针对特定 NP-Hard 问题的优化算法。

但是，BK 算法的核心思想是 **“回溯 + 集合过滤 + 剪枝”**。为了练好这个算法，我建议你按照由浅入深的顺序做以下几类题目。这些题目能帮你打好基础，最终让你彻底掌握 BK 算法的精髓。

### 第一阶段：打好“回溯”和“子集”基础
BK 算法本质上是在找符合条件的**子集**。你先要熟练掌握如何穷举所有组合。

1.  **LeetCode 78. 子集 (Subsets)** —— **入门必做**
    *   **理由：** BK 算法的基础就是“选还是不选这个点”。这道题让你练习如何生成所有可能的组合。
2.  **LeetCode 90. 子集 II (Subsets II)**
    *   **理由：** 练习如何处理**重复**（类似 BK 算法中 X 盒子的作用，防止重复计算）。

---

### 第二阶段：进阶“条件约束下的搜索”
BK 算法不是找所有子集，而是找“两两互为好友”的子集。

3.  **LeetCode 1255. 得分最高的单词组合**
    *   **理由：** 这道题要求你在搜索过程中不断检查剩余资源（类似于 P 盒子的过滤）。如果你能用 DFS 做出来，说明你已经具备了 BK 算法的思维。
4.  **LeetCode 1601. 最多可达成的换楼请求数目**
    *   **理由：** $N$ 非常小（$N \le 16$），这和 BK 算法适用的场景非常像。你需要搜索出满足特定“平衡”条件的子集。

---

### 第三阶段：最接近 BK 算法逻辑的题目
这些题目涉及图中节点的互相约束。

5.  **LeetCode 2151. 基于陈述统计最多好人数** —— **强烈推荐**
    *   **理由：** 这是 LeetCode 上逻辑最像 BK 算法的题。
    *   你需要找出一个最大的“好人”群体，使得他们说的话互不矛盾。这本质上就是在一个约束图中找一个**最大相容子集**。你可以尝试用 BK 算法的“尝试 + 过滤”逻辑去写这道题。
6.  **LeetCode 1349. 参加考试的最大学生数**
    *   **理由：** 这是一道经典的“最大独立集”问题（在特定图中）。**最大独立集**和**最大团**是镜像问题（在补图中找团就是找独立集）。虽然这题通常用状压 DP 做，但理解它的独立集性质对理解 BK 算法非常有帮助。

### 第四阶段：实战挑战（如果你想挑战自己）
如果你想找一个真正需要高效搜索的图论题：

7.  **LeetCode 2002. 两个回文子序列长度的最大乘积**
    *   **理由：** 虽然题目说的是回文，但解法往往涉及寻找两个“互不干扰”的集合，这种在小范围内进行极致搜索的思路与 BK 算法的优化策略（Pivot）异曲同工。

### 给你的刷题建议：

1.  **先不要追求 Pivot 优化：**
    先尝试用最简单的 `bron_kerbosch(R, P, X)` 逻辑去解题。
2.  **学会用 Python 的集合运算：**
    刷这些题时，强迫自己使用 `s1 & s2`（交集）、`s1 | {v}`（并集）、`s1 - {v}`（差集）。这会让你的代码和 BK 算法的模板神似。
3.  **关注数据范围：**
    当你看到题目中 $N$ 的范围在 **15 到 40** 之间，且要求找某种“最优群体”时，大脑里要立刻闪过 BK 算法或类似的 DFS 剪枝搜索。
