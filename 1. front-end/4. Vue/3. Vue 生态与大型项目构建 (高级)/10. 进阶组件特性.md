### **第十章：进阶组件特性**

在日常开发中，我们经常会遇到一些挑战：如何处理一个无论在哪个组件里调用，都能在页面顶层显示的弹窗？如何优雅地处理组件加载时的等待状态？如何直接操作 DOM 来实现一些特殊效果？当组件嵌套很深时，如何避免“Props 钻探”地狱？

这一章，我们将学习 Vue 提供的一系列高级工具，它们就像瑞士军刀一样，为我们提供了应对这些复杂场景的解决方案。

**我们的目标：**

1.  使用 `Teleport` 创建一个不受父组件样式和布局影响的全局模态框。
2.  利用 `Suspense` 来展示优雅的加载状态，提升异步组件的用户体验。
3.  创建一个自定义指令，实现一个自动聚焦的输入框。
4.  通过 `Provide / Inject` 实现跨越多层组件的轻松通信。

#### **10.1 Teleport (传送门)：打破组件 DOM 结构的束缚**

**问题：** 假设你在一个嵌套很深的组件 A 中，需要显示一个模态框（Modal）或通知（Toast）。从组件化的角度看，这个模态框的逻辑应该属于组件 A。但从 DOM 结构的角度看，它的 HTML 应该被渲染在 `<body>` 的直接子节点下，以避免受到父组件的 `overflow: hidden`、`z-index` 或特定 CSS 转换的影响。

**解决方案：`<Teleport>` 组件**

`<Teleport>` 是一个内置组件，它可以将它的插槽内容“传送”到 DOM 树的另一个位置进行渲染，但同时保持其在 Vue 组件树中的逻辑关系不变。

**案例实践：创建一个 `BaseModal.vue` 组件**

```vue
<!-- src/components/BaseModal.vue -->
<script lang="ts" setup>
defineProps<{
  show: boolean
}>();

const emit = defineEmits<{
  (e: 'close'): void
}>();
</script>

<template>
  <!-- 1. 使用 Teleport 内置组件，并指定 `to` 属性为目标位置 -->
  <!-- `to="body"` 是最常见的用法，它会将内容传送到 <body> 标签的末尾 -->
  <Teleport to="body">
    <!-- 只有当 show 为 true 时才渲染模态框 -->
    <div v-if="show" class="modal-mask" @click.self="emit('close')">
      <div class="modal-content">
        <header>
          <slot name="header">默认标题</slot>
        </header>
        <main>
          <slot></slot>
        </main>
        <footer>
          <slot name="footer">
            <button @click="emit('close')">关闭</button>
          </slot>
        </footer>
      </div>
    </div>
  </Teleport>
</template>

<style scoped>
.modal-mask {
  position: fixed;
  top: 0;
  left: 0;
  width: 100%;
  height: 100%;
  background-color: rgba(0, 0, 0, 0.5);
  display: flex;
  justify-content: center;
  align-items: center;
}
.modal-content {
  background-color: white;
  padding: 20px;
  border-radius: 8px;
  min-width: 300px;
}
</style>
```

**在任何组件中使用它：**

```vue
<!-- src/App.vue -->
<script lang="ts" setup>
import { ref } from 'vue';
import BaseModal from './components/BaseModal.vue';

const isModalVisible = ref(false);
</script>

<template>
  <div>
    <button @click="isModalVisible = true">打开模态框</button>

    <!-- 逻辑上，BaseModal 仍然是 App.vue 的子组件 -->
    <BaseModal :show="isModalVisible" @close="isModalVisible = false">
      <template #header>
        <h3>这是一个传送门模态框！</h3>
      </template>
      <p>这段内容在 Vue 组件树中属于 App.vue，但在真实的 DOM 树中，它被渲染到了 `<body>` 下。</p>
    </BaseModal>
  </div>
</template>
```
现在，无论你把这个 `<button>` 和 `<BaseModal>` 放在多深的组件里，弹出的模态框 DOM 都会被干净地渲染在 `<body>` 下，完美解决了样式和层级问题。

#### **10.2 Suspense：优雅地处理异步**

**问题：** 在第七章我们学习了路由懒加载，组件会在需要时才被加载。在加载期间，页面可能会出现短暂的空白或闪烁。我们如何为用户提供一个平滑的过渡，比如显示一个加载动画？

**解决方案：`<Suspense>` 组件 (目前仍是实验性特性)**

`<Suspense>` 是一个内置组件，用于在等待某个异步依赖（如异步组件或带 `async setup` 的组件）解析完成时，协调渲染“加载中”和“加载完成”的状态。

它有两个插槽：
*   `#default`: 当异步操作完成时，显示这里的内容。
*   `#fallback`: 在等待异步操作时，显示这里的内容。

**案例实践：为懒加载的路由组件添加加载状态**

```vue
<!-- src/App.vue -->
<template>
  <div id="app">
    <nav>...</nav>
    
    <router-view v-slot="{ Component }">
      <!-- 1. 使用 Suspense 组件包裹 router-view -->
      <Suspense timeout="0">
        <!-- 2. #default 插槽：正常渲染路由组件 -->
        <template #default>
          <component :is="Component" />
        </template>
        
        <!-- 3. #fallback 插槽：在路由组件加载完成前，显示这里的内容 -->
        <template #fallback>
          <div class="loading-spinner">
            <h2>正在加载页面...</h2>
          </div>
        </template>
      </Suspense>
    </router-view>
  </div>
</template>

<style>
.loading-spinner { padding: 40px; text-align: center; }
</style>
```
现在，当你切换到一个懒加载的路由时，用户会先看到“正在加载页面...”，直到组件文件下载并解析完毕，`<Suspense>` 会自动切换到 `#default` 插槽，显示真正的页面内容。这极大地提升了用户体验。

#### **10.3 自定义指令：与 DOM 的亲密接触**

**问题：** 虽然 Vue 的声明式渲染模型能处理绝大部分情况，但有时我们确实需要直接操作 DOM，比如页面加载后让某个输入框自动获得焦点。

**解决方案：自定义指令 (Custom Directives)**

Vue 允许我们注册自己的指令，它们以 `v-` 开头，可以直接用在模板的元素上。自定义指令提供了一系列钩子函数，让我们可以在元素的生命周期不同阶段执行 DOM 操作。

**案例实践：创建一个 `v-focus` 指令**

```javascript
// main.js 或一个单独的 directives.js 文件
const app = createApp(App);

// 注册一个全局自定义指令 `v-focus`
app.directive('focus', {
  // 当被绑定的元素挂载到 DOM 中时……
  mounted(el) {
    // 聚焦元素
    el.focus();
  }
});

app.mount('#app');
```

**在组件中使用它：**

```vue
<template>
  <h2>自定义指令示例:</h2>
  <!-- 页面加载后，这个输入框会自动获得焦点 -->
  <input type="text" v-focus placeholder="我会自动聚焦">
</template>
```

你也可以在组件内部创建局部指令，或者为指令传递参数和修饰符，实现更复杂的功能，比如 `v-tooltip="'提示内容'"` 或 `v-debounce-click="handleClick"`。

#### **10.4 Provide / Inject：跨层级“空投”数据**

**问题：** 假设你有一个顶层 `App` 组件，它获取了当前网站的主题色（比如 `'dark'`）。现在，一个嵌套在 `App` 内部 5 层深处的 `GrandChildButton` 组件需要根据这个主题色来改变自己的样式。如果使用 Props，我们需要将 `theme` 这个 prop 一层一层地传递下去，非常繁琐。

**解决方案：Provide (提供) 和 Inject (注入)**

`Provide/Inject` 是一种依赖注入模式，允许一个祖先组件向其所有后代组件（无论层级多深）“提供”数据或方法，而后代组件可以“注入”并使用这些数据或方法。

**祖先组件 (`App.vue`):**

```vue
<!-- src/App.vue -->
<script lang="ts" setup>
import { ref, provide } from 'vue';

const theme = ref('light');

function toggleTheme() {
  theme.value = theme.value === 'light' ? 'dark' : 'light';
}

// 1. 使用 provide 函数提供数据
// 第一个参数是 key (推荐使用 Symbol 或字符串)，第二个参数是要提供的值
provide('theme', theme);
provide('toggleTheme', toggleTheme);
</script>

<template>
  <div :class="theme">
    <h1>Provide / Inject 示例</h1>
    <button @click="toggleTheme">切换主题</button>
    <hr>
    <SomeChildComponent />
  </div>
</template>
```

**任何后代组件 (`GrandChildButton.vue`)**

```vue
<!-- 嵌套在 SomeChildComponent 内部的某个组件 -->
<script lang="ts" setup>
import { inject, type Ref } from 'vue';

// 2. 使用 inject 函数注入祖先提供的数据
// 注入时，最好为 inject 提供一个默认值，以防祖先没有 provide
const theme = inject<Ref<string>>('theme', ref('light'));
const toggleTheme = inject<() => void>('toggleTheme', () => {});
</script>

<template>
  <div class="grandchild">
    <p>我是孙子组件，我感知到的主题是: <strong>{{ theme }}</strong></p>
    <button @click="toggleTheme">从孙子组件切换主题</button>
  </div>
</template>
```
`Provide/Inject` 就像一个“无线信号”，祖先组件是发射塔，任何在信号范围内的后代组件都可以用正确的“频率”（`key`）接收到这个信号。这对于开发可复用的插件或组件库，或者传递全局性的配置数据时非常有用。

> **大师兄提示:** 虽然 `Provide/Inject` 很强大，但不要滥用它来替代 Pinia。它更适合用于传递那些不经常变化、或者与特定组件树强相关的数据。对于真正的**全局应用状态**，Pinia 依然是更好的选择。
