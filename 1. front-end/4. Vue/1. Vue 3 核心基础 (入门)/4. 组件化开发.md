### **第四章：组件化开发**

到目前为止，我们所有的代码都写在 `App.vue` 这一个文件里。对于一个小小的课程卡片来说，这完全没问题。但想象一下，当你要构建一个完整的电商网站时，页面会包含导航栏、侧边栏、商品列表、购物车、页脚……如果把所有代码都塞进一个文件，那将是一场无法维护的灾难。

**组件化 (Component-based)** 是现代前端开发的基石。它允许我们将一个庞大的用户界面，拆分成一个个独立的、可复用的“**积木块**”。每一块“积木”（组件）都有自己独立的逻辑 (`<script>`)、模板 (`<template>`) 和样式 (`<style>`)。

**我们的目标：**

1.  将我们现有的“课程卡片”拆分成多个更小的、功能专一的组件。
2.  学习组件之间如何像进行一场优雅的“对话”一样传递信息（父子通信）。
3.  掌握 `slot`，让我们的组件变得像“变形金刚”一样灵活，能适应各种内容。
4.  理解组件从诞生到消亡的完整过程（生命周期）。
5.  打造一个我们自己的、支持 `v-model` 的自定义输入组件。

---

#### **4.1 组件基础：搭建你的第一块“积木”**

**1. 什么是组件以及组件化的优势？**

*   **什么是组件？** 一个组件就是一个 `.vue` 文件，一个拥有自身模板、脚本和样式的独立单元。我们一直在写的 `App.vue` 本身就是一个根组件。
*   **优势 (面试常考)：**
    *   **可复用性 (Reusability):** 同样一个“按钮”组件，可以在网站的任何地方使用，无需重复编写代码。
    *   **可维护性 (Maintainability):** 当你需要修改某个功能时，只需找到对应的组件进行修改，而不会影响到其他不相关的部分。
    *   **代码组织 (Organization):** 代码结构更清晰，每个文件只关注自己的功能，极大地便于团队协作。

**2. 创建和注册组件**

让我们马上动手！我们将把课程信息和操作按钮分离开，创建一个 `CourseInfo.vue` 组件。

**步骤一：创建新组件文件**

1.  在 `src` 目录下，找到 `components` 文件夹。
2.  在 `components` 文件夹内，创建一个新文件，命名为 `CourseInfo.vue`。

**步骤二：迁移逻辑和模板**

将 `App.vue` 中所有**只负责展示课程信息**的部分（名称、价格、描述、特色列表等），剪切并粘贴到 `CourseInfo.vue` 中。

```vue
<!-- src/components/CourseInfo.vue -->
<script setup>
// 我们暂时将数据写死在这里，稍后会学习如何从父组件接收
const course = {
  name: 'Vue 3 大师课',
  price: 89.9,
  onSale: true,
  description: '这是一门帮助你<strong>从入门到精通</strong>Vue 3的课程。',
  features: [
    '核心基础', 'Composition API', 'Vue Router', 'Pinia', '实战项目'
  ]
}
</script>

<template>
  <h1 :class="{ 'on-sale': course.onSale }">{{ course.name }}</h1>
  <p :style="{ color: course.onSale ? 'red' : 'black', fontSize: '20px' }">
    价格: ¥{{ course.price }}
  </p>
  <h2>课程描述:</h2>
  <p v-html="course.description"></p>
  <h3>课程特色:</h3>
  <ul>
    <li v-for="feature in course.features" :key="feature">
      {{ feature }}
    </li>
  </ul>
</template>

<style scoped>
/* 
  `scoped` 属性是一个极其重要的概念！
  它会确保这里的样式只对当前组件内的元素生效，
  绝对不会“污染”到其他组件或 App.vue 的全局样式。
*/
.on-sale {
  color: red;
  text-decoration: line-through;
}
</style>
```

**步骤三：在父组件 (`App.vue`) 中使用新组件 (局部注册)**

在 Vue 3 的 `<script setup>` 中，注册组件变得异常简单：**只需导入，即可在模板中使用**。

```vue
<!-- src/App.vue -->
<script setup>
// 1. 导入你的新组件
import CourseInfo from './components/CourseInfo.vue'

import { ref, reactive, computed, watch } from 'vue'

const course = reactive({ /* ... 保留完整的数据对象 ... */ })
const cart = ref(0)
// ... 其他逻辑和 watch ...
</script>

<template>
  <div class="card">
    <img :src="course.image" :alt="course.name" class="course-image">
    
    <!-- 2. 像使用普通 HTML 标签一样使用你的组件 -->
    <CourseInfo />
    
    <!-- 其他部分暂时保留 -->
    <h3>库存状态:</h3>
    <p>{{ stockStatusText }}</p>
    <hr>
    <p>购物车数量: {{ cart }}</p>
    <!-- ... 操作按钮 ... -->
  </div>
</template>

<style>
/* App.vue 的全局样式 */
/* ... */
</style>
```

刷新页面，你会看到课程信息依然显示在那里。恭喜你，你已经成功创建并使用了你的第一个子组件，迈出了组件化开发最重要的一步！

> **大师兄提示：局部注册 vs 全局注册**
>
> *   **局部注册 (推荐):** 正如我们刚才做的，在使用组件的父组件中单独导入。这是**最佳实践**，因为它能更好地配合构建工具进行 Tree-Shaking。如果某个页面没用到这个组件，它就不会被打包进去，从而减小最终的文件体积。
> *   **全局注册:** 你也可以在入口文件 `main.js` 中通过 `app.component('MyComponent', MyComponent)` 来注册一个全局组件。这样你就可以在任何地方直接使用它，而无需导入。这通常只适用于那些在整个应用中频繁使用的基础组件，比如自定义的按钮、弹窗、图标等。

#### **4.2 父子组件通信 (Props & Events)**

现在，我们的 `CourseInfo` 组件是孤立的，它使用的是自己内部写死的数据。我们需要让父组件 (`App.vue`) 将**真实的数据**传递给它。这就是父子通信。

**把父子通信想象成一场对话：**

*   父亲对儿子说话：**Props** (单向指令)
*   儿子回应父亲：**Events** (发出通知)

**1. Props：父组件向子组件传递数据**

`Props` (properties的缩写) 是父组件向子组件单向传递数据的机制。

**子组件 (`CourseInfo.vue`)：** 使用 `defineProps` 宏声明它期望接收哪些数据。

```vue
<!-- src/components/CourseInfo.vue -->
<script setup>
// 删除内部写死的 course 对象
// 使用 defineProps 宏来定义该组件可以接收的 props
const props = defineProps(['course'])

// 在模板中，所有用到 course 的地方，现在都需要通过 props.course 来访问
</script>

<template>
  <!-- 将所有 course.xxx 修改为 props.course.xxx -->
  <h1 :class="{ 'on-sale': props.course.onSale }">{{ props.course.name }}</h1>
  <p :style="{ color: props.course.onSale ? 'red' : 'black', fontSize: '20px' }">
    价格: ¥{{ props.course.price }}
  </p>
  <!-- ... 其他地方同样修改 ... -->
</template>
```

**父组件 (`App.vue`)：** 通过 `v-bind` (缩写 `:`) 将数据“绑定”到子组件的 prop 上。

```vue
<!-- src/App.vue -->
<template>
  <div class="card">
    <img :src="course.image" :alt="course.name" class="course-image">
    
    <!-- 像绑定 HTML 属性一样，将父组件的 course 对象传递给子组件的 course prop -->
    <CourseInfo :course="course" />
    
    <!-- ... -->
  </div>
</template>
```

现在，子组件的显示完全由父组件的数据驱动了！这才是真正的组件化。

**Props 校验与默认值 (面试高频点)**

为了让组件更健壮、更易于他人使用，我们应该对 Props 进行类型校验。这是一种非常重要的专业习惯。

```javascript
// src/components/CourseInfo.vue -> <script setup>

defineProps({
  // 将数组形式改为对象形式以进行校验
  course: {
    type: Object, // 规定 course 必须是对象类型
    required: true, // 规定 course 是必传的
    // default: () => ({ name: '默认课程' }) // 如果不是必传(required: false)，可以这样设置一个默认值
  }
})
```
如果父组件忘记传递 `course` 或者传递了错误的类型，Vue 会在控制台给出清晰的警告。

**2. Events (`$emit`)：子组件向父组件发送消息**

现在我们把操作按钮也拆分出去，创建一个 `CourseActions.vue` 组件。当用户点击按钮时，子组件需要**通知**父组件：“嘿，用户想把商品加入购物车！”

**子组件 (`CourseActions.vue`)：**

```vue
<!-- src/components/CourseActions.vue -->
<script setup>
import { ref } from 'vue';

defineProps({
  stock: {
    type: Number,
    required: true
  }
});

// 1. 使用 defineEmits 宏声明该组件会触发哪些自定义事件
const emit = defineEmits(['addToCart']);

const quantity = ref(1);

function handleAddToCart() {
  // 2. 当按钮被点击时，触发 addToCart 事件，并可以附带参数 (payload)
  emit('addToCart', quantity.value);
}
</script>

<template>
  <div class="controls">
    <label for="quantity">购买数量:</label>
    <!-- v-model.number 确保 quantity 是数字 -->
    <input type="number" id="quantity" v-model.number="quantity" min="1" :max="stock">
    
    <!-- 3. 监听原生的 click 事件，并调用我们自己的方法 -->
    <button v-if="stock > 0" @click="handleAddToCart">
      加入购物车
    </button>
    <button v-else :disabled="true" class="disabled-button">
      已售罄
    </button>
  </div>
</template>

<style scoped> /* ... 样式 ... */ </style>
```

**父组件 (`App.vue`)：** 使用 `v-on` (缩写 `@`) 监听子组件触发的自定义事件。

```vue
<!-- src/App.vue -->
<script setup>
import CourseInfo from './components/CourseInfo.vue';
import CourseActions from './components/CourseActions.vue';
// ...

// 父组件的 addToCart 方法现在变成了事件处理函数，并接收子组件传来的参数
function handleAddToCart(quantity) {
  if (course.stock >= quantity) {
    cart.value += quantity;
    course.stock -= quantity;
  } else {
    alert('库存不足！');
  }
}
</script>

<template>
  <div class="card">
    <!-- ... -->
    <hr>
    <p>购物车数量: {{ cart }}</p>

    <!-- 监听子组件触发的 addToCart 事件，并调用 handleAddToCart 方法 -->
    <CourseActions :stock="course.stock" @add-to-cart="handleAddToCart" />
  </div>
</template>
```

> **面试核心：单向数据流 (One-Way Data Flow)**
> 你已经亲手实现了 Vue 最核心的设计原则之一。数据总是通过 **Props** 从父组件流向子组件。子组件**绝不能**直接修改 Props，而是通过触发 **Events** 来通知父组件进行数据更新。这种模式使得数据流向清晰可控，极大地简化了大型应用的状态管理和问题排查。

#### **4.3 组件插槽 (Slots)**

`Props` 让我们能传递数据，但如果我们想传递更灵活的东西，比如整个 **HTML 结构**呢？比如，我们想创建一个通用的卡片组件 `BaseCard.vue`，它的头部和脚部内容由父组件来决定。这时就需要**插槽 (Slot)**。

插槽是**父组件向子组件**内部指定位置分发内容的“**占位符**”。

**子组件 (`BaseCard.vue`)：**

```vue
<!-- src/components/BaseCard.vue -->
<template>
  <div class="base-card">
    <div class="card-header" v-if="$slots.header">
      <slot name="header"></slot> <!-- 1. 名为 header 的插槽 -->
    </div>
    <div class="card-body">
      <slot></slot> <!-- 2. 默认插槽，没有名字 -->
    </div>
    <div class="card-footer" v-if="$slots.footer">
      <slot name="footer"></slot> <!-- 3. 名为 footer 的插槽 -->
    </div>
  </div>
</template>

<style scoped>
/* ... 卡片的基础样式 ... */
.base-card { border: 1px solid #ccc; border-radius: 8px; margin: 20px; }
.card-header, .card-footer { padding: 10px; border-bottom: 1px solid #eee; background-color: #f7f7f7; }
.card-body { padding: 20px; }
</style>
```
*小技巧: `$slots.header` 可以判断父组件是否为这个插槽提供了内容。*

**父组件 (`App.vue`)：** 使用 `<template>` 配合 `v-slot` 指令 (缩写 `#`) 来填充具名插槽。

```vue
<!-- src/App.vue -->
<script setup>
import BaseCard from './components/BaseCard.vue';
// ...其他组件导入
</script>

<template>
  <!-- 用 BaseCard 组件包裹所有内容 -->
  <BaseCard>
    <!-- 使用 #header 来指定内容要填充到名为 header 的插槽 -->
    <template #header>
      <h1>{{ course.name }}</h1>
    </template>

    <!-- 没有指定名字的内容，会进入默认插槽 -->
    <img :src="course.image" :alt="course.name" class="course-image">
    <!-- 将 CourseInfo 也放入默认插槽 -->
    <CourseInfo :course="course" /> 
    
    <!-- 使用 #footer 来指定内容要填充到名为 footer 的插槽 -->
    <template #footer>
      <CourseActions :stock="course.stock" @add-to-cart="handleAddToCart" />
      <hr>
      <p>购物车数量: {{ cart }}</p>
    </template>
  </BaseCard>
</template>
```

现在，`App.vue` 的结构变得异常清晰！它只负责**组织**和**布局**，而具体的内容和逻辑则被封装在了各自的组件中。

**作用域插槽 (Scoped Slots) - 让插槽更强大 (面试高阶考点)**

想象一个场景：一个子组件负责循环一个列表，但它**不决定**列表项如何展示，而是把这个决定权**交还给父组件**。这时，子组件需要把循环中的每一项数据传回给父组件的插槽。

**子组件 (`UserList.vue`)：**

```vue
<!-- src/components/UserList.vue -->
<script setup>
import { ref } from 'vue';
const users = ref([
  { id: 1, name: '张三', role: 'Admin' },
  { id: 2, name: '李四', role: 'User' }
]);
</script>

<template>
  <ul>
    <li v-for="user in users" :key="user.id">
      <!-- 通过 v-bind 将循环中的 user 对象暴露给父组件 -->
      <slot :user="user"></slot>
    </li>
  </ul>
</template>
```

**父组件 (`App.vue`)：**

```vue
<!-- App.vue -->
<UserList v-slot="slotProps">
  <!-- slotProps 会是一个对象，形如 { user: { id: 1, ... } } -->
  <strong>{{ slotProps.user.name }}</strong> ({{ slotProps.user.role }})
</UserList>

<!-- 更简洁的解构语法 (推荐) -->
<UserList v-slot="{ user }">
  <strong>{{ user.name }}</strong> ({{ user.role }})
</UserList>
```

作用域插槽是一种高级模式，它极大地提升了组件的灵活性和复用性，是编写高质量基础组件的必备技能。

#### **4.4 组件生命周期**

每个 Vue 组件实例在被创建时都要经过一系列的初始化过程——例如，需要设置数据监听、编译模板、将实例挂载到 DOM 并在数据变化时更新 DOM 等。同时，在这个过程中也会运行一些叫做**生命周期钩子**的函数，这给了用户在不同阶段添加自己的代码的机会。

**把组件的生命周期想象成一个人的“生老病死”：**

*   **创建 (Creation):** `setup()` (组件的大部分逻辑都在这里)
*   **挂载 (Mounting):** 组件被插入到真实 DOM 中。
    *   `onMounted()`: **最常用**的钩子。当组件**第一次**被渲染到页面上后调用。非常适合执行需要 DOM 元素存在的操作，比如：初始化第三方图表库、发送网络请求获取初始数据等。
*   **更新 (Updating):** 组件因响应式数据变化而重新渲染。
    *   `onUpdated()`: 组件更新完毕后调用。
*   **卸载 (Unmounting):** 组件从 DOM 中被移除。
    *   `onUnmounted()`: 组件被销毁前调用。适合进行清理工作，比如：移除手动添加的事件监听器、清除定时器等，防止内存泄漏。

**案例实践：** 在 `CourseInfo.vue` 中体验生命周期。

```vue
<!-- src/components/CourseInfo.vue -->
<script setup>
import { onMounted, onUnmounted } from 'vue'

defineProps({ /* ... */ })

console.log('组件 setup: 组件被创建了')

onMounted(() => {
  console.log('组件 onMounted: DOM 已经挂载，现在可以操作 DOM 了')
  // 比如：fetch('/api/course/details').then(...)
})

onUnmounted(() => {
  console.log('组件 onUnmounted: 组件即将被销毁，在这里进行清理')
})
</script>
```

打开浏览器的控制台，你就能清晰地看到这些钩子函数的触发时机。

#### **4.5 `v-model` 应用于组件**

我们知道 `v-model` 可以轻松地在原生 `<input>` 上实现双向数据绑定。那么，我们能让我们自己封装的组件也支持 `v-model` 吗？当然可以！

**面试核心：`v-model` 在组件上的本质是什么？**
`v-model` 只是一个语法糖。在 Vue 3 中，`v-model="myData"` 等同于：
`:modelValue="myData" @update:modelValue="value => myData = value"`

它本质上就是**一个名为 `modelValue` 的 prop** 和 **一个名为 `update:modelValue` 的事件**的组合。

**案例实践：创建一个 `CustomInput.vue` 组件。**

**子组件 (`CustomInput.vue`)：**

```vue
<!-- src/components/CustomInput.vue -->
<script setup>
// 1. 接收名为 modelValue 的 prop
defineProps(['modelValue']);

// 2. 声明会触发名为 update:modelValue 的事件
const emit = defineEmits(['update:modelValue']);

function onInput(event) {
  // 3. 在 input 事件中，将新的值通过事件发射出去
  emit('update:modelValue', event.target.value);
}
</script>

<template>
  <input 
    type="text"
    :value="modelValue" 
    @input="onInput"
    class="custom-input"
  >
</template>

<style scoped>
.custom-input { border: 1px solid skyblue; padding: 8px; }
</style>```
```
**父组件 (`App.vue`)：**

```vue
<!-- App.vue -->
<script setup>
import { ref } from 'vue'
import CustomInput from './components/CustomInput.vue'
const searchText = ref('Hello Vue')
</script>

<template>
  <!-- ... -->
  <hr>
  <h2>自定义输入组件:</h2>
  <!-- 像使用原生 input 一样使用 v-model -->
  <CustomInput v-model="searchText" />
  <p>你输入的内容是: {{ searchText }}</p>
</template>
```

你成功了！你创建了一个完全支持双向数据绑定的自定义组件。

> **Vue 3 新特性：多个 `v-model`**
> Vue 3 还允许在一个组件上绑定多个 `v-model`，只需给它一个参数即可：
> `<CustomInput v-model:name="name" v-model:age="age" />`
> 这在实现复杂的表单组件时非常有用。
