### **第五章：Composition API 核心**

在前四章，我们已经一直在使用 `<script setup>`，这本身就是 Composition API 的一部分。我们学会了如何创建组件、如何让数据响应。但我们还没有真正触及其设计的**灵魂**——为什么 Vue 3 要引入一种全新的 API？它到底解决了什么问题？

这一章，我们将深入 Composition API 的“**道**”与“**术**”。你将理解其背后的设计哲学，并掌握一系列强大的进阶 API，为编写出高内聚、可复用、易维护的“大师级”代码打下坚实的基础。

**我们的目标：**

1.  深刻理解为什么要用 Composition API，能清晰地向面试官阐述其优势。
2.  学习其“前身” `setup` 函数，了解其工作原理。
3.  掌握 `readonly`, `shallowRef`, `toRefs` 等进阶响应式工具，用于性能优化和解决特定问题。
4.  彻底明白 `<script setup>` 到底为我们简化了什么。

#### **5.1 为什么需要 Composition API (面试核心)**

面试官：“你为什么选择用 Composition API？它比 Vue 2 的 Options API 好在哪里？” 这是一个几乎必问的问题。

要回答好这个问题，我们必须理解 Options API 的**痛点**。

**Options API 的问题：逻辑分散**

在 Vue 2 的 Options API 中，我们是按“**选项**”(`data`, `methods`, `computed`, `mounted` 等)来组织代码的。对于小组件来说，这很清晰。但当组件变得复杂时，灾难就开始了。

**想象一下我们的课程卡片变得更复杂：**

1.  **功能A：获取课程数据** (需要 `data` 里的 `course`，`methods` 里的 `fetchCourse`，`mounted` 里的调用)
2.  **功能B：处理用户收藏** (需要 `data` 里的 `isFavorited`，`methods` 里的 `toggleFavorite`)
3.  **功能C：鼠标位置追踪** (一个好玩的功能，需要 `data` 里的 `x` 和 `y`，`mounted` 里监听事件，`unmounted` 里移除监听)

在 Options API 中，代码会像这样分布：

```javascript
// Vue 2 Options API 风格
export default {
  data() {
    return {
      course: {},       // <-- 功能 A
      isFavorited: false, // <-- 功能 B
      x: 0,             // <-- 功能 C
      y: 0              // <-- 功能 C
    }
  },
  methods: {
    fetchCourse() { /* ... */ },    // <-- 功能 A
    toggleFavorite() { /* ... */ }, // <-- 功能 B
    updateMouse(e) { /* ... */ }    // <-- 功能 C
  },
  mounted() {
    this.fetchCourse();                      // <-- 功能 A
    window.addEventListener('mousemove', this.updateMouse); // <-- 功能 C
  },
  unmounted() {
    window.removeEventListener('mousemove', this.updateMouse); // <-- 功能 C
  }
}
```

**发现问题了吗？** 同一个功能的代码，像被打散的拼图一样，散落在文件的不同角落。当你想修改“鼠标追踪”功能时，你需要在 `data`, `methods`, `mounted`, `unmounted` 之间来回跳转。这被称为“**逻辑分散**”问题。

**Composition API 的解决方案：按逻辑组织**

Composition API 允许我们**按逻辑功能（或叫“逻辑关注点”）来组织代码**。所有与同一功能相关的代码都可以放在一起。

```javascript
// Vue 3 Composition API 风格
import { ref, onMounted, onUnmounted } from 'vue';

// --- 功能 A: 获取课程数据 ---
const course = ref({});
function fetchCourse() { /* ... */ }
onMounted(() => fetchCourse());

// --- 功能 B: 处理用户收藏 ---
const isFavorited = ref(false);
function toggleFavorite() { /* ... */ }

// --- 功能 C: 鼠标位置追踪 ---
const x = ref(0);
const y = ref(0);
function updateMouse(e) { /* ... */ }
onMounted(() => window.addEventListener('mousemove', updateMouse));
onUnmounted(() => window.removeEventListener('mousemove', updateMouse));
```
看，现在所有“鼠标追踪”的代码都在一个地方！这就是 Composition API 带来的最大好处：**高内聚、低耦合**。代码更易读、更易维护，并且为逻辑复用提供了巨大的便利（我们将在下一章详细讲解）。

#### **5.2 `setup` 函数：梦开始的地方**

在我们现在使用的 `<script setup>` 语法糖出现之前，Composition API 的所有逻辑都写在一个名为 `setup()` 的函数中。虽然现在我们不常手动写它了，但**理解它**对于深入了解 Vue 的工作原理至关重要。

*   **`setup` 是什么？** 它是一个特殊的函数，是组件中使用 Composition API 的**入口**。
*   **执行时机 (面试高频点)？** 它在组件实例被创建**之前**执行，即在 `beforeCreate` 和 `created` 钩子之前。因此，在 `setup` 函数内部，**无法访问 `this`**。

一个组件如果使用了 `setup` 函数，会是这样：

```vue
<script>
import { ref } from 'vue';
import CourseInfo from './components/CourseInfo.vue';

export default {
  components: { CourseInfo },
  props: {
    // ... props 定义
  },
  setup(props, context) {
    console.log('组件 setup 函数执行');
    
    // 1. 定义响应式数据
    const cart = ref(0);

    // 2. 定义方法
    function addToCart() {
      cart.value++;
    }

    // 3. 必须显式地 return，模板才能使用
    return {
      cart,
      addToCart
    };
  }
}
</script>
```

**`setup` 的参数**

`setup` 函数接收两个参数：`props` 和 `context`。

1.  **`props`**:
    这是一个响应式对象，包含了父组件传递过来的所有 props。
    > **大师兄警告 (面试必考点):**
    > **永远不要解构 `props` 对象！**
    > ```javascript
    > // 错误的做法 ❌
    > setup(props) {
    > const { stock } = props; // stock 将会失去响应性！
    > // ...
    > }
    > ```
    > 因为解构会使 `stock` 变成一个普通的 JavaScript 变量，切断了它与 `props` 对象的响应式联系。当父组件的数据变化时，这个 `stock` 变量不会更新。我们稍后会学习如何安全地处理它。

2.  **`context`**:
    一个普通的 JavaScript 对象，它暴露了三个组件的 property：
    *   `context.attrs`: attribute，父组件传递的、但没有在 `props` 中声明的属性。
    *   `context.slots`: 插槽，一个包含了所有插槽内容的对象。
    *   `context.emit`: 等同于我们之前用的 `defineEmits` 返回的 `emit` 函数。

#### **5.3 响应式 API 进阶**

除了我们熟悉的 `ref` 和 `reactive`，Vue 还提供了一些更精细的工具来应对复杂的场景。

**1. `readonly`: 创建数据的“只读副本”**

有时候，你需要将响应式数据传递给一个子组件，但又不希望它被意外修改。`readonly` 可以接收一个响应式对象（由 `reactive` 或 `ref` 创建），并返回一个只读的代理。

```javascript
import { reactive, readonly } from 'vue';

const originalState = reactive({ count: 10 });
const readOnlyState = readonly(originalState);

originalState.count++; // ✅ 允许，originalState.count 变为 11
console.log(readOnlyState.count); // 输出 11，它会跟随原始数据的变化

readOnlyState.count++; // ❌ 不允许！控制台会给出一个警告
```
**使用场景：** 在提供（Provide/Inject）全局状态时，为了防止消费方（Inject）随意修改状态，可以提供一个 `readonly` 版本的数据。

**2. `shallowRef` 与 `shallowReactive`: 性能优化的利器**

`ref` 和 `reactive` 默认都是“深层”响应式的。这意味着 Vue 会递归地遍历对象的所有属性，把它们都转换成响应式代理。对于大型、深层嵌套的数据结构，这可能会带来不必要的性能开销。

`shallow` 版本的 API 只会使数据的第一层变为响应式。

*   **`shallowRef`**: 只追踪 `.value` 属性的**重新分配**，而不会关心 `.value` 内部属性的变化。

    ```javascript
    const state = shallowRef({ count: 1 });

    // 这样修改是无效的，不会触发视图更新 ❌
    state.value.count++; 

    // 必须替换整个 .value 对象才会触发更新 ✅
    state.value = { count: 2 };
    ```

*   **`shallowReactive`**: 只追踪对象**第一层**属性的变化。

    ```javascript
    const state = shallowReactive({
      foo: 1,
      nested: { bar: 2 }
    });

    state.foo++; // ✅ 会触发更新

    state.nested.bar++; // ❌ 不会触发更新
    ```
**使用场景：** 当你有一个非常大的、层级很深的数据对象，而你只需要关心它的顶层属性变化时，使用 `shallow` 版本可以显著提升性能。

**3. `toRefs` 和 `toRef`: 安全地解构响应式对象**

还记得我们之前说的“不能解构 `props`”吗？`toRefs` 就是解决这个问题的完美方案。

*   **`toRefs`**: 接收一个响应式对象，返回一个普通对象。这个普通对象的**每个属性**都是一个指向原始对象对应属性的 `ref`。

**案例实践：**

```javascript
import { reactive, toRefs } from 'vue';

const course = reactive({
  name: 'Vue 3 大师课',
  price: 89.9
});

// 错误解构 ❌
const { name, price } = course; // name 和 price 只是普通字符串和数字，非响应式

// 正确解构 ✅
const { name: nameRef, price: priceRef } = toRefs(course);

console.log(nameRef.value); // 'Vue 3 大师课'
console.log(priceRef.value); // 89.9

// 修改原始对象
course.price = 99.9;

// toRefs 创建的 ref 会自动更新！
console.log(priceRef.value); // 输出 99.9
```
`toRefs` 非常适合在 `setup` 函数中解构 `props`，或者当你需要将一个响应式对象的多个属性分别传递给其他函数时使用。

*   **`toRef`**: 只为响应式对象的一个属性创建 `ref`。

#### **5.4 `<script setup>`：现代 Vue 的最佳实践**

现在，我们终于可以揭开 `<script setup>` 的神秘面纱了。它并不是一项新技术，而是 `setup()` 函数的一个**语法糖**，一个能让我们的代码变得极其简洁的编译器宏。

**对比一下，你就明白了：**

| 使用 `setup()` 函数                                          | 使用 `<script setup>` (我们一直在用的)                       |
| :----------------------------------------------------------- | :----------------------------------------------------------- |
| ```vue<br><script><br>import { ref } from 'vue';<br>import MyButton from './MyButton.vue';<br><br>export default {<br>  components: { MyButton },<br>  setup() {<br>    const count = ref(0);<br>    function increment() {<br>      count.value++;<br>    }<br>    return {<br>      count,<br>      increment<br>    };<br>  }<br>}<br></script><br>``` | ```vue<br><script setup><br>import { ref } from 'vue';<br>import MyButton from './MyButton.vue';<br><br>const count = ref(0);<br>function increment() {<br>  count.value++;<br>}<br>// 无需任何 return<br></script><br>``` |

**`<script setup>` 为我们做了什么？**

1.  **自动暴露**: 在 `<script setup>` 中声明的所有**顶层**变量、函数和导入，都会被自动暴露给模板。你不再需要写一个冗长的 `return` 对象。
2.  **自动注册组件**: 导入的组件（如 `MyButton`）可以直接在模板中使用，无需在 `components` 选项中注册。
3.  **更简洁的宏**: 像 `defineProps` 和 `defineEmits` 这样的编译器宏只能在 `<script setup>` 中使用，它们让 props 和 emits 的声明更加直观。
4.  **更好的性能**: `<script setup>` 在编译时能生成更高效的代码，因为它能更好地分析变量和函数的用法。

**结论：** `<script setup>` 是目前编写 Vue 3 组件的**官方推荐和最佳方式**。它极大地提升了开发体验，减少了模板代码，并带来了更好的性能。
