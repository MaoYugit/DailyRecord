## 十、http-创建你的第一个服务器

### **点亮网络世界 — 你的第一个HTTP服务器**

#### **1. 准备工作 — 引入“HTTP协议”管理员**

与`fs`和`path`一样，`http`模块也是Node.js的“内阁成员”，无需安装，直接“召唤”即可。

在你的项目文件夹中，创建一个新文件 `server.js`，并写入第一行代码：

```javascript
// server.js
const http = require('http');
```

这行代码告诉Node.js：“我接下来的工作需要处理HTTP网络协议，请把相关的工具和管理员(`http`对象)都准备好。”

---

#### **2. 创建服务器 — `http.createServer()`**

现在，我们要创建服务器的核心。服务器本质上就是一个**持续运行、时刻等待请求**的程序。

```javascript
// server.js (续)
const server = http.createServer((req, res) => {
  // 这部分代码是“请求处理中心”
  // 每次有用户访问我们的服务器，这里的代码就会被执行一次
  
  console.log('收到一个来自客户端的请求！');

  // 我们将在这里构建并发送响应
});
```

让我们来深度解析这行代码：

*   `http.createServer()`: 这是创建服务器对象的命令。
*   `(...)`: 它接收一个函数作为参数。这个函数就是我们服务器的“大脑”，我们称之为**请求监听器 (Request Listener)** 或**请求处理器 (Request Handler)**。
*   ` (req, res) => { ... } `: 这个箭头函数就是我们的请求处理器。
    *   **它什么时候执行？** **不是在创建服务器时执行**，而是在服务器**运行后**，**每当有一个新的HTTP请求进来时**（比如用户刷新浏览器），它就会被触发执行一次。
    *   **`req` (Request 对象)**: 把它想象成一封“客户订单”。里面包含了这次请求的所有信息：客户想要什么页面的 (`req.url`)，他是用什么方式请求的 (`req.method`)，他还附带了什么额外说明 (`req.headers`) 等等。现在我们暂时不用它，但很快它就会变得至关重要。
    *   **`res` (Response 对象)**: 把它想象成一个“空白的快递包裹和发货单”。这是我们用来打包货物（响应内容）、填写发货单（响应头），并发回给客户的工具。

---

#### **3. 监听端口 — `server.listen()`**

我们已经创建了`server`对象，但它现在只是一个存在于内存中的“待命”员工。我们必须告诉它去哪个“服务窗口”（端口）开始工作，并接待访客。

**什么是端口 (Port)？**
如果说你电脑的IP地址（比如`127.0.0.1`，也叫`localhost`，代表“本机”）是你的公寓楼地址，那么**端口号**就是你的**房间号**。一台电脑上可以同时运行很多个网络服务（比如Web服务器、数据库、游戏服务器），操作系统就是通过不同的端口号，来确保数据能被准确地送达到正确的程序。

Web服务器常用的端口有 `80`(HTTP默认), `443`(HTTPS默认), `3000`, `8000`, `8080`等。作为开发者，我们通常使用`3000`以上的端口以避免与系统服务冲突。

```javascript
// server.js (续)
const PORT = 3000; // 将端口号定义为常量，便于管理

server.listen(PORT, () => {
  // 这部分回调函数，只在服务器成功启动时执行一次
  console.log(`服务器已成功启动，正在监听 ${PORT} 端口...`);
  console.log(`请在浏览器中访问: http://localhost:${PORT}`);
});
```

*   `server.listen(PORT, ...)`: 这行代码才是真正让服务器“上线”的命令。它告诉操作系统：“请开始在`3000`号端口监听所有进来的HTTP请求，并把它们都交给我的`server`对象来处理。”
*   `() => { ... }`: 这是一个可选的回调函数。它会在服务器**成功启动并开始监听**后被执行一次。我们通常在这里放一些提示信息，告诉开发者服务器已经准备就绪。

---

#### **4. 作出响应 — `res.end()`**

现在，我们的服务器已经能“听到”请求了，但它还不知道该如何“回答”。如果现在就运行，浏览器会一直转圈等待，直到超时。

我们必须在请求处理器中，使用`res`对象来发送一个响应，并**结束**这次对话。`res.end()` 就是最简单直接的结束方式。

让我们来完成`server.js`的最后一块拼图：

```javascript
// server.js (最终完整版)

// 1. 引入 http 模块
const http = require('http');

// 2. 定义端口号
const PORT = 3000;

// 3. 创建服务器
const server = http.createServer((req, res) => {
  // 每次有请求时，这个函数都会执行
  console.log('收到一个请求！正在准备响应...');

  // 4. 发送响应并结束对话
  res.end('Hello from your first Node.js server!');
});

// 5. 启动服务器并监听端口
server.listen(PORT, () => {
  // 这个回调只在启动时执行一次
  console.log(`服务器已成功启动，正在监听 ${PORT} 端口...`);
  console.log(`请在浏览器中访问: http://localhost:${PORT}`);
});
```

### **HTTP的“读心术” — 解剖Request与Response对象**

#### **1. 解剖 `req` (Request) 对象 — 客户端到底想干嘛？**

`req`对象就像是从客户端（浏览器）发来的一封详细的“信件”。我们作为服务器，需要学会阅读这封信，才能知道如何回应。让我们来看看信里最重要的几项内容。

*   **`req.url` — 他想访问哪个“房间”？**
    这是`req`对象上**最常用**的属性。它记录了浏览器地址栏里，域名和端口号**之后**的所有部分。
    *   如果访问 `http://localhost:3000/`，`req.url` 就是 `/`。
    *   如果访问 `http://localhost:3000/about-us`，`req.url` 就是 `/about-us`。
    *   如果访问 `http://localhost:3000/products?category=books&page=2`，`req.url` 就是 `/products?category=books&page=2`。
        通过检查`req.url`，我们就能知道用户想获取哪个页面的信息，这是实现**路由 (Routing)** 的基础。

*   **`req.method` — 他想用什么“姿势”进来？**
    这个属性告诉我们客户端发起的HTTP请求类型。对于初级阶段，我们最关心的是`'GET'`。
    *   `'GET'`: 通常用于**获取**数据。当你在浏览器地址栏输入网址并回车时，发出的就是GET请求。
    *   `'POST'`: 通常用于**提交**新数据（比如提交一个注册表单）。
    *   其他还有`'PUT'`（更新数据）、`'DELETE'`（删除数据）等。
        检查`req.method`可以让我们对同一个URL，根据请求类型的不同，执行不同的操作。

*   **`req.headers` — 他还带了什么“名片”或“附加说明”？**
    `req.headers`是一个对象，包含了所有HTTP请求头。请求头提供了关于请求的元信息。
    *   `host`: 客户端想要访问的主机名。
    *   `user-agent`: 客户端的“身份标识”，包含了浏览器类型、操作系统等信息。
    *   `accept`: 客户端能理解什么类型的内容。
    *   在后期学习用户认证时，`authorization`头会变得非常重要。

**【实战练习 1】 — 让服务器成为“侦探”**

让我们修改`server.js`，让它把每次收到的请求的关键信息都打印到自己的控制台里。

```javascript
// server.js (侦探版)

const http = require('http');
const PORT = 3000;

const server = http.createServer((req, res) => {
  // --- 开始侦查 ---
  console.log('--- 收到新请求 ---');
  console.log('请求的 URL:', req.url);
  console.log('请求的方法:', req.method);
  // console.log('请求头:', req.headers); // 暂时注释掉，因为内容很多

  // --- 响应部分 ---
  res.end('侦查报告已记录在服务器控制台！');
});

server.listen(PORT, () => {
  console.log(`侦探服务器已就位，正在监听 ${PORT} 端口...`);
  console.log(`请尝试用浏览器访问不同的URL，例如:`);
  console.log(`- http://localhost:${PORT}/`);
  console.log(`- http://localhost:${PORT}/users/profile`);
  console.log(`- http://localhost:${PORT}/search?q=nodejs`);
});
```

1.  **运行 `node server.js`**。
2.  **打开浏览器**，依次访问上面提示的三个URL。
3.  **观察终端**！每访问一次，你都会看到一组新的侦查报告，清晰地显示了不同访问对应的`req.url`和`req.method`。

---

#### **2. 精雕 `res` (Response) 对象 — 如何优雅地回应？**

我们不仅要回应，还要回应得**得体、正确**。`res`对象就是我们用来打造完美响应的“工具箱”。

* **`res.statusCode` — 表明你的“态度”**
  HTTP状态码是服务器对请求处理结果的官方表态。

  *   `200`: "OK"，一切顺利。这是默认值。
  *   `404`: "Not Found"，你要找的东西我这里没有。
  *   `500`: "Internal Server Error"，糟糕，我自己出问题了。
  *   设置它非常简单：`res.statusCode = 404;`

* **`res.setHeader(name, value)` — 告诉浏览器这是什么“货”**
  响应头是给浏览器的“阅读指南”。其中最重要的一个就是`Content-Type`。

  *   **`res.setHeader('Content-Type', 'text/plain');`**: 告诉浏览器：“我发给你的是纯文本，请直接显示，不要试图解析成网页。”
  *   **`res.setHeader('Content-Type', 'text/html');`**: 告诉浏览器：“这是HTML代码，请用你的渲染引擎把它解析成一个漂亮的网页。”
  *   **`res.setHeader('Content-Type', 'application/json');`**: 告诉浏览器：“这是JSON数据，你可能会想用特殊的方式来展示它。”
      如果你不设置`Content-Type`，很多浏览器会猜测内容类型，有时会猜错，导致显示混乱。

* **`res.writeHead(statusCode, headersObject)` — 一步到位的便捷操作**
  `writeHead` (Write Head) 允许你把设置状态码和设置响应头这两个步骤合二为一。

  ```javascript
  // 下面两行代码...
  res.statusCode = 200;
  res.setHeader('Content-Type', 'text/html');
  
  // ...等价于这一行代码：
  res.writeHead(200, { 'Content-Type': 'text/html' });
  ```

  **注意**: `writeHead`一旦调用，响应头就发出去了，你不能再修改它。

* **`res.write()` 与 `res.end()`**

  *   `res.write(data)`: 向客户端发送一块数据，但**不关闭连接**。你可以多次调用它，比如在发送大文件时。
  *   `res.end([data])`: 发送**最后一块**数据，然后**关闭连接**。对于简单的、一次性就能发完的响应，我们直接把所有内容放在`res.end()`里就行了。**每个响应都必须以`end()`结尾**。

**【组合演练】 — 发送一份HTML**

让我们把服务器升级一下，让它能返回一个真正的HTML标题。

```javascript
// server.js (HTML版)
const http = require('http');
const PORT = 3000;

const server = http.createServer((req, res) => {
  // 设置状态码和响应头
  res.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' }); // charset=utf-8 确保中文不乱码

  // 准备HTML内容
  const htmlContent = '<h1>欢迎来到我的第一个HTML页面！</h1><p>这是用Node.js原生http模块发送的。</p>';

  // 发送内容并结束响应
  res.end(htmlContent);
});

server.listen(PORT, () => {
  console.log(`HTML服务器已启动，正在监听 ${PORT} 端口...`);
});
```

*   运行 `node server.js`，然后在浏览器访问 `http://localhost:3000`。
*   这次你看到的不再是纯文本，而是一个经过浏览器渲染的、加粗的一级标题和一段话！这就是`Content-Type`的魔力。

**小结:**

*   我们通过**`req.url`**和**`req.method`**来“读取”客户端的意图。
*   我们通过**`res.statusCode`**和**`res.setHeader('Content-Type', ...)`**来“定制”我们的响应。
*   `writeHead`是设置状态码和响应头的便捷方法。
*   所有响应都必须调用**`res.end()`**来结束。

### **服务器的“交通指挥” — 手动实现基础路由**

#### **1. 路由逻辑 — `if/else` 指挥棒**

在没有框架的情况下，实现路由最直观、最简单的方式，就是使用 `if / else if / else` 条件语句。

我们的“指挥逻辑”非常清晰：

1.  **`if`** 来的请求想去 `/`（首页）？ 好的，让他走“首页处理车道”。
2.  **`else if`** 来的请求想去 `/about`（关于页面）？ 没问题，让他走“关于页处理车道”。
3.  **`else`** 来的请求想去一个我根本不认识的地方？ 拦下他，告诉他“此路不通”（404 Not Found）。

我们将把这个逻辑，完整地写在 `http.createServer` 的回调函数里。

#### **2. 处理“404 Not Found” — 未知目的地的处理方案**

一个健壮的服务器，必须能优雅地处理未知或错误的请求。当用户访问了一个我们没有定义的URL时，我们不能让他看到一个无尽加载的白屏，或者一个浏览器默认的错误页。

我们需要主动地、明确地告诉他：“你找的地方不存在”。这就是HTTP `404 Not Found` 状态码的意义。

**实现步骤：**

1.  在 `if / else if` 链的**最后**，放一个 `else` 块。这个块会捕获所有**未被前面条件匹配**的请求。
2.  在这个 `else` 块里，我们要做两件事：
    *   **设置状态码**: `res.statusCode = 404;` 或者直接用 `res.writeHead(404, ...)`。
    *   **发送错误信息**: `res.end('404 - Page Not Found');`

---

#### **3. 实战练习 — 构建一个多路径服务器**

现在，让我们亲手来编写这个“交通警察”服务器。

创建 `router-server.js` 文件：

```javascript
// router-server.js
const http = require('http');
const PORT = 3000;

const server = http.createServer((req, res) => {
  const url = req.url;
  const method = req.method;

  console.log(`收到请求: ${method} ${url}`);

  // --- 开始我们的路由逻辑 ---

  // 路由1: 首页 (GET /)
  if (url === '/' && method === 'GET') {
    // 设置响应头
    res.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' });
    // 发送HTML响应
    res.end('<h1>Welcome to our Homepage!</h1><p>This is the main page.</p>');
  
  // 路由2: 关于页 (GET /about)
  } else if (url === '/about' && method === 'GET') {
    // 设置响应头
    res.writeHead(200, { 'Content-Type': 'text/plain; charset=utf-8' });
    // 发送纯文本响应
    res.end('This is the about page. We are a cool company!');
  
  // 路由3: 处理所有其他未匹配的URL (404 Not Found)
  } else {
    // 设置404状态码和响应头
    res.writeHead(404, { 'Content-Type': 'text/html; charset=utf-8' });
    // 发送HTML错误信息
    res.end('<h1>404 - Page Not Found</h1><p>Sorry, the page you are looking for does not exist.</p>');
  }
});

server.listen(PORT, () => {
  console.log(`路由服务器已启动，正在监听 ${PORT} 端口...`);
  console.log('请尝试访问:');
  console.log(`- http://localhost:${PORT}/`);
  console.log(`- http://localhost:${PORT}/about`);
  console.log(`- http://localhost:${PORT}/contact`); // 这是一个不存在的路径
});
```

**代码解析与重要提示：**

*   **检查 `method`**: 注意到我们在条件判断里也加入了 `&& method === 'GET'` 吗？这是一个很好的习惯。它确保了只有GET请求才会匹配到这些路由，防止了未来可能的混淆（比如一个 `POST /about` 请求）。
*   **为每个响应设置`Content-Type`**: 这是一个关键点！首页我们希望浏览器渲染HTML，所以用了`text/html`。关于页我们想显示纯文本，所以用了`text/plain`。404页面我们也用了`text/html`来让错误信息更友好。

**动手演练：**

1.  **启动服务器**: `node router-server.js`
2.  **测试首页**: 在浏览器中打开 `http://localhost:3000/`。你应该会看到一个加粗的大标题 "Welcome to our Homepage!"。
3.  **测试关于页**: 访问 `http://localhost:3000/about`。你应该会看到一行纯文本 "This is the about page..."。
4.  **测试404**: 访问一个我们没有定义的路径，比如 `http://localhost:3000/contact` 或者 `http://localhost:3000/some/random/path`。你应该会看到我们定制的 "404 - Page Not Found" 页面。
5.  **观察终端**: 每一次访问，你都会在终端里看到对应的日志，清晰地记录了你请求的URL和方法。

**小结:**

*   **路由**是Web服务器根据**URL**将请求分发到不同处理逻辑的过程。
*   使用`if/else if/else`结构是原生Node.js中实现基础路由的直接方式。
*   **404处理**是一个健壮服务器的必备功能，它用于响应所有未定义的路径。

### **数据的“通用语” — 服务JSON API**

#### **1. 为什么是JSON？**

JSON之所以能成为标准，因为它有两个巨大的优点：

1.  **机器友好**: 它的格式极其规整，任何编程语言都有现成的库可以轻松地解析它。
2.  **人类可读**: 它的语法基本上就是JavaScript对象的子集，我们开发者可以一目了然地看出数据结构。

#### **2. 服务JSON的两大“戒律”**

要让你的服务器正确地提供JSON数据，你必须遵守两条简单的“戒律”。忘记任何一条，都可能导致客户端无法正确解析你的数据。

**戒律一：设置正确的 `Content-Type` 头**

这是你在“发货”前，必须贴在“包裹”上的**标签**。

```javascript
res.setHeader('Content-Type', 'application/json');
```

或者

```javascript
res.writeHead(200, { 'Content-Type': 'application/json' });
```

这个头信息明确地告诉客户端：“嘿，我发给你的不是HTML，也不是普通文本，而是一段**JSON格式的字符串**。请用你的JSON解析器来处理它！”

如果少了这一步，客户端（比如一个前端`fetch`请求）可能会把它当成普通文本，导致后续的 `response.json()` 方法失败。

**戒律二：发送字符串，而非对象 — `JSON.stringify()`**

这是初学者最容易犯的错误。在你的Node.js代码里，数据通常是以JavaScript对象或数组的形式存在的。

```javascript
// 这是内存中的一个JavaScript对象
const user = { name: "Alice", id: 1 };
```

但是，HTTP协议的响应体（Response Body）部分，只能传输**文本（字符串）**或**二进制数据**。你**不能**直接把一个JavaScript对象塞进去。

你需要一个“翻译官”，把内存中的JS对象，翻译成符合JSON语法规范的字符串。这个“翻译官”就是 `JSON.stringify()`。

```javascript
const user = { name: "Alice", id: 1 };

// 使用JSON.stringify()进行“序列化”
const userJsonString = JSON.stringify(user);

// userJsonString 的值现在是: '{"name":"Alice","id":1}'
// 这个字符串，才是可以通过HTTP发送的内容。
```

#### **3. 实战练习 — 构建你的第一个API端点 (Endpoint)**

现在，我们将这两条“戒律”付诸实践。我们要对上一课的 `router-server.js` 进行升级，为它增加一个能够提供用户数据的API端点。

**修改 `router-server.js`:**

```javascript
// router-server.js (API升级版)
const http = require('http');
const PORT = 3000;

const server = http.createServer((req, res) => {
  const url = req.url;
  const method = req.method;

  console.log(`收到请求: ${method} ${url}`);

  // 路由1: 首页 (GET /)
  if (url === '/' && method === 'GET') {
    res.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' });
    res.end('<h1>Welcome to our API Homepage!</h1><p>Try visiting /api/user</p>');
  
  // 路由2: 关于页 (GET /about)
  } else if (url === '/about' && method === 'GET') {
    res.writeHead(200, { 'Content-Type': 'text/plain; charset=utf-8' });
    res.end('This is the about page.');

  // 【新增】路由3: 用户数据API (GET /api/user)
  } else if (url === '/api/user' && method === 'GET') {
    // 戒律一：设置正确的Content-Type
    res.writeHead(200, { 'Content-Type': 'application/json' });
    
    // 准备要发送的JavaScript对象
    const userData = {
      name: "Alice",
      job: "Backend Developer",
      id: 1,
      skills: ["Node.js", "Databases", "API Design"]
    };
    
    // 戒律二：将JS对象转换为JSON字符串再发送
    res.end(JSON.stringify(userData));
  
  // 路由4: 处理所有其他未匹配的URL (404 Not Found)
  } else {
    res.writeHead(404, { 'Content-Type': 'text/html; charset=utf-8' });
    res.end('<h1>404 - Not Found</h1>');
  }
});

server.listen(PORT, () => {
  console.log(`API服务器已启动，正在监听 ${PORT} 端口...`);
  console.log(`请在浏览器中访问: http://localhost:${PORT}/api/user`);
});
```

**动手演练：**

1.  **启动服务器**: `node router-server.js`
2.  **访问API端点**: 在你的浏览器中，打开 `http://localhost:3000/api/user`。
3.  **观察结果**:
    *   你看到的不再是渲染后的HTML，而是一段结构化的文本。
    *   很多现代浏览器（如Chrome, Firefox）有内置的JSON查看器，它们会自动检测到`Content-Type: application/json`，并将JSON数据格式化成一个可折叠、易于阅读的树状结构。这再次证明了设置正确`Content-Type`的重要性。
    *   如果你用的是一些比较老的浏览器或者禁用了JSON查看器，你可能会看到原始的字符串：`{"name":"Alice","job":"Backend Developer","id":1,"skills":["Node.js","Databases","API Design"]}`。

**小结:**

*   **API (Application Programming Interface)** 的核心是提供**结构化数据**给**程序**使用。
*   **JSON** 是现代Web API的事实标准数据格式。
*   提供JSON服务的两大要素：
    1.  **`Content-Type` 必须是 `application/json`**。
    2.  发送前，必须用 **`JSON.stringify()`** 将JavaScript对象/数组**序列化为字符串**。

### **毕业项目 — 构建一个模拟博客API**

#### **1. 项目规划 — 我们的“需求文档”**

在动手之前，我们先清晰地梳理一下要做什么：

*   **数据源**: 我们没有数据库，所以用一个简单的JavaScript数组 `posts` 存在内存里，作为我们的“模拟数据库”。
*   **API端点**: 我们需要设计和实现4种不同的“交通规则”（路由）：
    1.  **根路径 `/`**: 作为一个友好的入口，告诉用户这里是什么地方。
    2.  **文章列表 `/posts`**: 获取所有文章数据。
    3.  **单篇文章 `/posts/:id`**: 获取一篇特定ID的文章。这里的 `:id` 是一个**动态参数**，可以是 `/posts/1`, `/posts/2` 等。这是本次的挑战点。
    4.  **404处理**: 捕获所有不属于上面三种情况的访问，并给出统一的错误提示。

#### **2. 挑战环节：如何处理动态URL `/posts/:id`？**

`req.url` 会给我们一个完整的字符串，比如 `/posts/1` 或 `/posts/abc`。我们如何从中提取出那个ID（`1` 或 `abc`）呢？

这里我们需要用到一些基础的**字符串处理**技巧。一个简单可靠的方法是：

1.  **检查URL是否以 `/posts/` 开头**: `url.startsWith('/posts/')`
2.  **分割URL字符串**: `url.split('/')` 会把 `/posts/1` 变成一个数组 `['', 'posts', '1']`。
3.  **提取ID**: 我们需要的ID就在数组的第三个位置（索引为2）。
4.  **转换ID类型**: 从URL中提取出的ID是**字符串** `"1"`，而我们数据里的`id`是**数字** `1`。在比较之前，需要用 `parseInt()` 将其转换为数字。

#### **3. 最终代码实现 (`blog-api-server.js`)**

现在，让我们把所有逻辑组装起来。

```javascript
// blog-api-server.js
const http = require('http');
const PORT = 3000;

// 1. 我们的“模拟数据库”
const posts = [
  { id: 1, title: 'My First Blog Post', content: 'This is the content of my very first post!' },
  { id: 2, title: 'Learning Node.js HTTP Module', content: 'It is fundamental for building web applications.' },
  { id: 3, title: 'Understanding Streams', content: 'Streams are powerful for handling large data.' }
];

// 辅助函数：创建一个标准的JSON响应
function jsonResponse(res, statusCode, data) {
  res.writeHead(statusCode, { 'Content-Type': 'application/json' });
  res.end(JSON.stringify(data));
}

const server = http.createServer((req, res) => {
  const url = req.url;
  const method = req.method;

  console.log(`Request received: ${method} ${url}`);

  // --- 路由逻辑 ---

  // Endpoint 1: GET / - 欢迎页
  if (url === '/' && method === 'GET') {
    res.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' });
    res.end('<h1>Welcome to our Blog API</h1><p>Available endpoints: /posts, /posts/:id</p>');

  // Endpoint 2: GET /posts - 获取所有文章
  } else if (url === '/posts' && method === 'GET') {
    jsonResponse(res, 200, posts);

  // Endpoint 3 (挑战): GET /posts/:id - 获取单篇文章
  } else if (url.startsWith('/posts/') && method === 'GET') {
    // 解析ID
    const urlParts = url.split('/'); // e.g., '/posts/1' -> ['', 'posts', '1']
    const postIdStr = urlParts[2];
    const postId = parseInt(postIdStr, 10); // 10表示十进制

    // 在“数据库”中查找文章
    const post = posts.find(p => p.id === postId);

    if (post) {
      // 如果找到了文章
      jsonResponse(res, 200, post);
    } else {
      // 如果没找到
      jsonResponse(res, 404, { error: `Post with ID ${postIdStr} not found` });
    }
  
  // Endpoint 4: 404 - 处理所有其他URL
  } else {
    jsonResponse(res, 404, { error: 'Endpoint not found' });
  }
});

server.listen(PORT, () => {
  console.log(`Blog API server is running on port ${PORT}`);
  console.log(`Try accessing:`);
  console.log(`- http://localhost:${PORT}/posts`);
  console.log(`- http://localhost:${PORT}/posts/2`);
  console.log(`- http://localhost:${PORT}/posts/99`); // 一个不存在的ID
});
```

**代码亮点解析：**

*   **`jsonResponse` 辅助函数**: 我们发现发送JSON响应的逻辑（设置头、字符串化、发送）是重复的，所以我们把它封装成一个可复用的函数。这是代码重构的好习惯！
*   **`url.startsWith('/posts/')`**: 这是一个比直接用`===`更灵活的检查，它能匹配所有以`/posts/`开头的路径。
*   **`Array.prototype.find()`**: 这是在数组中查找特定元素的现代、简洁的方法。
*   **`parseInt(string, radix)`**: 将字符串转换为整数。第二个参数`10`表示使用十进制，这是一个安全的好习惯。

### **进阶挑战 — 实现`POST /posts`创建新文章**

我们已经学会了如何“读”数据，现在来学习如何“写”数据。当用户想发布一篇新文章时，前端会发送一个`POST`请求到`/posts`端点，并在请求体（Request Body）中附带上新文章的JSON数据。

#### **1. `POST`请求的特殊性**

与`GET`请求不同，`POST`请求的数据不是放在URL里的，而是放在一个叫做**请求体 (Request Body)** 的地方。因为数据可能很大，所以Node.js不会一次性把它全部读到内存里，而是像我们之前学的`createReadStream`一样，把请求体也当作一个**可读流 (Readable Stream)** 来处理。

这意味着我们需要在`req`对象上监听`'data'`和`'end'`事件来接收数据。

#### **2. 实现步骤**

我们需要在`blog-api-server.js`的路由逻辑中，增加一个新的`else if`块。

```javascript
// ... 省略之前的代码 ...

const server = http.createServer((req, res) => {
  const url = req.url;
  const method = req.method;

  // ... 省略 GET / 和 GET /posts 的代码 ...

  // 【新增】Endpoint: POST /posts - 创建一篇新文章
  } else if (url === '/posts' && method === 'POST') {
    let body = ''; // 用于累积接收到的数据块

    // 1. 监听 req 对象的 'data' 事件
    req.on('data', (chunk) => {
      // chunk 默认是 Buffer 对象，我们将其转换为字符串并拼接
      body += chunk.toString(); 
    });

    // 2. 监听 req 对象的 'end' 事件
    req.on('end', () => {
      try {
        // 当所有数据接收完毕后，body就是完整的JSON字符串
        const newPostData = JSON.parse(body); // 使用 JSON.parse 将字符串变回JS对象
        
        // 简单验证一下
        if (!newPostData.title || !newPostData.content) {
          return jsonResponse(res, 400, { error: 'Title and content are required.' });
        }

        // 创建新文章
        const newPost = {
          id: posts.length + 1, // 简单地用长度+1作为新ID
          title: newPostData.title,
          content: newPostData.content
        };
        
        // 将新文章存入我们的“数据库”
        posts.push(newPost);
        
        // 3. 返回成功响应
        // HTTP状态码 201 表示 "Created" (已创建)
        jsonResponse(res, 201, newPost);

      } catch (error) {
        // 如果JSON.parse失败，说明客户端发来的数据格式有问题
        jsonResponse(res, 400, { error: 'Invalid JSON format' });
      }
    });

  // ... 省略 GET /posts/:id 和 404 的代码 ...
  
  } else {
    jsonResponse(res, 404, { error: 'Endpoint not found' });
  }
});

// ... 省略 server.listen 的代码 ...
```

#### **3. 如何测试`POST`请求？**

浏览器地址栏只能发送`GET`请求。要测试`POST`，你需要使用专门的API测试工具，比如 **Postman**, **Insomnia**，或者在终端里使用`curl`命令。

**使用`curl`的例子:**

打开一个新的终端窗口（不要关闭正在运行服务器的那个），输入以下命令：

```bash
curl -X POST http://localhost:3000/posts \
-H "Content-Type: application/json" \
-d '{"title":"My New Post via POST","content":"This is awesome!"}'
```

*   `-X POST`: 指定请求方法为POST。
*   `-H "Content-Type: application/json"`: 设置请求头，告诉服务器我发送的是JSON。
*   `-d '{...}'`: `-d`后面跟着的就是请求体（Request Body）的内容。

执行后，你应该会看到服务器返回了类似下面的成功信息，并且状态码是201：

```json
{"id":4,"title":"My New Post via POST","content":"This is awesome!"}
```

现在，如果你再去浏览器访问 `http://localhost:3000/posts`，你就能看到这篇新文章已经被加进去了！
