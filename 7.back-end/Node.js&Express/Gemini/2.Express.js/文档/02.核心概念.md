## **二、 核心概念 (Core Concepts)**

### **路由 (Routing)**

路由（Routing）指的是应用程序如何响应客户端向特定端点（URI）发出的请求，这个请求包含一个特定的 HTTP 请求方法（GET, POST 等）。

你可以把路由想象成一个交通指挥系统。当一个请求（一辆车）到达时，路由系统会根据它的目的地（URL 路径）和它的意图（HTTP 方法），将它引导到正确的处理程序（一个函数）去处理。

---

#### **1. 基本路由 (Basic Routing)**

每个路由定义都具有以下结构：

```javascript
app.METHOD(PATH, HANDLER);
```

*   `app`：是 `express` 的一个实例。
*   `METHOD`：是一个小写的 HTTP 请求方法，如 `get`, `post`, `put` 等。
*   `PATH`：是服务器上的一个路径（URI）。
*   `HANDLER`：是当路由匹配时执行的回调函数，它接收 `req` 和 `res` 对象作为参数。

在我们的 "Hello World" 例子中，`app.get('/', ...)` 就是一个最基本的路由定义。

---

#### **2. 路由方法 (Routing Methods)**

Express 为所有主要的 HTTP 请求方法都提供了相应的路由方法。这些方法通常与 **CRUD**（创建、读取、更新、删除）操作相对应。

*   `app.get()`：用于**读取**或**获取**数据。例如，获取用户列表或文章详情。
*   `app.post()`：用于**创建**新数据。例如，提交一个新用户的注册表单。
*   `app.put()`：用于**更新**或**替换**现有数据。例如，更新一个用户的完整个人资料。
*   `app.delete()`：用于**删除**数据。例如，删除一篇指定的文章。

**代码示例** (`app.js`)：

```javascript
const express = require('express');
const app = express();
const port = 3000;

// GET 方法：获取用户列表
app.get('/users', (req, res) => {
  res.send('GET request to the /users endpoint');
});

// POST 方法：创建一个新用户
app.post('/users', (req, res) => {
  res.send('POST request to the /users endpoint');
});

// PUT 方法：更新指定 ID 的用户
app.put('/users/:id', (req, res) => {
  res.send(`PUT request to update user with id: ${req.params.id}`);
});

// DELETE 方法：删除指定 ID 的用户
app.delete('/users/:id', (req, res) => {
  res.send(`DELETE request to delete user with id: ${req.params.id}`);
});

app.listen(port, () => {
  console.log(`服务器正在监听 http://localhost:${port}`);
});
```

> **提示**：你无法直接在浏览器地址栏中测试 `POST`, `PUT`, `DELETE` 请求。你需要使用 Postman、Insomnia 或 VS Code 的 REST Client 等 API 测试工具来发送这些类型的请求。

#### **3. 路由路径 (Route Paths)**

路由路径结合请求方法，定义了可以向哪些端点发出请求。Express 提供了非常灵活的路径定义方式。

* **字符串**：最简单的方式，精确匹配。

  ```js
  app.get('/about', (req, res) => { /* ... */ }); // 只匹配 /about
  ```

* **字符串模式 (通配符)**：

  *   `?`：匹配前面的字符 0 次或 1 次。
      
      ```javascript
      // 匹配 /acd 和 /abcd
      app.get('/ab?cd', (req, res) => { /* ... */ });
      ```
  *   `+`：匹配前面的字符 1 次或多次。
      ```javascript
      // 匹配 /abcd, /abbcd, /abbbcd 等
      app.get('/ab+cd', (req, res) => { /* ... */ });
      ```
  *   `*`：匹配任意字符序列。
      ```javascript
      // 匹配 /abcd, /abRANDOMcd, /ab123cd 等
      app.get('/ab*cd', (req, res) => { /* ... */ });
      ```
  *   `()`：将一组字符视为一个整体。
      
      ```javascript
      // 匹配 /fly 和 /butterfly
      app.get('/butter(fly)?', (req, res) => { /* ... */ });
      ```

* **正则表达式**：为了实现最复杂的匹配逻辑，你可以直接使用正则表达式。
  ```javascript
  // 匹配所有路径中包含 'book' 的路由
  app.get(/.*book.*/, (req, res) => { /* ... */ });
  ```

---

#### **4. 路由参数 (Route Parameters)**

路由参数用于捕获 URL 中动态变化的部分。这对于构建如 `users/123` 这样的 URL 非常有用，其中 `123` 是一个动态的用户 ID。

*   在路径中使用冒号 `:` 来定义路由参数。
*   Express 会将捕获到的参数值填充到 `req.params` 对象中。

**代码示例** (`app.js`)：

````javascript
const express = require('express');
const app = express();
// ...

// 定义一个包含 userId 参数的路由
app.get('/users/:userId', (req, res) => {
  // 通过 req.params.userId 访问这个动态值
  res.send(`正在获取 ID 为 ${req.params.userId} 的用户信息。`);
});

// 定义一个包含多个参数的路由
app.get('/users/:userId/books/:bookId', (req, res) => {
  const userId = req.params.userId;
  const bookId = req.params.bookId;
  res.send(`正在获取用户 ${userId} 的图书 ${bookId} 的信息。`);
});

// ...
app.listen(3000);
```
````
现在，如果你在浏览器中访问 `http://localhost:3000/users/123`，页面会显示 "正在获取 ID 为 123 的用户信息。"。
如果你访问 `http://localhost:3000/users/abc/books/xyz`，页面会显示 "正在获取用户 abc 的图书 xyz 的信息。"。

---

#### **5. 模块化路由 (Modular Routing)**

当应用变得复杂时，将所有路由都写在 `app.js` 文件里会变得难以维护。Express 提供了 `express.Router` 类来帮助我们创建模块化的、可挂载的路由处理器。

**思路**：将功能相关的路由（例如所有与用户相关的路由）分组到单独的文件中。

**步骤**：

1.  **创建路由文件**：在你的项目下创建一个 `routes` 文件夹，并在其中创建一个 `users.js` 文件。
2.  **在 `users.js` 中定义路由**：
    ```javascript
    // routes/users.js
    
    const express = require('express');
    // 1. 创建一个新的路由实例
    const router = express.Router();
    
    // 2. 在 router 实例上定义路由
    // 注意：这里的 '/' 实际上是相对于它被挂载的路径
    router.get('/', (req, res) => {
      res.send('获取所有用户列表');
    });
    
    router.get('/:id', (req, res) => {
      res.send(`获取 ID 为 ${req.params.id} 的用户`);
    });
    
    // 3. 导出这个 router
    module.exports = router;

3. **在主文件 `app.js` 中使用路由模块**：

   ```javascript
   // app.js
   
   const express = require('express');
   const app = express();
   const port = 3000;
   
   // 1. 导入用户路由模块
   const usersRouter = require('./routes/users');
   
   // 2. 使用 app.use() 来挂载路由模块
   // 这行代码告诉 Express：所有以 /users 开头的请求，都应该由 usersRouter 来处理
   app.use('/users', usersRouter);
   
   app.get('/', (req, res) => {
     res.send('这是首页');
   });
   
   app.listen(port, () => {
     console.log(`服务器正在监听 http://localhost:${port}`);
   });
   ```
   现在，你的路由逻辑被清晰地分开了：

*   访问 `http://localhost:3000/` 会由 `app.js` 处理。
*   访问 `http://localhost:3000/users` 会被 `app.use('/users', ...)` 捕获，然后请求被转发到 `usersRouter`，并匹配其中的 `/` 路由。
*   访问 `http://localhost:3000/users/123` 会匹配 `usersRouter` 中的 `/:id` 路由。

#### **6. RESTful API 设计原则**

虽然 Express 不强制任何设计模式，但遵循 REST (Representational State Transfer) 架构风格来设计 API 是一种被广泛接受的最佳实践。

**核心原则**：

1.  **资源 (Resources)**：API 的核心是“资源”，用 URL 来标识。资源应该是**名词**，而不是动词。
    *   推荐：`/users`, `/products`
    *   不推荐：`/getAllUsers`, `/createNewProduct`

2.  **HTTP 方法 (Verbs)**：使用 HTTP 方法来描述对资源的操作。
    | HTTP 方法 | 操作               | 示例                | 描述                              |
    | :-------- | :----------------- | :------------------ | :-------------------------------- |
    | `GET`     | 读取 (Read)        | `GET /users`        | 获取所有用户列表                  |
    |           |                    | `GET /users/123`    | 获取 ID 为 123 的用户             |
    | `POST`    | 创建 (Create)      | `POST /users`       | 创建一个新用户 (数据在请求体中)   |
    | `PUT`     | 更新/替换 (Update) | `PUT /users/123`    | 完整替换 ID 为 123 的用户信息     |
    | `PATCH`   | 部分更新 (Update)  | `PATCH /users/123`  | 只更新 ID 为 123 的用户的部分信息 |
    | `DELETE`  | 删除 (Delete)      | `DELETE /users/123` | 删除 ID 为 123 的用户             |

3.  **使用复数名词**：通常使用复数形式来表示资源集合，例如 `/users` 代表所有用户的集合。

4.  **使用 HTTP 状态码**：用标准化的 HTTP 状态码来表示响应结果。
    *   `200 OK`：请求成功 (GET, PUT)。
    *   `201 Created`：资源创建成功 (POST)。
    *   `204 No Content`：请求成功但无返回内容 (DELETE)。
    *   `400 Bad Request`：客户端请求有误 (例如，无效的 JSON)。
    *   `401 Unauthorized`：未认证。
    *   `404 Not Found`：请求的资源不存在。
    *   `500 Internal Server Error`：服务器内部错误。

遵循这些原则可以让你设计出清晰、直观、易于理解和使用的 API。

### **中间件 (Middleware)**

#### **1. 核心理念：请求处理“管道”**

你可以把 Express 的中间件想象成一个**处理请求的流水线**或**管道**。

当一个 HTTP 请求到达你的应用时，它不会直接被最终的路由处理器（例如 `(req, res) => { res.send(...) }`）处理。相反，它会进入一个由多个中间件函数组成的管道。

每个中间件函数都是一个“工人”，它有机会：
1.  **检查和修改请求**：查看请求头 (`req.headers`)、添加新属性到 `req` 对象上（例如 `req.user = ...`）。
2.  **检查和修改响应**：设置响应头 (`res.setHeader(...)`)。
3.  **决定是否将请求传递下去**：
    *   调用 `next()` 函数，将请求传递给管道中的**下一个中间件**。
    *   **结束请求-响应周期**，直接向客户端发送响应（例如调用 `res.send()` 或 `res.status(401).send(...)`）。

**关键点**：**中间件的顺序至关重要**。请求会按照你定义中间件的顺序依次通过它们。

一个中间件函数的基本结构如下：
```javascript
function(req, res, next) {
  // ... 执行代码 ...
  next(); // 将控制权交给下一个中间件
}
```
*   `req`：HTTP 请求对象。
*   `res`：HTTP 响应对象。
*   `next`：一个回调函数，用于调用下一个中间件。**如果你不调用它，请求将被“挂起”，客户端将永远等不到响应。**

---

#### **2. 编写自定义中间件**

让我们来编写一个最简单的中间件：一个请求日志记录器。

1.  在你的 `app.js` 中，添加以下函数：
    ```javascript
    // 一个简单的日志中间件函数
    const requestLogger = (req, res, next) => {
      console.log(`[${new Date().toISOString()}] 收到一个 ${req.method} 请求，访问路径是 ${req.originalUrl}`);
      // 非常重要：调用 next() 将请求传递给下一个处理程序
      next();
    };
    ```
    这个函数打印了请求的时间、方法和 URL，然后调用 `next()` 继续处理。现在，我们来看看如何使用它。

---

#### **3. 中间件类型**

##### **a. 应用级中间件 (Application-level Middleware)**

这是最常见的中间件。它使用 `app.use()` 或 `app.METHOD()` 绑定到 `app` 对象上。

*   **应用到所有请求**：
    如果你不指定路径，中间件会对应用的**每一个**请求生效。这对于日志、身份验证等全局任务非常有用。

    ```javascript
    const express = require('express');
    const app = express();
    
    // 自定义日志中间件
    const requestLogger = (req, res, next) => {
      console.log(`[${new Date().toISOString()}] 收到一个 ${req.method} 请求，访问路径是 ${req.originalUrl}`);
      next();
    };
    
    // 在所有路由之前使用这个中间件
    app.use(requestLogger);
    
    app.get('/', (req, res) => {
      res.send('这是首页');
    });
    
    app.get('/users', (req, res) => {
      res.send('这是用户列表页');
    });
    
    app.listen(3000);
    ```
    现在，无论你访问 `/` 还是 `/users`，你的终端都会打印出相应的日志。

*   **应用到特定路径的请求**：
    你也可以提供一个路径，这样中间件将只对以该路径开头的请求生效。
    
    ```javascript
    const adminAuth = (req, res, next) => {
      console.log('正在检查管理员权限...');
      // 这是一个伪代码，实际应用中会有复杂的逻辑
      const isAdmin = true; 
      if (isAdmin) {
        next(); // 权限通过，继续
      } else {
        res.status(403).send('禁止访问'); // 权限不通过，直接返回
      }
    };
    
    // 这个中间件只对 /admin 和其子路径（如 /admin/dashboard）生效
    app.use('/admin', adminAuth);
    
    app.get('/admin/dashboard', (req, res) => {
      res.send('欢迎来到管理员面板');
    });
    ```

##### **b. 路由级中间件 (Router-level Middleware)**

它的工作方式与应用级中间件完全相同，但它是绑定到 `express.Router()` 的实例上。这在你进行模块化路由时非常有用，可以为一组特定的路由应用中间件。

```javascript
// routes/users.js
const express = require('express');
const router = express.Router();

// 一个只对用户路由生效的中间件
const userSpecificMiddleware = (req, res, next) => {
  console.log('正在处理一个用户相关的请求...');
  next();
};

// 将中间件应用到这个路由实例的所有路由上
router.use(userSpecificMiddleware);

router.get('/', (req, res) => { /* ... */ });
router.post('/', (req, res) => { /* ... */ });

module.exports = router;
```

##### **c. 内置中间件 (Built-in Middleware)**

Express 提供了一些开箱即用的中间件来处理常见任务。

*   `express.json()`: 解析传入的 `Content-Type: application/json` 请求体，并将解析后的数据填充到 `req.body` 对象。**这是构建 API 的必备中间件**。
    
    ```javascript
    // 必须在你的路由之前定义
    app.use(express.json());
    
    app.post('/api/users', (req, res) => {
      // 如果没有 app.use(express.json())，这里的 req.body 将是 undefined
      const userName = req.body.name;
      res.send(`用户 ${userName} 已创建`);
    });
    ```
*   `express.urlencoded({ extended: true })`: 解析传入的 `Content-Type: application/x-www-form-urlencoded` 请求体（通常来自 HTML 表单提交）。解析后的数据也会被放入 `req.body`。
*   `express.static('folder_name')`: 用于提供静态文件服务（如 HTML, CSS, JavaScript 文件, 图片）。
    
    ```javascript
    // 创建一个名为 'public' 的文件夹，并在其中放入一张图片 'logo.png'
    
    // 这行代码会让 'public' 文件夹下的所有文件都可以通过 URL 直接访问
    app.use(express.static('public'));
    
    // 现在，你可以通过 http://localhost:3000/logo.png 访问这张图片
    ```

##### **d. 第三方中间件 (Third-party Middleware)**

Express 拥有庞大的生态系统，你可以通过 npm 安装由社区开发的中间件来快速添加功能。

*   **示例：`cors`**
    用于处理跨域资源共享（CORS）。如果你的前端应用和后端 API 不在同一个域（或端口），浏览器会出于安全策略阻止前端发起的请求。`cors` 中间件可以轻松解决这个问题。

    1.  安装：`npm install cors`
    2.  使用：
        ```javascript
        const express = require('express');
        const cors = require('cors'); // 1. 引入 cors
        const app = express();
        
        app.use(cors()); // 2. 作为应用级中间件使用
        
        // ... 你的其他路由
        ```
*   其他常用第三方中间件：
    *   `morgan`: 更强大的 HTTP 请求日志记录器。
    *   `cookie-parser`: 解析 Cookie 请求头，并填充 `req.cookies`。
    *   `helmet`: 通过设置各种 HTTP 头来帮助保护你的应用免受一些众所周知的 Web 漏洞的影响。

##### **e. 错误处理中间件 (Error-handling Middleware)**

这是一种特殊的中间件，它有 **4 个参数** `(err, req, res, next)`。多出来的第一个 `err` 参数是它的标志。

*   **必须定义在所有其他 `app.use()` 和路由之后**，否则它将无法捕获它们抛出的错误。
*   用于集中处理应用中发生的各种错误。

```javascript
// ... 你的所有路由和普通中间件

app.get('/error', (req, res, next) => {
  // 创建一个错误对象
  const err = new Error('这是一个测试错误');
  // 将错误传递给 next()，Express 会跳过所有普通中间件，直接寻找错误处理中间件
  next(err);
});

// 错误处理中间件
app.use((err, req, res, next) => {
  console.error(err.stack); // 在服务器终端打印错误堆栈
  // 向客户端发送一个通用的错误响应
  res.status(500).send('服务器发生了一些错误！');
});

// ... app.listen()
```

这个机制非常强大，可以让你将业务逻辑和错误处理逻辑完全分离开，使代码更清晰、更健壮。
