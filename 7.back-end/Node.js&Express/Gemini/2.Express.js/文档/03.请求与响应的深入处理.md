### **三、 请求与响应的深入处理 (In-depth Request & Response Handling)**

可以把一次 Web 交互想象成在餐厅点餐：
*   **你（客户端）**：向服务员（服务器）递交一份详细的订单（HTTP 请求）。
*   **订单 (`req` 对象)**：上面写着你要的菜（URL 路径），具体要求比如“牛排要五分熟”（请求体），餐桌号（IP 地址），以及你的会员卡信息（Cookie/Headers）。
*   **服务员 (`res` 对象)**：拿到订单后，可以决定给你上什么菜，用什么盘子装，甚至告诉你某个菜卖完了（HTTP 响应）。

---

#### **请求对象 (`req`)：解读客户端的意图**

`req` 对象是 Express 对客户端 HTTP 请求的封装，它包含了请求的所有信息。让我们逐一分解如何从中提取数据。

##### **1. `req.params`：路由参数**

*   **是什么**：用于获取在路由路径中定义的**动态**部分。这些是 URL 中“嵌入”的变量。
*   **何时使用**：当你需要识别一个特定的资源时。例如，获取 ID 为 `123` 的用户信息，或者名为 `express-intro` 的文章。
*   **示例**：
    URL: `http://localhost:3000/users/123/posts/express-intro`
    ```javascript
    // 路由定义
    app.get('/users/:userId/posts/:postSlug', (req, res) => {
      // req.params 会是一个对象: { userId: '123', postSlug: 'express-intro' }
      const userId = req.params.userId;
      const postSlug = req.params.postSlug;
    
      res.send(`正在查找用户 ${userId} 的文章，文章标识是 ${postSlug}`);
    });
    ```

##### **2. `req.query`：URL 查询参数**

*   **是什么**：用于获取 URL 中 `?` 之后的部分，通常用于**过滤、排序或分页**。
*   **何时使用**：当你想提供一些**可选的**查询选项时。例如，搜索商品、按价格排序、指定返回结果的页码。
*   **示例**：
    URL: `http://localhost:3000/search?q=laptops&sort=price_asc&page=2`
    ```javascript
    // 路由定义
    app.get('/search', (req, res) => {
      // req.query 会是一个对象: { q: 'laptops', sort: 'price_asc', page: '2' }
      const searchTerm = req.query.q;
      const sortBy = req.query.sort;
      const page = req.query.page;
    
      res.send(`搜索词: ${searchTerm}, 排序方式: ${sortBy}, 页码: ${page}`);
    });
    ```
    > **注意**：`req.query` 中的所有值默认都是字符串。如果需要数字，请使用 `parseInt()` 进行转换。

##### **3. `req.body`：请求体数据**

*   **是什么**：用于获取在请求体（Request Body）中发送的数据。这部分数据**不在 URL 中**。
*   **何时使用**：通常在 `POST`, `PUT`, `PATCH` 请求中使用，用于发送复杂的数据，如 JSON 对象或表单数据。例如，创建一个新用户时提交的注册信息。
*   **重要前提**：Express 默认**不会**解析请求体。你必须使用相应的中间件才能访问 `req.body`。
    *   对于 JSON 数据：`app.use(express.json());`
    *   对于 URL 编码的表单数据：`app.use(express.urlencoded({ extended: true }));`
*   **示例**：
    客户端发送一个 `POST` 请求到 `/api/users`，请求体为 `{"username": "Alice", "email": "alice@example.com"}`。
    ```javascript
    // 在所有路由之前，必须先使用中间件
    app.use(express.json());
    
    // 路由定义
    app.post('/api/users', (req, res) => {
      // req.body 会是解析后的 JavaScript 对象: { username: 'Alice', email: 'alice@example.com' }
      const username = req.body.username;
      const email = req.body.email;
    
      // 在这里执行创建用户的数据库操作...
      res.status(201).json({
        message: '用户创建成功',
        user: { username, email }
      });
    });
    ```
    **如果没有 `app.use(express.json())`，`req.body` 将会是 `undefined`！**

##### **4. `req.headers`：请求头**

*   **是什么**：一个包含了所有 HTTP 请求头的对象。请求头包含了关于请求的元数据，例如客户端类型 (`User-Agent`)、认证令牌 (`Authorization`) 等。
*   **何时使用**：当你需要检查认证信息、内容类型或客户端环境时。
*   **示例**：
    ```javascript
    app.get('/me', (req, res) => {
      // req.headers 是一个包含所有头信息的对象（键为小写）
      // 例如: { 'host': 'localhost:3000', 'user-agent': '...', 'authorization': 'Bearer ...' }
    
      // 推荐使用 req.get() 方法来获取头信息，它不区分大小写
      const userAgent = req.get('User-Agent');
      const authToken = req.get('Authorization');
    
      res.send(`你的浏览器是: ${userAgent}。 你的认证令牌是: ${authToken}`);
    });
    ```

##### **5. `req.cookies` / `req.signedCookies`：读取 Cookie**

*   **是什么**：用于访问客户端发送过来的 Cookie。
*   **重要前提**：和 `req.body` 类似，你需要 `cookie-parser` 这个**第三方中间件**来解析 Cookie。
    1.  安装：`npm install cookie-parser`
    2.  在 `app.js` 中使用：
        ```javascript
        const cookieParser = require('cookie-parser');
        // 使用 cookie-parser 中间件。'your-secret-key' 是用于签名 cookie 的密钥。
        app.use(cookieParser('your-secret-key'));
        ```
*   **示例**：
    ```javascript
    app.get('/read-cookie', (req, res) => {
      // 读取普通 cookie
      const theme = req.cookies.theme; // 例如 'dark'
    
      // 读取签名的 cookie
      // 如果 cookie 被篡改，signedSessionId 会是 undefined
      const signedSessionId = req.signedCookies.sessionId;
    
      res.send(`主题是: ${theme}, 会话 ID 是: ${signedSessionId}`);
    });
    ```
    *   **`req.cookies`**: 包含所有未签名的 Cookie。
    *   **`req.signedCookies`**: 包含所有已签名的 Cookie。签名是一种安全措施，用于确保 Cookie 的值没有在客户端被篡改。

#### **响应对象 (`res`)：向客户端发送数据**

`res` 对象封装了所有与 HTTP 响应相关的功能。一旦你调用了`res.send()`、`res.json()`或`res.sendFile()`等结束请求的方法，你就不能再发送任何东西了，否则会报错。

##### **1. `res.send()`：发送通用响应**

*   **是什么**：一个功能全面的方法，可以发送多种类型的响应。它是最基础也是最常用的响应方法之一。
*   **可以发送什么**：
    *   **字符串**: `res.send('Hello World');`
    *   **HTML**: `res.send('<h1>This is a title</h1>');`
    *   **JSON 对象或数组**: `res.send({ user: 'Alice' });`
    *   **Buffer**: (用于二进制数据)
*   **智能的 `Content-Type`**：`res.send()` 会自动分析你发送的内容，并设置合适的 `Content-Type`响应头。例如，发送一个包含 HTML 标签的字符串，它会设置 `Content-Type: text/html`。发送一个对象或数组，它会设置 `Content-Type: application/json`。
*   **示例**：
    ```javascript
    app.get('/greeting', (req, res) => {
      res.send('你好，欢迎访问！');
    });
    
    app.get('/status', (req, res) => {
      // 虽然可以发送 JSON，但更推荐使用 res.json()
      res.send({ status: 'OK', uptime: '120s' });
    });
    ```

##### **2. `res.json()`：发送 JSON 格式响应**

*   **是什么**：专门用于发送 JSON 响应的方法。**这是构建 API 时的首选方法**。
*   **为什么用它**：
    1.  **明确意图**：代码可读性更强，一看就知道这里返回的是 JSON。
    2.  **保证 `Content-Type`**：它会强制将 `Content-Type` 响应头设置为 `application/json; charset=utf-8`。
    3.  **JSON 转换**：它会自动将 JavaScript 对象或数组转换为 JSON 字符串格式。
*   **示例**：
    ```javascript
    app.get('/api/users/:id', (req, res) => {
      // 假设我们从数据库找到了用户
      const user = {
        id: req.params.id,
        name: 'Bob',
        roles: ['editor', 'viewer']
      };
      res.json(user);
    });
    ```

##### **3. `res.status()`：设置 HTTP 状态码**

*   **是什么**：这个方法**只设置**响应的 HTTP 状态码，它**不会**发送响应。
*   **链式调用**：它通常与 `.send()` 或 `.json()` 等方法连在一起使用，形成链式调用。
*   **何时使用**：当你需要明确地告诉客户端请求的结果时。
    *   `200 OK` (默认，通常不用手动设置)
    *   `201 Created` (成功创建资源后)
    *   `400 Bad Request` (客户端请求格式错误)
    *   `401 Unauthorized` (需要认证)
    *   `403 Forbidden` (已认证但无权限)
    *   `404 Not Found` (资源未找到)
    *   `500 Internal Server Error` (服务器内部错误)
*   **示例**：
    ```javascript
    app.post('/api/products', (req, res) => {
      const { name, price } = req.body;
      if (!name || !price) {
        // 请求数据不完整，返回 400 状态码和错误信息
        return res.status(400).json({ error: '产品名称和价格不能为空' });
      }
      // ... 创建产品的逻辑 ...
      const newProduct = { id: 123, name, price };
      // 创建成功，返回 201 状态码和新创建的产品信息
      res.status(201).json(newProduct);
    });
    ```
    > **重要**：在 `if` 语句中发送响应后，使用 `return` 是一个好习惯，可以防止后续代码意外执行。

##### **4. `res.redirect()`：重定向请求**

*   **是什么**：指示客户端（通常是浏览器）跳转到另一个 URL。
*   **如何工作**：它会发送一个 `302 Found` (临时重定向) 的状态码，并在 `Location` 响应头中指定新的 URL。
*   **示例**：
    ```javascript
    app.get('/old-profile', (req, res) => {
      // 将访问旧地址的用户重定向到新地址
      res.redirect('/new-profile-page');
    });
    
    app.get('/google', (req, res) => {
      // 也可以重定向到外部链接
      res.redirect('https://www.google.com');
    });
    ```

##### **5. `res.sendFile()`：发送文件**

*   **是什么**：将服务器本地文件系统中的文件作为响应发送给客户端。
*   **关键点**：**必须提供文件的绝对路径**。为了安全和可靠，强烈建议使用 Node.js 内置的 `path` 模块来构建路径。
*   **自动 `Content-Type`**：和 `res.send()` 类似，它会根据文件的扩展名（如 `.html`, `.jpg`, `.css`）自动设置正确的 `Content-Type` 头。
*   **示例**：
    假设你的项目结构如下：
    ```
    my-app/
    ├── public/
    │   └── images/
    │       └── nature.jpg
    ├── views/
    │   └── index.html
    └── app.js
    ```
    
    ```js
    const path = require('path'); // 引入 path 模块
    
    app.get('/', (req, res) => {
      // path.join(__dirname, ...) 会生成一个跨平台兼容的绝对路径
      res.sendFile(path.join(__dirname, 'views', 'index.html'));
    });
    
    app.get('/image', (req, res) => {
      res.sendFile(path.join(__dirname, 'public', 'images', 'nature.jpg'));
    });
    ```

##### **6. `res.cookie()` / `res.clearCookie()`：设置与清除 Cookie**

*   **前提**：同样需要 `cookie-parser` 中间件。
*   **`res.cookie(name, value, [options])`**：
    *   **作用**：在响应中添加一个 `Set-Cookie` 头，让浏览器保存一个 Cookie。
    *   **`options` 对象 (非常重要)**：
        *   `maxAge`: Cookie 的有效期（毫秒）。
        *   `expires`: Cookie 的过期时间 (一个 `Date` 对象)。
        *   `httpOnly: true`: **强烈推荐！** 设置为 `true` 后，该 Cookie 无法通过客户端 JavaScript (`document.cookie`) 访问，有助于防止 XSS 攻击。
        *   `secure: true`: 仅在 HTTPS 连接中发送该 Cookie。
        *   `signed: true`: 对 Cookie 进行签名，防止篡改 (需要在 `cookieParser` 中提供密钥)。
*   **`res.clearCookie(name)`**：
    *   **作用**：告诉浏览器删除一个 Cookie。它通过设置一个已过期的日期来实现。
*   **示例**：
    ```javascript
    // 登录路由
    app.post('/login', (req, res) => {
      // ... 验证用户名和密码成功后 ...
    
      // 设置一个普通的 cookie
      res.cookie('user_preference', 'dark_mode', { maxAge: 900000 }); // 15分钟
    
      // 设置一个用于身份验证的、更安全的 cookie
      res.cookie('session_id', 'some-random-session-string', {
        httpOnly: true, // 关键安全设置
        maxAge: 24 * 60 * 60 * 1000 // 24小时
      });
      
      res.json({ message: '登录成功' });
    });
    
    // 登出路由
    app.get('/logout', (req, res) => {
      res.clearCookie('session_id');
      res.send('登出成功');
    });
    ```
