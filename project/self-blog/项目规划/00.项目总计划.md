### 第二阶段：项目初始化与基础架构

这个阶段的目标是“把架子搭起来，能跑通 Hello World”。

1.  **创建 Spring Boot 项目**
    * 使用 IDEA 的 Spring Initializr 创建。
    
    *   **依赖勾选:**
        
        * Spring Web
        
        * MyBatis Framework
        
        * MySQL Driver
        
        * Lombok 
        
        * PageHelper （在 Spring Initializr（也就是你现在的 IDEA 勾选界面）里，**通常是搜不到 PageHelper 的**。因为它不是 Spring 官方维护的库，而是第三方开源大神写的。）
        
          ```java
          <!-- PageHelper 分页插件 -->
          <dependency>
              <groupId>com.github.pagehelper</groupId>
              <artifactId>pagehelper-spring-boot-starter</artifactId>
              <version>1.4.7</version>
          </dependency>
          ```
        
          ![](C:\Users\28745\AppData\Roaming\Typora\typora-user-images\image-20251120161554666.png)
    
2.  **配置 `application.yml`**
    
    * 配置数据库连接 URL、用户名、密码。

    * 配置 MyBatis 的 Mapper XML 扫描路径。
    
      ```java
      # ==========================================
      # 服务器配置
      # ==========================================
      server:
        port: 8080  # 后端运行端口，默认 8080
      
      # ==========================================
      # Spring 核心配置
      # ==========================================
      spring:
        application:
          name: myblog-backend # 应用名称
      
        # 数据库连接配置
        datasource:
          # MySQL 8.x 驱动
          driver-class-name: com.mysql.cj.jdbc.Driver
          # 数据库连接串：
          # 1. localhost:3306/myblog_db -> 对应我们之前创建的数据库名
          # 2. serverTimezone=Asia/Shanghai -> 解决时差问题
          # 3. useUnicode=true&characterEncoding=utf-8 -> 解决中文乱码
          url: jdbc:mysql://localhost:3306/myblog_db?useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai&useSSL=false
          username: root
          password: 123456
      
      # ==========================================
      # MyBatis 配置
      # ==========================================
      mybatis:
        # 告诉 MyBatis SQL XML 文件放在哪里 (classpath 对应 resources 目录)
        mapper-locations: classpath:mapper/*.xml
        # 别名扫描包 (写 XML 时 resultType 可以直接写 "User" 而不用写全限定名)
        type-aliases-package: com.my.blog.entity
        configuration:
          # 开启驼峰命名映射
          # 自动把数据库的 create_time 映射为 Java 的 createTime
          map-underscore-to-camel-case: true
          # 打印 SQL 日志
          log-impl: org.apache.ibatis.logging.stdout.StdOutImpl
      
      # ==========================================
      # PageHelper 分页插件配置
      # ==========================================
      pagehelper:
        helper-dialect: mysql
        reasonable: true           # 分页合理化 (比如查第100页没数据，会自动返回最后一页，防止报错)
        support-methods-arguments: true
      ```
    
      
    
3.  **规划包结构 (Standard Packaging)**
    良好的目录结构能让你思路清晰：
    
    ```text
    com.my.blog
    ├── common          // 通用模块 (结果封装类、工具类)
    ├── config          // 配置类 (跨域配置、拦截器配置)
    ├── controller      // 控制层 (接收前端请求)
    ├── entity          // 实体类 (对应数据库表)
    ├── mapper          // DAO层 (MyBatis接口)
    ├── service         // 业务逻辑层接口
    │   └── impl        // 业务逻辑层实现
    └── BlogApplication.java
    ```
    
4.  **封装统一响应结果 (`Result` 类)**
    
    *   不要直接返回 String 或 Object。
    *   定义一个 `Result<T>` 类，包含 `code` (状态码), `msg` (消息), `data` (数据)。前后端交互必须统一格式。

### 第三阶段：逆向工程与实体映射 
**目标：** 将数据库表转换为 Java 代码（Entity实体类），并打通数据库的最基础操作。

1.  **创建 Entity 实体类**
    *   根据数据库表结构，在 `com.my.blog.entity` 包下创建对应的 Java 类。
    *   **注意数据类型映射：**
        *   `bigint` -> `Long`
        *   `datetime` -> `java.util.Date` 或 `java.time.LocalDateTime`
        *   `tinyint` -> `Integer`
    *   **Lombok 加持：** 给每个类加上 `@Data` 注解。
    *   **需创建类：** `SysUser`, `BlogCategory`, `BlogTag`, `BlogArticle` 等所有表对应类。

2.  **创建 Mapper 接口与 XML**
    *   在 `com.my.blog.mapper` 下创建接口（如 `SysUserMapper`）。
    *   在 `resources/mapper` 下创建对应的 XML 文件（如 `SysUserMapper.xml`）。
    *   **任务：** 先只写最简单的 `selectById` 和 `insert` 方法，确保代码能跑通。

3.  **单元测试 (Unit Test)**
    *   在 `src/test/java` 下写一个测试类。
    *   注入 `SysUserMapper`，试着往数据库插入一条假数据，再查出来，看能不能打印成功。

### 第四阶段：核心业务功能开发 
**目标：** 完成博客最核心的功能（写博客、看博客、管理分类）。

1.  **分类与标签管理 (练手热身)**
    *   **对应表：** `blog_category`, `blog_tag`
    *   **功能点：**
        *   查询分类列表 (下拉菜单用)
        *   新增/修改分类
        *   删除分类 (注意：如果有子分类或关联文章，是否允许删除？这里可以先做简单直接删除)

2.  **文章管理 (核心重难点)**
    *   **对应表：** `blog_article`, `blog_article_meta`, `blog_article_tag`
    *   **功能点：**
        *   **发布文章：** 接收前端 JSON -> 插入 `blog_article` -> 插入 `blog_article_tag` (关联表) -> 插入 `blog_article_meta` (如果有扩展属性)。需要用到 `@Transactional` 事务。
        *   **文章列表：** 使用 `PageHelper` 分页查询 `blog_article`。
        *   **文章详情：** 根据 ID 查询内容，同时把 Markdown 转换后的 HTML 返回给前端（或者前端自己转）。
        *   **逻辑删除：** 编写 Update 语句，将 `is_deleted` 字段设为 1，而不是真正的 DELETE。

3.  **前台首页展示**
    *   **功能点：**
        *   查询置顶文章 (`is_top = 1`)。
        *   按时间倒序查询最新文章列表。
        *   增加阅读量 (`view_count` + 1 接口)。

### 第五阶段：认证与权限模块 
**目标：** 实现登录功能，保护后台接口不被乱调。

1.  **管理员登录**
    *   **对应表：** `sys_user`
    *   **逻辑：** 接收账号密码 -> 查库 -> 校验密码 (推荐使用 BCrypt 加密，不要存明文) -> **生成 JWT Token** 返回给前端。

2.  **登录拦截器 (Interceptor)**
    *   在 `config` 包下创建拦截器。
    *   **规则：** 拦截 `/admin/**` 开头的路径（或者发布、删除文章的接口）。
    *   **校验：** 检查请求头里的 Token 是否合法，不合法直接返回 `Result.error(401, "未登录")`。

### 第六阶段：进阶功能完善 
**目标：** 让博客功能更丰富，体验更好。

1.  **文件上传 (图片存储)**
    *   **对应表：** `sys_attachment`
    *   **功能：** 编写 `/upload` 接口，接收 `MultipartFile`。
    *   **实现：** 先实现保存到本地磁盘（`storage_location = 0`），成功后把文件路径写入数据库，并返回 URL 给前端用于文章插图。

2.  **评论系统**
    *   **对应表：** `blog_comment`
    *   **功能：** 发表评论、后台审核评论（修改 `status` 字段）。
    *   **难点：** 处理评论的层级结构（父子评论）。

3.  **全局异常处理**
    *   创建 `GlobalExceptionHandler` 类。
    *   捕获所有异常，统一返回 `Result.error()` 格式，防止前端看到 500 报错页面。

4.  **接口文档 (Swagger/Knife4j)**
    *   引入 Knife4j 依赖。
    *   给 Controller 加上注解，自动生成接口文档，方便以后对接前端。
