     * 对应字段: id (bigint)
     */
    private Long id;

    /**
     * 用户名
     * 对应字段: username (varchar)
     */
    private String username;

    /**
     * 密码 (BCrypt加密)
     * 对应字段: password (varchar)
     */
    private String password;

    /**
     * 邮箱
     * 对应字段: email (varchar)
     */
    private String email;

    /**
     * 昵称
     * 对应字段: nickname (varchar)

    private String nickname;

    /**

     * 对应字段: avatar (varchar)
     */
    private String avatar;

    /**
     * 简介
     * 对应字段: bio (varchar)
     */
    private String bio;

    /**
     * 角色: 0-普通用户, 1-管理员
     * 对应字段: role (tinyint)

### 💡 给新手的知识点 (必读)

1.  **类型对应关系**
    *   数据库 `bigint` -> Java `Long`
    *   数据库 `varchar` -> Java `String`
    *   数据库 `tinyint` -> Java `Integer`
    *   数据库 `datetime` -> Java `java.util.Date`

2.  **驼峰命名法 (CamelCase)**
    *   你的数据库里字段叫 `create_time` (下划线)。
    *   Java 类里必须叫 `createTime` (驼峰)。
    *   **不用担心无法匹配**，因为我们在 `application.yml` 里配置了 `map-underscore-to-camel-case: true`，MyBatis 会自动帮我们把这两者对应起来。

3.  **Lombok 的作用**
    *   你看这个类里只有字段，没有 `getIds()`, `setId()` 这种代码。
    *   这就是 `@Data` 的功劳，它在编译时会自动帮你生成这些繁琐的代码，保持代码清爽。

### 第一步：创建 Mapper 接口

package com.my.blog.mapper;

import com.my.blog.entity.SysUser;
import org.apache.ibatis.annotations.Mapper;

/**
 * 用户表 DAO 接口
 * 这里的每个方法对应 XML 中的一个 SQL 语句
 */
@Mapper // 告诉 Spring Boot 这是一个 MyBatis 的 Mapper 接口，启动时会自动扫描并创建实现类
public interface SysUserMapper {

    /**
     * 新增用户
     * @param sysUser 用户对象
     * @return 影响行数 (1表示成功)
     */
    int insert(SysUser sysUser);

    /**
     * 根据ID查询用户
     * @param id 用户ID
     * @return 用户对象
     */
    SysUser selectById(Long id);
}

### 第二步：创建 XML 映射文件

1.  在 IDEA 左侧项目树中，找到 **`src/main/resources/mapper`** 文件夹 (这是我们之前配置 `application.yml` 时新建的)。
2.  右键点击 `mapper` 文件夹 -> **New -> File** (或者 XML Configuration File -> MyBatis Mapper，如果没有这个选项就直接选 File)。
3.  输入文件名：**`SysUserMapper.xml`** (注意后缀是 .xml)。
4.  复制以下代码：

```xml
<?xml version="1.0" encoding="UTF-8" ?>
<!DOCTYPE mapper
        PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-mapper.dtd">

<!-- namespace 必须必须必须 对应 Mapper 接口的全限定名 -->
<mapper namespace="com.my.blog.mapper.SysUserMapper">

    <!-- 
         1. id="insert": 对应接口中的方法名 insert
         2. useGeneratedKeys="true": 告诉数据库，insert后把生成的主键ID取回来
         3. keyProperty="id": 把取回来的主键ID赋值给 SysUser 对象的 id 属性
    -->
    <insert id="insert" useGeneratedKeys="true" keyProperty="id">
        INSERT INTO sys_user (
            username, password, email, nickname, avatar, bio, role, create_time, update_time, is_deleted
        ) VALUES (
            #{username}, #{password}, #{email}, #{nickname}, #{avatar}, #{bio}, #{role}, #{createTime}, #{updateTime}, #{isDeleted}
        )
    </insert>

    <!-- 
         1. id="selectById": 对应接口中的方法名 selectById
         2. resultType="SysUser": 返回值的类型。
            因为我们在 yaml 里配置了 type-aliases-package，所以这里不用写全名 com.my.blog.entity.SysUser，直接写 SysUser 即可。
            MyBatis 会自动根据 map-underscore-to-camel-case 把数据库的 create_time 塞给实体的 createTime。
    -->
    <select id="selectById" resultType="SysUser">
        SELECT * FROM sys_user WHERE id = #{id}
    </select>

</mapper>
```

### 💡 写完后的自检 (防坑指南)

1.  **Namespace 对不对？**
    *   XML 里的 `<mapper namespace="...">` 必须完全等于接口的包名+类名 (`com.my.blog.mapper.SysUserMapper`)。
    *   如果这里写错，启动不报错，但调用时会报 `Invalid bound statement (not found)`。

2.  **ResultType 对不对？**
    *   你的 `application.yml` 里必须有 `type-aliases-package: com.my.blog.entity`，否则 XML 里的 `resultType="SysUser"` 会报错说找不到类。

3.  **XML 文件放对了吗？**
    *   必须在 `src/main/resources/mapper` 下。
    *   如果你不小心放到了 `src/main/java/.../mapper` 下，打包时会被漏掉（除非额外配置）。

这是一个非常关键的问题！一定要理清楚，否则后面会越学越晕。我来逐一回答你的疑问。

### 1. `application.yml` 放在哪里？

**❌ 绝对不要放在 `mapper` 文件夹下面！**

`application.yml` 是整个项目的“总指挥部”，它必须直接放在 **`src/main/resources`** 的根目录下。
而 `mapper` 文件夹是专门用来存放 SQL XML 文件的。

**正确的目录结构是这样的：**

```text
src
└── main
    └── resources
        ├── mapper               <-- 文件夹：放 SysUserMapper.xml
        │   └── SysUserMapper.xml
        ├── static               <-- 文件夹
        ├── templates            <-- 文件夹
        └── application.yml      <-- 文件：直接在 resources 根目录下
```

如果你把它放进 `mapper` 文件夹，Spring Boot 启动时找不到配置文件，你的数据库连接就会失败。

---

### 2. 为什么需要写 XML？MyBatis 不是不用写吗？

你可能把 **MyBatis** 和 **MyBatis-Plus** 搞混了，或者听到了“注解版 MyBatis”的说法。

*   **原生 MyBatis (Standard):**
    *   **方式 A (XML 方式):** **推荐。** 把 SQL 写在 XML 里。优点是 SQL 和 Java 代码分离，维护方便，支持复杂的动态 SQL（比如：如果有名字就查名字，没名字就查全部）。
    *   **方式 B (注解方式):** 把 SQL 写在 Java 接口的方法头上，如 `@Select("select * from sys_user")`。优点是简单，但如果 SQL 很长（几十行），Java 代码会变得非常难看，且不好维护。
*   **MyBatis-Plus (MP):**
    *   这是国内团队在 MyBatis 基础上做的**增强工具**。
    *   **特点：** 对于简单的单表增删改查（CRUD），它**完全不用写 SQL，也不用写 XML**。它内置了 `BaseMapper`，你继承它，自动就有了 `insert`, `selectById`, `delete` 等方法。

所以，你印象中“不用写 XML”的，大概率是指 **MyBatis-Plus**。

---

### 3. 给新手的诚恳建议：用哪一个？

作为新手，我**强烈建议你先使用原生 MyBatis + XML (也就是我们现在的方案)**。

**为什么？(肺腑之言)**

1.  **基础才是王道：**
    MyBatis-Plus 虽然爽，但它是个“黑盒”。如果你一上来就用 MP，你根本不知道底层的 SQL 是怎么拼出来的，也不知道 Java 对象是怎么映射到数据库字段的。
    **你要做的是程序员，而不是“配置员”。** 先学会手写 SQL，理解了原理，以后用 MP 是分分钟的事。
2.  **复杂业务必需：**
    在真实工作中，稍微复杂的查询（比如多表关联查询：查询文章的同时查出作者名字和 3 个热门标签），MyBatis-Plus 自带的方法是不够用的，**你最终还是要手写 XML**。
3.  **面试必问：**
    面试官问你：“MyBatis 的 `#` 和 `$` 有什么区别？”、“XML 里的 ResultMap 是干嘛的？”如果你只用过 MP，你可能一个都答不上来。

**💡 我的建议路线：**

*   **现在的阶段：** 坚持把这个博客项目的核心模块（用户、文章）用 **原生 MyBatis + XML** 写出来。感受一下 SQL 是怎么流转的。
*   **未来的优化：** 等你项目写完了，或者你觉得写 SQL 写吐了（比如一些简单的字典表），你可以尝试引入 MyBatis-Plus 来简化代码。

### 第二步：编写测试代码

请将下面的代码**完整复制**到 `SysUserMapperTest.java` 中。

```java
package com.my.blog.mapper;

// 同包下的类，不需要 import SysUserMapper

import com.my.blog.entity.SysUser;
import org.junit.jupiter.api.Assertions; // 【新】引入断言工具
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.transaction.annotation.Transactional; // 【新】引入事务控制

import java.util.Date;

/**
 * 单元测试类
 * @SpringBootTest: 这个注解非常重要！
 * 它会启动整个 Spring Boot 容器，读取 application.yml 的配置，
 * 连接数据库，把 Mapper 接口生成代理对象，这样我们才能测试。
 */
@SpringBootTest
public class SysUserMapperTest {

    // 注入我们要测试的 Mapper 接口
    @Autowired
    private SysUserMapper sysUserMapper;

    @Test
    @Transactional  // 【神器】测试结束后，自动回滚事务。也就是说，插入的数据会被撤销，不会污染数据库！
    public void testInsertAndSelect() {
        // =================================
        // 1. 准备数据(模拟一个新用户)
        // =================================
        SysUser user = new SysUser();
        user.setUsername("junit_test_user"); // 有了回滚，不用担心用户名重复，可以写死
        user.setPassword("123456");
        user.setEmail("test@example.com");
        user.setNickname("单元测试员");
        user.setRole(0);
        user.setCreateTime(new Date());
        user.setUpdateTime(new Date());
        user.setIsDeleted(0);
        
        System.out.println("插入前的主键 ID: " + user.getId()); // 应该是 null

        // =================================
        // 2. 执行插入(Insert)
        // =================================
        int rows = sysUserMapper.insert(user);
        System.out.println("插入影响行数: " + rows); // 应该是 1
        
        // 【断言 1】断言影响行数必须是 1，如果不是，测试直接爆红失败
        Assertions.assertEquals(1, rows, "插入数据失败，影响行数不为1");
        
        // 【断言 2】断言 ID 不为空 (MyBatis 应该回填 ID)
        Assertions.assertNotNull(user.getId(), "主键ID未回填");

        // 关键点：因为 XML 里配置了 useGeneratedKeys="true"，
        // 插入成功后，MyBatis 会把数据库生成的 ID 回填给 user 对象。
        System.out.println("生成的ID是: " + user.getId());

        // =================================
        // 3. 测试查询 (Select)
        // =================================
        // 用刚才生成的 ID 去数据库查一下，看能不能查出来
        SysUser foundUser = sysUserMapper.selectById(user.getId());
        System.out.println("查询结果: " + foundUser);

        // 【断言 3】断言查出来的对象不为空
        Assertions.assertNotNull(foundUser, "根据ID查询失败");
        
        // 【断言 4】断言查出来的用户名和存进去的一样
        Assertions.assertEquals(user.getUsername(), foundUser.getUsername(), "用户名不一致");

        System.out.println(">>> 测试完美通过！(且数据库不会留下垃圾数据) <<<");
    }
}
```

### ⏳ 常见错误排查 (如果变红了看这里)

对于新手，**90% 的错误**都在下面这三点：

1.  **`Access denied for user` (数据库连不上)**
    *   **原因：** `application.yml` 里的账号密码写错了，或者数据库服务没开。
    *   **解决：** 检查 yml 文件，用 DBeaver 试一下能不能连上。

2.  **`Invalid bound statement (not found)` (找不到 XML)**
    *   **原因：** 你的 XML 文件没放对位置，或者 XML 里的 `namespace` 写错了。
    *   **解决：** 
        *   检查 `src/main/resources/mapper/SysUserMapper.xml` 是否存在。
        *   检查 XML 里的 `<mapper namespace="com.my.blog.mapper.SysUserMapper">` 是不是和你的接口全名完全一致。
        *   检查 `application.yml` 里 `mybatis.mapper-locations` 配置是否正确。

3.  **`BeanCreationException` (启动失败)**
    *   **原因：** 通常是因为包结构不对。
    *   **解决：** 确保 `SysUserMapperTest` 位于 `com.my.blog` 包下（或其子包下）。如果你的主启动类在 `com.my.blog`，而测试类在 `com.example`，Spring Boot 就会找不到家。

首先，关于你写的 `SysUserMapper.xml`，整体逻辑是对的，但有两个**小错误**需要修正，否则运行会报错：

### 🛠️ 修正你的 SysUserMapper.xml

1.  **大小写敏感错误**：
    在 `selectByUsername` 中，你写的是 `<include refid="Base_column_List" />`（column 是小写）。
    但你上面定义的 `<sql id="Base_Column_List">`（Column 是大写）。
    **修正**：XML 中 ID 引用是大小写敏感的，必须完全一致，改为 `Base_Column_List`。

2.  **缺少 selectList 实现**：
    你的 Interface 里定义了 `List<SysUser> selectList();`，但 XML 里没写对应的 `<select>` 标签。这会报错 `Invalid bound statement`。

修正后的 `SysUserMapper.xml` 片段：

```xml
    <!-- 2. 根据用户名查询 (注意 refid 大小写) -->
    <select id="selectByUsername" resultMap="BaseResultMap">
        SELECT
        <include refid="Base_Column_List" />  <!-- 这里改为了大写 C -->
        FROM sys_user
        WHERE username = #{username} AND is_deleted = 0
    </select>

    <!-- 补上: 6. 查询所有 -->
    <select id="selectList" resultMap="BaseResultMap">
        SELECT <include refid="Base_Column_List"/>
        FROM sys_user
        WHERE is_deleted = 0
    </select>
```
