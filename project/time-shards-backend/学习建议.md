### 第一阶段：跑通项目 (环境与配置)
**目标：** 让项目在你的本地跑起来，确保没有任何报错。这是最基础的一步。

1.  **检查依赖 (`pom.xml`)：**
    *   打开 `pom.xml`，查看使用了哪些核心库。
    *   **关注点：**
        *   Spring Boot 版本是多少？
        *   数据库连接池用的什么 ?
        *   ORM 框架是什么 ? 
        *   工具库 ?

2.  **配置数据库 (`application.yml` & `resources/db`)：**
    *   打开 `src/main/resources/application.yml`，找到 `spring.datasource` 部分。
    *   **关键动作：**
        *   查看数据库名、用户名、密码。
        *   去 `src/main/resources/db` 文件夹，找到 SQL 脚本，在你的本地数据库中执行建表语句。
    *   **思考：** 这个项目的数据库设计是否规范？有哪些表？表之间的关系是什么？

3.  **启动项目：**
    *   运行 `TimeShardsApplication` 类。
    *   观察控制台日志，确保 Tomcat 启动成功
    *   **验证：** 用浏览器或`apifox `访问一个简单的接口

### 第二阶段：理解架构 (骨架与规范)
**目标：** 理解代码是如何分层的，以及一个请求是如何被处理的。

1.  **通用层分析 (`common` 包)：**
    *   **`ApiResponse`：** 打开这个类。它是后端返回给前端的统一数据格式（通常包含 `code`, `message`, `data`）。弄懂它是如何封装数据的。
    *   **`GlobalExceptionHandler`：** 这是全局异常处理。看它是如何捕获异常并转化为友好的错误提示的。**这是后端健壮性的关键。**

2.  **剖析分层架构 (MVC)：**
    *   **Controller (控制层)：** 它是入口。看它是如何接收 HTTP 请求、校验参数的。
    *   **Service (业务层)：** 它是核心。看业务逻辑（如：“判断用户是否有权限”、“计算时间碎片”）是写在哪里的。
    *   **Mapper (持久层)：** 它是数据库交互。看 SQL 是写在注解里，还是 XML 文件里。
    *   **Entity (实体层)：** 对应数据库表结构。

3.  **阅读 `frontend_guide`：**
    *   既然有这个文件夹，说明开发者留下了前后端对接文档。阅读它能让你快速知道这个后端提供了什么功能，而不需要去猜代码。

### 一、 前台门户 (面向读者/访客)
*核心目标：展示 `blog_article`，利用 `category` 和 `tag` 进行聚合，通过 `comment` 互动。*

#### 1. 极致的文章阅读体验
*   **SEO 友好链接 (Slug)**
    *   **利用字段**：`blog_article.slug`
    *   **功能**：文章详情页不使用 `id`（如 `/article/1`），而是使用自定义别名（如 `/article/spring-boot-guide`），利于搜索引擎收录。
*   **Markdown 渲染与缓存**
    *   **利用字段**：`content` (MD源码) vs `content_html` (渲染后的HTML)
    *   **功能**：后台保存时自动将 Markdown 转为 HTML 存入 `content_html`。前台直接读取 `content_html` 展示，极大提升页面加载速度（无需每次请求都解析 Markdown）。
*   **文章元数据扩展 (自定义属性)**
    *   **利用表**：`blog_article_meta` (Key-Value 结构)
    *   **功能**：不修改表结构即可给文章加功能。例如：
        *   Key: `music_url`, Value: `http://...mp3` -> 前台文章顶部自动渲染播放器。
        *   Key: `copyright_notice`, Value: `true` -> 文章底部显示版权声明。
        *   Key: `theme_color`, Value: `#ff0000` -> 针对该文章改变页面背景色。

#### 2. 多维度的内容检索与聚合
*   **层级分类导航**
    *   **利用表**：`blog_category` (`parent_id`)
    *   **功能**：支持多级菜单（如：技术 -> 后端 -> Java）。前台生成面包屑导航（首页 > 技术 > Java > 正文）。
*   **标签云与关联推荐**
    *   **利用表**：`blog_tag` + `blog_article_tag` (多对多)
    *   **功能**：
        1.  **标签墙**：按标签下文章数量排序展示标签。
        2.  **相关文章推荐**：在文章底部，通过 SQL 查询“拥有相同标签的其他文章”，提高用户留存率。
*   **归档 (Archives)**
    *   **利用字段**：`blog_article.create_time`
    *   **功能**：按“年-月”归档文章（例如：2023年10月 (5篇)）。

#### 3. 互动评论系统 (盖楼式)
*   **利用表**：`blog_comment` (`parent_id`, `is_admin`, `user_id`)
*   **功能**：
    *   **游客/会员评论**：`user_id` 为空则是游客（需填昵称邮箱），不为空则是注册用户（自动拉取头像）。
    *   **嵌套回复**：利用 `parent_id` 实现“楼中楼”或“引用回复”。
    *   **博主认证高亮**：前端判断 `is_admin == 1`，给博主头像加“官方认证”标识或高亮边框。

---

### 二、 后台管理 (面向博主/管理员)
*核心目标：管理 `sys_config`，维护 `sys_attachment`，审核内容。*

#### 1. 动态系统配置 (无需重启改代码)
*   **利用表**：`sys_config` (Key-Value 结构)
*   **功能**：将硬编码的配置存入数据库。
    *   `site_title`: 网站标题
    *   `site_footer`: 底部备案号
    *   `seo_keywords`: 全局 SEO 关键词
    *   `oss_type`: 切换图片存储源（本地/阿里云/七牛云）
    *   `comment_open`: 全局开启/关闭评论功能

#### 2. 统一图床/文件管理
*   **利用表**：`sys_attachment`
*   **功能**：
    *   **上传策略切换**：根据 `storage_location` (0/1/2) 决定文件上传到服务器磁盘还是对象存储（OSS）。
    *   **文件库管理**：类似 Windows 资源管理器，查看所有上传过的图片，支持复制 URL 插入到 Markdown 编辑器中。

#### 3. 内容发布工作流
*   **利用字段**：`blog_article.status` (草稿/发布/下架)
*   **功能**：
    *   **草稿箱**：写一半自动保存，不展示在前台。
    *   **置顶管理**：`is_top` 字段控制文章是否在首页轮播图或列表顶部展示。
    *   **评论审核**：后台有个“待审核评论”列表（`status=0`），一键通过或标记为垃圾评论（`status=2`）。

---

### 三、 用户与权限 (基础安全)
*核心目标：利用 `sys_user` 保护系统。*

#### 1. 个人中心
*   **利用字段**：`sys_user.avatar`, `sys_user.bio`
*   **功能**：用户修改密码、上传头像、修改个人简介。

#### 2. 角色分流
*   **利用字段**：`sys_user.role`
*   **功能**：
    *   `role=1` (管理员)：进入后台管理界面，拥有所有权限。
    *   `role=0` (普通用户)：只能在前台浏览，或者（如果你打算做多人博客）只能管理自己的评论/文章。

---

### 四、 统计与监控 (数据价值)
*核心目标：利用计数器字段。*

#### 1. 流量统计
*   **利用字段**：`blog_article.view_count`
*   **功能**：
    *   **热门文章排行榜**：按阅读量降序展示 Top 10。
    *   **阅读量防刷**：(逻辑层功能) 同一 IP 短时间内访问只增加 1 次阅读量。

### 总结：你的开发路线图建议

为了完全利用这些表，建议你的开发顺序如下：

1.  **第一阶段 (基础)**：完成 `sys_user` 登录注册 (JWT)，完成 `blog_article` 的 CRUD（配合 `blog_article_tag` 和 `blog_category`）。*此时博客能跑起来了。*
2.  **第二阶段 (增强)**：实现 `sys_attachment` 文件上传，并在写文章时集成图片上传功能。实现 `sys_config` 接口，让前端标题读库。
3.  **第三阶段 (互动)**：开发 `blog_comment` 评论功能，处理好父子层级关系。
4.  **第四阶段 (高阶)**：开发 `blog_article_meta` 的动态属性功能，利用 `content_html` 做缓存优化。

这套设计完全覆盖了你的 9 张表，且每一张表都有其存在的明确业务价值。你可以根据这个蓝图开始写 Service 层代码了。
