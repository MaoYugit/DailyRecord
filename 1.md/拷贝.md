**深浅拷贝**可以说是前端面试中**“出场率最高、最能考察候选人 JavaScript 基本功底”**的一道题。

很多初中级前端只能说出 `Object.assign` 和 `JSON.parse(JSON.stringify())`。但在我这里，如果想要拿到**高级前端**的评价，你不能只停留在 API 的调用上。你需要从**内存模型、数据类型边界、循环引用（WeakMap）、现代浏览器原生 API（structuredClone），甚至上升到性能优化与不可变数据（Immutable）**的层面来向我汇报。

以下是为你整理的“降维打击”级别的满分回答框架：

---

### 一、 破题：一句话讲透本质（展现底层思维）

**面试官期望的开场白：**
“深浅拷贝的本质区别，源于 JavaScript 对不同数据类型的**内存存储方式**不同。
基础数据类型（如 String、Number）存在**栈内存（Stack）**中，而引用数据类型（如 Object、Array）存在**堆内存（Heap）**中，栈里只保存了一个指向堆内存的**引用地址（指针）**。
*   **浅拷贝（Shallow Copy）**：只拷贝了第一层。如果属性是引用类型，拷贝的只是**内存地址**。修改拷贝后的嵌套对象，**会影响原对象**。
*   **深拷贝（Deep Copy）**：在堆内存中开辟一块**全新的空间**，递归地将原对象的所有层级完整复制过来。两者在内存中完全独立，**互不影响**。”

---

### 二、 浅拷贝：日常开发中最常用的手段

你可以快速向面试官列举几种常见的浅拷贝方式，证明你的熟练度：
1.  **扩展运算符 (`...`)**：最优雅、目前工作中最常用的方式（如 `const newObj = { ...oldObj }`）。
2.  **`Object.assign(target, ...sources)`**：常用于对象的合并。
3.  **数组专属方法**：`Array.prototype.slice()`、`Array.prototype.concat()`。

**高级补充（加分项）**：“面试官您好，需要补充的是，无论是 `...` 还是 `Object.assign`，它们都**只能拷贝对象自身的可枚举属性**，无法拷贝继承的属性，也无法拷贝不可枚举的属性。”

---

### 三、 深拷贝：从“土法炼钢”到“现代原生”（重点考察区）

讲深拷贝时，一定要按照**演进过程**来聊，展现你对技术发展的关注。

#### 1. 经典 Hack 方案：`JSON.parse(JSON.stringify(obj))`
*   **优点**：代码极简，能应付 80% 的纯数据（Plain Object）拷贝场景。
*   **致命缺陷（面试必问陷阱，必须一口气报出来）**：
    1.  **丢失类型**：会忽略 `undefined`、`Symbol` 和 `函数`。
    2.  **数据异变**：`Date` 对象会变成字符串，`RegExp`（正则）和 `Error` 对象会变成空对象 `{}`，`NaN` 和 `Infinity` 会变成 `null`。
    3.  **致命报错**：遇到**循环引用**（对象互相引用）时，直接抛出异常，导致程序崩溃。

#### 2. 现代浏览器原生 API：`structuredClone()` （2022年起全面普及，高级候选人必提！）
*   **你的回答亮点**：
    “以前为了完美的深拷贝，我们要么手写，要么引入 `lodash` 的 `cloneDeep`。但现在，我会优先使用现代浏览器原生的 **`structuredClone(obj)`** API。
    它基于结构化克隆算法，完美解决了 JSON 方案的痛点：**支持拷贝 Date、Set、Map、RegExp，并且完美支持循环引用！**”
*   **它的局限性**：仍然不能拷贝函数（会报错）和 DOM 节点。

#### 3. 工业级标准方案：`lodash.cloneDeep`
*   如果在复杂的企业级老项目中，涉及到极其复杂的数据兜底，直接用 Lodash 依然是最稳妥的方案。

### 🧐 详细场景分析

#### 1. `JSON.parse(JSON.stringify(obj))` —— “快但不准”
*   **适用场景**：纯粹的业务数据（只有字符串、数字、数组、简单对象），且确定没有 `undefined`。
*   **致命弱点**：
    *   它会把 `Date` 变成 `String`，导致你拿回数据后无法调用 `.getTime()` 等方法。
    *   它会直接删掉对象里的函数和 `undefined`。
    *   遇到循环引用直接崩溃。

#### 2. `structuredClone(obj)` —— “现代标准的优选”
*   **适用场景**：现代 Web 应用、Node.js 后端开发。它是目前浏览器官方唯一指定的深拷贝标准。
*   **核心优势**：
    *   它是 HTML 规范的一部分，性能非常强。
    *   完美处理循环引用、`Map/Set`、`Date`、`RegExp`。
*   **局限性**：
    *   **不能拷贝函数**：如果你的对象里有方法（Method），这个方法会报错。
    *   **不能拷贝 DOM 节点**。

#### 3. `lodash.cloneDeep` —— “功能最全的终极武器”
*   **适用场景**：
    *   需要兼容旧版浏览器（如 IE）。
    *   对象中包含 **Symbol** 属性。
    *   **最关键的一点**：你需要**保持对象的构造函数信息（原型链）**。
*   **核心优势**：
    *   它非常“聪明”，如果你拷贝的是一个 `User` 类的实例，它拷贝出来的东西依然是 `User` 的实例。而上面两个方案拷贝出来的都会变成一个“普通的对象”。

---

### 💡 总结建议：我该选哪个？

1.  **首选 `structuredClone`**：
    只要你的项目不需要兼容 2022 年以前的旧浏览器，且数据中不包含函数，**无脑选它**。它是原生的，不需要安装包，且逻辑最严谨。

2.  **次选 `lodash.cloneDeep`**：
    如果你的数据里有**函数**、**Symbol**，或者你正在写一个极其复杂的**插件/类库**，需要精确维持原型链关系，选 Lodash。

3.  **最后选 `JSON` 方案**：
    除非你在写一个非常简单的脚本，或者你确定数据只包含基础的 JSON 格式数据（比如从后端接口拿到的 JSON），否则不建议在正式项目中使用，坑太多。

### 四、 终极 Boss 题：手写深拷贝核心逻辑

面试官通常会顺势追问：“如果让你自己实现一个完美的深拷贝，核心要解决哪些问题？”

你不需要在白板上默写无懈可击的代码，但你必须**讲出清晰的设计思路和这三个关键难点**：

#### 1. 基础骨架：递归与类型判断
“首先，深拷贝的核心是**递归**。我会先写一个判断，如果遇到基础类型或者 `null`，直接返回。如果遇到对象或数组，就创建一个新的 `{}` 或 `[]`，然后遍历原对象的键，**递归地**对每一个子属性调用深拷贝函数。”

#### 2. 核心难点 A：循环引用（防止死循环）
**这是区分普通程序员和资深程序员的分水岭。**
“如果一个对象指向了它自己（例如 `obj.self = obj`），简单的递归会导致**栈溢出（Infinite Loop）**。
**解决方案：** 我会引入一个 **`WeakMap`**。在每次拷贝对象前，先去 `WeakMap` 里查一下：‘这个对象我之前拷贝过吗？’
*   如果有，直接返回之前拷贝过的那个副本。
*   如果没有，就把当前对象和它的副本存进 `WeakMap`，然后继续拷贝。
*   *（加分点：为什么用 WeakMap 而不是 Map？因为它对键是弱引用，不会导致内存泄漏。）*”

#### 3. 核心难点 B：特殊类型的处理
“普通的递归只能处理 `Object` 和 `Array`。
*   如果是 **Date** 或 **RegExp**（正则），我会直接根据原值 `new` 一个新实例返回。
*   如果是 **Function**（函数），通常在深拷贝中不需要处理（直接返回引用），或者通过 `toString` 重新生成（但一般不推荐修改函数作用域）。”

---

### 🚀 终极深拷贝代码实现（TS/JS 通用逻辑版）

这是一段既简洁又考虑到循环引用的标准实现：

```javascript
/**
 * 深拷贝核心实现
 * @param target 要拷贝的对象
 * @param map 用于存储已拷贝的对象，解决循环引用
 */
function deepClone(target, map = new WeakMap()) {
  // 1. 处理基本类型、null 和 undefined
  if (typeof target !== 'object' || target === null) {
    return target;
  }

  // 2. 处理特殊对象：Date 和 RegExp
  if (target instanceof Date) return new Date(target);
  if (target instanceof RegExp) return new RegExp(target);

  // 3. 检查循环引用：如果已经拷贝过，直接返回
  if (map.has(target)) {
    return map.get(target);
  }

  // 4. 初始化容器（兼容对象和数组）
  const cloneTarget = Array.isArray(target) ? [] : {};

  // 5. 存入 map，标记该对象正在处理中
  map.set(target, cloneTarget);

  // 6. 递归处理每一层属性
  for (const key in target) {
    if (Object.prototype.hasOwnProperty.call(target, key)) {
      // 递归赋值
      cloneTarget[key] = deepClone(target[key], map);
    }
  }

  return cloneTarget;
}
```

---

### 💡 为什么不用 `JSON.parse(JSON.stringify(obj))`？

面试官可能会问：“我用 JSON 一行代码就能深拷贝，为什么要手写？”
**你必须指出它的三个致命缺陷：**
1.  **无法处理循环引用**（会报错：`Converting circular structure to JSON`）。
2.  **数据丢失**：它会忽略 `undefined`、`Symbol` 和 `Function`。
3.  **类型转换错误**：它会把 `Date` 对象转成字符串，把 `RegExp` 转成空对象 `{}`。

---

### 总结给面试官的一段话：
“浅拷贝只是‘搬运’了第一层，深拷贝则是‘克隆’了整个关系网。在实际开发中，如果追求严谨和性能，我会优先考虑成熟的库（如 **Lodash 的 `_.cloneDeep`**），或者在不需要兼容旧浏览器的情况下使用原生 API **`structuredClone()`**。但手写深拷贝的思路体现了对递归控制和内存闭环的底层认知。”
