### 一、 核心问题：什么时候该用 Pinia？

很多初学者容易把所有东西都塞进 Pinia，这会导致代码变得臃肿。你可以记住以下三个原则：

1.  **全局共享的数据：** 多个页面、多个组件都要用的信息。
    *   *例子：* 用户登录后的个人信息（头像、昵称、Token）、权限列表、当前的语言/主题设置。
2.  **跨组件层级太深的数据（解决 Prop Drilling）：**
    *   *场景：* A 组件嵌套 B，B 嵌套 C，C 嵌套 D。如果 D 要用 A 的数据，通过 Props 一层层传太痛苦了。这时候直接用 Pinia。
3.  **需要持久化或缓存的数据：**
    *   *场景：* 用户填了一半的表单、购物车里的商品。即便切了页面再回来，数据还得在。

**反例（不需要用 Pinia）：**
*   只在某一个组件内使用的控制变量（比如一个弹窗的显示隐藏 `isDialogShow`）。这种直接写在组件内部的 `ref` 里就行。

### 二、 Pinia 的核心用法（面试要点）

面试官可能会问：“Pinia 和 Vuex 有什么区别？它由哪几部分组成？”

1.  **三大核心概念：**
    *   **State：** 存放数据的地方（相当于 `data`）。
    *   **Getters：** 对数据进行加工（相当于 `computed`），具有缓存功能。
    *   **Actions：** 修改数据的方法（相当于 `methods`），**支持同步和异步**（这是和 Vuex 最大的区别，Vuex 还要分 Mutation 和 Action，Pinia 把它们合并了）。

2.  **模块化设计：**
    不要把所有状态写在一个 Store 里。应该按功能拆分，比如 `userStore.js`、`cartStore.js`、`configStore.js`。

### 三、 面试必考：解构丢失响应式的问题

这是面试中最喜欢考的细节，如果你能主动说出来，面试官会觉得你基础非常扎实。

*   **坑点：** 如果你直接解构 Pinia 的 state，它会失去响应式。
    ```javascript
    const store = useUserStore()
    const { name } = store // ❌ 这样解构出来的 name 不是响应式的，页面不会随之更新
    ```
*   **解决方法：** 使用 **`storeToRefs`**。
    ```javascript
    import { storeToRefs } from 'pinia'
    const store = useUserStore()
    const { name } = storeToRefs(store) // ✅ 这样解构出来的 name 依然是响应式的
    ```

### 四、 进阶技巧：持久化存储

面试官问：“页面一刷新 Pinia 数据就丢了，你怎么处理？”

*   **回答：** “我会使用插件 **`pinia-plugin-persistedstate`**。只需要在配置里开启 `persist: true`，它就会自动帮我把数据同步到 `localStorage` 中。下次刷新页面时，Pinia 会自动从本地存储里恢复数据。”

### 五、 面试话术模拟

**面试官：** “你在项目里是怎么使用 Pinia 的？为什么选择它而不是传统的组件传参？”

**你的回答：**
> “在我的项目中，我主要用 Pinia 来管理那些**全局性**或者**跨组件通信频繁**的数据。
>
> 比如在处理**用户信息和 Token** 时，我会创建一个 `userStore`。因为几乎每个页面都要校验登录状态或展示用户头像，如果用 Props 传参会非常混乱。
>
> 我之所以选择 Pinia 而不是传统的 Vuex 或者 Event Bus，是因为：
> 1.  **它非常轻量**，对 TypeScript 支持极好。
> 2.  **去掉了 Mutation**，代码更简洁，Actions 同时支持同步和异步。
> 3.  **符合 Vue3 的组合式 API (Composition API)** 风格，上手很快。
>
> 在使用过程中，我也特别注意**解构响应式**的问题，会配合 `storeToRefs` 使用。此外，对于需要持久化的数据，我会配置持久化插件，避免刷新页面导致状态丢失。”

### 给你的建议：

1.  **动手拆分一次：** 把你现在项目里的 Pinia 按照 `user.js`、`settings.js` 这种方式拆开，并在 `index.js` 里统一导出。
2.  **学一下 storeToRefs：** 在代码里写一遍，感受一下加和不加的区别。
3.  **了解一下持久化插件：** 去搜一下 `pinia-plugin-persistedstate` 的配置，非常简单，几行代码就能搞定。

对于 7k 的岗位，你不需要掌握 Pinia 的底层源码，但你必须知道：**为什么用它、怎么解构、怎么做模块化、怎么做持久化。** 掌握这四点，Pinia 这块面试就稳了。加油！
