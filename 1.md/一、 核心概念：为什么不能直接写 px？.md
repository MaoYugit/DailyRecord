### 一、 核心概念：为什么不能直接写 px？

在电脑屏幕上，1px 通常就是 1个物理像素。但在手机上（比如 iPhone），为了让屏幕更细腻，厂家用了“视网膜屏（Retina）”，一个逻辑像素点（CSS 中的 1px）其实对应着 2个甚至 3个物理像素。

**面试必考词：**

*   **物理像素（Physical Pixels）：** 手机屏幕真实的像素点。
*   **逻辑像素（CSS Pixels）：** 我们在代码里写的 px。
*   **设备像素比（DPR）：** 物理像素 / 逻辑像素。
*   **视口（Viewport）：** 简单理解就是手机浏览器的可视区域。

---

### 二、 三大主流适配方案（面试及工作重点）

现在市面上主要有三种做法，你必须都能说出优缺点：

#### 1. Rem 方案（最经典，目前公司用得最多）
*   **原理：** `rem` 是相对于根元素（`html`）的 `font-size` 来计算的。
*   **做法：** 动态计算当前手机屏幕宽度，按比例修改 `html` 的 `font-size`。
*   **例子：** 如果 750px 宽的设计稿，我们设置 `html` 为 `75px`。那么设计稿上一个 `150px` 的盒子，代码里就写 `2rem`。
*   **缺点：** 需要引入一段 JS（如 `amfe-flexible`）来动态计算。

#### 2. Vw/Vh 方案（大势所趋，现代标准）
*   **原理：** `vw` 代表视口宽度的 1%。`100vw` = 整个屏幕宽。
*   **优点：** 不需要写 JS，纯 CSS 解决。
*   **现状：** 现在大部分新项目都推荐用 `vw`。
*   **换算公式：** 如果设计稿是 750px，一个 150px 的元素，对应的 vw 就是 `(150 / 750) * 100 = 20vw`。

#### 3. 响应式布局（Media Queries）
*   **做法：** `@media screen and (max-width: 600px) { ... }`
*   **场景：** 这种方案主要用于“同一套代码适配手机和电脑”，如果只是纯移动端项目，一般不推荐全篇用这个，太累了。

### 三、 实战：如何摆脱手动换算？

面试官会问：“你难道每次都要拿计算器算 150px 等于多少 rem 吗？”
**标准答案：** “我会使用工程化工具，自动把 px 转成 rem 或 vw。”

**你的工具箱：**
*   **PostCSS 插件：** 在项目（Vue/React）里配置 `postcss-pxtorem` 或 `postcss-px-to-viewport`。
*   **效果：** 你在 CSS 里照着设计稿写 `width: 150px;`，打包时工具自动帮你变成 `2rem` 或 `20vw`。

### 四、 移动端适配的“坑” (进阶加分项)

如果你能主动提这几个点，面试官会觉得你很有经验：

1.  **1px 边框问题：** 在 DPR=2 的屏幕上，1px 的边框看起来会比设计稿粗。
    *   *解决方案：* 使用 CSS3 的 `transform: scale(0.5)` 进行缩放。
2.  **图片模糊问题：**
    *   *解决方案：* 准备两倍图（@2x）或三倍图（@3x），或者使用 `srcset`。
3.  **安全区域适配：** 比如 iPhone 的“刘海”和底部的“小黑条”。
    *   *解决方案：* 使用 `viewport-fit=cover` 属性和 CSS 环境变量 `env(safe-area-inset-bottom)`。

这是一个非常经典的问题，很多初学者都会搞混 **rem** 和 **em**。我们先来纠正概念，再看具体配置。

### 1. 概念纠偏：rem 到底相对谁？

你记混了，**rem** 的全称是 **Root EM**。

*   **em**：相对的是**父元素**的 `font-size`。如果父元素没设置，就一直往上找，直到根元素。
*   **rem**：相对的是**根元素**（也就是 `<html>` 标签）的 `font-size`。

**为什么移动端适配用 rem 而不用 em？**
因为 `em` 会发生“嵌套计算”。比如父元素是 1.2倍，子元素也是 1.2倍，孙子元素又是 1.2倍，最后尺寸就乱套了。
而 `rem` 统一盯着 `<html>` 看，全网页的比例是统一的。**你要控制全网页的缩放，只需要改 `<html>` 的一个数字就行。**

---

### 2. 如何统一规定所有 rem 相对的是谁？

要实现自动适配，通常需要 **“两条腿走路”**：

#### 第一步：用 JS 动态改 `<html>` 的字号
你需要一段代码，根据手机屏幕宽度动态计算 `<html>` 的 `font-size`。
最常用的工具是 **`amfe-flexible`**。

*   **原理：** 它会把屏幕分成 10 份。
*   **例子：** 如果手机宽是 375px，它就把 `html` 设置为 `37.5px`。这时候，`1rem` 就等于 `37.5px`。

#### 第二步：用 PostCSS 插件把 px 转成 rem
你在写代码时，还是照着设计稿写 `px`，插件会自动除以一个基准值，转成 `rem`。

---

### 3. 如何配置 `postcss-pxtorem`？

假设你使用的是目前最主流的 **Vue CLI** 或 **Vite** 环境。

#### 安装
```bash
npm install postcss-pxtorem --save-dev
# 如果你用 JS 动态设置字号，还要装这个
npm install amfe-flexible --save
```

#### 项目入口文件 (main.js) 引入
```javascript
import 'amfe-flexible' // 这一步保证了 html 的 font-size 会随屏幕变
```

#### 配置文件 (postcss.config.js)
在项目根目录新建或修改这个文件：

```javascript
module.exports = {
  plugins: {
    'postcss-pxtorem': {
      // 1. 根元素字体大小：这里通常设置为设计稿宽度的 1/10
      // 如果你的设计稿是 750px，这里写 75
      // 如果你的设计稿是 375px，这里写 37.5
      rootValue: 37.5, 
      
      // 2. 允许转换的 CSS 属性
      // ['*'] 表示所有属性（宽、高、边距、字号等）都转成 rem
      propList: ['*'], 
      
      // 3. 过滤掉不需要转化的类名
      // 比如你写了 .ignore { width: 10px; }，它就不会变
      selectorBlackList: ['.ignore'], 
      
      // 4. 最小转化数值。比如写 2，表示小于 2px 的就不转了
      minPixelValue: 2 
    }
  }
}
```

---

### 4. 重点：rootValue 怎么定？

这是最容易让人懵逼的地方。记住这个公式：
**`rootValue` 必须和 `amfe-flexible` 计算出来的比例一致。**

*   **如果设计稿是 750px：** 
    *   `amfe-flexible` 在 750px 的屏幕下会设置 `html` 为 `75px`。
    *   所以你的 `rootValue` 填 **75**。
    *   你在代码里写 `width: 750px`，插件会自动算出 `750 / 75 = 10rem`。
    *   **结果：** 在任何屏幕上，这个元素永远占满全屏（10rem = 100% 宽度）。

*   **如果设计稿是 375px：** 
    *   `rootValue` 填 **37.5**。
    *   代码写 `width: 375px` -> 插件转成 `10rem`。

---

### 5. 面试加分回答（显得你不仅会用，还懂原理）

**面试官：** “说说 postcss-pxtorem 的原理。”

**你的回答：**
> “它的原理很简单，它是在代码**编译阶段**（打包时），利用 PostCSS 遍历所有的 CSS 规则，把我们写的 `px` 单位按照预设的 `rootValue` 进行除法运算，转换成 `rem` 单位。
>
> 比如我的设计稿是 750px，我配置 `rootValue` 为 75。当我写 `margin: 150px` 时，插件会把它转成 `margin: 2rem`。
>
> 到了运行阶段，我配合 `amfe-flexible` 脚本，它会根据当前手机屏幕宽度动态设置 `html` 的 `font-size`。如果是 iPhone 6/7/8（宽度375px），`html` 就会变成 37.5px。
>
> 最终浏览器计算结果是：`2rem * 37.5px = 75px`。这个 75px 刚好是 375px 屏幕的一半，完美还原了 150px 在 750px 设计稿中占一半的比例。”

### 总结
1.  **rem** 相对的是 **html 根元素**。
2.  **配置插件**是为了让你不用手动算数，直接对着设计稿抄 `px`。
3.  **amfe-flexible** 是为了让 `html` 的字号动起来。

**你现在可以试着在你现有的练习项目中配置一下。如果能跑通，你就已经掌握了 90% 的移动端适配工作流程了！**

面试官问 PC 端网页开发，其实考察的重点和移动端完全不同。移动端重点在“适配屏幕”，而 **PC 端重点在“布局方案、组件化和兼容性”**。

如果你的目标是 7k，你不能只说“我会写 HTML/CSS”，你要表现出你对**大型页面结构**和**用户体验**的思考。

以下是针对 PC 端开发的 5 个核心回答维度：

---

### 1. 布局方案（从“切图”升级到“架构”）
不要只说 `float` 或 `position`，要显得你很专业：

*   **话术：** “在 PC 端布局上，我主要采用 **Flex 布局**，因为它在处理垂直居中、等高布局和响应式排列上非常高效。对于一些复杂的、不规则的网格系统，我会使用 **CSS Grid**。”
*   **加分点：** “我会根据设计稿确定页面的**版心宽度**（通常是 1200px 或 1440px）。为了防止在大屏幕下页面拉伸变形，我会给容器设置 `max-width` 并配合 `margin: 0 auto` 实现居中。”

### 2. 响应式与自适应（解决“屏幕大到 27寸，小到笔记本”的问题）
PC 端不是只有一种分辨率，面试官想看你怎么处理不同尺寸的电脑。

*   **话术：** “我会结合 **媒体查询（Media Queries）** 来做响应式处理。比如在 1440px 以上显示四列，在 1200px 以下切换为三列。
*   **加分点：** “我还会利用 **栅格系统（Grid System）**。如果项目使用了 UI 框架（如 Element Plus 或 Ant Design），我会利用它们自带的 `row` 和 `col` 组件，通过 `sm, md, lg` 等断点快速实现自适应。”

### 3. 组件化思维（这是 3k 和 7k 的分水岭）
如果你只是一个页面写到底，那你只值 3k。如果你会拆分组件，你就值 7k。

*   **话术：** “在 PC 端开发中，我非常注重**代码复用**。我会把公共部分抽离成组件，比如：
    *   **通用的 Header/Footer**。
    *   **侧边栏菜单**。
    *   **自定义按钮或搜索表单**。
    这样不仅提高开发效率，以后修改逻辑也只需要改一个地方。”

### 4. 浏览器兼容性（面试必答题）
PC 端绕不开兼容性，虽然现在 IE 已经退休了，但你得表现出你懂这个坑。

*   **话术：** “现在的项目主要适配 Chrome、Safari、Edge 等现代浏览器。对于兼容性，我通常会注意以下几点：
    1.  使用 **Normalize.css** 或 **Reset.css** 统一不同浏览器的默认样式。
    2.  利用 **Autoprefixer** 自动补全 CSS 前缀（如 `-webkit-`）。
    3.  如果遇到老旧浏览器（如要求兼容 IE11），我会注意避开 CSS 原生变量，并使用 Babel 处理 ES6 语法。”

### 5. PC 端的特殊细节（表现你很有经验）
提到这些点，面试官会觉得你“踩过坑”，是个熟练工：

*   **滚动条样式：** “我会对 PC 端的滚动条进行美化，避免系统默认滚动条太丑破坏 UI 设计。”
*   **悬浮效果（Hover）：** “PC 端有鼠标，所以我会给交互元素（按钮、链接）加上明显的 `hover` 态反馈。”
*   **图片优化：** “PC 屏幕大，我会注意图片的清晰度，同时使用**懒加载（Lazy Load）**防止首屏加载过慢。”
