### 一、 核心生命周期与业务场景（按照执行顺序）

#### 1. 初始化阶段：`setup()` (涵盖了原本的 `beforeCreate` / `created`)
*   **执行时机**：组件实例创建之初，props 解析之后，响应式系统建立之时。DOM 还未挂载。
*   **实际开发场景**：
    *   **初始化响应式数据**：定义 `ref` 和 `reactive`。
    *   **非强依赖 DOM 的首屏接口请求**：在这里发请求会比 `onMounted` 更早触发，有助于稍微提前一点获取数据。但要注意，此时拿不到 DOM 节点。
    *   **获取路由参数**：利用 `useRoute()` 拿到参数以便发起查询。

#### 2. 挂载阶段：`onBeforeMount` 与 `onMounted` (极高频)
*   **执行时机**：
    *   `onBeforeMount`：模板编译完成，但还没渲染到真实 DOM。
    *   `onMounted`：**组件挂载完成，真实 DOM 已经存在。**
*   **实际开发场景（重点强调 `onMounted`）**：
    *   **DOM 操作与第三方库初始化**：这是最经典的场景。比如在这里初始化 **ECharts 图表**实例、实例化 **Swiper 轮播图**、或者获取某个 `ref` 绑定的 DOM 元素的宽高（`getBoundingClientRect`）。
    *   **依赖 DOM 的网络请求**：如果你的请求参数需要依据屏幕或某个容器的尺寸，必须在这里发请求。
    *   **绑定全局事件**：例如针对 `window` 绑定 `resize` 或 `scroll` 事件监听。

#### 3. 更新阶段：`onBeforeUpdate` 与 `onUpdated`
*   **执行时机**：响应式数据发生变化，导致虚拟 DOM 重新渲染前后。
*   **实际开发场景**：
    *   **面试高级陷阱（高亮注意）**：在实际开发中，我们**极少直接使用 `onUpdated`**。
    *   **你的回答亮点**：“面试官您好，虽然有 `onUpdated`，但在业务中我很少用它。因为当我们需要对数据变化做出反应并操作 DOM 时，通常会使用 **`watch` 配合 `nextTick`**，或者使用 **`watchPostEffect`**。如果在 `onUpdated` 里直接修改状态，很容易导致无限循环更新的死循环。”
    *   **适用场景**：只适用于一些粗粒度的调试，或者需要对整个组件的 DOM 更新做统一的、非状态修改类的后处理操作。

#### 4. 卸载阶段：`onBeforeUnmount` 与 `onUnmounted` (Vue2 中叫 beforeDestroy/destroyed)
*   **执行时机**：组件实例被卸载之前/之后。
*   **实际开发场景（面试官最爱听的“防坑/优化”经验）**：
    *   **清理工作以防止内存泄漏（核心考点）**：
        1.  **清除定时器**：`clearInterval`、`clearTimeout`。
        2.  **解绑全局事件**：如果在 `onMounted` 中往 `window` 或 `document` 上绑定了 `addEventListener`，必须在这里 `removeEventListener`。
        3.  **销毁第三方实例**：比如离开页面前，调用 `echartsInstance.dispose()` 销毁 ECharts 实例，或者断开 WebSocket 连接。
        4.  **取消全局事件总线（EventBus/Mitt）的订阅**。

### 二、 特殊场景的生命周期（区分中高级开发的试金石）

#### 5. Keep-Alive 专属钩子：`onActivated` 与 `onDeactivated`
*   **背景**：当组件被 `<keep-alive>` 包裹时，切换组件并不会触发 `onUnmounted`，而是被缓存了。
*   **实际开发场景**：
    *   **列表页到详情页的缓存控制**：用户从商品列表（记住浏览位置）进入详情页再退回，列表页不应该重新走 `onMounted`。
    *   `onActivated`：每次进入被缓存的组件时触发。可以用来**刷新页面上必须保持最新的局部数据**（例如获取未读消息数），或者**重置/恢复滚动条位置**。
    *   `onDeactivated`：离开缓存组件时触发。可以用来暂停组件内部的定时轮询，节省性能。

#### 6. 错误捕获：`onErrorCaptured`
*   **执行时机**：捕获一个来自后代组件的错误时被调用。
*   **实际开发场景**：
    *   **前端异常监控与上报**：在应用的根组件（如 `App.vue`）中捕获子组件抛出的异常，防止白屏，并格式化后上报给**Sentry 或内部的日志监控系统**。
    *   可以在此钩子中返回 `false` 来阻止错误继续向上传播。

#### 7. 调试钩子 (Vue 3 新增)：`onRenderTracked` 与 `onRenderTriggered`
*   **执行时机**：仅在开发模式下可用。分别在响应式依赖被收集和被触发时调用。
*   **实际开发场景**：
    *   **性能调优**：当遇到复杂组件莫名其妙地频繁重复渲染时，使用 `onRenderTriggered` 打印出 `event` 对象，精准定位是哪个响应式变量引起了无效渲染。

### 三、 面试官总结提示与追问预判

如果你像上面这样有条理地回答，我会觉得你具备扎实的实战经验。为了进一步考察你的深度，我可能会**追问**：

**追问 1：父子组件的生命周期执行顺序是怎样的？**
*   **你的回答**：这也是经典题，类似于洋葱模型。
    *   **加载过程**：父 `setup` -> 父 `onBeforeMount` -> 子 `setup` -> 子 `onBeforeMount` -> 子 `onMounted` -> 父 `onMounted`。（子组件先挂载完成，父组件才算挂载完成）。
    *   **卸载过程**：父 `onBeforeUnmount` -> 子 `onBeforeUnmount` -> 子 `onUnmounted` -> 父 `onUnmounted`。

**追问 2：如果在 `setup` 中发起异步请求（async/await），会有什么问题？**
*   **你的回答**：如果在 `setup` 顶层使用 `await`，该组件会变成一个**异步组件**。这意味着它的挂载会被阻塞，直到 Promise resolve。此时，**父组件必须用 `<Suspense>` 标签来包裹它**，提供 `fallback` 的加载状态（如 loading 动画），否则该组件将无法渲染。
