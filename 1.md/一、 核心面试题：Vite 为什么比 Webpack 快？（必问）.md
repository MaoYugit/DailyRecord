作为一名目标薪资 7k 的前端，面试官问 Vite，并不是指望你能写出复杂的构建插件，而是看你**是否理解现代前端工具链**，以及**能不能解决实际开发中的配置问题**（比如跨域、路径别名等）。

你可以从这四个维度来准备 Vite 的面试：

---

### 一、 核心面试题：Vite 为什么比 Webpack 快？（必问）

这是面试官最喜欢问的“原理题”。你不需要背代码，只需要记住下面这个形象的对比：

*   **Webpack（冷启动慢）：** 它像是一个严谨的管家。在你改代码之前，它必须把**所有代码**（包括你没改的部分、几十个第三方库）打包成一个巨大的文件，然后才能启动服务器。项目越大，打包越久。
*   **Vite（秒开）：** 它像是一个聪明的按需分发员。
    1.  **利用了原生 ESM（ES Modules）：** 现代浏览器（Chrome/Edge）本身就支持 `import` 语法。Vite 启动时**不打包**，浏览器请求哪个文件，它才实时处理哪个文件并发给浏览器。
    2.  **esbuild 预构建：** Vite 用 Go 语言写的 `esbuild` 来处理那些不怎么变动的第三方库（比如 Vue、Axios），速度比 Webpack 快几十倍。

**面试话术：**
> “Vite 快的原因主要有两个：一是它利用了浏览器的 **原生 ESM**，在开发环境省去了打包的过程，实现了‘按需加载’；二是它在处理第三方依赖时使用了 **esbuild** 进行预构建，性能比传统的 Webpack 高出很多。”

---

### 二、 你在项目中是怎么配置 Vite 的？（实战题）

面试官想看你是否真的动过 `vite.config.js` 文件。你至少要能说出以下三个常用配置：

#### 1. 配置路径别名（Alias）
每次写 `../../../components/MyButton.vue` 太痛苦了。
*   **配置后：** 可以写成 `@/components/MyButton.vue`。
*   **代码长这样：**
    ```javascript
    resolve: {
      alias: {
        '@': path.resolve(__dirname, 'src')
      }
    }
    ```

#### 2. 配置跨域代理（Server Proxy）—— **重中之重**
做项目必然会遇到跨域问题。你需要告诉面试官你是怎么在 Vite 里解决的。
*   **话术：** “在开发环境下，我会配置 `server.proxy`。当前端请求以 `/api` 开头时，让 Vite 帮我转发到后端的服务器地址，从而绕过浏览器的同源策略。”
*   **配置：**
    ```javascript
    server: {
      proxy: {
        '/api': {
          target: 'http://localhost:8080', // 后端地址
          changeOrigin: true,
          rewrite: (path) => path.replace(/^\/api/, '')
        }
      }
    }
    ```

#### 3. 自动导入插件（提升效率的利器）
如果你能提到这个，面试官会觉得你很关注开发体验。
*   **插件：** `unplugin-auto-import`。
*   **作用：** 以前每个文件都要写 `import { ref, reactive } from 'vue'`，配了这个插件就不用写了，直接用。

### 三、 生产环境用的是什么？

面试官可能会追问：“既然 Vite 不打包，那上线怎么办？”
*   **回答：** “Vite 在生产环境下依然会进行打包，它使用的是 **Rollup**。因为虽然现代浏览器支持 ESM，但在生产环境，为了减少网络请求次数和进行代码压缩，打包依然是必须的。”

### 四、 针对 7k 薪资的面试话术总结

**面试官：** “说说你对 Vite 的了解，你在项目里怎么用它？”

**你的回答：**
> “我目前的项目都是基于 Vite 构建的。
>
> 首先，我非常认可它的**开发体验**。相比 Webpack，它的**热更新（HMR）**速度极快，几乎是秒级的。这主要得益于它利用了浏览器的原生 ESM 机制。
>
> 在具体配置方面，我通常会在 `vite.config.js` 中做以下几件事：
> 1.  **配置路径别名**，用 `@` 指向 `src` 目录，简化导入路径。
> 2.  **配置开发服务器的 Proxy 代理**，解决前端开发时的跨域问题，确保能正常调用后端接口。
> 3.  **集成一些常用的插件**，比如 `unplugin-vue-components` 实现组件自动按需引入，减少样板代码。
> 4.  **优化打包配置**，比如通过 `build.terserOptions` 去掉生产环境的 `console.log`，减小包体积。”

---

### 一、 生产环境打包：你怎么把代码给公司？

你平时开发运行的是 `npm run dev`，那是给开发看的（有热更新、不压缩代码）。
真正要上线的代码，需要经过**打包**。

1.  **怎么打？**
    在终端输入：`npm run build`。
    这个命令实际上运行的是 `vite build`。

2.  **打完后发生了什么？**
    *   Vite 会调用 **Rollup**（这是它的打包引擎）把你的 Vue、JS、CSS 全部压缩混淆。
    *   项目根目录下会出现一个 **`dist`** 文件夹。
    *   **重点：** 你只需要把这个 `dist` 文件夹交给后端或运维，他们放到服务器上，用户就能访问了。

3.  **面试加分点：**
    面试官问：“Vite 生产环境怎么处理？”
    **你的回答：** “我会运行 `npm run build`，Vite 会利用 **Rollup** 进行构建。它会进行 **Tree-shaking**（摇树优化，把没用的代码删掉）、代码压缩和分包，最后生成 `dist` 静态资源目录。”

---

### 二、 区分开发和生产环境：为什么需要它？

想象一下，你请求接口的地址：
*   **开发时：** 接口地址可能是 `http://192.168.1.100:8080/api`（你同事的电脑）。
*   **上线后：** 接口地址可能是 `https://www.company.com/api`（真正的服务器）。

**你总不能上线前手动去代码里一个一个改地址吧？** 万一改错了就完了。所以我们要“自动切换”。

---

### 三、 如何配置环境区分（实战操作）

Vite 使用 **`.env` 文件** 来管理这些变量。

#### 1. 创建两个文件（在项目根目录）
*   新建文件：`.env.development` （写开发环境的配置）
*   新建文件：`.env.production` （写生产环境的配置）

#### 2. 在文件里写内容
**注意：变量名必须以 `VITE_` 开头！**

`.env.development`：
```text
VITE_API_URL = 'http://test-api.com'
VITE_APP_TITLE = '我的项目(开发版)'
```

`.env.production`：
```text
VITE_API_URL = 'https://api.real-production.com'
VITE_APP_TITLE = '我的项目(正式版)'
```

#### 3. 在代码里怎么用？
在你的 Axios 封装文件或页面里，这样写：
```javascript
// Vite 会根据你运行的是 dev 还是 build，自动选择对应的地址
const baseURL = import.meta.env.VITE_API_URL; 

console.log(import.meta.env.VITE_APP_TITLE); 
```

---

### 四、 在 `vite.config.js` 中如何判断？

有时候，你不仅要在代码里用，还要在配置文件里区分环境（比如生产环境删掉 `console.log`，开发环境不用）。

**配置方法：**
```javascript
import { defineConfig, loadEnv } from 'vite'

export default defineConfig(({ command, mode }) => {
  // 根据当前工作目录中的 `mode` 加载 .env 文件
  const env = loadEnv(mode, process.cwd())

  return {
    // Vite 配置
    define: {
      __APP_ENV__: JSON.stringify(env.APP_ENV),
    },
    build: {
      // 如果是生产环境，打包时去掉 console
      minify: 'terser',
      terserOptions: {
        compress: {
          drop_console: command === 'build', // 只有打包时才删 console
          drop_debugger: true,
        },
      },
    },
  }
})
```

**面试官：** “你是如何处理开发环境和生产环境配置的？”
