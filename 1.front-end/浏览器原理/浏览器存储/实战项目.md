### 🚀 项目名称：Secure-Note (Web端安全离线笔记)

#### 🛠️ 技术栈建议
*   **前端**：Vue 3 + 原生 JS (为了练习 Storage API)。
*   **后端**：Node.js (Express )。**理由**：可以亲手写 `res.cookie()`，最直观地理解 HttpOnly 和 SameSite。

---

#### 📚 核心需求拆解（满足“每种存储 3 个应用场景”）

我们把功能强行拆分到不同的存储方式上，虽然在实际生产中可能不会分得这么细，但为了**教学演练**，这样设计最完美：

### 1. Cookie —— 身份与安全 (与后端强交互)
**场景 A：HttpOnly 的鉴权 Token (JWT)**
*   **功能**：用户登录后，后端通过 `Set-Cookie` 下发 Token，设置 `HttpOnly` 和 `Secure`。
*   **目的**：练习后端如何种 Cookie，前端如何“看不见”但能自动携带它请求接口。

**场景 B：用户追踪 / AB测试分组**
*   **功能**：后端给用户打一个标记（比如 `group=A`），前端 JS 可以读取（非 HttpOnly），用于统计。
*   **目的**：练习 JS 读取 `document.cookie`，并与 HttpOnly Cookie 做对比。

**场景 C：CSRF Token (双重 Cookie 验证模式)**
*   **功能**：后端除了发 HttpOnly Token，还发一个允许 JS 读取的 `csrf_token`。前端发 POST 请求时，需手动从 Cookie 读出来放到 Header 里。
*   **目的**：实战防御 CSRF 攻击，理解为什么有了 HttpOnly 还需要 JS 读 Cookie。

---

### 2. LocalStorage —— 偏好设置与持久化
**场景 A：草稿箱 (Draft Auto-save)**
*   **功能**：当用户正在打字但还没点击“保存”时，每隔 5 秒把内容存入 LocalStorage。如果用户意外关闭浏览器，下次打开自动恢复内容。
*   **目的**：练习 `setItem/getItem` 和 JSON 序列化。

**场景 B：主题色与布局 (Theme & Layout)**
*   **功能**：切换“暗黑模式”或“侧边栏收起/展开”。刷新页面后保持状态。
*   **目的**：理解 LocalStorage 的同步阻塞特性（防止页面闪烁）。

**场景 C：用户不感兴趣的弹窗 (Do Not Show Again)**
*   **功能**：首页有个“新手指引”，用户点击“不再提示”后，记录一个 Boolean 值。
*   **目的**：练习简单的逻辑判断和布尔值存储陷阱。

---

### 3. SessionStorage —— 临时状态与流
**场景 A：单次会话的浏览历史 (Breadcrumb)**
*   **功能**：记录用户在这个标签页内看过的笔记路径（如：首页 -> 文件夹A -> 笔记B）。关闭标签页后清空。
*   **目的**：区分 Tab 隔离性，练习 SessionStorage。

**场景 B：敏感数据的“一次性剪贴板”**
*   **功能**：点击“生成分享链接”，链接只在屏幕上显示一次，存在 SessionStorage 里。刷新页面或新开 Tab 就没了。
*   **目的**：体验 SessionStorage 的生命周期。

**场景 C：搜索条件暂存**
*   **功能**：在笔记列表页输入了复杂的搜索过滤条件，点进详情页再返回时，搜索条件还在；但新开一个窗口去搜，条件是空的。
*   **目的**：典型的 SessionStorage 场景。

---

### 4. IndexedDB —— 离线内容与多媒体
**场景 A：笔记全量离线缓存**
*   **功能**：登录后，把后端返回的所有笔记列表（JSON）存入 IndexedDB。断网时，直接从 IndexedDB 读数据展示。
*   **目的**：练习 IndexedDB 的异步读取和结构化存储。

**场景 B：图片/附件的本地存储 (Blob)**
*   **功能**：用户在笔记里粘贴一张截图，图片不立刻传给服务器（为了省流量），而是先以 Blob 二进制形式存在 IndexedDB，点击“同步”后再上传。
*   **目的**：练习存储 Blob 二进制数据（LocalStorage 做不到的核心点）。

**场景 C：全文检索索引 (Search Index)**
*   **功能**：为了实现毫秒级搜索，将所有笔记的标题和正文拆词，建立一个简单的倒排索引存在 IndexedDB 中。
*   **目的**：练习 IndexedDB 的索引（Index）查询功能。

---

### 🏗️ 项目架构图（简述）

1.  **Server (Node.js)**
    *   API: `/login` (Set-Cookie)
    *   API: `/notes` (Get/Post Data)
    *   Middleware: 校验 Cookie, 设置 CORS (跨域允许带 Cookie)

2.  **Client (Frontend)**
    *   **Auth Module**: 处理登录，拦截 401，引导跳转。
    *   **StorageHelper**: 我们之前封装的 LocalStorage 类。
    *   **DBHelper**: 封装 Dexie.js 或原生 IndexedDB 操作。
    *   **SyncManager**: 负责把 IndexedDB 的数据和后端 API 同步。
