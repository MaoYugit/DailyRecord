## 🔵第一阶段：核心原理与词法作用域。

很多教程一上来就背定义，导致大家觉得“闭包”很玄学。其实，闭包不是什么魔法，它是 **JavaScript 词法作用域（Lexical Scoping）** 规则下的自然产物。

我们先不管“闭包”这两个字，先看两个核心概念。

---

### 1. 词法作用域：代码写在哪，决定了能访问谁

这是理解闭包的**前提**。

*   **规则**：函数能访问哪些变量，取决于**函数声明（定义）的位置**，而不是函数**调用**的位置。
*   **通俗说**：函数出生在哪里，它就属于哪个圈子，就能访问那个圈子里的资源。不管它后来被卖到了哪里去执行，它依然记得它的“老家”。

#### 🌰 例子 A：认祖归宗
```javascript
let name = "全局";

function outer() {
    let name = "内部";
    
    function inner() {
        console.log(name);
    }
    
    return inner;
}

const myFunc = outer(); // myFunc 现在就是 inner 函数
myFunc(); // 输出什么？
```

> **答案**：输出 `"内部"`。
> **原因**：虽然 `myFunc` 是在全局作用域下**调用**的，但 `inner` 函数是**定义**在 `outer` 里面的。根据词法作用域，它向外查找变量时，第一站是 `outer` 的作用域，那里有 `name = "内部"`。

---

### 2. 闭包的本质：带着“背包”的旅行者

现在我们来定义闭包。

当一个函数 `inner` 被 `outer` 函数返回，并且在 `outer` 函数外部被使用时，`outer` 函数明明已经执行完了（出栈了），为什么 `inner` 还能访问 `outer` 里的变量？

**因为 `inner` 函数在出生时，身上背了一个“背包”。**

*   **背包里装了什么？**：装了它定义时所在作用域的所有变量（即 `outer` 里的变量）。
*   **官方定义**：闭包 = 函数 + 该函数能够访问的周边环境（词法环境）。
*   **我的定义**：闭包就是**一个函数**加上**它记住了的老家变量**。

#### 💻 核心代码图解
```javascript
function createCounter() {
    let count = 0; // 这个 count 就是“老家”的变量

    function add() {
        count++; // add 函数引用了“老家”的 count
        console.log(count);
    }

    return add; // 把 add 函数交出去
}

const counter = createCounter(); 
// 此时 createCounter 执行完毕，按理说 count 变量应该被销毁（垃圾回收）。
// 但是！因为 counter (也就是 add) 还背着引用，所以 count 被保住了。

counter(); // 输出 1
counter(); // 输出 2
```

> **图解内存**：
> 1.  `createCounter` 执行完，本该销毁作用域。
> 2.  但 JS 引擎发现：哎哟，返回的 `add` 函数身上有一根“隐形的线”连着 `count` 变量。
> 3.  **结果**：`createCounter` 的壳子销毁了，但 `count` 变量被**留在了堆内存中**，专门供 `counter` 函数独享。

---

### 3. 闭包的两大特征（判断是否是闭包）

在代码中看到这种情况，那就是闭包：

1.  **函数嵌套**：外部函数里定义了内部函数。
2.  **引用外部变量**：内部函数使用了外部函数的变量。
3.  **保留引用**：内部函数被返回或保存到了外部（导致外部环境无法被释放）。

---

### 4. 深入理解：是“引用”不是“快照”

这是一个非常重要的细节，很多初学者会搞错。
**闭包“背包”里装的变量，是活的引用，不是死的快照。**

```javascript
function outer() {
    let num = 10;
    
    function get() {
        console.log(num);
    }
    
    function add() {
        num++;
    }
    
    return { get, add };
}

const instance = outer();

instance.get(); // 10
instance.add(); // num 变成了 11
instance.get(); // 11 (看到没？闭包里的变量是可以被修改的！)
```
> 这说明闭包里的变量和普通变量一样，是**动态**的。

---

### 🔍 第一阶段总结

1.  **词法作用域**：函数能访问哪些变量，由它**写在哪里**决定，跟在哪里调用无关。
2.  **闭包**：当内部函数被拿到外部去执行时，它依然持有对原作用域变量的引用。
3.  **内存机制**：本来该被垃圾回收的局部变量，因为被闭包“抓着不放”，所以一直存活在内存中。

---

**🔥 第一阶段测试题：**
请看下面的代码，回答输出什么？（不要运行，试着脑补）

```javascript
let a = 1;
function fn1() {
  console.log(a);
}

function fn2() {
  let a = 2;
  fn1();
}

fn2();
```
思考一下 `fn1` 在哪里定义的？它能看到 `fn2` 里的 `a` 吗？

我们将用这道题引出面试中最经典的**循环陷阱**！

> **解析**：`fn1` 是在**全局作用域**定义的。根据词法作用域规则，它查找变量 `a` 时，只会去它**出生的地方**（全局）找，根本看不到 `fn2` 内部的变量。记住：**函数的作用域链在定义时就确定了，跟在哪里调用无关。**

## 🔵 第二阶段：经典面试题——循环与变量陷阱

这一阶段我们要攻克一道出现率高达 99% 的面试题。如果你面试过前端，你一定见过它；如果你还没面试过，那你必须背下来。

### 1. ☠️ 死亡陷阱：`for` 循环与 `setTimeout`

**题目**：下面的代码会输出什么？

```javascript
for (var i = 1; i <= 5; i++) {
    setTimeout(function() {
        console.log(i);
    }, 1000);
}
```

**新手直觉**：`1, 2, 3, 4, 5`（每隔一秒输出来）。
**实际结果**：**`6, 6, 6, 6, 6`** （一秒后瞬间同时输出 5 个 6）。

### 2. 🔍 为什么会翻车？

这里有两个核心原因叠加：
1.  **`var` 的作用域问题**：`var` 定义的变量没有块级作用域（Block Scope），只有函数作用域。在这里，`i` 实际上是一个**全局变量**。整个循环只有**一个** `i`。
2.  **JS 的异步机制**：`setTimeout` 是异步的。它会等主线程代码（也就是那个 `for` 循环）全部跑完，才会去执行回调函数。

**过程还原**：
*   循环开始狂奔：`i` 从 1 变到 2...一直变到 6（导致循环结束）。
*   此时设定了 5 个定时器，它们都拿着同一个引用——那个全局的 `i`。
*   1 秒后，定时器开始执行：大家回头一看，`i` 早就变成 6 了。
*   结果：大家都打印 6。

---

### 3. ✅ 解决方案一：利用闭包（IIFE）—— 老派解法

在 ES6 之前，我们需要人为制造一个作用域来“锁住”当前的 `i`。最常用的就是 **IIFE（立即执行函数表达式）**。

```javascript
for (var i = 1; i <= 5; i++) {
    // 创建一个立即执行函数，把当前的 i 当作参数 j 传进去
    (function(j) {
        setTimeout(function() {
            console.log(j);
        }, 1000);
    })(i);
}
```

**原理分析**：
*   每次循环，我们都定义并立马执行了一个新函数。
*   我们将当前的 `i`（比如 1）作为参数传给函数，参数 `j` 就变成了这个函数内部的局部变量。
*   `setTimeout` 里的闭包引用的是**当前这一轮函数的局部变量 `j`**，而不是那个全局的 `i`。
*   虽然全局 `i` 还在变，但我背包里的 `j` 是 1（因为基本类型传参是**值复制**）。

---

### 4. ✅ 解决方案二：使用 `let` —— 现代解法（推荐）

ES6 的 `let` 简直是为此而生的。

```javascript
for (let i = 1; i <= 5; i++) { // 把 var 改成 let
    setTimeout(function() {
        console.log(i);
    }, 1000);
}
```

**原理分析**：
*   `let` 拥有**块级作用域**（Block Scope）。
*   在 `for` 循环中使用 `let`，JS 引擎会为**每一次循环**都创建一个**全新的、独立的**变量 `i`。
*   第一次循环的 `i` 是 1，第二次循环的 `i` 是 2... 它们互不干扰，住在不同的内存地址里。
*   闭包引用的就是属于它那一轮的那个 `i`。

---

### 5. 🛠️ 变体考法（面试官追问）

**追问 1**：如果我想每隔 1 秒输出一个数（即：第 1 秒输 1，第 2 秒输 2...），代码怎么改？

**回答**：
单纯解决闭包问题只能保证输出 `1,2,3,4,5`，但它们是同时出来的（因为定时器都是 1000ms）。要产生间隔，需要修改定时器的时长。

```javascript
for (let i = 1; i <= 5; i++) {
    setTimeout(function() {
        console.log(i);
    }, i * 1000); // 时间变成 1000, 2000, 3000...
}
```

**追问 2**：不用 `let` 也不用 IIFE，有没有第三种办法？（考查 API 熟悉度）

**回答**：
利用 `setTimeout` 的第三个参数（它会作为参数传给回调函数）。

```javascript
for (var i = 1; i <= 5; i++) {
    // 第三个参数 i 会被拷贝一份，传给回调函数的第一个参数
    setTimeout(function(num) {
        console.log(num);
    }, 1000, i); 
}
```

---

### 🔍 第二阶段总结

1.  **现象**：`for` 循环 + `var` + 异步 = 灾难（所有闭包共享同一个最终变量）。
2.  **原理**：闭包引用的是变量的**最终状态**，除非你为每一轮循环创建一个独立的作用域。
3.  **解法**：
    *   **IIFE**：函数传参（值拷贝）来保存快照。
    *   **let**：块级作用域，自动为每轮循环生成新变量。

## 🔵 **第三阶段：闭包实战——手写防抖与节流**。

这是闭包在前端开发中最经典、最高频的应用场景。
**面试官潜台词**：

1.  “你会不会用闭包解决实际问题？”
2.  “你懂不懂高阶函数？”
3.  “你的 `this` 指向搞得清吗？”

---

### 1. 热身：利用闭包实现“私有变量”

在手写复杂逻辑前，先看一个最简单的闭包模型。这也是 Java/C++ 程序员转 JS 时最喜欢用的模式。

**需求**：我想做一个计数器，但我不想把 `count` 变量放在全局（怕被别人乱改）。

```javascript
function createCounter() {
    let count = 0; // 【核心】这就是那个“背包”里的私有变量

    return {
        add: function() {
            count++;
            console.log(count);
        },
        minus: function() {
            count--;
            console.log(count);
        },
        get: function() {
            return count;
        }
    };
}

const counter = createCounter();
counter.add(); // 1
counter.add(); // 2
// counter.count // undefined (外界无法直接访问 count，安全！)
```

**原理**：`count` 被 `add` 和 `minus` 函数共同引用，它一直存在于内存中，但外界访问不到，实现了**封装**。

---

### 2. 防抖 (Debounce) —— “最后一个人说了算”

#### 🟢 概念与场景
*   **场景**：搜索框输入（用户打字 `abc`，不希望每打一个字母都发请求，而是等用户停下来才发）、窗口调整大小（resize）。
*   **通俗比喻**：**坐电梯**。
    *   你进电梯，门准备关（计时 2 秒）。
    *   突然又跑进来一个人，电梯门重新打开，**重新倒计时** 2 秒。
    *   如果一直有人进来，电梯就一直不走。
    *   直到 2 秒内没人进来了，电梯才关门出发。

#### 💻 手写代码（面试背诵版）

面试官让你写防抖，其实就是让你写一个**利用闭包保存定时器 ID** 的函数。

```javascript
// fn: 要执行的函数 (比如发请求)
// delay: 等待时间 (比如 500ms)
function debounce(fn, delay) {
    let timer = null; // 【核心】闭包变量，用来保存定时器 ID

    // 返回的新函数，就是绑定给 DOM 事件的函数
    return function(...args) {
        // 1. 如果之前有定时器（说明上次操作还没结束），赶紧把上次的取消掉
        if (timer) clearTimeout(timer);

        // 2. 重新设定一个新的定时器
        // 这里的箭头函数是为了让内部的 this 指向正确（指向调用者，如 input 元素）
        timer = setTimeout(() => {
            // 3. 时间到了，终于可以执行真正的逻辑了
            fn.apply(this, args); 
        }, delay);
    };
}
```

#### 🧪 验证一下

```javascript
// 模拟发请求的函数
function search(keyword) {
    console.log("发起请求：" + keyword);
}

// 包装一下，得到具有防抖功能的函数
const debouncedSearch = debounce(search, 1000);

// 模拟用户快速输入
debouncedSearch("a");
debouncedSearch("ab");
debouncedSearch("abc");

// 结果：前两次的定时器都被 clearTimeout 杀死了。
// 只有最后一次 "abc" 会在 1 秒后打印出来。
```

---

### 3. 节流 (Throttle) —— “不管你多快，我就按这个频率来”

#### 🟢 概念与场景
*   **场景**：页面滚动（scroll）、鼠标移动（mousemove）、抢购按钮（疯狂点击）。
*   **通俗比喻**：**机关枪开火**。
    *   不管你按扳机的手速有多快（一秒按 100 次）。
    *   机关枪的射速是固定的（比如每 0.5 秒发一颗子弹）。
    *   在冷却时间内，你按也是白按。

#### 💻 手写代码（定时器版）

面试官让你写节流，其实就是利用闭包保存一个 **“锁” (Lock)** 标志。

```javascript
function throttle(fn, delay) {
    let timer = null; // 【核心】闭包变量，充当“锁”的角色

    return function(...args) {
        // 1. 如果 timer 有值，说明“锁”是锁住的（正在冷却中）
        // 直接返回，什么都不做
        if (timer) return;

        // 2. 只有没锁的时候，才设立定时器
        timer = setTimeout(() => {
            // 3. 时间到了，执行逻辑
            fn.apply(this, args);

            // 4. 【关键】执行完后，把锁打开（置为 null），允许下一次执行
            timer = null; 
        }, delay);
    };
}
```

*(注：节流还有一种“时间戳版”，但在面试中写出这个“定时器版”通常就够了，逻辑更符合“锁”的直觉)*

#### 🧪 验证一下

```javascript
function shoot() {
    console.log("开枪！");
}

const throttledShoot = throttle(shoot, 1000); // 1秒一次

// 模拟疯狂点击
setInterval(() => {
    throttledShoot();
}, 100); // 每 100ms 点一次

// 结果：虽然你点得很快，但控制台依然是稳稳地 每隔 1 秒 输出一次 "开枪！"
```

---

### 4. 🔍 为什么这必须用闭包？

面试官可能会问：**“为什么要把 `timer` 定义在外面，而不直接定义在返回的函数里面？”**

**错误写法（没有闭包）：**
```javascript
function debounce(fn, delay) {
    // 没用闭包
    return function() {
        let timer = null; // ❌ 每次调用都重新定义了 timer = null
        if (timer) clearTimeout(timer); // 永远清除不了上次的，因为 timer 总是新的
        timer = setTimeout(fn, delay);
    };
}
```

**你的回答**：
> “如果不利用闭包将 `timer` 保存在外部作用域，那么每次触发事件时，`timer` 都会被重新初始化为 `null`。
> 我们需要一个**跨越多次函数调用依然存在**的变量来记录上一次定时器的状态，这就是闭包的核心作用。”

---

### 5. 面试中的加分细节

如果面试官让你手写，注意以下两个细节（我在上面的代码里已经写了），能体现你的专业度：

1.  **`...args` (剩余参数)**：
    用户的事件回调通常会有参数（比如 `event` 对象）。
    `function(...args)` 能接收所有参数，并通过 `fn.apply(this, args)` 透传给原函数。

2.  **`this` 指向**：
    在 DOM 事件中，`this` 通常指向触发事件的元素（比如 `<input>`）。
    使用 `fn.apply(this, args)` 是为了保证原函数里的 `this` 依然指向该元素，而不是指向 Window。

---

### 📝 第三阶段总结

*   **闭包实战**：核心在于用一个外部函数的局部变量（背包）来存储**状态**（定时器 ID 或 锁的状态）。
*   **防抖 (Debounce)**：**清零重置**。只要你还在动，我就不执行。适合输入框。
*   **节流 (Throttle)**：**加锁冷却**。不管你动多快，我按节奏来。适合 Scroll/Resize。

## **🔵第四阶段：进阶应用——柯里化与 Vue 3 的闭包本质**。

---

### 🟢 1. 函数柯里化 (Currying) —— 面试装逼利器

这是前端面试中“高阶函数”板块的必考题。无论你用 Vue 还是 React，面试官都爱问。

#### 1.1 什么是柯里化？

简单说，就是把“一次接受多个参数的函数”，变成“多次接受单个参数的函数”。

*   **普通形式**：`add(1, 2, 3)`
*   **柯里化形式**：`add(1)(2)(3)`

#### 1.2 💡 核心疑问：为什么要这样写？

说实话，90% 的初学者看到 `add(1)(2)(3)` 这种代码时，内心都是崩溃的：“明明 `add(1, 2, 3)` 就能解决，非要写这么多括号，这不是脱裤子放屁吗？”

**你是对的：如果只是为了计算 1+2+3，柯里化确实毫无意义。**

柯里化的真正威力不在于简单的数学计算，而在于 **“参数复用”** 和 **“定制化工具函数”**。把它想象成 **“生产流水线”** 或者 **“模具”** 就好理解了。

---

#### 1.3 实战场景一：通用函数变专用 (表单验证)

假设你在做一个表单验证功能，你需要验证：用户名是不是纯文本？手机号是不是数字？

**❌ 不用柯里化（普通写法）**

你需要写一个超级通用的正则验证函数，每次调用都要传两个参数：**正则规则** 和 **要验证的内容**。

```javascript
function check(reg, text) {
    return reg.test(text);
}

// 痛点：每次都要重复传正则，很烦，而且容易写错
check(/\d+/, '13800000000'); // 验证手机
check(/\d+/, '13912345678'); // 验证手机
check(/[a-z]+/, 'jerry');     // 验证名字
```

**✅ 使用柯里化（工厂模式写法）**

我们利用柯里化（闭包），把 **“正则规则”** 这个参数提前锁死（固定下来），生成一个个 **“专用验证函数”**。

```javascript
// 柯里化函数：第一层接收正则，返回一个新函数
function createChecker(reg) {
    // 闭包记住了 reg
    return function(text) {
        return reg.test(text);
    }
}

// 1. 生产工具（定制化）
const isNumber = createChecker(/\d+/);      // 专门验数字的函数
const isString = createChecker(/[a-z]+/);   // 专门验字符串的函数

// 2. 实际使用（这时候只需要传一个参数了，语义非常清晰）
isNumber('13800000000'); // true
isString('jerry');       // true
```

---

#### 1.4 实战场景二：Vue 项目中的 API 请求封装

这是你在 Vue 开发中 100% 会遇到的场景。

**❌ 普通写法**

每次发请求都要写一遍域名，非常冗余。

```javascript
function request(protocol, domain, path) {
    return `${protocol}://${domain}${path}`;
}

const url1 = request('https', 'api.myapp.com', '/users');
const url2 = request('https', 'api.myapp.com', '/login');
```

**✅ 柯里化写法**

我们可以把“公共参数”（域名）提取出来，通过柯里化提前固定好。

```javascript
// 柯里化：第一层传基础地址
function createApi(baseUrl) {
    // 闭包锁死 baseUrl
    return function(path) {
        return `${baseUrl}${path}`;
    }
}

// 1. 生成一个专门针对 myapp 的请求生成器
const myAppApi = createApi('https://api.myapp.com');

// 2. 以后用的时候，只管具体的路径就行了
const url1 = myAppApi('/users');
const url2 = myAppApi('/login');
```

---

#### 1.5 🚀 总结：柯里化的本质

不要把柯里化看作是 `add(1)(2)(3)`，那是为了考试。在实际工程中，柯里化就是 **“参数预设”**：

1.  我有 3 个参数 `(a, b, c)`。
2.  参数 `a` 和 `b` 在很多地方都是一样的（比如公用的正则、公用的 URL 前缀）。
3.  那我先传 `a` 和 `b`，生成一个 **“半成品函数”**。
4.  以后我只需要传参数 `c` 给这个“半成品函数”，它就能跑起来了。

**一句话解释：**
柯里化就是让函数的职责更单一，通过“预加载”参数，让后续的调用代码写得更少、读得更爽。

#### 1.6 💻 面试手写题：实现 add(1)(2)(3)

这是利用闭包最典型的“俄罗斯套娃”结构。

```javascript
// 普通写法
function add(a, b, c) {
    return a + b + c;
}

// 柯里化写法 (利用闭包记住每一层的参数)
function curryAdd(a) {
    // 第一层闭包：记住了 a
    return function(b) {
        // 第二层闭包：记住了 a 和 b
        return function(c) {
            // 第三层：利用之前记住的所有变量进行计算
            return a + b + c;
        }
    }
}

// 箭头函数极简版 (面试写这个最帅)
const curryAddArrow = a => b => c => a + b + c;

console.log(curryAdd(1)(2)(3)); // 6
```

### 🟢 2. Vue 3 Composition API 的闭包本质

如果你用过或学过 Vue 3，你肯定见过 `setup` 或者 `<script setup>`。
**其实，Composition API 的核心原理就是闭包。**

#### 对比 Vue 2 (Options API) vs Vue 3
*   **Vue 2 (`data`, `methods`)**：
    依靠 `this` 上下文。所有属性挂载在 `this` 上。这其实**不是**闭包，而是对象属性访问。
*   **Vue 3 (`setup`)**：
    依靠**闭包**。

#### 🌰 Vue 3 的 Hook (Composable) 其实就是闭包

我们来看一个标准的 Vue 3 计数器逻辑（Composable）：

```javascript
// useCounter.js
import { ref } from 'vue';

export function useCounter() {
    // 1. 定义局部变量 (这就是闭包里的“背包”变量)
    const count = ref(0);

    // 2. 定义操作函数 (引用了上面的局部变量)
    const increment = () => {
        count.value++;
    };

    // 3. 返回出去 (让外部组件能访问这些内部变量)
    return {
        count,
        increment
    };
}
```

**解析**：
这不就是我们在**第一阶段**学的 `createCounter` 吗？
1.  `useCounter` 执行，创建了一个作用域。
2.  `count` 是局部变量。
3.  `increment` 函数引用了 `count`。
4.  最后 `return` 出去，导致 `useCounter` 执行完了，`count` 依然不销毁。

**结论**：
Vue 3 抛弃 `this` 拥抱 Composition API，其实就是拥抱了 JS 的词法作用域和闭包能力。这样做的好处是**代码压缩更方便**（变量名可以被压缩成 `a`, `b`，而 `this.something` 的属性名很难压缩）。

### 🟢 3. 实际业务场景：偏函数 (Partial Application)

在 Vue 模板中，闭包也有妙用。
假设你有一个列表，点击每一项要删除它。

#### 场景：列表点击传参

```vue
<template>
  <div v-for="(item, index) in list" :key={item.id}>
    <!-- 方式 A: 直接传参 -->
    <button @click="deleteItem(index)">删除</button>
  </div>
</template>

<script>
export default {
  methods: {
    deleteItem(index) {
      console.log('删除第几个：', index);
    }
  }
}
</script>
```

#### 进阶：如果不想在模板里写括号 `()` 怎么办？
有时候我们需要在 JS 里提前把参数“绑死”，这就是闭包的用武之地（类似 `bind` 的效果）。

```javascript
// JS 逻辑生成闭包函数
function createDeleteHandler(index) {
    // 返回一个函数，这个函数才是真正的事件处理函数
    return function() {
        console.log('删除索引：', index); // 闭包锁死了 index
    };
}

// 此时 handler 就是一个记住了 index 的闭包
const handler = createDeleteHandler(5);
handler(); // 删除索引：5
```

### 🔍 第四阶段总结

1.  **柯里化**：`fn(a)(b)(c)`。利用多层闭包，一层层收集参数，最后再计算。
2.  **Vue 3 原理**：`setup()` 就是一个大闭包函数，它里面的 `ref/reactive` 变量之所以能一直存在且响应，就是因为被返回的 render 函数或 `return` 的对象引用着。
3.  **工程意义**：理解了闭包，你就理解了 Vue 3 为什么比 Vue 2 更容易逻辑复用（Hooks 本质就是闭包工厂）。

### 🟢 1. 闭包的阴暗面：内存泄漏（Memory Leak）

#### 什么是内存泄漏？
简单说：**该释放的内存没释放，一直占着茅坑不拉屎。** 如果泄漏得多了，浏览器就会变卡，甚至崩溃。

#### 闭包为什么容易导致泄漏？
回顾一下闭包的定义：**函数 + 背包（引用的外部变量）**。
只要这个函数还“活着”（比如被挂载到了 `window` 上，或者被 DOM 事件引用着），它背着的“背包”就绝对不会被垃圾回收（GC）。

#### 🌰 Vue 实战中的经典泄漏场景

这是 Vue 开发中最容易踩的坑。

**场景**：你在组件 `mounted` 时给 `window` 绑了个事件，用了闭包，但**忘记解绑**。

```javascript
// MyComponent.vue
<script setup>
import { onMounted, onUnmounted } from 'vue';

// 一个巨大的数据对象 (模拟占用大量内存)
const bigData = new Array(10000).fill('数据');

const handleResize = () => {
    // 闭包！handleResize 引用了 bigData
    console.log(bigData.length); 
};

onMounted(() => {
    // 😱 危险操作：把闭包函数挂到了全局 window 上
    window.addEventListener('resize', handleResize);
});

// ❌ 如果你忘记写 onUnmounted 去 removeEventListener...
</script>
```

**后果分析**：
1.  用户切换路由，离开了这个组件。
2.  组件本该被销毁，`bigData` 本该被回收。
3.  **但是！** `window` 对象上还挂着 `resize` 事件，指向 `handleResize`。
4.  `handleResize` 是闭包，它死死抓着 `bigData` 不放。
5.  **结果**：组件虽然看不见了，但 `bigData` 依然在内存里。用户切进切出几次，内存就爆了。

**✅ 正确做法**：
在 `onUnmounted` 中解绑事件，切断引用。

```javascript
onUnmounted(() => {
    window.removeEventListener('resize', handleResize);
});
// 只有断开了 window -> handleResize 的连接，
// handleResize 才会死，它背着的 bigData 才会死。
```

### 🟢 2. 面试高频题：现代浏览器还需要担心循环引用吗？

很多老旧教程会告诉你：*“闭包会导致循环引用（Circular Reference），在 IE 下会内存泄漏。”*

**面试标准回答**：
> “在早期的 IE（IE6/7）中，由于 DOM 对象使用引用计数算法，循环引用确实会导致内存泄漏。
> 但在 **现代浏览器（Chrome/Firefox/Edge）** 中，垃圾回收使用的是 **标记清除（Mark-and-Sweep）** 算法。只要对象从根节点（Root）无法触达，即使它们互相引用，也会被回收。”

**人话**：
不用太担心纯 JS 对象的循环引用（`a.b = a`），现在的浏览器很聪明。你需要担心的是**“挂在全局（DOM/Window/Timer）上忘了解绑”**。

### 🟢 3. 性能考量

闭包虽好，不要贪杯。
1.  **内存消耗**：闭包会让变量常驻内存，比普通函数消耗更多 RAM。
2.  **查找速度**：闭包涉及多级作用域链查找，理论上比访问局部变量慢一点点（微秒级，现代引擎优化后几乎忽略不计）。

**结论**：不要因为怕性能差而不用闭包（代码可读性更重要），但也不要滥用（比如在循环里疯狂创建闭包）。

如果面试官问你闭包，你能流畅回答这 3 个问题，这块知识点就满分了。

#### Q1: "请用一句话介绍什么是闭包？"
> **参考回答**：
> 闭包就是一个函数能够访问并记住它定义时所在的词法作用域，即使这个函数在当前作用域之外执行。
> 通俗地说，就是函数背了一个“背包”，里面装着它出生时的局部变量。

#### Q2: "闭包有哪些实际应用场景？"
> **参考回答**：
> 1.  **数据封装（私有变量）**：比如手写的计数器，外部无法直接修改 count。
> 2.  **功能扩展（高阶函数）**：比如 **防抖（Debounce）** 和 **节流（Throttle）**，利用闭包保存定时器状态。
> 3.  **函数柯里化**：比如 Vue 中封装通用的 API 请求函数，利用闭包预设 baseUrl。
> 4.  **Vue 3 Composition API**：`setup` 本质就是一个大的闭包环境。

#### Q3: "闭包会导致内存泄漏吗？"
> **参考回答**：
> 不会直接导致泄漏，闭包只是让变量生命周期延长了。
> 真正的泄漏通常是因为**使用不当**：比如闭包被挂载到 `window` 或 DOM 事件上，在组件销毁时忘记解绑，导致闭包无法被垃圾回收。解决办法是在 `unmounted` 钩子中及时清除定时器或解绑事件。
