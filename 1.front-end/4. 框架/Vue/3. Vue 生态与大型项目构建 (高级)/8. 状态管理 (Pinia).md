### **第八章：状态管理 (Pinia)**

随着应用变得越来越复杂，你很快会遇到一个棘手的问题：**多个远房亲戚般的组件，如何共享和修改同一份数据？**

想象一下，你的网站有一个显示用户名的导航栏组件，还有一个用户个人资料页面组件。当用户在个人资料页修改了TA的名字后，导航栏应该如何知道并立即更新显示呢？

我们可以通过 Props 和 Events 一层一层地传递数据，但这很快会变成一场“Prop 钻探 (Prop Drilling)”的噩梦。我们需要一个更优雅的解决方案——**全局状态管理**。

**Pinia** (发音为 `/piːnjʌ/`，类似于 a piece of pineapple 🍍)，是 Vue 官方推荐的、为 Vue 3 量身打造的新一代状态管理库。它轻量、简单、易于上手，并且拥有出色的 TypeScript 支持。

**我们的目标：**

1.  理解为什么需要像 Pinia 这样的状态管理库。
2.  掌握 Pinia 的三大核心概念：`State`, `Getters`, `Actions`。
3.  创建一个管理用户信息的 `Store`，并在多个组件中轻松地使用它。
4.  了解如何通过插件为 Pinia 扩展功能，例如实现数据持久化。

---

#### **8.1 为什么需要状态管理？**

一个集中的状态管理库（如 Pinia）为我们提供了一个“**全局单例**”，可以把它想象成一个所有组件都能访问的“**中央仓库 (Store)**”。

*   **状态 (State):** 仓库里存放的数据，例如用户信息 `user`，购物车列表 `cartItems`。
*   **视图 (View):** 所有使用这些数据的组件。
*   **动作 (Actions):** 唯一可以修改仓库数据的方式，例如 `login()`, `addToCart()`。

**这种模式的好处：**

1.  **集中管理：** 所有全局状态都存放在一个地方，使得状态的变化变得可预测和可追踪。
2.  **告别 Prop 钻探：** 任何组件，无论嵌套多深，都可以直接从 Store 中读取或修改状态，无需通过中间组件传递。
3.  **逻辑解耦：** 将全局状态逻辑（如用户认证、购物车操作）从组件中抽离出来，让组件更专注于 UI 展示。

---

#### **8.2 Pinia 核心概念**

> **大师兄提示 (面试必考点): Pinia vs. Vuex**
> Vuex 是 Vue 2 时代官方的状态管理库。Pinia 是它的继任者。
>
> | 特性           | Pinia (新)                                                   | Vuex (旧)                                                    |
> | :------------- | :----------------------------------------------------------- | :----------------------------------------------------------- |
> | **API 设计**   | 更简洁、更直观。没有 `Mutations`，只有 `State`, `Getters`, `Actions`。异步操作可以直接在 `Actions` 中进行。 | 概念更多，有 `Mutations` (只能同步) 和 `Actions` (可以异步)，心智负担更重。 |
> | **TypeScript** | **完美支持**。无需复杂配置即可获得完整的类型推断。           | 支持不佳，需要大量手写类型定义。                             |
> | **模块化**     | **天生模块化**。每个 `Store` 都是一个独立的模块，无需手动注册。 | 需要手动注册模块，命名空间的概念有时会造成困惑。             |
> | **体积**       | **极其轻量**，只有约 1KB。                                   | 体积更大。                                                   |
>
> **结论：** 在新的 Vue 3 项目中，**毫无疑问应该选择 Pinia**。

**步骤一：安装 Pinia**

```bash
npm install pinia
```

**步骤二：在应用中“安装” Pinia**

和 Vue Router 一样，我们需要在 `main.js` 中创建并安装 Pinia 实例。

```javascript
// src/main.js
import { createApp } from 'vue'
import { createPinia } from 'pinia' // 1. 导入
import App from './App.vue'
import router from './router'

const app = createApp(App)
const pinia = createPinia() // 2. 创建 Pinia 实例

app.use(router)
app.use(pinia) // 3. 安装 Pinia

app.mount('#app')
```

**步骤三：定义你的第一个 Store**

Store 是 Pinia 的核心。按照约定，我们通常在 `src` 目录下创建一个 `stores` 文件夹来存放所有的 store 文件。

让我们创建一个 `user.js` 来管理用户信息。

```javascript
// src/stores/user.js
import { defineStore } from 'pinia';
import { ref, computed } from 'vue';

// 1. 定义 Store
// `defineStore` 的第一个参数是 store 的唯一 ID，Pinia 用它来连接 store 和 devtools
// 推荐的命名约定：`use...Store`
export const useUserStore = defineStore('user', () => {
  // 这是一个 Composition API 风格的 setup store

  // 🍍 2. State (状态)
  // 使用 ref() 来定义 state 属性
  const user = ref(null); // 初始时没有用户信息
  const token = ref(null);

  // 🍍 3. Getters (计算属性)
  // 使用 computed() 来定义 getters
  const isLoggedIn = computed(() => !!token.value);
  const userName = computed(() => user.value?.name || '游客');

  // 🍍 4. Actions (方法)
  // 使用 function 来定义 actions
  async function login(username, password) {
    // 模拟 API 调用
    return new Promise((resolve) => {
      setTimeout(() => {
        user.value = { name: username, email: `${username}@example.com` };
        token.value = `fake-token-for-${username}`;
        resolve(true);
      }, 1000);
    });
  }

  function logout() {
    user.value = null;
    token.value = null;
  }

  // 5. 必须返回所有你想暴露给外部使用的 state, getters, 和 actions
  return {
    user,
    token,
    isLoggedIn,
    userName,
    login,
    logout
  };
});
```

#### **8.3 在组件中使用 Store**

在任何组件中，使用 Store 都像调用一个普通的组合式函数一样简单。

**案例实践：创建一个 `Login.vue` 和一个 `UserProfile.vue`**

**1. `Login.vue` 组件**

```vue
<!-- src/views/Login.vue -->
<script setup>
import { ref } from 'vue';
import { useRouter } from 'vue-router';
import { useUserStore } from '../stores/user.js'; // 1. 导入你的 store

const router = useRouter();
const userStore = useUserStore(); // 2. 获取 store 实例

const username = ref('admin');
const password = ref('password');
const isLoading = ref(false);

async function handleLogin() {
  isLoading.value = true;
  const success = await userStore.login(username.value, password.value); // 3. 调用 action
  isLoading.value = false;
  
  if (success) {
    router.push('/'); // 登录成功后跳转到首页
  } else {
    alert('登录失败！');
  }
}
</script>

<template>
  <div>
    <h2>登录</h2>
    <input type="text" v-model="username" placeholder="用户名">
    <input type="password" v-model="password" placeholder="密码">
    <button @click="handleLogin" :disabled="isLoading">
      {{ isLoading ? '登录中...' : '登录' }}
    </button>
  </div>
</template>
```

**2. 在导航栏 (`App.vue`) 显示用户信息**

```vue
<!-- src/App.vue -->
<script setup>
import { useUserStore } from './stores/user.js';
import { useRouter } from 'vue-router';
import { storeToRefs } from 'pinia'; // 导入 storeToRefs

const userStore = useUserStore();
const router = useRouter();

// 错误的做法 ❌: 直接解构会丢失响应性
// const { userName, isLoggedIn } = userStore;

// 正确的做法 ✅: 使用 storeToRefs 来保持响应性
const { userName, isLoggedIn } = storeToRefs(userStore);

function handleLogout() {
  userStore.logout();
  router.push('/login');
}
</script>

<template>
  <div id="app">
    <nav>
      <router-link to="/">首页</router-link> |
      <router-link to="/course/1">课程详情</router-link>
      <span v-if="isLoggedIn" class="user-info">
        | 欢迎, {{ userName }}!
        <button @click="handleLogout">退出登录</button>
      </span>
      <router-link v-else to="/login"> | 登录</router-link>
    </nav>
    <router-view></router-view>
  </div>
</template>

<style scoped>
.user-info { margin-left: 15px; }
.user-info button { margin-left: 5px; }
</style>
```

> **大师兄提示 (面试高频点): 为什么需要 `storeToRefs`?**
> Pinia 的 store 是一个用 `reactive` 包装的对象，这意味着你不能直接解构它，否则会失去响应性，这和解构 `props` 的问题是一样的。`storeToRefs` 这个辅助函数就是为了解决这个问题。它会把 store 中的 state 和 getters 转换成一系列的 `ref`，让你可以在保持响应性的同时，安全地进行解构。**Actions 可以直接解构**，因为它们是普通的函数。

#### **8.4 Pinia 插件**

Pinia 的强大之处在于它的可扩展性。你可以通过插件来添加全局功能，例如数据持久化、同步到其他标签页等。

**案例实践：使用 `pinia-plugin-persistedstate` 实现数据持久化**

当用户刷新页面时，我们希望他们的登录状态能够被保留下来。`pinia-plugin-persistedstate` 这个插件可以自动将你的 store 数据保存到 `localStorage` 中。

**步骤一：安装插件**

```bash
npm install pinia-plugin-persistedstate
```

---

**步骤二：在 `main.in.js` 中注册插件**

和路由、Pinia 本身一样，插件也需要在应用的主入口文件中进行“安装”。

```javascript
// src/main.js
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import piniaPluginPersistedstate from 'pinia-plugin-persistedstate' // 1. 导入插件
import App from './App.vue'
import router from './router'

const app = createApp(App)
const pinia = createPinia()

pinia.use(piniaPluginPersistedstate) // 2. 将插件应用到 Pinia 实例上

app.use(router)
app.use(pinia)

app.mount('#app')
```

**步骤三：在 Store 中开启持久化**

现在，插件已经准备就绪。你只需要在你想要持久化的 Store 中，添加一个 `persist: true` 的选项即可。

Pinia 支持两种定义 Store 的风格：Setup 风格（我们之前用的函数式风格）和 Options 风格（类似 Vue 2 的对象风格）。插件通常更容易在 Options 风格下配置。让我们用 **Options 风格**重写 `userStore`，这也是官方文档中常见的风格，两种风格你都应该了解。

```javascript
// src/stores/user.js
import { defineStore } from 'pinia';

// 使用 Options API 风格定义 Store
export const useUserStore = defineStore('user', {
  // 🍍 State: 推荐使用一个函数返回初始状态，以支持 SSR
  state: () => ({
    user: null,
    token: null,
  }),

  // 🍍 Getters: 相当于 store 的计算属性
  getters: {
    isLoggedIn: (state) => !!state.token,
    userName: (state) => state.user?.name || '游客',
  },

  // 🍍 Actions: 相当于 store 的方法
  actions: {
    async login(username, password) {
      try {
        // 模拟 API 调用
        const response = await new Promise((resolve) => {
          setTimeout(() => {
            resolve({ 
              name: username, 
              email: `${username}@example.com`,
              token: `fake-token-for-${username}`
            });
          }, 1000);
        });
        
        // 在 action 中，`this` 指向 store 实例
        this.user = { name: response.name, email: response.email };
        this.token = response.token;
        return true;
      } catch (error) {
        console.error('Login failed:', error);
        return false;
      }
    },

    logout() {
      this.user = null;
      this.token = null;
    },
  },

  // ✨ 开启数据持久化
  persist: true,
});
```

**就这样！**

现在，当你登录后，`userStore` 的 `user` 和 `token` 状态会被自动保存到浏览器的 `localStorage` 中。你可以打开开发者工具 -> Application -> Local Storage 查看，会看到一个以 `user` (store 的 ID) 为键的值。

当你刷新页面时，Pinia 会自动从 `localStorage` 读取并恢复这些状态。你的应用现在拥有了“记忆”能力！

**插件的强大之处**

`pinia-plugin-persistedstate` 还支持更复杂的配置，比如：
*   选择性地持久化某些 state。
*   使用 `sessionStorage` 代替 `localStorage`。
*   自定义序列化方式。

这仅仅是众多 Pinia 插件中的一个。通过插件，你可以极大地扩展 Pinia 的能力，而无需修改其核心代码。
