### React 中的事件绑定

#### 1. 语法
React 事件绑定采用**驼峰命名法**（如 `onClick`, `onMouseEnter`），且在大括号 `{}` 中传入一个函数作为事件处理程序，而不是字符串。

*   **基本格式**：`<button onClick={handleClick}>点击</button>`

#### 2. 拿到事件参数 e
在事件回调函数中，第一个参数默认就是事件对象 `e`。
*   **注意**：React 中的 `e` 是 **SyntheticEvent（合成事件）**，它是 React 模拟原生 DOM 事件实现的跨浏览器包装器。

```jsx
function App() {
  const handleClick = (e) => {
    console.log(e); // 获取合成事件对象
    e.preventDefault(); // 阻止默认行为
  };
  return <button onClick={handleClick}>点击查看事件对象</button>;
}
```

#### 3. 传递自定义参数
不能直接写成 `onClick={handleClick(123)}`，因为这会产生立即执行。需要使用**箭头函数**进行包裹。

```jsx
function App() {
  const handleClick = (name) => {
    console.log('Hello, ' + name);
  };
  return <button onClick={() => handleClick('Jack')}>传递参数</button>;
}
```

#### 4. 既要 e 又要自定义参数
在箭头函数中显式地将 `e` 传入，并作为参数传递给目标函数。

```jsx
function App() {
  const handleClick = (name, e) => {
    console.log(name, e);
  };
  // 箭头函数第一个参数是 e，后面手动传入自定义参数
  return <button onClick={(e) => handleClick('Jack', e)}>双重参数</button>;
}
```

## ⚡ 面试高频考点 (事件系统篇)

### Q1: 什么是 React 的合成事件 (SyntheticEvent)？为什么要这样做？
*   **定义**：React 并不是将事件直接绑定在真实 DOM 上，而是通过一个中间层来处理，这个中间层就是合成事件。
*   **目的/优势**：
    1.  **跨浏览器兼容**：抹平了不同浏览器之间的事件差异（如 IE 和 Chrome）。
    2.  **性能优化（事件委托）**：React 17 之前将事件委托在 `document` 上，17 之后委托在 **渲染根节点 (Root Container)** 上。这样可以减少内存消耗，避免频繁解绑/绑定。
    3.  **更好的管理**：方便 React 调度系统（如 Concurrent Mode）对事件进行优先级管理。

### Q2: React 事件和原生 DOM 事件有什么区别？
1.  **命名**：React 驼峰式（`onClick`），原生全小写（`onclick`）。
2.  **处理器**：React 接收函数，原生接收字符串。
3.  **委托机制**：原生事件绑定在目标节点，React 事件通过**事件委托**统一管理。
4.  **执行顺序**：通常情况下，**原生事件先执行，React 合成事件后执行**（因为合成事件要等原生事件冒泡到根节点后才触发）。

### Q3: 在 Class 组件中为什么需要 bind(this) 或使用箭头函数？
*   **原因**：在 JS 中，如果将一个类的方法作为回调函数传递，其 `this` 可能会丢失（变为 `undefined`）。
*   **解决方案**：
    1.  在构造函数中使用 `this.handleClick = this.handleClick.bind(this)`。
    2.  使用 **Class 属性语法（箭头函数）**：`handleClick = () => { ... }` (最推荐)。
    3.  在渲染时使用箭头函数：`onClick={() => this.handleClick()}`（每次渲染都会创建新函数，大数据量下有微弱性能影响）。

### Q4: 如何在 React 中阻止事件冒泡？
*   **合成事件内**：使用 `e.stopPropagation()` 只能阻止 React 合成事件间的冒泡。
*   **注意**：如果你想阻止“原生事件”冒泡到“合成事件”，情况会很复杂。通常使用 `e.nativeEvent.stopImmediatePropagation()`。但在 React 开发中，应尽量避免混合使用原生事件和合成事件。

### Q5: 为什么不能在异步操作（如 `setTimeout`）后访问事件对象 `e`？(针对 React 16 及以下版本)
*   **事件池化 (Event Pooling)**：在旧版 React 中，合成事件对象会被放入池中复用。当事件回调执行完毕，`e` 的属性会被置空。
*   **解决方案**：调用 `e.persist()`。
*   **注意**：**React 17 已经废弃了事件池机制**，所以现在你可以安全地在异步代码中访问 `e` 了。这是面试中的一个“版本差异点”，答出来很加分。
