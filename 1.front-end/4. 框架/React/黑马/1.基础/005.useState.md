# useState 全深度解析

## 1. 基础使用：赋予函数组件“记忆”

在 React 之前，函数组件是“无状态”的（纯 UI 渲染）。`useState` 的出现让函数组件能保存自己的数据。

*   **语法**：`const [state, setState] = useState(initialValue);`
*   **解构赋值**：
    *   `state`: 当前状态的值。
    *   `setState`: 修改状态的**唯一函数**。
    *   `initialValue`: 初始值，只在首次渲染时起作用。

```jsx
import { useState } from 'react';

function Counter() {
  // count 是数据，setCount 是改变数据的“开关”
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      当前计数：{count}
    </button>
  );
}
```

## 2. 修改状态的规则：异步与批处理

这是新手最容易踩坑的地方，也是面试常考点。

### 2.1 状态更新是异步的（在 React 18 之前更明显）
你不能在调用 `setState` 后立即获取最新值。
```jsx
const [count, setCount] = useState(0);
const handleClick = () => {
  setCount(count + 1);
  console.log(count); // 打印出来的依然是旧值 0！
};
```
**原因**：`setState` 会触发重新渲染，而 `count` 是一个常量，在当前渲染周期内它的值永远是 0。

### 2.2 自动批处理 (Automatic Batching)
React 18 会将多次 `setState` 合并为一次重新渲染，以提升性能。

### 2.3 函数式更新
**场景**：当新状态依赖于旧状态时，为了避免闭包陷阱或多次更新丢失，**必须使用函数式写法**。
```jsx
// ❌ 错误写法：连续调用三次，结果可能只加了 1
setCount(count + 1);
setCount(count + 1);
setCount(count + 1);

// ✅ 正确写法：确保拿到的是最新的状态底数
setCount(prev => prev + 1);
setCount(prev => prev + 1);
setCount(prev => prev + 1); // 结果准确加 3
```

## 3. 核心原则：状态不可变 (Immutability)

这是 React 的底层逻辑。**你永远不能直接修改 state 变量的值。**

*   **错误做法**：`state = 123` 或者 `list.push(item)`。
*   **正确做法**：始终传给 `setState` 一个**全新的值（引用地址必须变）**。

**为什么要“不可变”？**
React 底层通过比较新旧值的**引用地址（Object.is）**来决定是否需要更新。如果你直接修改旧对象的属性，引用地址没变，React 会认为数据没动，从而**拒绝重新渲染**。

## 4. 对象与数组状态的操作（重点）

处理对象或数组时，必须先**拷贝**，再**修改**。

### 4.1 修改对象
使用**展开运算符 `...`** 拷贝旧属性。
```jsx
const [user, setUser] = useState({ name: 'Jack', age: 18 });

const updateAge = () => {
  setUser({
    ...user,    // 1. 复制所有旧属性
    age: 20     // 2. 覆盖需要修改的属性
  });
};
```

### 4.2 修改数组
不要用 `push`, `pop`, `splice`，要用 `filter`, `map`, `[...arr]`。
```jsx
const [list, setList] = useState([1, 2, 3]);

// 添加：
setList([...list, 4]);
// 删除：
setList(list.filter(item => item !== 2));
// 修改：
setList(list.map(item => item === 1 ? 100 : item));
```

## 5. 面试高频考点 (Q&A) —— 决定胜负的深度

### Q1: 为什么 useState 返回的是数组而不是对象？
*   **回答**：为了**方便重命名**。如果返回对象 `{state, setState}`，你在一个组件用多个 state 时就必须写成 `{state: count, setState: setCount}`；而数组解构允许你直接自定义名字：`const [name, setName]`，代码更简洁。

### Q2: 如果 setState 传入的值和当前值完全一样，会发生什么？
*   **回答**：React 会使用 `Object.is` 算法进行比较。如果一致，React 会**跳过渲染（Bail out）**以节省性能。这就是为什么修改对象属性而不换引用地址会导致 UI 不更新。

### Q3: useState 的初始值可以写函数吗？有什么好处？
*   **回答**：可以，这叫 **惰性初始化 (Lazy Initialization)**。
*   **价值**：如果初始值需要通过复杂计算（如读取 localStorage），写成 `useState(calculate())` 每次渲染都会执行计算；写成 `useState(() => calculate())` 则**只在组件首次挂载时执行一次**，极大优化性能。

### Q4: 什么是“闭包陷阱” (Stale Closure)？
*   **回答**：在异步回调（如 `setTimeout`）中访问 state 时，由于闭包机制，函数抓取的是该函数**被创建时**的那一帧 state 值，而不是最新的值。
*   **解决**：使用 `useEffect` 监听状态，或者使用 `useRef` 存储最新值，或者使用 `setState(prev => ...)` 函数式更新。

### Q5: 为什么 Hooks 不能写在 if 语句里？
*   **回答**：React 内部是通过 **数组/链表** 按顺序记录 Hooks 的。每次渲染，Hooks 执行的**顺序必须完全一致**。如果写在 `if` 里导致某个 Hook 没执行，React 就会“对错位”，导致状态读取混乱。

## 6. 进阶 Tip：状态拆分原则
**不要把整个页面的所有变量都塞进一个巨大的对象 state 里！**
*   **原因**：如果对象太大，只要其中一个属性变了，整个对象都会被重新创建，且相关的逻辑更难拆分。
*   **建议**：将**不相关的状态拆分为多个 `useState`**；将**逻辑关联紧密的状态合并为一个对象**。
