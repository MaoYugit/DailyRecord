# React 中的组件

## 1. 组件是什么？（抽象概念）

在现代前端开发中，组件是 **UI 构建的最小单元**。

*   **形象比喻**：组件就像 **乐高积木**。你可以独立开发每一个积木（按钮、导航栏、列表），然后通过组合这些积木，搭建出复杂的城堡（网页应用）。
*   **本质**：组件是将 **HTML（结构）、CSS（样式）、JS（逻辑）** 封装在一起的独立实体。
*   **核心目标**：
    *   **高复用性**：写一次，到处用。
    *   **高维护性**：逻辑解耦，哪里坏了修哪里。
    *   **声明式渲染**：你只需要描述组件在不同状态下“长什么样”，React 负责同步到 DOM。

---

## 2. React 组件（具体实现）

在 React 中，组件主要分为两类：**函数组件** 和 **类组件**。

### 2.1 函数组件 (Function Component) —— 目前的主流
本质上就是一个接收 `props` 并返回 `JSX` 的 JavaScript 函数。
*   **特点**：简单、易读、性能高。配合 **Hooks**（如 `useState`）后，已成为开发首选。

```jsx
function Welcome(props) {
  return <h1>Hello, {props.name}</h1>;
}
```

### 2.2 类组件 (Class Component) —— 历史遗产/底层理解
基于 ES6 Class 语法，继承 `React.Component`。
*   **特点**：有完整的生命周期，有 `this`，有 `state`。在 Hooks 出现前是唯一能处理状态的手段。

```jsx
class Welcome extends React.Component {
  render() {
    return <h1>Hello, {this.props.name}</h1>;
  }
}
```

### 2.3 必须遵守的规则（教学重点）
1.  **大写字母开头**：React 通过首字母判断是组件（`Header`）还是原生 HTML 标签（`header`）。
2.  **单一根节点**：必须返回一个单一的 JSX 根元素（或使用 `<Fragment>` / `<>`）。
3.  **纯函数（针对函数组件）**：组件不应该修改它接收到的 `props`。

## 3. 组件的两大“驱动引擎”：Props vs State

| 特性       | Props (属性)                         | State (状态)                                 |
| :--------- | :----------------------------------- | :------------------------------------------- |
| **定义**   | 组件的外部入参，由父组件传入         | 组件内部维护的私有数据                       |
| **可变性** | **只读 (Immutable)**，不可由自身修改 | **可变**，通过 `setState` 或 `useState` 修改 |
| **目的**   | 数据传递，配置组件                   | 响应用户交互，驱动 UI 更新                   |

---

## 4. 组件通讯（组件间如何“说话”）

1.  **父传子**：通过 `props` 传递数据。
2.  **子传父**：父组件传一个**回调函数**给子组件，子组件调用该函数并传回数据。
3.  **兄弟通讯**：找共同的“爸爸”（状态提升）或使用 Context / Redux。

## 5. 面试高频考点 (Q&A) —— 深度扩充

### Q1: 函数组件 vs 类组件，到底有什么区别？
*   **心智模型**：类组件是**面向对象**的，侧重于“实例”和“生命周期”；函数组件是**函数式编程**，侧重于“捕获渲染时的值”（Capture Value）。
*   **性能**：函数组件通常更轻量，没有实例化的开销。
*   **逻辑复用**：类组件用 HOC（高阶组件）或 Render Props，容易造成“嵌套地狱”；函数组件用 **Custom Hooks**，逻辑组织更扁平、清晰。

### Q2: 为什么组件内部不能直接修改 Props？
*   **单向数据流**：React 核心原则是数据单向流动。如果子组件能改父组件传来的数据，会导致数据流向混乱，排查 Bug 极其困难（谁改了我的值？）。
*   **纯函数特性**：React 假设组件是纯函数，相同的 Props 应该得到相同的 UI。

### Q3: 什么是“受控组件”与“非受控组件”？
*   **受控组件**：表单的值由 React 的 `state` 完全控制（通过 `value` 和 `onChange`）。
*   **非受控组件**：表单数据由 DOM 节点本身处理（使用 `ref` 获取值）。通常推荐受控组件，以便实时校验和状态同步。

### Q4: 什么是“状态提升” (Lifting State Up)？
*   当多个组件需要共享同一个状态时，将这个状态移到它们最近的公共父组件中。这是 React 解决兄弟组件通信的官方推荐方案。

### Q5: 什么是 React 的“组合 (Composition) ”？
*   **回答**：React 推荐使用“组合”而非“继承”来实现代码复用。
*   **体现**：通过 `props.children` 将子内容插入到组件模板中。这使得组件非常灵活（类似于 Vue 的插槽 Slot）。

### Q6: 为什么 React 组件一定要 return JSX？
*   **回答**：如果不 return，React 就不知道该如何渲染 UI。React 会调用你的函数/render 方法，获取返回的虚拟 DOM (Vnode)，通过 Diff 算法对比后更新真实 DOM。

## 6. 组件性能优化 (加分项)

1.  **React.memo**：对函数组件进行“记忆”，只有 Props 改变时才重绘。
2.  **PureComponent**：类组件的浅层对比优化。
3.  **按需加载**：使用 `React.lazy` 和 `Suspense` 进行组件级分包。
