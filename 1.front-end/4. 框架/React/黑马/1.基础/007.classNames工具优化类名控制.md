在 React 开发中，随着业务逻辑变复杂，手动拼接字符串类名（如 `` className={`btn ${active ? 'btn-active' : ''} ${disabled ? 'btn-disabled' : ''}`} ``）会变得极其臃肿且难以维护。

`classnames`（以及更现代的 `clsx`）就是为了解决这个痛点而生的。

---

# classNames 动态类名工具

## 1. 为什么需要它？
在处理动态样式时，原生 JS 的模板字符串存在以下问题：
*   **逻辑杂乱**：三元运算符嵌套过多，一眼看不清最终有哪些类名。
*   **空格问题**：容易多出或少掉空格，导致样式失效。
*   **冗余判断**：需要手动处理 `undefined` 或 `null` 导致的 `"null"` 字符串类名。

---

## 2. 核心用法
首先需要安装：`npm install classnames`

### 2.1 基础组合
```jsx
import classNames from 'classnames';

// 简单拼接
classNames('foo', 'bar'); // => 'foo bar'
```

### 2.2 对象语法（最常用）
键是 **类名**，值是 **布尔值**。只有值为 `true` 时，类名才会被添加。
```jsx
const isActive = true;
const isError = false;

classNames({
  'btn-active': isActive,
  'btn-error': isError
}); 
// => 'btn-active'
```

### 2.3 混合使用
支持同时传入字符串、对象、数组，它会自动过滤掉 `false`、`null`、`undefined` 和 `0`。
```jsx
classNames('base-btn', { 'is-active': true }, ['custom-class']);
// => 'base-btn is-active custom-class'
```

---

## 3. 进阶方案：`clsx`
目前大厂项目（如使用 Tailwind CSS 的项目）更倾向于使用 `clsx`。
*   **区别**：`clsx` 体积更小（仅 228 字节），性能更高，API 与 `classnames` 完全兼容。
*   **用法**：完全一致。

---

## 4. 面试高频考点 (Q&A)

### Q1: `classNames` 这个库的工作原理是什么？
*   **核心逻辑**：它内部通过遍历传入的参数，判断其类型。
    *   如果是**字符串或数字**，直接加入结果数组。
    *   如果是**数组**，递归调用自身。
    *   如果是**对象**，遍历 key，如果 value 为真值，则将 key 加入结果数组。
*   最后通过 `.join(' ')` 将数组转换成空格分隔的字符串。

### Q2: 既然模板字符串也能实现，为什么非要用这个库？
*   **可读性**：对象语法极其直观，一眼就能看出某种状态对应哪个类。
*   **鲁棒性**：它会自动处理掉 `falsy` 值（如 `undefined`、`null`）。如果你用模板字符串拼接了一个 `undefined`，HTML 可能会出现 `class="btn undefined"`。
*   **清洁度**：自动处理多余的空格。

### Q3: 能不能手写一个简易版的 `classNames`？（高阶面试题）
面试官考察你的逻辑严密性。
```javascript
function myClassNames(...args) {
  const classes = [];
  args.forEach(arg => {
    if (!arg) return; // 过滤掉 falsy 值

    if (typeof arg === 'string' || typeof arg === 'number') {
      classes.push(arg);
    } else if (Array.isArray(arg)) {
      classes.push(myClassNames(...arg)); // 递归处理数组
    } else if (typeof arg === 'object') {
      for (const key in arg) {
        if (arg[key]) classes.push(key); // 对象逻辑
      }
    }
  });
  return classes.join(' ');
}
```

### Q4: 在 React 中，类名工具如何配合 CSS Modules 使用？
这是实际开发中最常见的组合。
```jsx
import styles from './Button.module.css';
import cx from 'classnames';

function Button({ type }) {
  return (
    <button className={cx(styles.base, {
      [styles.primary]: type === 'primary',
      [styles.danger]: type === 'danger'
    })}>
      提交
    </button>
  );
}
```
*注：这里的 `[styles.primary]` 使用了 JS 的计算属性名语法。*

---

## 5. 总结要点（Tips）

1.  **别写死**：避免在 JSX 中写长达 100 字符的 `className` 字符串，建议在 `return` 之前先用 `classNames` 计算出类名变量。
2.  **默认值**：始终给基础样式一个固定类名，动态样式通过对象控制。
3.  **Tailwind 黄金搭档**：如果你用 Tailwind CSS，`clsx` (或 `classnames`) + `tailwind-merge` 是目前公认的最优解，可以解决类名冲突问题。
