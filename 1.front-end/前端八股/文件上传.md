### 🚀 全栈文件上传通关大纲

#### 第一阶段：洪荒时代 —— 原生 HTML 表单上传
**目标**：理解文件上传最底层的 HTTP 机制。

*   **1.1 最简单的上传**
    *   `<input type="file">` 标签的使用。
    *   `<form>` 表单的提交机制。
*   **1.2 关键知识点：`enctype`**
    *   为什么必须是 `multipart/form-data`？
    *   它和 `application/x-www-form-urlencoded` 的区别（抓包分析请求体）。
*   **1.3 基础限制与痛点**
    *   **不足**：页面会刷新，用户体验极差，无法预览，无法验证文件大小。

#### 第二阶段：青铜时代 —— 原生 JS + AJAX (FormData)
**目标**：实现无刷新上传，掌握浏览器文件 API。
*   **2.1 DOM 操作文件**
    *   通过 JS 获取文件对象：`inputElement.files` 和 `FileList` 对象。
    *   `File` 对象里有什么？(name, size, type, lastModified)。
*   **2.2 神器 `FormData`**
    *   如何将文件塞入 HTTP 请求体？
    *   `append` 方法的使用。
*   **2.3 发送请求**
    *   使用 `XMLHttpRequest` (XHR) 或 `fetch` 发送文件。
    *   **踩坑点**：手动设置 `Content-Type` 请求头导致的边界（Boundary）丢失问题。
*   **2.4 基础验证**
    *   前端限制文件类型（`accept` 属性 vs JS 判断）。
    *   前端限制文件大小。

#### 第三阶段：白银时代 —— 交互体验优化 (预览与进度)
**目标**：让用户知道“传了什么”以及“传了多少”。
*   **3.1 图片预览的两种流派**
    *   **方案 A (Base64)**: `FileReader` API。适合小图，兼容性好。
    *   **方案 B (Blob URL)**: `URL.createObjectURL()`。性能好，适合大图。
    *   **踩坑点**：内存泄漏问题（如何释放 ObjectURL）。
*   **3.2 进度条实现**
    *   利用 `XHR.upload.onprogress` 事件计算百分比。
    *   Axios 中的 `onUploadProgress`。
*   **3.3 多文件上传**
    *   `multiple` 属性。
    *   如何循环处理 `FileList` 并添加到同一个 FormData 或分批发送。
    *   **UI 实现**：用户点击删除某一个待上传文件，JS 内部如何维护文件列表（因为 input.files 是只读的）。

#### 第四阶段：黄金时代 —— Vue 3 + Axios 实战
**目标**：在现代框架中封装可复用的上传组件。
*   **4.1 Vue 3 基础集成**
    *   `ref` 绑定 file input。
    *   `@change` 事件处理。
*   **4.2 组件化封装**
    *   设计一个 `<Uploader v-model="fileList" />` 组件。
    *   Props 设计：accept, limit, maxSize, action (上传地址)。
    *   Slots 设计：自定义触发按钮、自定义预览列表。
*   **4.3 拖拽上传 (Drag & Drop)**
    *   原生拖拽事件：`dragover`, `dragleave`, `drop`。
    *   如何从 `e.dataTransfer.files` 获取文件。

#### 第四阶段：钻石时代 —— 大文件切片与断点续传 (核心难点)
**目标**：解决 GB 级别大文件上传慢、失败需重传的问题。
*   **5.1 文件切片 (Chunking)**
    *   核心 API：`Blob.prototype.slice()`。
    *   如何将一个大文件切成 100 个小块。
*   **5.2 文件指纹 (Hash)**
    *   如何识别文件变没变？(不用文件名，用内容)。
    *   使用 `spark-md5` 计算文件 Hash。
    *   **性能优化**：Web Worker 计算 Hash（避免卡死主线程）。
*   **5.3 断点续传逻辑**
    *   上传前先问后端：“这个 Hash 的文件，我传过哪些切片了？”（秒传机制）。
    *   过滤掉已传切片，只传剩下的。
*   **5.4 并发控制**
    *   一次发 100 个请求会把浏览器搞挂。
    *   实现一个 `Promise` 并发控制器（如限制同时只传 3 个切片）。

## **第一阶段：洪荒时代 —— 原生 HTML 表单上传**。

### 0. 环境准备

安装 **Node.js**。
在电脑上创建一个文件夹， `file-upload-demo`。

### 1. 编写代码

在这个文件夹里，我们需要两个文件：
1.  `index.html` (前端页面)
2.  `server.js` (后端服务，用来接收并保存文件)

#### A. 后端代码 (`server.js`)
我们将使用 Express 框架和 Multer 中间件（专门处理文件上传的标准库）。

```javascript
// server.js
const express = require('express');
const multer = require('multer'); // 引入专门处理文件上传的中间件
const path = require('path');
const fs = require('fs');

const app = express();

// 1. 配置上传存储位置
// 为了演示方便，我们直接把文件存在项目根目录下的 'uploads' 文件夹
if (!fs.existsSync('uploads')) {
    fs.mkdirSync('uploads');
}

const storage = multer.diskStorage({
    destination: function (req, file, cb) {
        cb(null, 'uploads/') // 文件保存路径
    },
    filename: function (req, file, cb) {
        // 为了防止同名覆盖，我们加上时间戳
        // file.originalname 是用户计算机上的原始文件名
        const uniqueSuffix = Date.now() + '-' + Math.round(Math.random() * 1E9);
        // 保留原始后缀名 (例如 .png, .txt)
        const ext = path.extname(file.originalname); 
        cb(null, file.fieldname + '-' + uniqueSuffix + ext);
    }
});

const upload = multer({ storage: storage });

// 2. 托管静态文件，这样你才能访问到 index.html
app.use(express.static('public'));

// 3. 编写上传接口
// upload.single('myFile') 这里的 'myFile' 必须和前端 input 的 name 属性一致
app.post('/upload', upload.single('myFile'), (req, res) => {
    // 如果走到这里，说明文件上传成功了
    console.log('收到文件:', req.file);
    res.send(`
        <h1>上传成功!</h1>
        <p>文件已保存到服务器 uploads 文件夹。</p>
        <p>文件名: ${req.file.filename}</p>
        <p>大小: ${req.file.size} bytes</p>
        <a href="/">返回</a>
    `);
});

app.listen(3000, () => {
    console.log('服务器启动成功: http://localhost:3000');
});
```

#### B. 前端代码 (`public/index.html`)
请在项目根目录下新建一个文件夹叫 `public`，然后在里面新建 `index.html`。

```html
<!-- public/index.html -->
<!DOCTYPE html>

    <title>原生 HTML 上传演示</title>
</head>

```

### 3. 大师视角的深度解析

虽然代码跑通了，但作为未来的大师，你需要理解背后的细节：

#### 知识点 1：`enctype="multipart/form-data"` 是什么？
如果你把 HTML 里的 `enctype` 删掉，或者改成默认的 `application/x-www-form-urlencoded`，后端会报错或收不到文件。
*   **默认方式**：只会把文件名当作字符串发给后端（比如 `myFile=photo.jpg`），并没有发送文件内容。
*   **multipart/form-data**：浏览器会把请求体切分成多个部分（Part），每一部分有自己的 Header。它通过一个 **Boundary（边界符）** 来区分不同字段和文件数据。

#### 容易踩的坑
1.  **Name 不匹配**：前端 `<input name="abc">`，后端却是 `upload.single('xyz')`。这会导致后端报错 `MulterError: Unexpected field`。
2.  **忘记 POST**：文件上传数据量大，GET 请求带不动（且 GET 没有 Body），必须用 POST。

#### 这种方式的不足 (Deficiency)
你可能已经注意到了，当你点击上传后，**页面发生了跳转/刷新**。
*   **用户体验差**：用户正在填表单，传个头像页面就白屏刷新了，之前的操作可能丢失。
*   **无法交互**：在上传过程中，用户不知道传了多少（没有进度条），也不能取消。
*   **结果处理僵硬**：后端只能返回一段 HTML 或者重定向，无法灵活地在当前页面提示“上传成功”。

### 修正不足的方法
为了解决**页面刷新**的问题，我们需要在这个基础上，引入 **JavaScript (AJAX)** 来接管表单的提交过程。我们将不再依赖 `<form>` 的自动提交，而是自己手动打包数据发送。
