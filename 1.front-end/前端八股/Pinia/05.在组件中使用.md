### 第三课：在组件中读写 Store

#### 1. 核心代码实现

请打开 `src/App.vue`（或者任意一个组件），清除原来的内容，写入以下代码。

**重点关注三件事**：
1.  **引入**：导入我们在上一节写的 `useCounterStore`。
2.  **实例化**：在 `setup` 中调用它，拿到 store 实例。
3.  **使用**：在 `template` 中直接通过 `store.xxx` 读取和修改。

```html
<script setup lang="ts">
// 1. 引入我们定义好的 Store 钩子
import { useCounterStore } from './stores/counter'

// 2. 实例化 Store
// 注意：一定要在 setup() 内部调用，否则会报错（找不到 Pinia 实例）
const counterStore = useCounterStore()

// 这里的 counterStore 是一个 Proxy 对象（Reactive）
console.log(counterStore) 
</script>

<template>
  <div class="card">
    <!-- 3. 读取 State -->
    <h2>用户名：{{ counterStore.name }}</h2>
    
    <!-- 读取 Getters (用法和 State 一模一样) -->
    <h3>当前数字：{{ counterStore.count }}</h3>
    <h3>两倍数字：{{ counterStore.doubleCount }}</h3>

    <hr/>

    <!-- 4. 调用 Actions -->
    <!-- 像调用普通函数一样简单 -->
    <button @click="counterStore.increment()">
      点击 +1 (同步)
    </button>

    <button @click="counterStore.registerUser()">
      一键升级 (异步)
    </button>
  </div>
</template>

<style scoped>
.card {
  border: 1px solid #ccc;
  padding: 20px;
  border-radius: 8px;
}
button {
  margin-right: 10px;
  padding: 8px 16px;
  cursor: pointer;
}
</style>
```

### 2. 深度解析 (面向开发)

#### A. 为什么是 `const store = useXxxStore()`？
*   `useCounterStore` 本质上是一个工厂函数。
*   当你调用它时，Pinia 会检查：“嘿，名为 `counter` 的这个仓库创建了吗？”
    *   如果**没有**：创建它，挂载到 Pinia 根实例上，然后返回给你。
    *   如果**已经有了**：直接把那个单例返回给你。
*   **这意味着**：你在 Component A 和 Component B 里分别调用 `useCounterStore()`，拿到的都是**同一个对象**。改了 A，B 也会变。

#### B. 模板中的使用
*   **直接点（Dot Notation）**：`counterStore.count`。
*   **不需要 `.value`**：虽然 Vue 3 的 `ref` 在 JS 中需要 `.value`，但 Pinia 的 Store 实例是被 `reactive` 包裹的，所以你可以直接访问属性。

---

### ⚠️ 关键警告：新手最容易犯的错（面试必考）

很多初学者觉得 `counterStore.count` 写起来太长了，想解构（Destructuring）。

**❌ 错误写法：直接解构**
```typescript
const counterStore = useCounterStore()

// 🚫 危险操作！
// 这相当于：const count = 0 (把当前的数值赋值给了一个普通变量)
const { count, name } = counterStore 
```

**后果**：
*   **失去响应式**！
*   当你点击按钮 `count` 变成 1、2、3 时，页面上解构出来的 `count` 永远停留在 `0`。
*   **原理**：这是 ES6 解构赋值的特性，对于基本数据类型（number, string），解构是“值拷贝”，而不是“引用拷贝”。

### 👹 面试官视角：这部分怎么考？

#### ❓ 面试题 1：可以在组件外（比如 `api.ts` 文件里）使用 Store 吗？
**答案**：
可以，但有前提。
必须在 **Pinia 安装（`app.use(pinia)`）之后** 才能使用。
*   ❌ 错误：在文件顶层直接 `const store = useStore()`，这会在 Pinia 安装前执行，报错。
*   ✅ 正确：在函数内部调用。
    ```typescript
    // api.ts
    import { useAuthStore } from './stores/auth'
    
    export function requestInterceptor() {
      const auth = useAuthStore() // 在调用函数时，Pinia 肯定已经准备好了
      return auth.token
    }
    ```

#### ❓ 面试题 2：Pinia 的 `store` 是 `ref` 还是 `reactive`？
**答案**：
Pinia 的 store 实例是一个 **Reactive** 对象。所以我们不需要写 `.value`，但也正因为它是 Reactive，直接解构会丢失响应性。
