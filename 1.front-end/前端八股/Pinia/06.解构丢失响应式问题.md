### 第四课：storeToRefs —— 拯救响应式

#### 1. 案发现场：为什么直接解构会“死”掉？

我们在 JS 里写过无数次解构赋值：
```javascript
const obj = { count: 0, name: 'Jack' }
const { count } = obj // count = 0
```
这里 `count` 只是一个普通的数字 `0`，它和 `obj` 没有任何关系了。

**在 Pinia 中同理**：
Store 本质上是一个 `reactive` 对象（Proxy）。
*   当我们写 `store.count` 时，是通过 Proxy 去访问，Proxy 说：“好，我帮你记着，你在读这个值，以后变了我通知你。”
*   当我们写 `const { count } = store` 时，相当于把 `0` 取出来赋值给局部变量。Proxy 根本不知道你拿走了这个值，以后 Store 变了，Proxy 也没法通知这个局部变量。

**比喻**：
*   **`store.count`**：你看的是**直播**（数据变，画面就变）。
*   **`const { count } = store`**：你是**截了一张图**（直播再怎么变，你的截图永远不动）。

---

#### 2. 救世主：storeToRefs

Vue 官方为了解决这个问题，提供了 `toRefs`。Pinia 为了更方便（且过滤掉非数据的方法），专门封装了 **`storeToRefs`**。

它的作用是：**把 Store 里面的每一个属性（State 和 Getters），都变成一个个的 Ref 对象。**

Ref 对象依然保持着引用的关系（它指向那个直播源）。

#### 3. 正确的代码写法

请修改你的 `App.vue`（或者组件代码）：

```html
<script setup lang="ts">
import { useCounterStore } from './stores/counter'
// 1. 引入 storeToRefs
import { storeToRefs } from 'pinia'

const counterStore = useCounterStore()

// ❌ 错误写法：失去响应式
// const { count, doubleCount } = counterStore 

// ✅ 正确写法：保持响应式
// 原理：name 和 count 现在变成了 ref(Proxy)
const { name, count, doubleCount } = storeToRefs(counterStore)

// ⚠️ 注意：
// Actions 不需要（也不能）用 storeToRefs 包裹！
// Actions 本身就是函数，直接解构即可，不会丢失上下文
const { increment } = counterStore

// 测试一下
console.log(name) // RefImpl { ... value: 'Pinia 初学者' }
</script>

<template>
  <div class="card">
    <!-- 在模板里，ref 自动解包，不需要写 .value -->
    <h2>用户名：{{ name }}</h2>
    <h3>当前数字：{{ count }}</h3>
    <h3>两倍数字：{{ doubleCount }}</h3>

    <hr/>

    <!-- 直接调用解构出来的 action -->
    <button @click="increment()">点击 +1</button>
  </div>
</template>
```

### 4. 深度细节：Action 怎么办？

这是面试官喜欢挖坑的地方。

**千万不要**这样写：
```javascript
// ❌ 甚至会导致报错或奇怪的行为
const { increment } = storeToRefs(counterStore)
```

**规则**：
*   **State (数据)**：必须用 `storeToRefs`。
*   **Getters (计算属性)**：必须用 `storeToRefs`。
*   **Actions (方法)**：**直接解构**。

**为什么？**
`storeToRefs` 内部会检测，它只把“属性”变成 Ref，它会忽略掉“函数”。因为函数不需要响应式，函数只需要被调用。

### 👹 面试官/架构师 视角（深度解析）

#### ❓ 面试题 1：`storeToRefs` 和 Vue 原生的 `toRefs` 有什么区别？
**答案**：
*   **Vue 的 `toRefs`**：不管三七二十一，把对象里所有的属性都转成 ref。如果你把整个 store 丢进去，它连函数（Actions）和其他私有属性也都转成 ref 了，这很浪费性能，而且用起来怪怪的（调用函数变成了 `action.value()`）。
*   **Pinia 的 `storeToRefs`**：是专门定制的。它会**过滤**掉那些非 State/Getter 的属性（比如 Actions 和 Pinia 的内部属性），只处理数据，更加智能和轻量。

#### ❓ 面试题 2：解构之后，在 Script 里怎么修改值？
**答案**：
因为 `storeToRefs` 把它变成了 **Ref**，所以在 `<script setup>` 里修改时，必须加 **`.value`**。
```typescript
const { count } = storeToRefs(counterStore)

// ❌ 错
// count++ 

// ✅ 对
count.value++ 
```
*这也是为什么有些人宁愿不解构，直接写 `store.count++`，因为不用写 `.value`。*
