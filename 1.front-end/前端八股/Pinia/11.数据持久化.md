**数据持久化**是从“写 Demo”跨越到“写产品”最重要的一步。
如果没有持久化，你的用户只要手滑按了一下 F5，刚填好的表单、刚登录的状态、购物车的商品就全部归零。这在商业项目中是不可接受的。

---

### 第九课：数据持久化 (Persistence)

#### 1. 痛点分析
*   **Pinia/Vuex 的数据**：存放在**内存 (RAM)** 中。速度快，但页面刷新（进程重启）就会丢失。
*   **浏览器缓存 (LocalStorage/SessionStorage)**：存放在**硬盘**中。刷新不丢，但读写速度比内存慢，且只能存字符串。

**目标**：把 Pinia 的数据自动同步到 LocalStorage，刷新时再自动读回来。

---

#### 2. 手写方案（原理与面试）

在没有插件之前，或者面试官问你“**不使用插件，怎么实现持久化？**”时，你需要展示这个逻辑。

**核心 API**：`store.$subscribe` (监听 store 变化)。

```typescript
// src/stores/cart.ts
export const useCartStore = defineStore('cart', () => {
  // 1. 初始化时：尝试从 LocalStorage 读取
  const savedCart = localStorage.getItem('cart-data')
  const items = ref(savedCart ? JSON.parse(savedCart) : [])

  function addItem(item) {
    items.value.push(item)
  }

  return { items, addItem }
})

// 在组件中或者 main.ts 中调用监听
const cartStore = useCartStore()

// 2. 监听变化：只要 items 变了，就写入 LocalStorage
// mutation: 变动的细节
// state: 变动后的最新状态
cartStore.$subscribe((mutation, state) => {
  localStorage.setItem('cart-data', JSON.stringify(state.items))
})
```

*   **缺点**：每个 Store 都要写一遍读写逻辑，极其繁琐。

---

#### 3. 企业级方案：`pinia-plugin-persistedstate`

这是目前 Pinia 生态中最流行的持久化插件，**配置极简，功能强大**。

**Step 1: 安装插件**
```bash
npm install pinia-plugin-persistedstate
```

**Step 2: 在 `main.ts` 注册插件**
```typescript
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import piniaPluginPersistedstate from 'pinia-plugin-persistedstate' // 1. 引入

const app = createApp(App)
const pinia = createPinia()

// 2. 注册插件
pinia.use(piniaPluginPersistedstate)

app.use(pinia)
app.mount('#app')
```

**Step 3: 在 Store 中开启 (Setup Store 写法)**

这是重点！`defineStore` 的参数结构略有变化。
*   参数1：ID
*   参数2：Setup 函数
*   **参数3：配置对象 (persist 写在这里)**

```typescript
import { defineStore } from 'pinia'
import { ref } from 'vue'

export const useUserStore = defineStore(
  'user', 
  () => {
    const token = ref('')
    const name = ref('Jack')
    return { token, name }
  },
  // 第三个参数：配置项
  {
    persist: true // ✅ 开启持久化，就这一行！
  }
)
```

**效果**：
1.  你修改 `token`，插件自动存入 LocalStorage (key 默认为 Store ID，即 `'user'`)。
2.  刷新页面，插件自动从 LocalStorage 读出来并赋值给 `token`。

---

#### 4. 进阶配置 (必学)

默认情况下，它会把**整个 Store** 里的数据都存到 `localStorage`。但在实际开发中，我们往往有更细致的需求。

**场景 A：我不想存 localStorage，我想存 sessionStorage (关闭浏览器就销毁)**
**场景 B：我只想存 `token`，不想存 `name`**

```typescript
export const useUserStore = defineStore('user', () => {
    const token = ref('')
    const name = ref('Jack') // 这个不需要持久化
    const age = ref(18)
    return { token, name, age }
  },
  {
    persist: {
      // 1. 自定义 Key (默认是 store id)
      key: 'my-app-user', 

      // 2. 指定存储位置 (默认是 localStorage)
      storage: sessionStorage, 

      // 3. 指定要持久化的字段 (核心功能)
      // 数组里填你想存的变量名
      paths: ['token', 'age'] 
    }
  }
)
```

### 👹 面试官/架构师 视角 (深度解析)

#### ❓ 面试题 1：持久化插件的底层原理是什么？
**答案**：
它利用了 Pinia 的插件机制 `pinia.use()`。
1.  **初始化 (`init`)**：在 Store 创建时，插件会去检查 Storage 里有没有旧数据。如果有，用 `store.$patch` 把数据合并进去。
2.  **监听 (`subscribe`)**：利用 `store.$subscribe` 监听状态变化，一旦变化，利用 `JSON.stringify` 序列化并写入 Storage。

#### ❓ 面试题 2：敏感数据（如密码、Token）存 LocalStorage 安全吗？
**答案**：
*   **绝对不存密码**：密码永远不该在前端存储。
*   **Token**：一般存 LocalStorage 是业界常规做法（为了方便），但有 XSS 攻击风险（黑客注入脚本读取 localStorage）。
    *   **更安全的做法**：存 `HttpOnly Cookie`（但这需要后端配合）。
    *   **面试回答**：对于普通 Token，存 LocalStorage + HTTPS + 严格的 CSP (内容安全策略) 是可接受的权衡方案。

#### ❓ 面试题 3：如果 State 数据量特别大（比如 10MB），用这个插件会怎么样？
**答案**：
*   **性能卡顿**：`JSON.stringify` 和 `localStorage` 的读写都是**同步**的。数据量大时，每次修改都会阻塞主线程，导致页面卡顿。
*   **容量限制**：LocalStorage 一般只有 5MB 左右。
*   **解决方案**：不要全量持久化，使用 `paths` 只存关键数据；或者使用 `IndexedDB` (异步存储)。
