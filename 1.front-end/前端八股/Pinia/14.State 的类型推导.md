**TS 深度集成**是让你代码变得“高级”的关键。

Pinia 最大的卖点就是对 TypeScript 的支持几乎是完美的（比 Vuex 4 强太多）。在企业级项目中，**严禁**写出隐式的 `any` 类型。

我们先从最基础、也是最重要的 **State 类型约束** 开始。

---

### 第十二课：State 的类型推导与约束

#### 1. 为什么需要手动定义接口？

Pinia 很聪明，它会自动推导类型。
```typescript
const count = ref(0) // TS 自动推导为 number
const name = ref('Jack') // TS 自动推导为 string
```
对于简单类型，自动推导够用了。

**但是**，遇到复杂类型（比如数组、对象、联合类型）时，自动推导就会“傻”掉：
```typescript
const users = ref([]) // ❌ TS 推导为 never[]，你永远无法往里面 push 数据
const user = ref(null) // ❌ TS 推导为 any 或 null，你失去了代码提示
```

这时候，我们需要 **Interface (接口)** 来立规矩。

---

#### 2. 定义接口 (The Contract)

假设我们要管理一个用户信息，包含 ID、名字、年龄（可选）、角色（枚举）。

在 `src/types/user.ts` (或者就在 store 文件顶部) 定义：

```typescript
// 定义 User 的结构
export interface UserInfo {
  id: number
  name: string
  age?: number // 可选属性
  role: 'admin' | 'editor' | 'guest' // 联合类型 (字面量)
}

// 定义整个 State 的结构 (可选，视复杂度而定)
export interface UserState {
  currentUser: UserInfo | null // 初始可能是 null
  token: string
  loginHistory: string[] // 字符串数组
}
```

---

#### 3. 在 Setup Store 中使用 (推荐)

在 Setup Store 中，我们利用 Vue 的 **泛型** 来约束 `ref`。

```typescript
import { defineStore } from 'pinia'
import { ref } from 'vue'
import type { UserInfo } from '@/types/user'

export const useUserStore = defineStore('user', () => {
  
  // 1. 简单类型：依然靠自动推导
  const token = ref('') 

  // 2. 复杂对象：使用泛型 <Type>
  // 含义：user 的值要么是 UserInfo 对象，要么是 null
  const user = ref<UserInfo | null>(null)

  // 3. 数组：必须指定类型！
  // 否则 ref([]) 会被推导成 never[]，导致 push 报错
  const userList = ref<UserInfo[]>([])

  function login(newUser: UserInfo) {
    user.value = newUser
    // user.value.role 会自动提示 'admin' | 'editor' | 'guest'
  }

  return { token, user, userList, login }
})
```

> **实战技巧**：
> 当你敲 `user.value.` 时，VS Code 会自动列出 `id`, `name`, `role`。如果你不小心把 `name` 拼成了 `neme`，编辑器会直接标红报错。这就是 TS 的安全感。

---

#### 4. 在 Options Store 中使用

如果你维护的是老项目，用的是 Options API，有两种写法。

**写法 A：利用 state 函数的返回类型 (推荐)**

```typescript
import { defineStore } from 'pinia'
import type { UserState } from '@/types/user'

export const useUserStore = defineStore('user', {
  // 显式标注箭头函数的返回类型
  state: (): UserState => ({
    currentUser: null,
    token: '',
    loginHistory: []
  }),
  
  actions: {
    updateName(name: string) {
      // TS 知道 currentUser 可能为 null
      // 所以这里会强制你用 ?. (可选链) 或者 if 判断
      this.currentUser?.name = name 
    }
  }
})
```

**写法 B：利用 defineStore 泛型 (较啰嗦，不推荐)**
`defineStore<Id, State, Getters, Actions>(...)` 参数太多，容易写错位置。

### ⚠️ 经典报错与解决方案

**报错场景**：
```typescript
const list = ref([]) // 推导为 never[]
list.value.push(1) // ❌ Error: Argument of type 'number' is not assignable to parameter of type 'never'.
```

**原因**：
TS 看到空数组 `[]`，为了安全起见，它认为这个数组“永远不应该有内容”（never）。

**解决**：
```typescript
const list = ref<number[]>([]) // ✅ 明确告诉它这是数字数组
```

### 👹 面试官/架构师 视角

#### ❓ 面试题 1：什么时候可以用 `any`？
**答案**：
**永远不要**在定义 State 时用 `any`。
如果用 `any`，Pinia 就退化成了普通的 JS 对象，失去了 90% 的价值。如果实在不知道类型，可以用 `unknown`，或者定义一个 `Record<string, any>`（如果是动态对象）。

#### ❓ 面试题 2：Interface 和 Type Alias 选哪个？
**答案**：
在定义对象结构（比如 User, Product）时，Vue 社区和 TS 官方通常推荐 **Interface**（因为它可以被 `extends`，报错信息也更友好）。但在定义联合类型（Union Types）时必须用 **Type**。
*   `interface User { ... }` (推荐)
*   `type Status = 'success' | 'fail'`
