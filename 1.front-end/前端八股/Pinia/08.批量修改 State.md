在企业级开发中，我们经常从后端获取一大坨数据（比如用户信息接口返回了 name, age, avatar, token...），如果一行一行地赋值，代码既难看，调试记录也会很乱。

这时候，**`$patch`** 就派上用场了。

### 第六课：批量修改 State 的三种姿势

为了演示，假设我们有一个 `UserStore`，里面有 `name`（字符串）、`age`（数字）和 `skills`（数组）。

#### 1. 第一种：直接修改（最常用）

适用于：**修改单个字段**。

```typescript
const store = useUserStore()

// 每一行代码都会触发一次状态更新（但在 Vue 3 中，视图更新会被合并）
store.name = 'Jack'
store.age = 25
```

*   **优点**：符合直觉，代码短。
*   **缺点**：如果你连写 5 行修改，Pinia 的 DevTools（时间旅行调试器）里就会记下 5 条记录，回滚调试时很麻烦。

---

#### 2. 第二种：`$patch` 对象写法（推荐）

适用于：**多字段同步更新**。
你可以传入一个对象，Pinia 会把它和当前的 State 进行**合并**（Merge）。

```typescript
// 一次性修改多个属性
store.$patch({
  name: 'Rose',
  age: 18,
  // ⚠️ 注意：数组不能只传新增的项，必须替换整个数组
  // 如果只是想 push，这种写法不方便
  skills: ['Vue', 'Pinia'] 
})
```

*   **优点**：
    1.  **原子性**：在 DevTools 中只显示**一条**名为 "patch" 的记录，非常干净。
    2.  **订阅触发**：只会触发一次 `store.$subscribe`（后面会讲）。

---

#### 3. 第三种：`$patch` 函数写法（高级）

适用于：**复杂逻辑** 或 **数组操作**。
有时候对象写法不够用，比如我想给数组 `push` 一个数据，而不是替换整个数组。

```typescript
store.$patch((state) => {
  // state 就是当前的 store.$state
  
  state.name = 'Tom'
  state.age += 1 // 可以在原有基础上修改
  
  // 数组操作非常方便，不需要重新赋值整个数组
  state.skills.push('TypeScript')
})
```

*   **优点**：既能批量修改，又能写逻辑。

### 👹 面试官/架构师 视角（深度解析）

这部分是**高薪考点**，请仔细阅读。

#### ❓ 面试题 1：Vue 3 已经有自动的批量更新（Reactivity Batching）了，为什么还需要 `$patch`？

**答案（这是一个区分新手和高手的点）：**

*   **性能角度**：在 Vue 2 + Vuex 时代，连续提交 Mutation 可能会导致多次组件渲染。但在 **Vue 3** 中，Vue 的响应式系统本身就很智能，它会自动把同步代码块里的多次状态修改合并成一次视图更新。**所以，单纯为了减少组件渲染次数，使用 `$patch` 的意义已经不大了。**
*   **DevTools 角度（真正原因）**：`$patch` 的主要意义在于**开发体验**和**逻辑分组**。它让 DevTools 里的历史记录变成一条（Group），而不是刷屏的一堆。
*   **订阅角度**：如果你使用了 `store.$subscribe()` 监听 Store 变化，直接修改 N 次会触发 N 次回调，而 `$patch` 只会触发 **1 次**。

#### ❓ 面试题 2：`$patch` 替换整个对象时是深拷贝还是浅拷贝？

**答案**：
`$patch` 的对象写法执行的是**顶层合并**。
如果你传 `{ info: { age: 10 } }`，而 Store 里原本是 `info: { name: 'A', age: 20 }`，它不会简单粗暴地把 `info` 替换掉，而是会尝试合并。但为了安全起见，开发中尽量避免依赖这种深层合并行为，明确赋值最好。

### 💡 实战场景模拟

**场景**：用户点击“编辑资料”，保存后，我们需要更新 Store。

```typescript
// ❌ 普通写法（DevTools 里会产生 3 条记录）
function saveProfile(data) {
  userStore.name = data.name
  userStore.email = data.email
  userStore.avatar = data.avatar
}

// ✅ 优雅写法（DevTools 里只有 1 条记录，且语义清晰）
function saveProfile(data) {
  userStore.$patch({
    name: data.name,
    email: data.email,
    avatar: data.avatar
  })
}
```
