### 阶段一：基础上手（建立认知）
**目标**：会安装、会创建、会在组件里读写数据。

1.  **环境搭建**
    *   在 Vue 3 项目中安装 Pinia (`npm install pinia`)。
    *   在 `main.ts/js` 中挂载 `createPinia()`。
2.  **核心概念：Store 的定义**
    *   理解 `defineStore` 的两个参数（ID 和 配置对象）。
    *   **Options API 写法**（类似 Vue2/Vuex）：
        *   `state`: 定义数据（必须是函数返回对象）。
        *   `getters`: 计算属性（如何使用 `state`，如何使用 `this`）。
        *   `actions`: 修改数据的方法（同步和异步都在这里写）。
3.  **在组件中使用**
    *   如何引入 Store (`useXxxStore`)。
    *   读取 State。
    *   调用 Actions。
4.  **【重点】解构丢失响应式问题**
    *   错误写法：`const { count } = store` (数据会死掉，不再更新)。
    *   **核心解法**：`storeToRefs` 的使用（面试必考）。

> **🛑 阶段考核：** 你能写一个简单的“计数器”，并且在另一个组件点击按钮让它 +1 吗？你知道为什么不能直接解构 Store 里的变量吗？

### 阶段二：进阶语法（拥抱 Vue 3 风格）
**目标**：掌握 **Setup Store** 写法，这是企业级开发的主流，更灵活。

1.  **Setup Store 写法（函数式写法）**
    *   抛弃 `state/getters/actions` 对象。
    *   使用 `ref()` 定义 State。
    *   使用 `computed()` 定义 Getters。
    *   使用 `function` 定义 Actions。
    *   **对比**：理解 Options Store 和 Setup Store 的区别与优劣。
2.  **批量修改 State**
    *   直接修改：`store.count++`。
    *   `$patch` 对象写法：一次改多个字段。
    *   `$patch` 函数写法：处理复杂逻辑。
3.  **重置 State**
    *   Options Store 的 `$reset()`。
    *   Setup Store 如何自己实现重置（因为 Setup 模式原生不支持 `$reset`）。
4.  **Store 之间的相互调用**
    *   在 UserStore 的 action 里调用 CartStore 的数据。

> **🛑 阶段考核：** 你能用 Setup Store 重写之前的计数器吗？如果购物车 Store 需要用到用户信息 Store 里的 UserID，你怎么写？

### 阶段三：企业级实战（插件与持久化）
**目标**：解决刷新页面数据丢失问题，掌握插件机制。

1.  **数据持久化（必学）**
    *   痛点：F5 刷新页面，Pinia 里的数据全没了。
    *   手写方案：利用 `localStorage` + `store.$subscribe`。
    *   **企业方案**：使用 `pinia-plugin-persistedstate` 插件（配置简单，生产环境必备）。
2.  **Pinia 插件系统**
    *   理解 `pinia.use()`。
    *   如何给所有 Store 添加全局属性（比如全局的 API 请求实例）。
3.  **订阅 State 和 Actions**
    *   `$subscribe`：监听 State 变化（类似 Vue 的 `watch`）。
    *   `$onAction`：监听 Action 的调用（用于调试或埋点）。

> **🛑 阶段考核：** 刷新浏览器，你的计数器数值还在吗？如果不在，请配置插件让它保留。

### 阶段五：架构与最佳实践（团队协作）
**目标**：写出干净、可维护的代码。

1.  **目录结构规范**
    *   `src/stores` 下如何根据业务拆分文件（user.ts, cart.ts, global.ts）。
    *   是否需要 `index.ts` 进行统一导出。
2.  **模块化与命名空间**
    *   确保 Store ID 的唯一性。
3.  **业务逻辑剥离**
    *   不要把所有逻辑都写在组件里，尽量把业务逻辑移入 Pinia Actions（瘦组件，胖 Store）。
4.  **DevTools 调试**
    *   在 Vue DevTools 浏览器插件中查看 Pinia 面板，进行“时间旅行”调试。

### 阶段六：面试突击（收尾）
**目标**：应对面试官的“夺命连环问”。

**常见面试题准备：**
1.  **Pinia 和 Vuex 有什么区别？**（核心考点：去掉了 Mutation、体积更小、TS 支持更好、没有复杂的 Modules 嵌套）。
2.  **Pinia 为什么要去掉 Mutation？**（因为 Mutation 极其繁琐，且在 DevTools 升级后，Action 足以追踪状态变化）。
3.  **Setup Store 和 Options Store 选哪个？**（推荐 Setup Store，因为符合 Vue 3 组合式 API 心智，方便逻辑复用）。
4.  **Pinia 如何实现持久化？**（插件原理）。
5.  **`storeToRefs` 的作用是什么？原理是什么？**（将 State 里的非 Ref 数据转为 Ref，原理类似 `toRefs`）。
