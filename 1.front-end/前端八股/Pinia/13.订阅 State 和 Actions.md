**“订阅 State 和 Actions”**这两个功能（`$subscribe` 和 `$onAction`）属于 Pinia 的**进阶调试与副作用处理**功能。

简单来说：
*   如果你想在**数据变了**之后做点什么（比如存本地存储），用 `$subscribe`。
*   如果你想在**动作执行了**之后做点什么（比如埋点统计、计算耗时），用 `$onAction`。

---

### 第十一课：订阅机制 (Subscription)

#### 1. `$subscribe`: 监听状态变化

你可能会问：**“Vue 3 已经有 `watch` 了，为什么还要 `$subscribe`？”**

**区别在于**：
*   `watch`：通常用于监听**某个具体的 Ref**（比如 `store.count`）。
*   `$subscribe`：用于监听**整个 Store** 的变化，而且它能告诉你**是怎么变的**（是通过 `$patch` 还是直接赋值）。

**代码实战：**

```html
<script setup lang="ts">
import { useCartStore } from '@/stores/cart'

const cartStore = useCartStore()

// 开启订阅
// 参数 1: mutation (变化详情对象)
// 参数 2: state (变化后的最新状态 Proxy)
cartStore.$subscribe((mutation, state) => {
  
  // 1. 看看是谁改的数据
  console.log('变化类型:', mutation.type) 
  // 输出: 'direct' (直接赋值) | 'patch object' ($patch对象) | 'patch function'
  
  console.log('哪个Store变了:', mutation.storeId) // 'cart'

  // 2. 看看变成了什么 (这里可以做持久化)
  console.log('最新购物车:', state.items)
  
  // 实战用法：每次变化自动存 LocalStorage
  localStorage.setItem('cart', JSON.stringify(state.items))
}, { 
  // 【重要配置】
  // 默认情况下，如果组件卸载(unmount)，订阅也会被移除。
  // 如果你想让订阅一直存在（比如在 App.vue 里全局监听），设为 true
  detached: true 
})
</script>
```

#### 2. `$onAction`: 监听动作调用

这是 Vuex 没有的黑科技。它允许你拦截 Action 的执行过程（执行前、执行后、出错后）。

**最强应用场景：**
1.  **埋点分析**：用户点了“购买”，不管成功失败，我都要上报给后端统计。
2.  **错误日志**：所有 Action 只要报错，自动发送到 Sentry 监控平台。

**代码实战：**

```typescript
const store = useUserStore()

store.$onAction(({
  name,    // action 的名字 (例如 'login')
  store,   // store 实例
  args,    // 调用 action 传的参数数组
  after,   // 钩子：在 action 成功返回(promise resolve)后执行
  onError  // 钩子：在 action 报错(throw / promise reject)后执行
}) => {
  
  // --- 1. Action 执行前 ---
  const startTime = Date.now()
  console.log(`开始执行 Action: ${name}`)

  // --- 2. Action 执行后 (异步/同步均可) ---
  after((result) => {
    const duration = Date.now() - startTime
    console.log(`Action ${name} 执行成功! 耗时 ${duration}ms`)
    console.log('返回值:', result)
  })

  // --- 3. Action 报错后 ---
  onError((error) => {
    console.error(`Action ${name} 挂了! 原因:`, error)
    // uploadErrorLog(error) // 上报错误监控
  })
})
```

### 👹 面试官/架构师 视角 (深度解析)

#### ❓ 面试题 1：`$subscribe` 和 `watch()` 到底选哪个？
**答案**：
*   如果你只关心 **UI 逻辑**（比如 count 变了，我要把字体变红），用 **`watch`**。因为这符合 Vue 组件的开发习惯。
*   如果你要处理 **副作用**（Side Effects）或 **全局逻辑**（比如持久化、生成日志、同步 WebSocket），用 **`$subscribe`**。因为它更轻量（不需要深度遍历 Ref），且能提供 mutation 元数据。

#### ❓ 面试题 2：组件销毁后，Subscription 还在吗？
**答案**：
*   默认情况：**不在了**。Pinia 会自动清理绑定在当前组件上的订阅，防止内存泄漏。
*   特殊情况：如果你传入了 `{ detached: true }`，或者是在 `pinia.use()` 插件里调用的订阅，它们会**一直存在**，直到应用销毁。

#### ❓ 面试题 3：`$onAction` 能拦截并阻止 Action 执行吗？
**答案**：
**不能**。它只是一个“观察者”（Listener/Hook），它能知道 Action 什么时候开始、结束或出错，但它无法阻止 Action 本身的逻辑运行，也无法修改 Action 的返回值。它主要用于调试和审计。
