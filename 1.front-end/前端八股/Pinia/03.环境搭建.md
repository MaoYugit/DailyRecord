### 第一课：Pinia 环境搭建与初始化

#### 1. 安装 Pinia

打开你的 VS Code 终端（Terminal），确保你所在的目录是你的 Vue 项目根目录，执行以下命令：

```bash
npm install pinia
# 或者如果你用 yarn
# yarn add pinia
# 或者 pnpm
# pnpm add pinia
```

> **实战细节**：
> 安装完成后，建议去 `package.json` 看一眼 `dependencies`。
> *   如果你看到 **`pinia: "^2.x.x"`**，说明安装正确。
> *   **注意**：Pinia 2 是专门为 Vue 3 设计的。虽然 Pinia 2 也支持 Vue 2，但在 Vue 3 项目中我们默认使用 v2 版本。

---

#### 2. 在入口文件中挂载 (`main.ts` 或 `main.js`)

这是最关键的一步。我们需要创建一个 Pinia 实例，并把它“安装”到 Vue 应用中。

打开 `src/main.ts` (或 `main.js`)，修改代码如下：

```typescript
// src/main.ts

import { createApp } from 'vue'
import App from './App.vue'

// 1. 引入 createPinia
import { createPinia } from 'pinia'

const app = createApp(App)

// 2. 创建 Pinia 实例
const pinia = createPinia()

// 3. 将 Pinia 挂载到 Vue 应用上
// 这一步之后，所有的组件都可以使用 useStore 了
app.use(pinia)

app.mount('#app')
```

---

#### 3. 验证是否成功（实战技巧）

安装完了怎么知道好不好使？有两种方法：

**方法 A：查看 Vue DevTools（推荐）**
1.  运行项目 `npm run dev`。
2.  打开浏览器控制台（F12），切换到 **Vue** 标签页。
3.  点击 Inspector 里的设置或者组件树，如果能在左侧或者插件列表里看到 **🍍 Pinia** 的图标，说明安装成功！
    *   *如果没有安装 Vue DevTools，请务必去 Chrome/Edge 商店安装，开发 Vue 没有它是噩梦。*

**方法 B：简单粗暴 console**
在 `main.ts` 里打印一下：
```typescript
console.log(pinia)
```
如果控制台输出一个包含 `install`、`state`、`_s` 等属性的对象，说明实例创建成功。

### 👹 面试官/架构师 视角（深度解析）

这部分内容是让你在面试中脱颖而出的关键，也是从“码农”到“工程师”的区别。

#### ❓ 面试题 1：为什么是 `createPinia()` 而不是直接 `new Pinia()` 或者导出一个单例对象？

**答案：**
这是为了支持 **SSR (服务端渲染)** 和避免**单例污染**。

*   **场景**：如果 Pinia 导出一个全局单例对象（像老版本的 Vuex 经常做的那样），在服务端渲染时，如果不小心，用户 A 的数据可能会留在内存里，被用户 B 读到（比如用户 A 登录了，用户 B 刷新页面看到的也是 A 的登录状态）。
*   **Pinia 的做法**：每次调用 `createPinia()` 都会生成一个**全新、独立**的 Pinia 实例。
*   **Vue 3 风格**：这符合 Vue 3 `createApp` 的设计哲学——每个应用实例都是独立的。

#### ❓ 面试题 2：`app.use(pinia)` 到底干了什么？

**答案：**
这是 Vue 的插件机制（Plugin System）。
当执行 `app.use(pinia)` 时，Pinia 会在内部执行它的 `install` 方法：
1.  它把这个 Pinia 实例通过 `provide` 注入到 Vue 的全局系统中。
2.  它在 Vue 的全局属性（`config.globalProperties`）上挂载了 `$pinia`。
3.  **最重要的一点**：它让后续你在任何组件里调用 `useUserStore()` 时，这个 store 都能自动找到这个唯一的 Pinia 实例，而不需要你手动传递参数。

### ⚠️ 新手常见报错（坑）

**错误场景**：
你在 `main.ts` 还没执行 `app.use(pinia)` 之前，就在某个地方（比如路由守卫 `router/index.ts` 或者 API 拦截器外层）试图调用 Store。

**报错信息**：
`"getActivePinia()" was called but there was no active Pinia. Are you trying to use a store before calling "app.use(pinia)"?`

**解决方法**：
永远确保 `app.use(pinia)` 是在你的应用逻辑开始运行之前执行的。如果你要在路由守卫里用 Store，请在路由钩子函数**内部**调用 `useStore()`，而不是在文件最外层。
