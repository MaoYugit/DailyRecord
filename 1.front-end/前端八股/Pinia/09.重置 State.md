没问题。**“批量修改懂了，教我 Store 之间的相互调用”** 这一步我们先放一放，因为你现在的提纲要求是 **“重置 State”**。这是一个非常实际且面试常考的痛点。

Pinia 在这点上有一个非常有趣的“分裂”：Options Store 自带重置，而 Setup Store 却把这个功能“弄丢了”。

---

### 第七课：重置 State (Reset)

场景：用户点击“注销/退出登录”，你需要把购物车清空、用户信息清空、搜索记录清空。

#### 1. Options Store：简单得令人发指

如果你用的是 **Options API**（对象写法），Pinia 官方内置了 `$reset()` 方法。

```typescript
// src/stores/cart.ts (Options API)
export const useCartStore = defineStore('cart', {
  state: () => ({
    items: [],
    totalPrice: 0
  }),
  actions: {
    checkout() {
      // 结算逻辑...
      
      // 结算完成后，一键重置！
      // 这会重新运行 state() 函数，把所有数据变回初始值
      this.$reset() 
    }
  }
})
```

**组件中使用：**
```typescript
const cartStore = useCartStore()
cartStore.$reset() // 搞定
```

---

#### 2. Setup Store：为什么报错？（面试坑点）

如果你在 **Setup Store**（函数写法）里调用 `$reset()`：

```typescript
const store = useSetupStore()
store.$reset() // ❌ 报错：store.$reset is not a function
```

**原因（原理）**：
在 Setup Store 中，State 是由你手动创建的一个个 `ref` 或 `reactive`。Pinia 并没有把初始值存下来（它不知道哪一行代码是“初始状态”），所以它无法自动帮你回滚。

---

#### 3. Setup Store：如何实现重置？（企业级解决方案）

我们要手动实现这个逻辑。有两种主流方案：

**方案 A：笨办法（手动赋值）—— 适合数据少的 Store**

```typescript
export const useCounterStore = defineStore('counter', () => {
  const count = ref(0)
  const name = ref('Jack')

  // 自己写一个 reset 函数并暴露出去
  function $reset() {
    count.value = 0
    name.value = 'Jack'
  }

  return { count, name, $reset }
})
```

**方案 B：聪明办法（提取初始状态函数）—— 适合数据多的 Store**

利用 `$patch` 和一个外部函数来达成“一键还原”。

```typescript
import { defineStore } from 'pinia'
import { ref } from 'vue'

// 1. 把初始值提取成一个独立的函数
// 这样我们在 Store 内部和重置时都能复用它
function getInitState() {
  return {
    count: 0,
    user: { name: 'Guest', token: '' },
    items: [] as string[]
  }
}

export const useAppStore = defineStore('app', () => {
  // 2. 初始化时使用这个函数
  // 注意：这里用 ref 还是 reactive 看个人喜好，
  // 如果用 ref，需要解构或者一个个赋值，这里推荐用 ref 定义简单数据，或者 reactive 定义大对象
  const count = ref(getInitState().count)
  const user = ref(getInitState().user)
  const items = ref(getInitState().items)
  
  // 3. 实现 $reset
  function $reset() {
    // 利用 $patch 批量修改
    // 重新调用 getInitState() 拿到全新的初始值
    const initState = getInitState()
    
    // 这里需要注意：$patch 传入对象时，是合并逻辑
    // 如果是 ref，需要 .value 赋值；如果是 store 的顶层属性，可以用 $patch
    
    // 最简单的 Setup Store 重置其实是手动重置每个 ref：
    count.value = initState.count
    user.value = initState.user
    items.value = initState.items
  }

  return { count, user, items, $reset }
})
```

> **实战技巧**：说实话，方案 B 在 Setup Store 里写起来还是有点啰嗦。所以，**在很多大型企业项目中，如果某个 Store 需要频繁重置，开发者可能会特意为了这个功能而选择 Options API 写法**，或者使用 **Pinia 插件**。

---

#### 4. 终极方案：使用 Pinia 插件（进阶）

如果你不想在每个 Store 里都手写一遍 `$reset`，你可以写一个简单的 Pinia 插件来全局注入这个功能。

*这是面试加分项，能写出来说明你懂 Pinia 的底层扩展。*

在 `main.ts` 中：

```typescript
// 定义插件
function ResetStorePlugin({ store }) {
  // 缓存初始状态（深拷贝一份）
  const initialState = JSON.parse(JSON.stringify(store.$state))
  
  // 给 store 加上 $reset 方法
  store.$reset = () => {
    store.$patch(initialState)
  }
}

const pinia = createPinia()
// 使用插件
pinia.use(ResetStorePlugin)
```
*注意：这个插件方案对 Setup Store 的支持有限制（取决于你怎么定义 State），但在面试中提到“可以通过插件扩展 $reset”就是满分回答。*

### 👹 面试官/架构师 视角

#### ❓ 面试题 1：为什么 Setup Store 没有 `$reset`？
**答案**：
因为 Setup Store 是基于 Vue Composition API 的 `setup` 函数执行的。它没有明确的 `state` 配置项，变量是在闭包中创建的。Pinia 无法像 Options API 那样重新运行 `state()` 工厂函数来获取初始值。

#### ❓ 面试题 2：Options Store 的 `$reset` 是深拷贝还是浅拷贝？
**答案**：
它通过重新执行 `state: () => ({ ... })` 函数来生成新的状态对象，然后替换掉旧的。因为是重新运行函数返回新对象，所以是**全新的引用**，不存在深浅拷贝的问题（相当于重新 New 了一个对象）。
