### 第十课：Pinia 插件系统 (Plugins)

#### 1. 为什么要用插件？（DRY 原则）
假设你的项目里有 10 个 Store，每个 Store 都需要发 HTTP 请求（Axios）。
*   **笨办法**：在这 10 个文件里分别 `import axios from 'axios'`。
*   **聪明办法**：写一个 Pinia 插件，给所有的 Store 自动注入一个 `$api` 对象。以后你在 Store 里直接 `this.$api.get()` 就能用了。

#### 2. `pinia.use()` 的核心机制
Pinia 插件本质上就是一个**函数**。
当你在 `main.ts` 里执行 `pinia.use(myPlugin)` 时，Pinia 会把这个插件函数保存起来。
**关键点**：每当你创建一个 Store (`useXxxStore()`)，Pinia 就会把这个插件函数运行一次，把当前的 Store 实例传进去让你“魔改”。

---

#### 3. 实战：全局注入 API 实例

我们来实现一个需求：**给所有 Store 加上 `$api` 属性，并且加上一个 `secretKey` 静态属性。**

**Step 1: 编写插件 (比如 `src/plugins/piniaApi.ts`)**

```typescript
import axios from 'axios'
import type { PiniaPluginContext } from 'pinia'

// 创建一个 axios 实例
const service = axios.create({
  baseURL: 'https://api.example.com',
  timeout: 5000
})

// 插件函数
// context 参数包含了：store, app, pinia, options 等信息
export function ApiPlugin(context: PiniaPluginContext) {
  // 1. 可以直接给 store 挂载属性
  // 这种方式挂载的属性，不会被 devtools 追踪，适合静态数据
  context.store.secretKey = 'SK-123456'

  // 2. 【推荐】通过 return 一个对象来扩展 store
  // Pinia 会自动把返回的对象合并到 store 里
  // 这样在 devtools 里能看到，也能在组件里解构出来
  return {
    $api: service,
    hello: () => 'world'
  }
}
```

**Step 2: 注册插件 (`main.ts`)**

```typescript
import { createPinia } from 'pinia'
import { ApiPlugin } from './plugins/piniaApi'

const pinia = createPinia()

// 关键代码：注册插件
pinia.use(ApiPlugin)

app.use(pinia)
```

**Step 3: 在 Store 中使用**

```typescript
// src/stores/user.ts
export const useUserStore = defineStore('user', () => {
  // 注意：在 Setup Store 中，插件注入的属性（如 $api）
  // 虽然在这个函数体内不可见（因为它是后注入的），但它真实存在于实例上。
  // 在组件里使用 store.$api 是没问题的。
  
  // 如果非要在 Setup Store 内部用，通常直接 import axios 更方便。
  // 插件主要方便 Options API 或者 组件调用。
  
  function login() {
    // 假设这是 Options Store: this.$api.post(...)
    console.log('Login...')
  }
  return { login }
})
```

**Step 4: 在组件中使用**

```html
<script setup lang="ts">
import { useUserStore } from '@/stores/user'

const userStore = useUserStore()

// 直接调用插件注入的方法
console.log(userStore.secretKey) // 'SK-123456'
userStore.$api.get('/users').then(res => console.log(res))
</script>
```

#### 4. 【企业级必修】TS 类型声明 (Module Augmentation)

如果你正在写 TypeScript（你应该写！），上面的代码在 VS Code 里会**报错**：
> `Property '$api' does not exist on type 'Store<...>'`

因为 TS 不知道你通过插件偷偷塞了一个 `$api` 进去。你需要告诉 TS：“嘿，别慌，所有的 Store 都有 `$api` 属性。”

请在 `src` 下新建一个 `pinia.d.ts` (或者放在 `types` 目录下)：

```typescript
import 'pinia'
import type { AxiosInstance } from 'axios'

// 扩展 Pinia 的类型定义
declare module 'pinia' {
  // 给 Store 定义接口扩展
  export interface PiniaCustomProperties {
    // 定义我们注入的属性类型
    $api: AxiosInstance
    secretKey: string
    hello: () => string
  }
}
```

加了这个文件后，你在 Store 实例上点 `.`，VS Code 就会智能提示 `$api` 了。**这是面试中展示你 TS 功底的关键细节。**

#### 5. 进阶：拦截器与 Context

插件函数的 `context` 参数非常强大，里面有 `options`。
这允许我们在定义 Store 时传递自定义参数，让插件去读取。

**场景**：有的 Store 需要持久化，有的不需要，我们在 Store 定义时标记一下。

```typescript
// definition
defineStore('user', () => { ... }, {
  debounce: 300 // 自定义选项：防抖时间
})

// plugin
export function DebouncePlugin({ options, store }: PiniaPluginContext) {
  if (options.debounce) {
    // 拦截 action，添加防抖逻辑 (伪代码)
    // wrapActions(store, options.debounce)
    console.log(`Store ${store.$id} 开启了防抖，时间 ${options.debounce}`)
  }
}
```

### 👹 面试官/架构师 视角 (深度解析)

#### ❓ 面试题 1：`pinia.use()` 和 Vue 的 `app.use()` 有什么区别？
**答案**：
*   `app.use()` 是 Vue 的插件机制，用于安装 Router、Pinia、ElementPlus 等库。
*   `pinia.use()` 是 Pinia **内部**的插件机制，专门用于扩展 Store 的功能。它的粒度更细，只作用于 Pinia Store。

#### ❓ 面试题 2：插件是什么时候执行的？
**答案**：
这是一个陷阱题。插件**不是**在 `pinia.use()` 的时候执行的，而是在**每个 Store 被初始化 (`useStore()`) 的时候**执行的。
如果有 5 个 Store，插件函数就会运行 5 次，分别把这 5 个 Store 实例传给插件进行处理。

#### ❓ 面试题 3：Setup Store 这种函数式写法，如何访问插件注入的 `$api`？
**答案**：
在 Setup Store 的函数体内部（`defineStore('id', () => { ... })`），直接访问 `this` 往往是不安全的或不可用的。
**最佳实践**：
1.  如果是 Setup Store，通常直接 `import api from '@/api'` 使用，不强求走插件注入。
2.  或者通过 `const app = getCurrentInstance()` 获取上下文（不推荐，太 hack）。
3.  插件主要增强的是 **组件调用 Store 时的体验**（`store.$api`）以及 **Options API** 的体验。
