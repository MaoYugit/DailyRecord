收到。**“Options 写法我懂了，教我 Setup Store 写法”**。

这节课我们将解锁 Pinia 最强大的形态——**Setup Store**。

如果你习惯写 `<script setup>`，你会发现 Setup Store 的写法简直是**天作之合**。它完全抛弃了 Vuex 那种条条框框的模版，让写 Store 变得像写普通函数一样自由。

---

### 第五课：Setup Store（企业级主流写法）

#### 1. 核心映射关系
在开始写代码之前，先记住这个“翻译对照表”，一通百通：

| Options Store (旧) | Setup Store (新)                | 对应 Vue 3 API |
| :----------------- | :------------------------------ | :------------- |
| `state`            | **`ref()`** 或 **`reactive()`** | 响应式变量     |
| `getters`          | **`computed()`**                | 计算属性       |
| `actions`          | **`function`**                  | 普通函数       |

#### 2. 代码实现

我们在 `src/stores` 下新建一个文件 `counterSetup.ts`（为了区分之前的），体验一下这种清爽的感觉。

```typescript
import { defineStore } from 'pinia'
// 1. 引入 Vue 的组合式 API
import { ref, computed } from 'vue'

// 2. defineStore 的第二个参数变成了 "函数"
export const useCounterSetupStore = defineStore('counter-setup', () => {
  
  // A. 定义 State (使用 ref)
  const count = ref(0)
  const name = ref('Pinia Setup 风格')

  // B. 定义 Getters (使用 computed)
  const doubleCount = computed(() => count.value * 2)

  // C. 定义 Actions (使用 function)
  function increment() {
    // 记得加 .value，就像在组件里写代码一样
    count.value++
  }

  async function registerUser() {
    // 模拟异步
    await new Promise(r => setTimeout(r, 1000))
    name.value = '高级开发者 (Setup版)'
  }

  // D. 【关键】必须 return 出去
  // 只有 return 出去的内容，外界（组件）才能访问到
  // 没 return 的变量就是"私有变量" (Private State)，这是 Setup Store 的独门绝技
  return {
    count,
    name,
    doubleCount,
    increment,
    registerUser
  }
})
```

> **感受一下**：是不是跟在组件的 `<script setup>` 里写逻辑一模一样？

#### 3. 为什么 Setup Store 更强？（对比分析）

这部分是**架构决策**的关键，也是面试必问。

| 特性         | Options Store (对象写法)         | Setup Store (函数写法)          |
| :----------- | :------------------------------- | :------------------------------ |
| **上手难度** | 低，结构清晰，适合新手           | 中，需要熟悉组合式 API          |
| **逻辑复用** | 差 (很难复用 store 内部逻辑)     | **极强 (可以使用 Composables)** |
| **私有属性** | 不支持 (所有 state 都是公开的)   | **支持 (不 return 即可)**       |
| **$reset()** | 原生支持 (自带重置功能)          | **不支持 (需要自己实现)**       |
| **代码组织** | 强制分开写 (State/Getter/Action) | **自由组织** (相关逻辑写在一起) |

**✅ 企业级开发推荐**：
**强烈推荐使用 Setup Store**。
原因：它允许你把其他的 hook（比如 `useVueUse`、`useRouter`）直接用在 Store 里面！这就形成了强大的逻辑复用能力。

**举个例子（组合式能力的体现）：**
```typescript
// 在 Setup Store 里可以直接用 watch
export const useSearchStore = defineStore('search', () => {
  const keyword = ref('')
  
  // 以前在 Vuex 里很难做到监听 state 变化自动触发逻辑
  // 现在直接写 watch
  watch(keyword, (newVal) => {
    console.log('搜索词变了，自动发起请求:', newVal)
    // fetchResults(newVal)
  })

  return { keyword }
})
```

### ⚠️ 唯一的坑：`$reset()` 不见了

在 **Options Store** 中，如果你想把数据清空回初始状态，只需要调用 `store.$reset()`，Pinia 帮你自动搞定。

但在 **Setup Store** 中，`$reset()` 方法是**不存在的**！因为 Pinia 不知道你的初始值是什么（函数里的闭包环境）。

**面试题：如何在 Setup Store 中实现 reset？**
**解决方案**：
```typescript
export const useCounterStore = defineStore('counter', () => {
  const count = ref(0)
  
  // 手写一个 reset 方法
  function $reset() {
    count.value = 0
  }

  return { count, $reset }
})
```
*注：也有插件可以自动给 Setup Store 加回 `$reset`，但在面试中你要回答“默认不支持，需手写或用插件”。*

### 👹 面试官/架构师 视角（深度解析）

#### ❓ 面试题 1：Setup Store 写法中，可以直接替换整个 State 吗？
**答案**：
不建议。
在 Options API 里，我们可以 `store.$state = { count: 10 }`。
在 Setup API 里，`count` 是一个 `const count = ref(0)`，你不能把 `count` 变量重新赋值，你只能修改 `count.value`。
如果你非要替换整个 store 的状态，依然可以使用 `$patch`。

#### ❓ 面试题 2：Setup Store 内部可以使用 `inject` 吗？
**答案**：
可以！
因为 `defineStore` 的函数体是在 Vue 的 `setup()` 上下文中执行的。所以你可以使用 `inject()` 来获取全局配置，比如获取 `router` 或者 `i18n` 实例。这是 Options Store 做不到的（或者很难做到的）。
