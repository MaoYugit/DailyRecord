**泛型 Store**是 Pinia 的**终极形态**。如果你能熟练写出泛型 Store，说明你不仅懂 Vue，还懂**设计模式（工厂模式）**和 **TS 高级泛型**。

在大型后台管理系统中，我们经常会有很多**相似的业务**。
比如：`User`（用户列表）、`Product`（商品列表）、`Order`（订单列表）。
它们都有：
1.  **State**: `list`, `total`, `loading`, `page`。
2.  **Actions**: `getList()`, `deleteItem()`, `updateItem()`。

如果每个 Store 都复制粘贴一遍代码，不仅累，而且维护困难。
我们可以写一个 **“Store 工厂”**，传入不同的类型和 URL，自动生成一个完整的 Store。

---

### 第十五课：泛型 Store (Generic Store Factory)

#### 1. 核心思想：函数返回函数

普通 Store 定义：
```typescript
const useUserStore = defineStore('user', ...)
```

泛型 Store 定义（工厂模式）：
```typescript
// 这是一个函数，它接收参数，然后 "生产" 出一个 useStore 函数
function createCrudStore<T>(id: string, apiUrl: string) {
  return defineStore(id, ...)
}
```

#### 2. 实战代码：通用的 CRUD Store

我们来实现一个通用的“列表管理” Store。

**Step 1: 定义数据接口**
假设后端返回的标准列表结构如下：
```typescript
// src/types/common.ts
export interface ApiResponse<T> {
  code: number
  data: {
    list: T[]
    total: number
  }
}
```

**Step 2: 编写泛型 Store 工厂 (src/stores/factory/createListStore.ts)**

这是核心代码，请仔细看泛型 `<T>` 的流动位置。

```typescript
import { defineStore } from 'pinia'
import { ref } from 'vue'
import axios from 'axios' // 假设你有 axios
import type { ApiResponse } from '@/types/common'

// <T> 是每一行数据的类型（比如 UserInfo, ProductInfo）
export function createListStore<T>(storeId: string, apiUrl: string) {
  
  // 返回 defineStore
  return defineStore(storeId, () => {
    
    // 1. 通用 State
    // 注意这里用 ref<T[]> 约束数组内容
    const list = ref<T[]>([])
    const loading = ref(false)
    const total = ref(0)
    const page = ref(1)

    // 2. 通用 Actions
    async function loadData() {
      loading.value = true
      try {
        // 发送请求，利用泛型 T 约束返回结构
        const res = await axios.get<ApiResponse<T>>(apiUrl, {
          params: { page: page.value }
        })
        
        // 赋值
        // 这里 TS 会自动知道 res.data.data.list 是 T[] 类型
        list.value = res.data.data.list
        total.value = res.data.data.total
      } catch (e) {
        console.error(e)
      } finally {
        loading.value = false
      }
    }

    function deleteItem(index: number) {
      list.value.splice(index, 1)
      total.value--
    }

    // 3. 必须 Return
    return {
      list,
      loading,
      total,
      page,
      loadData,
      deleteItem
    }
  })
}
```

#### 3. 如何使用这个工厂？

现在我们不需要手写 UserStore 和 ProductStore 了，直接“生成”出来。

**Step 3: 生成具体的 Store (src/stores/modules.ts)**

```typescript
import { createListStore } from './factory/createListStore'
import type { UserInfo } from '@/types/user'
import type { ProductInfo } from '@/types/product'

// 🏭 工厂开工！

// 1. 生成用户 Store
// 传入泛型 <UserInfo>，TS 就知道 list 里装的是用户
export const useUserListStore = createListStore<UserInfo>('user-list', '/api/users')

// 2. 生成商品 Store
export const useProductListStore = createListStore<ProductInfo>('product-list', '/api/products')
```

**Step 4: 在组件中使用**

体验一下极其丝滑的 TS 提示。

```html
<script setup lang="ts">
import { useUserListStore } from '@/stores/modules'
import { onMounted } from 'vue'

const userStore = useUserListStore()

onMounted(() => {
  userStore.loadData()
})

// ✅ TS 提示生效！
// userStore.list[0].name (自动提示 UserInfo 的字段)
// userStore.loading (自动提示 boolean)
</script>

<template>
  <div v-if="userStore.loading">加载中...</div>
  <li v-for="user in userStore.list" :key="user.id">
    {{ user.name }}
  </li>
</template>
```

#### 4. 高级扩展：混合模式 (Mixin)

**痛点**：有时候工厂生成的 Store 不够用。比如 `ProductStore` 除了基础列表，还需要一个 `promote()` (促销) 的独有动作。

**解决方案**：我们可以创建一个基础 Store，然后在具体的 Store 里**组合**它（Composition）。

*注意：这就不完全是 Factory 模式了，而是 Composition API 的魅力。*

```typescript
// src/stores/product.ts
import { defineStore } from 'pinia'
import { createListStore } from './factory/createListStore'

// 先生成一个基础 Store 函数
const useBaseProductStore = createListStore<ProductInfo>('product-base', '/api/products')

export const useProductStore = defineStore('product', () => {
  // 1. 把基础 Store 的能力拿进来
  const baseStore = useBaseProductStore()
  
  // 2. 定义独有的 State/Action
  function promoteProduct(id: number) {
    console.log('促销商品', id)
  }

  // 3. 把基础的和独有的一起暴露出去
  return {
    ...storeToRefs(baseStore), // 注意：解构 state 需要 storeToRefs
    loadData: baseStore.loadData, // action 直接赋值
    promoteProduct // 独有 action
  }
})
```

### 👹 面试官/架构师 视角

#### ❓ 面试题 1：泛型 Store 和 Vue Hooks (Composables) 有什么区别？
**答案**：
*   **Composables (`useFetch`)**：通常是**局部状态**。你在组件 A 和组件 B 里分别调用 `useFetch`，它们的状态是不共享的（除非你在外部定义了 reactive 变量）。
*   **泛型 Store**：是**全局状态**。它生成的 `useUserListStore` 是一个真正的 Pinia Store。无论你在哪个组件调用，拿到的都是同一份用户列表数据，且可以在 DevTools 里看到 `'user-list'` 这个 ID。

#### ❓ 面试题 2：为什么不用 Class 继承来实现（像 OOP 那样）？
**答案**：
虽然 JS 支持 Class，但在 Vue 3 生态中，**组合式函数 (Composition Functions)** 是更推荐的代码复用方式。
使用 Class 继承 Store 会导致 `this` 指向复杂、TS 类型推导困难，且不符合 `setup()` 的设计哲学。函数工厂 (`createXxxStore`) 更轻量、更清晰。
