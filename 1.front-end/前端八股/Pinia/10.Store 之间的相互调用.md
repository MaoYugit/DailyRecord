收到。**“重置学会了，教我 Store 之间的相互调用”**。

这在实际项目中太常见了。比如：
*   **结算时**：购物车 Store 需要调用用户 Store，查看余额够不够，或者是不是 VIP（打折）。
*   **注销时**：用户 Store 点击退出，需要调用购物车 Store 把数据清空。

在 Pinia 中，Store 之间的交互**非常简单**，甚至比 Vuex 还要简单。你只需要记住一句话：**在需要的地方引入，直接调用即可。**

### 第八课：Store 之间的相互调用

我们模拟一个最经典的场景：**购买商品**。
1.  **UserStore**：存着用户的余额（Wallet）。
2.  **ProductStore**：存着商品价格，且负责执行“购买”这个动作。

**需求**：在 `ProductStore` 的 `buy()` 动作中，去扣除 `UserStore` 里的钱。

#### 1. 准备 UserStore (被调用方)

先定义用户仓库，很简单，就存个钱。

```typescript
// src/stores/user.ts
import { defineStore } from 'pinia'
import { ref } from 'vue'

export const useUserStore = defineStore('user', () => {
  const balance = ref(100) // 用户有 100 块钱
  const name = ref('Jack')

  function deductMoney(amount: number) {
    if (balance.value >= amount) {
      balance.value -= amount
      return true
    }
    return false
  }

  return { balance, name, deductMoney }
})
```

#### 2. 编写 ProductStore (调用方)

这里是重点。看我们如何在一个 Store 里把另一个 Store 拿进来。

```typescript
// src/stores/product.ts
import { defineStore } from 'pinia'
import { ref } from 'vue'
// 1. 引入别的 Store
import { useUserStore } from './user'

export const useProductStore = defineStore('product', () => {
  const goodsName = ref('MacBook Pro')
  const price = ref(20) // 便宜卖了

  // Action: 购买逻辑
  function buy() {
    // 2. 【关键】在 Action 内部实例化另一个 Store
    // 注意：不要在最外层实例化，要在函数内部！
    const userStore = useUserStore()

    // 3. 像在组件里一样使用它
    console.log(`当前用户: ${userStore.name}, 余额: ${userStore.balance}`)

    // 调用 UserStore 的方法扣钱
    if (userStore.deductMoney(price.value)) {
      console.log('购买成功！')
    } else {
      console.log('购买失败，余额不足')
    }
  }
  
  // Getter: 也可以在 getter 里用
  // 比如：如果用户是 VIP (userStore.isVip)，商品打8折
  // computed(() => { ... const user = useUserStore() ... })

  return { goodsName, price, buy }
})
```

---

### 3. 核心原则（面试考点）

#### 为什么要在 Action/Getter **内部** 调用 `useUserStore()`？

虽然在 Store 顶部调用（定义完 state 后立马调用）有时候也能跑通，但**强烈建议**在 `actions` 或 `getters` 内部调用。

**原因**：
1.  **避免初始化顺序问题**：Pinia 是按需加载的。如果在文件顶部直接调用，可能会遇到“Pinia 还没安装好就尝试创建 Store”的报错。
2.  **性能优化**：只有当真正执行 `buy()` 这个动作时，才去获取 UserStore 的实例。

---

### ⚠️ 致命陷阱：循环依赖 (Circular Dependency)

这是架构设计中最大的坑，面试官如果问 Store 调用，必然会问这个问题。

**场景**：
*   Store A 的 action 引用了 Store B。
*   Store B 的 action 又引用了 Store A。

**代码表现**：
```typescript
// storeA.ts
import { useStoreB } from './storeB'
// ... action: storeB.doSomething()

// storeB.ts
import { useStoreA } from './storeA'
// ... action: storeA.doSomething()
```

**后果**：
浏览器会报错（堆栈溢出或者 undefined），因为两个文件在解析时互相等待对方。

**解决方案（面试标准答案）**：
1.  **让组件做中间人**：组件同时调用 Store A 和 Store B，分别传参。
    *   *组件说：StoreA，你给我数据；StoreB，你拿这个数据去处理。*
2.  **提取共享 Store**：把 A 和 B 共用的数据提取到第三个 `GlobalStore` 中，A 和 B 都去引用 Global。

---

### 👹 面试官/架构师 视角

#### ❓ 面试题 1：可以在 Getters 里调用其他 Store 吗？
**答案**：
可以。
```typescript
getters: {
  userDiscountPrice(state) {
    const userStore = useUserStore()
    // 如果用户是 VIP，打折
    return userStore.isVip ? state.price * 0.8 : state.price
  }
}
```
Pinia 会自动处理依赖追踪。当 `userStore.isVip` 变化时，这个 getter 也会自动重新计算。

#### ❓ 面试题 2：Store 之间的数据交互是耦合的吗？
**答案**：
是的，这引入了耦合。
`ProductStore` 此时强依赖于 `UserStore`。
**优化建议**：如果业务逻辑特别复杂，建议在组件层（Component）或者 服务层（Service/Composables）进行编排，保持 Store 的纯粹性。但在中小型项目中，Store 互相调用完全没问题，开发效率最高。
