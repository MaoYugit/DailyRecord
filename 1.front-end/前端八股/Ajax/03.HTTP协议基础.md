很多前端开发者会写代码，但不懂 HTTP，导致遇到 Bug 只会瞎猜，面试时问到底层原理就卡壳。

我们要把 HTTP 当作**“快递系统”**来理解：
*   **浏览器**是发货人。
*   **服务器**是收货人。
*   **HTTP 报文**就是快递单和包裹。

---

### 第一部分：请求报文与响应报文 (解剖快递)

你必须学会如何在浏览器控制台（Network 面板）看懂这些东西。

#### 1. 请求报文 (Request) —— 你发给后端的
它由三部分组成：
1.  **行 (Start Line)**：`POST /api/login HTTP/1.1` (方法 + 路径 + 协议版本)
2.  **头 (Headers)**：**最重要**。
    *   `Content-Type`: 告诉后端我发的是什么格式（JSON? 表单? 文件?）。
        *   `application/json` (Axios 默认)
        *   `multipart/form-data` (上传文件必用)
        *   `application/x-www-form-urlencoded` (老式表单)
    *   `Authorization`: `Bearer eyJhbGci...` (你的身份证/Token)。
3.  **体 (Body)**：具体数据（例如：`{ "username": "admin", "password": "123" }`）。**注意：GET 请求通常没有 Body。**

#### 2. 响应报文 (Response) —— 后端回给你的
1.  **行**：`HTTP/1.1 200 OK` (协议 + **状态码** + 描述)
2.  **头**：`Set-Cookie`, `Content-Type` (后端返回的是图片还是 JSON?)
3.  **体**：后端返回的实际数据 `data`。

#### 3. 核心状态码 (Status Codes) —— 面试必考

面试官问：“说一下你常见的状态码”，不要只背数字，要结合场景：

*   **2xx (成功)**
    *   🟢 **200 OK**：最常见，请求成功，数据拿到了。

*   **3xx (重定向/缓存)**
    *   🟡 **301 Moved Permanently**：永久重定向。比如网站从 `http` 升级到 `https`，浏览器下次会自动去新地址，不问服务器了。
    *   🟡 **304 Not Modified**：**（性能优化核心）** 资源未修改。浏览器去请求图片或 JS，服务器告诉浏览器：“如果你本地缓存里有这个文件，且没过期，就直接用本地的吧，别浪费我的带宽。”

*   **4xx (客户端错误 —— 你的锅)**
    *   🔴 **400 Bad Request**：前端参数传错了。比如后端要 JSON 你传了表单，或者必填字段没传。
    *   🔴 **401 Unauthorized**：**“你没登录”**。Authentication（认证）失败。通常是因为 Header 里没带 Token，或者 Token 过期了。
        *   *实战动作*：跳转到登录页。
    *   🔴 **403 Forbidden**：**“你登录了，但没权限”**。Authorization（授权）失败。比如普通用户想删管理员的数据。
        *   *实战动作*：提示“无权访问”。
        *   *面试陷阱*：401 是“不知道你是谁”，403 是“知道你是谁，但不让你进”。
    *   🔴 **404 Not Found**：**“地址写错了”**。请求的 URL 在服务器上找不到。

*   **5xx (服务端错误 —— 后端的锅)**
    *   💥 **500 Internal Server Error**：后端代码崩了（空指针、数据库连不上等）。前端要把锅甩过去。
    *   💥 **502 Bad Gateway**：通常是网关（Nginx）没连上后面的服务（Node/Java 挂了）。

### 第二部分：HTTP 方法 (动作指令)

RESTful API 设计风格中，不同的方法代表对资源的不同操作。

#### 1. 常见方法
*   **GET**：获取资源（读）。
*   **POST**：新建资源（写）。
*   **PUT**：更新资源（**全量**更新）。比如更新用户，你得把用户的所有字段都传过去，没传的可能会被覆盖为空。
*   **PATCH**：更新资源（**部分**更新）。比如只修改密码，只传密码字段即可。
*   **DELETE**：删除资源。
*   **OPTIONS**：**“侦察兵”**。浏览器在发送跨域请求前，会自动先发一个 OPTIONS 请求，询问服务器：“我能连你吗？我能带 Header 吗？”（后面讲 CORS 细说）。

#### 2. ⚔️ 面试重灾区：GET 和 POST 的区别？

不要只回答“GET 参数在 URL，POST 在 Body”，这太浅了。你要分三个层次回答：

**层次一：表面区别（规范层面）**
1.  **数据位置**：GET 参数拼在 URL 后面（`?id=1`）；POST 数据放在 Body 里。
2.  **长度限制**：浏览器对 URL 长度有限制（通常几 KB），所以 GET 不能传大数据；POST Body 理论上无限制。
3.  **安全性**：GET 参数直接暴露在浏览器地址栏和历史记录里，**绝对不能用 GET 传密码**；POST 相对隐蔽（但不用 HTTPS 一样被抓包）。
4.  **缓存**：GET 请求会被浏览器主动缓存；POST 默认不会。

**层次二：语义区别（RESTful）**
*   **GET 是幂等的（Idempotent）**：也就是无论请求多少次，资源的状态都不会改变（就像读新闻，你读 100 次，新闻内容还在那里，不会变）。
*   **POST 是非幂等的**：请求多次，可能会创建多份资源（就像下单，点两次可能下两单）。

**层次三：底层原理（TCP 层面 - 加分项）**
*   *本质*：GET 和 POST 本质都是 TCP 链接，没有差别。
*   *数据包传输（这也是争议点，但可以作为知识点提）*：
    *   对于 GET，浏览器通常会把 Header 和 Data 一起发送（发 1 个数据包）。
    *   对于 POST，浏览器（如 Chrome）可能会先发 Header，服务器响应 100 Continue，然后再发 Body（发 2 个数据包）。**但这取决于浏览器实现，不是 HTTP 协议的规定。**

### 第三部分：跨域 (CORS) —— 前端永远的痛

#### 1. 什么是同源策略 (Same-Origin Policy)？
这是浏览器的**安全机制**。
如果两个 URL 的 **协议 (Protocol)**、**域名 (Domain)**、**端口 (Port)** 只要有一个不一样，就是**跨域**。

*   `http://localhost:8080` (你的 Vue 项目)
*   `http://api.myserver.com` (后端接口)
*   **结果**：浏览器默认**禁止** Vue 代码读取后端返回的数据。

#### 2. 什么是 CORS (Cross-Origin Resource Sharing)？
跨域资源共享。它是解决跨域最标准的方案。
**关键点：跨域的决定权在后端。** 后端要在响应头里告诉浏览器：“我允许这个域名来请求我”。

#### 3. 预检请求 (Preflight Request - OPTIONS)
不是所有请求都需要预检。浏览器把请求分为两类：

*   **简单请求 (Simple Request)**：
    *   方法是 GET, HEAD, POST。
    *   Header 里只有通用的，没有自定义 Header（如 `Authorization`）。
    *   Content-Type 只能是表单格式，**不能是 application/json**。
    *   *流程*：直接发请求 -> 后端返回 -> 浏览器检查 Header 决定是否拦截。

*   **复杂请求 (Complex Request)** —— **Axios 默认发的几乎都是这个**
    *   因为 Axios 默认 Content-Type 是 `application/json`。
    *   因为我们通常会带 `Authorization` Token。
    *   *流程*：
        1.  浏览器自动先发一个 **OPTIONS** 请求（侦察兵）。
        2.  询问：“我可以用 JSON 吗？我能带 Token 吗？”
        3.  后端如果点头（返回 204 或 200，且 Header 正确）。
        4.  浏览器才会发出真正的 POST/GET 请求。

#### 4. 关键响应头
如果面试官问：“后端需要配什么头才能解决跨域？”
你回答：
*   `Access-Control-Allow-Origin`: 允许的域名（如 `http://localhost:8080` 或 `*`）。
*   `Access-Control-Allow-Headers`: 允许带的头（如 `Content-Type, Authorization`）。
*   `Access-Control-Allow-Methods`: 允许的方法（如 `PUT, DELETE`）。

#### 5. 实战中的跨域解决方案

1.  **开发环境 (Local)**:
    使用 Vite/Webpack 的 **Proxy (反向代理)**。
    *   *原理*：浏览器 -> 本地 Node 服务器 (同源，无跨域) -> 转发给后端。因为**服务器与服务器之间没有同源策略**。
    *   *配置* (`vite.config.ts`):
        ```typescript
        server: {
          proxy: {
            '/api': {
              target: 'http://backend-api.com',
              changeOrigin: true
            }
          }
        }
        ```
2.  **生产环境 (Prod)**:
    通常由 **Nginx** 进行反向代理，或者后端开启 **CORS**。

1. 如果在 Chrome Network 里看到一个请求状态码是 **OPTIONS**，这是什么意思？为什么会产生？

*   **是什么意思：**
    这是一个 **“预检请求” (Preflight Request)**。它不是你代码里直接写的业务请求，而是**浏览器自动发出**的一种探测请求。它的目的是在发送真正的请求之前，询问服务器：“我可以用这个方法、带这些 Header 来访问你吗？”
*   **为什么会产生：**
    这是 **CORS (跨域资源共享)** 机制的一部分。当你的请求被浏览器判定为 **“非简单请求” (Complex Request)** 时，就会触发 OPTIONS。
    常见的触发条件包括：
    1.  **Content-Type** 是 `application/json` (最常见的情况)。
    2.  请求方法是 PUT, DELETE, PATCH 等（非 GET/POST/HEAD）。
    3.  请求头里包含了**自定义 Header**（例如 `Authorization: Bearer xxx` 或 `X-Token`）。

2. 如果你发送请求收到 **401**，通常应该在前端代码里做什么操作？

*   **含义：** 401 Unauthorized 表示 **“未授权”**，即服务器不认识你，或者你的身份凭证（Token/Cookie）过期/无效了。
*   **前端的标准操作流程：**
    1.  **拦截错误：** 在 axios 拦截器或 fetch 的错误处理中捕获该状态码。
    2.  **清理状态：** 清除本地存储的过期的 Token、用户信息 (localStorage/sessionStorage/Vuex/Redux)。
    3.  **跳转登录：** 使用路由 (Router) 强制跳转到 **登录页 (Login Page)**，让用户重新登录。
    4.  *(进阶)* **尝试刷新 Token：** 如果系统设计了 Refresh Token 机制，可以在跳转登录前，先尝试用 Refresh Token 换取新的 Access Token，如果换取成功则重发原请求，只有换取失败才踢出用户。

3. GET 请求能不能传 JSON 数据？

*   **结论：** **在浏览器环境中，不能（或者说不应该）。**
*   **详细解释：**
    *   **技术层面：** HTTP 协议规范并没有明确禁止 GET 请求带 Body（请求体），但在语义上 GET 是用于“获取资源”的。
    *   **现实层面：** 绝大多数浏览器（Chrome, Firefox 等）和网络库（fetch, axios, XMLHttpRequest）会自动忽略或禁止在 GET 请求中发送 Body。如果你强行在 axios 的 GET 请求里放 `data`，它通常会被忽略或者报错。
    *   **正确做法：** GET 请求的数据应该拼接在 **URL 的查询参数 (Query String)** 中（例如 `?id=1&name=test`）。
    *   *特例：* 某些服务端工具（如 Elasticsearch）允许 GET 带 Body，但这属于非标准用法，前端开发中通常不予考虑。
