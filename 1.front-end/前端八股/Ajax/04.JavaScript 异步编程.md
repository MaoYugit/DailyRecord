这是 JS 进阶中最“劝退”但也最“拉分”的章节。
不懂 Event Loop，你永远不知道为什么数据明明回来了，页面却没更新；不懂 Promise 原理，面试官让你手写代码时只能干瞪眼。

我们要解决的核心问题是：**JavaScript 是单线程的（一次只能做一件事），那它是怎么处理成百上千个网络请求而不卡死的？**

---

### 第一部分：Event Loop (事件循环) —— JS 的调度中心

**面试必考题：** “请说出下面代码的打印顺序。”（先看懂原理，最后有题）

#### 1. 核心概念
JS 就像一个**很忙的餐厅厨师**（主线程），他一次只能炒一道菜。
*   **同步任务 (Synchronous)**：切菜、炒菜。厨师必须立刻做。
*   **异步任务 (Asynchronous)**：
    *   **宏任务 (MacroTask)**：客人下单（`script`）、定个闹钟（`setTimeout`）、网络请求回调（Ajax）。
    *   **微任务 (MicroTask)**：厨师自己答应的小承诺（`Promise.then`）、Vue 的 `nextTick`。

#### 2. 运行机制 (The Loop)
1.  **执行栈**：厨师先做完所有手头紧要的事（同步代码）。
2.  **微任务队列**：同步做完了，厨师擦汗时，**必须**先把所有答应的小承诺（MicroTask）做完。
3.  **渲染**：如果有必要，浏览器更新页面。
4.  **宏任务队列**：去接下一个大单（比如 `setTimeout` 时间到了，或者 Ajax 请求回来了），拿出**一个**来执行。
5.  **循环**：回到第 1 步。

**口诀：** **同步 > 所有微任务 > 渲染 > 一个宏任务**

#### 3. ⚔️ 实战/面试 经典代码题
```javascript
console.log('1'); // 同步

setTimeout(function() {
    console.log('2'); // 宏任务
}, 0);

Promise.resolve().then(function() {
    console.log('3'); // 微任务
});

console.log('4'); // 同步
```

*   **解析**：
    1.  遇到 `log('1')` -> **打印 1**。
    2.  遇到 `setTimeout` -> 把它扔到**宏任务队列**里排队（哪怕是 0ms，也要排队）。
    3.  遇到 `Promise.then` -> 把它扔到**微任务队列**里排队。
    4.  遇到 `log('4')` -> **打印 4**。
    5.  主线程（同步）空了。
    6.  **关键点**：先清空微任务！执行 `log('3')` -> **打印 3**。
    7.  微任务空了，去拿一个宏任务。执行 `setTimeout` 回调 -> **打印 2**。

*   **最终顺序**：1 -> 4 -> 3 -> 2

### 第二部分：Promise —— 异步编程的救世主

在 Promise 出现之前，我们处理异步全是“回调地狱”（Callback Hell）。

#### 1. 基础用法回顾
*   **三种状态**：
    *   `pending` (进行中)
    *   `fulfilled` (成功/resolved) -> 触发 `.then`
    *   `rejected` (失败) -> 触发 `.catch`
    *   **注意**：状态一旦改变（例如从 pending 变成 fulfilled），就永远不会再变了。

#### 2. ✋ 手写简易版 Promise (高频面试题)
面试官让你写 Promise，不是让你写一个完美的库，而是看你**懂不懂状态管理和回调存储**。

```javascript
class MyPromise {
    constructor(executor) {
        // 1. 初始化状态
        this.state = 'pending';
        this.value = undefined; // 成功的值
        this.reason = undefined; // 失败的原因
        
        // 存放回调函数（因为 .then 可能在状态改变前就调用了）
        this.onResolvedCallbacks = [];
        this.onRejectedCallbacks = [];

        // 2. 定义 resolve 函数（给开发者用的）
        const resolve = (value) => {
            // 只有 pending 才能改变状态
            if (this.state === 'pending') {
                this.state = 'fulfilled';
                this.value = value;
                // 状态变了，把之前存起来的 .then 回调都执行一遍
                this.onResolvedCallbacks.forEach(fn => fn());
            }
        }

        // 3. 定义 reject 函数
        const reject = (reason) => {
            if (this.state === 'pending') {
                this.state = 'rejected';
                this.reason = reason;
                this.onRejectedCallbacks.forEach(fn => fn());
            }
        }

        // 4. 立即执行传入的函数 (同步执行！)
        try {
            executor(resolve, reject);
        } catch (err) {
            reject(err);
        }
    }

    // 5. then 方法
    then(onFulfilled, onRejected) {
        // 如果状态还没变（比如请求还在发），就把回调存起来
        if (this.state === 'pending') {
            this.onResolvedCallbacks.push(() => {
                onFulfilled(this.value);
            });
            this.onRejectedCallbacks.push(() => {
                onRejected(this.reason);
            });
        }
        // 如果状态已经变了，直接执行
        if (this.state === 'fulfilled') {
            onFulfilled(this.value);
        }
        if (this.state === 'rejected') {
            onRejected(this.reason);
        }
    }
}
```

**面试关键点解释：**
1.  **Executor 是同步的**：`new Promise( (resolve) => { ... } )` 里的代码是**立即执行**的。
2.  **then 是异步的**：`.then` 里的代码会被放入微任务队列。
3.  **发布订阅模式**：如果状态是 pending，就把 `.then` 里的函数存到数组里；等 `resolve` 触发时，再遍历数组执行。

### 第三部分：Async/Await —— 终极解决方案

这也是你以后写 Vue 项目用得最多的写法。它本质上是 **Generator + Promise 的语法糖**。

#### 1. 为什么它是主流？
它让异步代码看起来像同步代码，可读性极高。

*   **Promise 写法**：
    ```javascript
    axios.get('/user')
        .then(res => {
            return axios.get('/posts?uid=' + res.data.id);
        })
        .then(posts => {
            console.log(posts);
        })
        .catch(err => {
            console.log(err);
        });
    ```
*   **Async/Await 写法**：
    ```javascript
    async function getData() {
        try {
            const user = await axios.get('/user');
            // 代码会在这里“暂停”，直到 user 请求回来，才往下走
            const posts = await axios.get('/posts?uid=' + user.data.id);
            console.log(posts);
        } catch (err) {
            // 专门捕获 reject 的情况
            console.log(err);
        }
    }
    ```

#### 2. ⚠️ 实战中的“性能陷阱” (企业级开发必知)

这是初级开发和高级开发的区别。

**场景**：你需要获取“用户信息”和“系统配置”，这两个接口**没有依赖关系**。

**❌ 错误的写法 (串行 - 慢)：**
```javascript
// 假设每个请求耗时 1秒
const user = await axios.get('/user'); // 等1秒
const config = await axios.get('/config'); // 再等1秒
// 总共耗时 2秒
```
这种写法会导致第二个请求必须等第一个请求结束才开始。

**✅ 正确的写法 (并行 - 快)：**
```javascript
// 同时发出两个请求
const userPromise = axios.get('/user');
const configPromise = axios.get('/config');

// 等待它们全部完成
const [user, config] = await Promise.all([userPromise, configPromise]);
// 总共耗时 1秒（取决于最慢的那个）
```
**面试官问：** “如何优化多个无关联的 await 请求？”
**答：** “使用 `Promise.all` 进行并发请求。”

### 🟢 随堂测试 (检查你懂没懂)

**题目 1 (Event Loop 升级版)**：
```javascript
console.log('1');

async function async1() {
    console.log('2');
    await async2(); // 注意：await 后面的代码相当于放在 .then 里
    console.log('3'); // 它是微任务
}

async function async2() {
    console.log('4');
}

setTimeout(() => {
    console.log('5');
}, 0);

async1();

new Promise((resolve) => {
    console.log('6');
    resolve();
}).then(() => {
    console.log('7');
});

console.log('8');
```

**请在心里推导一下顺序，然后再看答案。**

---
---
---

---

**答案解析：**

**第一步：执行同步代码**

1. console.log('1');
   - 直接打印 **1**。
2. setTimeout(...)
   - 这是**宏任务**。把它扔进【宏任务队列】，等待下一轮。
   - *目前宏任务队列：[log('5')]*
3. async1(); 被调用
   - 进入 async1 内部，执行 console.log('2');，直接打印 **2**。
   - 遇到 await async2();：
     - 先执行 async2() 函数。
     - 进入 async2，执行 console.log('4');，直接打印 **4**。
     - **关键点**：await 这一行执行完后，async1 剩下的代码（即 console.log('3')）被“冻结”了，它被包装成一个**微任务**，扔进【微任务队列】。
   - *目前微任务队列：[log('3')]*
4. new Promise(...)
   - **注意**：Promise 的构造函数（Constructor）部分是**同步**的，立即执行。
   - 执行 console.log('6');，直接打印 **6**。
   - resolve() 被调用，Promise 状态变为成功。
   - 遇到 .then(...)：这是**微任务**。把回调函数扔进【微任务队列】。
   - *目前微任务队列：[log('3'), log('7')]*
5. console.log('8');
   - 直接打印 **8**。

**第二步：清空微任务队列**

JS 引擎问：“有微任务吗？”
有，队列里是：[log('3'),log('7')]。按顺序执行。

1. 取出第一个微任务（async1 醒来继续执行）：
   - 执行 console.log('3');，打印 **3**。
2. 取出第二个微任务（Promise 的 .then）：
   - 执行 console.log('7');，打印 **7**。

**第三步：执行宏任务**

JS 引擎问：“有宏任务吗？”
有，队列里是：[log('5')]。

1. 取出 setTimeout 的回调：
   - 执行 console.log('5');，打印 **5**。

------

**结果：1 -> 2 -> 4 -> 6 -> 8 -> 3 -> 7 -> 5**

(注意：老版本浏览器 `await` 的微任务顺序可能略有不同，但现代浏览器遵循 V8 标准，通常是这个顺序)。
