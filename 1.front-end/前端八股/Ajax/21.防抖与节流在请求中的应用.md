这是前端性能优化中**最经典、最基础、面试必问**的话题。
它不仅仅是“写个函数”那么简单，它关乎到你对**服务器压力**的理解。

试想：如果不做防抖，用户在搜索框输入 "iPhone 15 Pro Max"（15个字符），你的前端会瞬间发出 15 次请求。
*   **后果**：服务器负载爆炸，用户带宽被占满，页面卡顿。
*   **目标**：把 15 次请求变成 1 次（只搜最后输入的完整关键词）。

### 第一部分：核心概念 (用人话解释)

面试官问：“简单说一下防抖和节流的区别？”
请用下面的**生活案例**回答，保准满分。

#### 1. 防抖 (Debounce) —— "最后一个人说了算"
*   **生活比喻**：**电梯关门**。
    *   电梯准备关门，突然跑过来一个人，电梯门重新打开，**重新倒计时**。
    *   如果一直有人进进出出，电梯就一直不关门。
    *   只有当门口没人进出了（静止了一段时间），电梯才会真的关门。
*   **应用场景**：**输入框搜索**、窗口缩放 (Resize) 后计算布局。
*   **策略**：动作停止后 X 秒才执行。

#### 2. 节流 (Throttle) —— "按规定的频率执行"
*   **生活比喻**：**机关枪开火** / **玩游戏技能冷却**。
    *   不管你怎么疯狂点击鼠标（触发事件），子弹只能按照每秒 10 发的频率打出去。
    *   技能 CD 是 5 秒，你按 100 次也只能放一次。
*   **应用场景**：**滚动加载 (Infinite Scroll)**、按钮防止重复点击（虽然按钮通常用 loading 状态更好）。
*   **策略**：不管触发多频繁，每隔 X 秒只执行一次。

### 第二部分：实战 —— 输入框搜索防抖 (Vue 3 写法)

在企业项目中，我们通常不需要自己手写防抖函数，而是直接用 `lodash-es` 库。这是标准做法。

**安装 Lodash:**
```bash
npm install lodash-es
npm install -D @types/lodash-es # TS 项目需要
```

#### 1. 基础用法 (结合 watch)

```vue
<script setup lang="ts">
import { ref, watch } from 'vue';
import { debounce } from 'lodash-es';
import axios from 'axios';

const keyword = ref('');
const result = ref([]);

// 定义具体的业务逻辑
const searchApi = async (val) => {
    if (!val) return;
    console.log('发起请求:', val); // 只有这里打印才说明真的发请求了
    const res = await axios.get('/api/search', { params: { q: val } });
    result.value = res.data;
};

// 🔥 核心：创建防抖函数
// debounce(函数, 延迟时间)
// 这意味着：handleSearch 被频繁调用时不会执行，只有停下来 500ms 后，才会执行 searchApi
const debouncedSearch = debounce((val) => {
    searchApi(val);
}, 500);

// 监听输入框变化
watch(keyword, (newVal) => {
    // 这里每输入一个字都会触发
    console.log('用户输入:', newVal);
    
    // 调用防抖后的函数
    debouncedSearch(newVal);
});
</script>

<template>
    <input v-model="keyword" placeholder="请输入搜索内容..." />
    <ul>
        <li v-for="item in result" :key="item.id">{{ item.name }}</li>
    </ul>
</template>
```

**效果演示：**
1.  用户快速输入 "123"。
2.  控制台打印 3 次 "用户输入..."。
3.  停顿 0.5 秒。
4.  控制台打印 **1 次** "发起请求: 123"。

### 第三部分：面试手写题 —— 手写防抖函数

面试官递给你纸和笔：“别用 lodash，给我手写一个简易的 debounce。”
考察点：**闭包 (Closure)** 和 **定时器 (Timer)**。

```javascript
/**
 * @param {Function} fn - 要执行的函数
 * @param {Number} delay - 延迟时间 (ms)
 */
function myDebounce(fn, delay) {
    let timer = null; // 1. 利用闭包保存定时器变量

    return function(...args) { // 返回一个新的函数
        // 2. 如果此时又有新动作，把之前的定时器清掉！
        // 这就是“电梯重新开门”
        if (timer) clearTimeout(timer);

        // 3. 重新开启倒计时
        timer = setTimeout(() => {
            // 4. 时间到了，执行真正的逻辑
            // apply 是为了修正 this 指向（虽然在箭头函数时代不那么重要了，但面试要写）
            fn.apply(this, args);
        }, delay);
    };
}

// 使用
const run = myDebounce((text) => console.log('发送请求', text), 1000);
run('a'); 
run('ab');
run('abc'); // 只有这最后一次会在 1秒后执行
```

### 第四部分：高级应用 —— Vue 3 `customRef` 实现防抖

这是 Vue 3 的**装逼技巧**。我们可以利用 `customRef` 创建一个自带防抖功能的变量。
面试时甩出这个，说明你对 Vue 3 响应式原理有研究。

**useDebounceRef.js:**
```javascript
import { customRef } from 'vue';

export function useDebouncedRef(value, delay = 500) {
    let timer;
    
    // customRef 允许我们控制依赖收集 (track) 和 触发更新 (trigger)
    return customRef((track, trigger) => {
        return {
            get() {
                track(); // 告诉 Vue 追踪这个变量
                return value;
            },
            set(newValue) {
                // 值的变化过程被拦截了
                clearTimeout(timer);
                
                timer = setTimeout(() => {
                    value = newValue;
                    trigger(); // 告诉 Vue 变量更新了，去刷新视图/触发 watch
                }, delay);
            }
        };
    });
}
```

**组件中使用：**
```vue
<script setup>
import { watch } from 'vue';
import { useDebouncedRef } from './useDebouncedRef';

// 这个 text 变量本身就是防抖的！
// 它的值不会随着输入立刻变，而是输入停止 500ms 后才变
const text = useDebouncedRef('', 500);

watch(text, (val) => {
    // 这里的 watch 不需要再套 debounce 了
    // 因为 text 变量本身的变化就是延迟的
    console.log('发起请求:', val);
});
</script>

<template>
    <!-- v-model 看起来没区别，但实际上数据更新被延迟了 -->
    <input v-model="text" />
    <p>搜索词: {{ text }}</p>
</template>
```

### 第五部分：防抖 vs 取消请求 (CancelToken) —— 终极辨析

**面试官问：** “既然你做了防抖，还需要做取消请求（AbortController）吗？”

**答：** **需要。两者解决的问题不同，互为补充。**

1.  **防抖 (Debounce)**：
    *   **作用阶段**：请求**发出前**。
    *   **目的**：减少请求发出的**次数**，给服务器省力。
    *   *局限*：如果用户输入 "A"，停了 1秒（发出了请求 A），然后又输入 "B"，停了 1秒（发出了请求 B）。这时候防抖拦不住。

2.  **取消请求 (AbortController)**：
    *   **作用阶段**：请求**发出后**。
    *   **目的**：解决**网络竞态**问题（防止旧请求覆盖新请求）。
    *   *局限*：它不能减少请求次数，它只是忽略旧的结果。

**最佳实践：**
**防抖 + 取消请求 = 完美搜索体验**
*   用户疯狂输入 -> 防抖拦截，不发请求。
*   用户停顿 -> 防抖放行，请求 A 发出。
*   用户又输入并停顿 -> 防抖放行，请求 B 发出。同时 **Abort** 掉还在路上的请求 A。

### 🟢 随堂测试

**题目 1**：
滚动加载更多数据（Infinite Scroll），应该用防抖还是节流？为什么？

**题目 2**：
下面的代码有什么 bug？
```javascript
<script setup>
import { debounce } from 'lodash-es';

// ❌ 错误示范
const handleInput = (val) => {
    // 每次输入都重新创建了一个新的 debounce 函数！
    // 结果：每次都会执行，防抖完全失效
    const fn = debounce(() => { axios.get(...) }, 500);
    fn();
}
</script>
```

---
---

**参考答案：**

1.  **节流 (Throttle)**。
    因为滚动时，用户没有“停下来”的动作，我们要的是“在滚动过程中，每隔 200ms 检查一次滚动条位置”。如果用防抖，用户一直滚，就一直不检查，直到用户停下来才加载，体验很卡。

2.  **Bug 原因**：`debounce` 函数必须在**组件初始化时创建一次**，保存起来反复调用。不能在事件回调里每次都 `new` 一个新的。
    *   *修正*：把 `const fn = debounce(...)` 移到函数外面去。
