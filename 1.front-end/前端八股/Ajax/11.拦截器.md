这是整个 Axios 封装中**含金量最高、代码最核心**的部分。
面试官问“你是如何封装 Axios 的？”，主要就是想听你讲这两个拦截器里的逻辑。

我们将拦截器比喻为**“高速公路的收费站”**：
1.  **请求拦截器 (进站口)**：在车（请求）上路之前，检查有没有驾照（Token），给车身贴个标签，顺便把栏杆抬起（Loading 开始）。
2.  **响应拦截器 (出站口)**：车回来了，检查车有没有撞坏（错误处理），把车上的货物卸下来（解包数据），放下栏杆（Loading 结束）。

我们基于 Vue 3 + Element Plus 来写一段企业级的标准代码。

---

### 0. 准备工作

先创建文件 `src/utils/request.ts`。

```typescript
import axios from 'axios';
import { ElMessage } from 'element-plus'; // UI 组件库
import router from '@/router'; // 路由对象
// 假设你用 Pinia 管理用户状态
import { useUserStore } from '@/store/user'; 

// 1. 创建实例 (上一节学的)
const service = axios.create({
    baseURL: import.meta.env.VITE_API_URL,
    timeout: 10000
});
```

### 第一部分：请求拦截器 (Request Interceptor)

**核心任务：**
1.  **注入 Token**：这是 JWT (JSON Web Token) 认证机制的标准做法。
2.  **开启全局 Loading**：让用户知道“正在加载中”，防止重复点击。

```typescript
service.interceptors.request.use(
    (config) => {
        // --- 任务 1: 自动携带 Token ---
        const userStore = useUserStore();
        if (userStore.token) {
            // ⚠️ 面试点：标准格式通常是 "Bearer " + token
            // 必须修改 config.headers
            config.headers.Authorization = `Bearer ${userStore.token}`;
        }

        // --- 任务 2: 开启 Loading (可选) ---
        // 实际开发中，通常会使用 NProgress (顶部进度条) 或全屏 Loading
        // NProgress.start(); 
        
        // ⚠️ 关键点：必须返回 config，否则请求就发不出去了！
        return config;
    },
    (error) => {
        // 请求还没发出去就崩了（很少见）
        return Promise.reject(error);
    }
);
```

---

### 第二部分：响应拦截器 (Response Interceptor) —— 重头戏

**核心任务：**
1.  **解包数据**：去掉 Axios 的壳。
2.  **关闭 Loading**。
3.  **统一错误处理**：这是最考验架构能力的。

```typescript
service.interceptors.response.use(
    // 🟢 1. 成功态 (HTTP 状态码 2xx)
    (response) => {
        // 关闭 Loading
        // NProgress.done();

        // --- 任务 1: 解包数据 ---
        // 我们只想要服务器返回的 data，不想要 axios 的 headers/config/status
        const res = response.data;

        // ⚠️ 进阶场景 (看后端约定)：
        // 有些后端虽然返回 HTTP 200，但在 body 里用 code 字段表示错误
        // 例如: { code: 50001, msg: "密码错误", data: null }
        if (res.code && res.code !== 200) {
            ElMessage.error(res.msg || '业务出错');
            return Promise.reject(new Error(res.msg || 'Error'));
        }

        return res;
    },

    // 🔴 2. 失败态 (HTTP 状态码 非 2xx，如 401, 404, 500)
    (error) => {
        // 关闭 Loading
        // NProgress.done();

        // 提取错误信息
        // error.response 包含后端返回的响应对象
        // error.message 是 axios 生成的错误信息
        const { response } = error;
        
        if (response) {
            // --- 任务 2: 根据状态码做不同的处理 ---
            const status = response.status;
            
            switch (status) {
                case 401:
                    // 💀 最重要的 401 处理：Token 过期或未登录
                    ElMessage.error('登录状态已过期，请重新登录');
                    
                    // 1. 清除本地过期的 Token
                    const userStore = useUserStore();
                    userStore.logout();

                    // 2. 跳转到登录页
                    // router.push('/login'); 
                    // 💡 优化：跳转后，登录成功带回当前页
                    router.push(`/login?redirect=${router.currentRoute.value.fullPath}`);
                    break;
                
                case 403:
                    ElMessage.error('您没有权限访问该资源');
                    break;
                
                case 404:
                    ElMessage.error('请求的接口不存在');
                    break;
                
                case 500:
                    ElMessage.error('服务器内部错误，请联系管理员');
                    break;
                    
                default:
                    ElMessage.error(response.data.msg || '未知错误');
            }
        } else if (error.message.includes('timeout')) {
            // 网络超时
            ElMessage.error('请求超时，请检查网络');
        } else {
            // 断网了
            ElMessage.error('网络连接断开');
        }

        // ⚠️ 关键点：一定要 reject 出去！
        // 这样组件里的 try...catch 才能捕获到错误
        return Promise.reject(error);
    }
);

export default service;
```

### 第三部分：使用效果对比

**封装前 (组件内代码)：**
```javascript
// 又臭又长
try {
    const res = await axios.get('/user', {
        headers: { Authorization: 'Bearer ' + token } // 每次都要手动加 Token
    });
    // 每次都要手动判断 200
    if (res.status === 200) {
         // 每次都要多写一层 .data
        console.log(res.data.data);
    }
} catch (err) {
    if (err.response.status === 401) {
        router.push('/login'); // 每次都要手动写跳转
    }
    // ...写一堆 switch case
}
```

**封装后 (组件内代码)：**
```javascript
import request from '@/utils/request';

// 清爽、专注于业务
try {
    const data = await request.get('/user'); // 自动加 Token，自动解包
    console.log(data); // 直接拿到数据
} catch (err) {
    // 错误处理已经被拦截器干掉了，这里只需要处理“业务逻辑错误”
    // 或者根本不用写 try-catch，因为拦截器里已经弹窗提示了
    console.log('组件知道出错了，停止 loading 动画即可');
}
```

### ⚔️ 面试突击检查

**Q1: 在响应拦截器里，为什么最后要 `return Promise.reject(error)`？**
*   **答**：如果不 return reject，Promise 链会进入“成功”的回调（`.then`）。
    这意味着组件会误以为请求成功了，拿到了一个 `undefined` 数据，导致页面报错（白屏）。必须 reject 才能中断 Promise 链，或者让组件进入 `catch` 块。

**Q2: 如何防止 401 弹窗重复出现？**
*   *场景*：页面并发了 5 个请求，Token 刚好过期。5 个请求都会报 401，导致拦截器弹 5 次窗，重定向 5 次登录页。
*   *思路*：设置一个标志位 `isRelogging`。如果正在重定向中，后续的 401 只拦截请求，不弹窗、不跳转。

**Q3: 解包数据有什么风险？**
*   *风险*：如果我们直接返回 `response.data`，我们就拿不到 HTTP Header 了。如果业务需要从 Header 里取分页总数 (`X-Total-Count`)，这种“一刀切”的解包就不行。
*   *解决*：可以约定一个特殊的配置参数，比如 `request.get('/url', { _returnRaw: true })`，在拦截器里判断如果为 true 就不解包。
