这一章标志着你从“写 Demo”正式跨入“工程化开发”。

在简单的练习项目中，直接 `import axios` 然后到处用是可以的。但在企业级项目中，如果你还在直接使用全局的 `axios` 对象，代码 Review 时一定会被骂。

**核心问题：为什么要用 `axios.create()`？**

---

### 第一部分：场景痛点 (为什么要用？)

想象一下，你正在开发一个大型电商管理后台，你的前端需要对接三个完全不同的后端服务：

1.  **业务 API** (`https://api.mall.com`)：
    *   响应快，超时设置 5秒。
    *   需要 Header 携带 `Token`。
2.  **文件上传服务** (`https://upload.server.com`)：
    *   文件很大，超时需要设置 60秒。
    *   不需要 Token，但需要特殊的 `Content-Type: multipart/form-data`。
3.  **第三方高德地图 API** (`https://restapi.amap.com`)：
    *   完全不同的域名。
    *   不需要 Token，但需要 `Key`。

**❌ 如果你只用全局 axios (错误示范)：**

```javascript
import axios from 'axios';

// 设置了全局默认值
axios.defaults.baseURL = 'https://api.mall.com';
axios.defaults.timeout = 5000;

// 请求业务 -> 没问题
axios.get('/user'); 

// 请求上传 -> 完蛋了
// 必须手动覆盖配置，代码极其丑陋，而且容易忘
axios.post('https://upload.server.com/file', data, {
    baseURL: '', // 必须重置，否则会拼成 api.mall.com/https://upload...
    timeout: 60000 // 手动覆盖超时
});
```
这种写法叫**“污染全局”**。一旦你改了全局配置，所有请求都会受影响，极其难以维护。

---

### 第二部分：解决方案 —— `axios.create()`

`axios.create()` 就像一个**工厂**。它可以生产出多个**相互独立**的 Axios 实例（Instance）。
每个实例都有自己的“私有配置”，互不干扰。

**✅ 正确示范 (多实例模式)：**

```javascript
// src/utils/request.js (或者 api/index.js)

// 1. 创建业务 API 实例
const service = axios.create({
    baseURL: 'https://api.mall.com', // 基础地址
    timeout: 5000,                   // 5秒超时
    headers: { 'X-Custom-Header': 'foobar' }
});

// 2. 创建上传服务实例
const uploadService = axios.create({
    baseURL: 'https://upload.server.com',
    timeout: 60000 // 60秒超时
    // 这里没有 X-Custom-Header，完全独立
});

// 3. 使用它们
// service.get('/user')  -> 请求 https://api.mall.com/user
// uploadService.post('/') -> 请求 https://upload.server.com/
```

---

### 第三部分：实例的功能

创建出来的实例（比如上面的 `service`），它**几乎拥有**全局 `axios` 的所有功能：

1.  **拥有同样的请求方法**：
    *   `service.get(...)`
    *   `service.post(...)`
    *   `service.request(...)`

2.  **拥有独立的拦截器 (Interceptors)** —— **这是最重要的！**
    *   你可以给 `service` 实例加一个拦截器：发现 401 就跳登录页。
    *   你可以给 `uploadService` 实例加另一个拦截器：上传进度条处理。
    *   它们互不影响。我们将在下一节详细讲这个。

---

### 第四部分：企业级项目结构推荐

在 Vue 3 项目中，我们通常会在 `src/utils/` 下创建一个 `request.ts` (或 .js) 文件，专门用来生成这个实例。

```typescript
// src/utils/request.ts
import axios from 'axios';

// 1. 创建实例
const request = axios.create({
    baseURL: import.meta.env.VITE_API_URL, // 从环境变量读取地址 (后面会讲)
    timeout: 5000
});

// 2. (后面会在这里添加拦截器...)

// 3. 导出实例
export default request;
```

然后在 API 文件中使用它：

```javascript
// src/api/user.js
import request from '@/utils/request'; // 引入我们创建的实例，而不是 axios 包

export function getUser(id) {
    return request.get(`/users/${id}`);
}
```

### 🟢 随堂测试 (面试模拟)

**面试官问：**
“在微服务架构下，前端可能要请求 `user-service` (端口8001) 和 `order-service` (端口8002)，你会怎么封装 Axios？”

**请简述你的思路。**

---
---

**参考回答：**
> “我会利用 `axios.create` 创建两个不同的实例。
> 比如创建 `userRequest` 实例，将 baseURL 设为 8001 端口；创建 `orderRequest` 实例，将 baseURL 设为 8002 端口。
> 这样它们的基础配置（如 baseURL、超时时间）是隔离的，而且我可以为它们分别配置不同的拦截器逻辑（比如订单服务可能需要特殊的加密 Header），从而实现代码的高内聚和低耦合。”

---

搞懂了“为什么要创建实例”，接下来就是 Axios 最强大的功能，也是封装的核心：
**拦截器（Interceptors）—— 请求拦截与响应拦截**。
