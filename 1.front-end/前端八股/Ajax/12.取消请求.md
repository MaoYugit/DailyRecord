**取消请求**是 Axios 高级应用中非常关键的一环，也是区分“初级切图仔”和“高级工程师”的分水岭。

在实际开发中，如果不处理取消请求，轻则导致**页面数据错乱（竞态问题）**，重则导致**服务器压力过大**或**组件卸载后报错**。

这一章我们将深入讲解 **旧标准 (CancelToken)** 和 **新标准 (AbortController)**，并重点解决两个业务场景。

---

### 为什么要取消请求？

想象一个场景：
1.  你在搜索框输入 "V"，前端发了请求 A。
2.  你紧接着输入 "Vu"，前端发了请求 B。
3.  **结果**：请求 B 先回来了（数据是 "Vu" 的结果），页面渲染正确。
4.  **灾难**：过了一会儿，请求 A 终于回来了（因为它网络慢）。**页面瞬间被覆盖成了 "V" 的搜索结果。**

这就叫**竞态问题 (Race Condition)**。用户明明搜的是 "Vu"，结果看到的是 "V"。
解决办法：**在发 B 之前，把 A 杀掉。**

---

### 第一部分：新旧方案对比

#### 1. AbortController (新标准 - 推荐 🔥)
这是现代浏览器原生提供的 API（Fetch 也是用它）。Axios 从 `v0.22.0` 开始支持。
*   **优点**：符合 DOM 标准，语法简洁。
*   **用法**：
    ```javascript
    const controller = new AbortController();
    
    axios.get('/user/123', {
       signal: controller.signal // 把信号传进去
    });
    
    // 取消请求
    controller.abort();
    ```

#### 2. CancelToken (旧标准 - 已废弃 ⚠️)
虽然官方标记为 Deprecated，但很多 2021 年以前的老代码还在用，面试可能会问到。
*   **用法**：
    ```javascript
    const CancelToken = axios.CancelToken;
    const source = CancelToken.source();
    
    axios.get('/user/123', {
       cancelToken: source.token
    });
    
    // 取消请求
    source.cancel('用户取消了操作');
    ```

**结论：** 新项目无脑用 **AbortController**。下文我们将全部使用新标准演示。

### 第二部分：场景实战一 —— 频繁点击/搜索 (竞态处理)

**场景描述**：用户疯狂点击“查询”按钮，或者在输入框快速打字。我们要保证**只有最后一次请求有效**，前面的全部取消。

**Vue 3 实战代码：**

```vue
<script setup>
import { ref } from 'vue';
import axios from 'axios';

const searchText = ref('');
const result = ref(null);

// 1. 定义一个变量用来存储当前的控制器
let abortController = null;

const handleSearch = async () => {
    // 2. 检查：如果之前有正在进行的请求，直接取消掉！
    if (abortController) {
        abortController.abort();
    }

    // 3. 创建新的控制器，分配给当前请求
    abortController = new AbortController();

    try {
        const response = await axios.get('/api/search', {
            params: { q: searchText.value },
            // ⚠️ 关键：绑定 signal
            signal: abortController.signal
        });

        // 请求成功回来，渲染数据
        result.value = response.data;
        // 请求完成了，控制器就可以置空了
        abortController = null;

    } catch (error) {
        // 4. ⚠️ 错误处理关键点
        // 被取消的请求也会进入 catch，必须区分“人为取消”和“真正报错”
        if (axios.isCancel(error)) {
            console.log('前一个请求被取消了，不用管');
        } else {
            console.error('网络真出错了:', error);
        }
    }
};
</script>

<template>
    <input v-model="searchText" @input="handleSearch" placeholder="输入搜索...">
    <div>{{ result }}</div>
</template>
```

**逻辑图解：**
输入 "A" -> 创建 Controller 1 -> 发请求 1
输入 "B" -> **Abort Controller 1** -> 创建 Controller 2 -> 发请求 2
结果：请求 1 即使回来了，也不会执行 `result.value = ...`，因为它在 `await` 那一步就抛出异常进 `catch` 了。

### 第三部分：场景实战二 —— 路由切换取消请求

**场景描述**：
用户进入“数据大屏”页面，这个页面有 10 个图表请求，加载很慢。
用户等不及了，点了“返回首页”。
**问题**：如果请求不取消，它们会在后台继续跑，浪费带宽。等请求回来时，由于组件已经卸载（Unmounted），如果代码里还试图更新响应式数据，Vue 可能会报警告，或者浪费内存。

#### 方案 A：单个组件内处理 (最基础)

利用 Vue 的生命周期钩子 `onBeforeUnmount`。

```javascript
import { onBeforeUnmount } from 'vue';
import axios from 'axios';

// 存储当前组件所有的控制器
const controllers = [];

const getChartData = async () => {
    const controller = new AbortController();
    controllers.push(controller); // 记录下来
    
    try {
        await axios.get('/chart-data', { signal: controller.signal });
    } catch (err) {
        // ...
    }
}

// 组件卸载前，把列表里所有的请求全部杀掉
onBeforeUnmount(() => {
    controllers.forEach(ctrl => ctrl.abort());
});
```

#### 方案 B：全局自动化处理 (架构师思维 🔥)

如果在每个页面都写上面的代码，太累了。我们可以在 **Axios 拦截器 + Vue Router** 层面做全局封装。

**思路**：
1.  定义一个全局 Map，存储所有正在进行的请求。
2.  **请求拦截器**：生成 `AbortController`，存入 Map。
3.  **响应拦截器**：请求完成了，从 Map 中删除。
4.  **路由守卫 (`router.beforeEach`)**：路由切换时，遍历 Map，把所有请求取消掉。

**代码实现 (request.js 进阶版)：**

```javascript
// src/utils/request.js
const pendingMap = new Map(); // 存储 key: url, value: controller

/**
 * 生成唯一的 Key，用于标识请求
 * 格式：[method] /api/user {"id":1}
 */
function getPendingKey(config) {
    return [config.method, config.url, JSON.stringify(config.params), JSON.stringify(config.data)].join('&');
}

/**
 * 添加请求到 Map
 */
function addPending(config) {
    // 自动移除重复请求（可选：防抖功能）
    removePending(config); 
    
    const controller = new AbortController();
    config.signal = controller.signal; // 绑定 signal
    
    const key = getPendingKey(config);
    pendingMap.set(key, controller); // 存进去
}

/**
 * 移除并取消请求
 */
function removePending(config) {
    const key = getPendingKey(config);
    if (pendingMap.has(key)) {
        const controller = pendingMap.get(key);
        controller.abort(); // 杀掉！
        pendingMap.delete(key); // 删掉记录
    }
}

// --- 拦截器集成 ---

service.interceptors.request.use(config => {
    addPending(config); // 请求开始，记录
    return config;
});

service.interceptors.response.use(
    response => {
        removePending(response.config); // 请求成功，移除
        return response.data;
    },
    error => {
        removePending(error.config || {}); // 请求失败，移除
        // 如果是取消的，不需要弹窗报错
        if (axios.isCancel(error)) {
            console.log('请求被取消:', error.message);
            return Promise.reject(error); // 依然 reject，但在组件里忽略
        }
        // ...其他错误处理
        return Promise.reject(error);
    }
);

/**
 * 暴露一个清空所有请求的方法 (给路由守卫用)
 */
export function clearAllPending() {
    for (const [key, controller] of pendingMap) {
        controller.abort();
    }
    pendingMap.clear();
}
```

**路由守卫集成 (router/index.js)：**

```javascript
import { clearAllPending } from '@/utils/request';

router.beforeEach((to, from, next) => {
    // 路由切换时，直接把上一页未完成的请求全部杀掉！
    clearAllPending();
    next();
});
```

这样一来，你的应用就具备了**自动清理**的能力，性能和健壮性直接拉满。

### ⚔️ 面试突击 Q&A

**Q1: `controller.abort()` 执行后，服务器那边还会处理请求吗？**
*   **答**：**会。**
    这是一个非常重要的概念。取消请求只是**浏览器**停止接收响应，并抛出一个错误。请求报文很可能已经到达服务器，服务器依然会查询数据库、计算逻辑。
    *除非*：是上传大文件，浏览器断开 TCP 连接，服务器读取流中断，才能真正省下服务器资源。

**Q2: 取消请求后，Promise 会变成什么状态？**
*   **答**：Promise 会变成 **Rejected** 状态。
    错误对象 `error` 的 `code` 通常是 `ERR_CANCELED`。
    一定要配合 `axios.isCancel(err)` 来判断，否则用户的控制台会全是红色的报错，以为系统崩了。

**Q3: 原生 fetch 怎么取消？**
*   **答**：完全一样。Fetch API 的第二个参数也接受 `{ signal: controller.signal }`。这是 DOM 标准，Axios 只是复用了它。

### 🟢 随堂测试

请阅读以下代码，判断控制台会打印什么？

```javascript
const controller = new AbortController();

axios.get('/api/slow-request', { signal: controller.signal })
    .then(() => console.log('成功'))
    .catch((err) => {
        if (axios.isCancel(err)) {
            console.log('A');
        } else {
            console.log('B');
        }
    });

// 立即执行取消
controller.abort();
```

---
---

**答案：**
打印 **"A"**。
因为 `abort()` 会导致 Promise 立即被 reject，并且错误类型被标记为 Cancel，所以 `axios.isCancel` 返回 true。
