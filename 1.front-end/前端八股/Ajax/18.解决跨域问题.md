这是前端开发环境配置中**最基础但也最容易配错**的环节。

很多新手遇到的情况是：明明配了 proxy，控制台还是报 404 或者跨域错误。原因通常是没理解 **Path Rewrite（路径重写）** 的原理。

---

### 第一部分：核心原理 —— “欺骗”浏览器

我们知道 **同源策略** 是浏览器的限制，**服务器与服务器之间** 通信是没有跨域限制的。

**Vite Proxy 的工作流程（中间人攻击）：**

1.  **前端 (浏览器)**：想请求 `http://backend.com/api/user`，但因为跨域被挡住了。
2.  **前端 (配置代理后)**：浏览器改为请求 `http://localhost:5173/api/user`（向 Vite 开发服务器发请求）。
    *   因为端口都是 5173，**同源**，浏览器放行 ✅。
3.  **Vite 开发服务器 (Node.js)**：收到 `/api/user`，发现你配置了代理。
4.  **Vite**：偷偷把请求转发给 `http://backend.com/api/user`。
5.  **后端**：收到请求，返回数据给 Vite。
6.  **Vite**：把数据转发回给浏览器。

**结论：** 浏览器以为自己在跟 Vite 玩，其实 Vite 只是个无情的转发机器。

---

### 第二部分：配置实战 (`vite.config.ts`)

假设你的后端接口真实地址是：`http://localhost:8080/user`。

打开 `vite.config.ts`，加入 `server` 配置：

```typescript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  
  // 🔥 核心配置在这里
  server: {
    // open: true, // 运行 npm run dev 时自动打开浏览器
    proxy: {
      // 1. 匹配规则：所有以 '/api' 开头的请求，都会被拦截
      '/api': {
        // 2. 目标地址：代理转发给谁？
        target: 'http://localhost:8080',
        
        // 3. 允许跨域 (其实是修改 Host 头，欺骗后端)
        // 如果后端限制了 Origin，这个必须为 true
        changeOrigin: true,

        // 4. 路径重写 (Path Rewrite) —— 最容易错的地方！
        // 解释：
        // 前端发：/api/user
        // 如果不重写，发给后端的是：http://localhost:8080/api/user
        // 如果后端接口就是 /user，那这就 404 了。
        // 所以要把 /api 抹去。
        rewrite: (path) => path.replace(/^\/api/, '')
      }
    }
  }
})
```

---

### 第三部分：路径重写 (Rewrite) 的三种情况

这是面试和实战中最搞脑子的地方。取决于**后端接口有没有 `/api` 前缀**。

**场景 A：后端接口本身【没有】 `/api`**
*   后端地址：`http://localhost:8080/user`
*   前端代码：`axios.get('/api/user')`
*   **需要重写**：我们需要把 `/api` 去掉，才能对上后端的号。
*   配置：`rewrite: (path) => path.replace(/^\/api/, '')`
*   结果：`/api/user` -> `/user` ✅

**场景 B：后端接口本身【有】 `/api`**
*   后端地址：`http://localhost:8080/api/user`
*   前端代码：`axios.get('/api/user')`
*   **不需要重写**：前端发的和后端要的刚好一样。
*   配置：**删除 rewrite 这一行**。
*   结果：`/api/user` -> `/api/user` ✅

**场景 C：由环境变量控制 (企业级写法)**
在 `request.js` 里，我们通常使用 `baseURL: import.meta.env.VITE_API_URL`。
*   `.env.development`: `VITE_API_URL = /api`
*   `.env.production`: `VITE_API_URL = https://api.prod.com`

### 第四部分：致命误区 —— 生产环境无效！

**面试官必问：** “Vite 配置的 proxy 在 `npm run build` 打包后还有效吗？”

**答：** **完全无效！**

*   `server.proxy` 是 **Vite 开发服务器 (Dev Server)** 的功能。
*   当你打包 (`build`) 后，生成的是纯静态的 `.html`, `.js`, `.css` 文件。这些文件通常部署在 Nginx 或 Apache 上，**Vite 服务器已经不存在了**。

**生产环境跨域怎么解？**
1.  **Nginx 反向代理** (最常用)：在 Nginx 配置里把 `/api` 转发给后端端口。
2.  **后端开启 CORS**：后端代码里设置 `Access-Control-Allow-Origin: *`。

### 🟢 随堂测试 (排错题)

**背景**：
后端接口地址是：`http://www.test.com/v1/list`
前端想写：`axios.get('/api/list')`

**你的配置**：
```javascript
proxy: {
  '/api': {
    target: 'http://www.test.com',
    changeOrigin: true,
    rewrite: (path) => path.replace(/^\/api/, '') 
  }
}
```

**问题**：请求发出去后，后端报 404。请问真实的请求地址变成了什么？为什么错了？

---
---

**答案解析：**

1.  **真实请求变成了**：`http://www.test.com/list`
2.  **为什么错了**：
    *   前端发 `/api/list`。
    *   `rewrite` 把 `/api` 删了，变成了 `/list`。
    *   拼接到 `target` 后面，变成 `http://www.test.com/list`。
    *   **漏了 `/v1`！** 后端要的是 `/v1/list`。

**修正方案**：
要么前端写 `axios.get('/api/v1/list')`。
要么 `rewrite` 改成：`path => path.replace(/^\/api/, '/v1')` (把 `/api` 替换成 `/v1`)。

**总结**：
1.  Vite Proxy 只是开发环境的“障眼法”。
2.  一定要搞清楚后端接口**到底有没有前缀**，以此决定要不要写 `rewrite`。
3.  生产环境要找运维配 Nginx。
