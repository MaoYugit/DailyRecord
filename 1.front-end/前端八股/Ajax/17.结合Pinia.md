这是 Vue 3 开发中**架构设计**的关键一环。

很多新手学会了 Pinia 后，会陷入一个误区：**“我是不是要把所有的 API 请求都挪到 Pinia 里去？”**
答案是：**绝对不要。**

这一章我们不仅要学**怎么写**，更要学**怎么选**。

### 第一部分：如何在 Pinia Actions 中调用 API

最典型的场景是 **“用户登录”**。
因为登录成功后，Token 和 用户信息 是**全局共享**的（头部导航栏要显示头像，路由守卫要检查权限），所以这个请求必须放在 Pinia 里。

#### 1. 定义 Store (`src/store/user.ts`)

我们将使用 Pinia 的 **Setup Store** 语法（也就是 `ref` + `function`），这和 Composition API 风格最搭。

```typescript
import { defineStore } from 'pinia';
import { ref } from 'vue';
import { login as loginApi, getUserInfo as getUserInfoApi } from '@/api/user'; // 引入 API
import { clearToken, setToken } from '@/utils/auth'; // 假设你封装了存取 Cookie/LocalStorage 的方法

export const useUserStore = defineStore('user', () => {
    // --- State (相当于 data) ---
    const token = ref(localStorage.getItem('token') || '');
    const userInfo = ref(null);

    // --- Actions (相当于 methods) ---
    
    // 动作 1: 登录
    const login = async (loginForm) => {
        try {
            // 1. 调用 API
            const data = await loginApi(loginForm);
            
            // 2. 更新 State
            token.value = data.token;
            
            // 3. 持久化 (存到 LocalStorage 或 Cookie)
            // 这一步很重要，否则刷新页面就退出了
            localStorage.setItem('token', data.token); 
            
            return data; // 继续抛出数据，供组件做跳转逻辑
        } catch (error) {
            throw error; // 抛出错误，让组件去处理 UI (比如停止按钮 loading)
        }
    };

    // 动作 2: 获取用户信息
    const getUserInfo = async () => {
        try {
            const data = await getUserInfoApi();
            userInfo.value = data;
        } catch (error) {
            console.error(error);
        }
    };

    // 动作 3: 退出登录
    const logout = () => {
        token.value = '';
        userInfo.value = null;
        localStorage.removeItem('token');
        // 可能还需要重置路由等操作
    };

    return { token, userInfo, login, getUserInfo, logout };
});
```

#### 2. 在组件中使用 (`Login.vue`)

组件现在只需要充当一个**“触发器”**，业务逻辑全部在 Store 里闭环。

```vue
<script setup>
import { reactive, ref } from 'vue';
import { useUserStore } from '@/store/user';
import { useRouter } from 'vue-router';

const router = useRouter();
const userStore = useUserStore(); // 获取 store 实例

const form = reactive({ username: '', password: '' });
const loading = ref(false);

const handleLogin = async () => {
    loading.value = true;
    try {
        // 🔥 关键：调用 Action
        await userStore.login(form);
        
        // 登录成功，跳转首页
        router.push('/'); 
    } catch (error) {
        // 登录失败，密码错了等
        console.error('登录挂了', error);
    } finally {
        loading.value = false;
    }
};
</script>
```

### 第二部分：灵魂拷问 —— 数据到底存 Pinia 还是存组件？

这是面试官考察你有没有**工程化经验**的必杀技。
如果你说“我都存 Pinia”，面试官会觉得你代码耦合度太高，内存占用大。

#### ❌ 什么时候【不应该】存 Pinia？
1.  **页面级的列表数据**：比如“订单列表页”的 `tableData`。
    *   *理由*：用户离开这个页面再回来，通常希望看到最新的数据，或者重置为空。存在 Pinia 里会导致数据“僵尸化”（上次的数据还留着），你还得手动写重置逻辑 `resetStore()`，徒增麻烦。
2.  **表单临时数据**：搜索框的关键词、弹窗的显示隐藏状态 (`dialogVisible`)。
    *   *理由*：这些只跟当前组件的 UI 有关，别的组件根本不关心。
3.  **很少变动的字典数据**：如果不常改，可以直接写死在常量文件里，或者利用浏览器的 Cache，不一定要占 Pinia 的内存。

#### ✅ 什么时候【应该】存 Pinia？
1.  **全局状态**：
    *   用户信息 (`User`)
    *   权限列表 (`Permissions`)
    *   应用配置 (`Theme`, `Language`)
2.  **跨组件通信**：
    *   比如：你在“购物车组件”添加了商品，头部的“购物车图标”数字要立马 +1。这时候购物车列表必须存 Pinia。
3.  **多页面缓存 (Keep-Alive 替代方案)**：
    *   *场景*：你在“步骤一”填了表单，去“步骤二”选了东西，再回“步骤一”，希望刚才填的数据还在。
    *   *做法*：把表单数据存 Pinia。

### 第三部分：总结决策图谱

在写代码前，问自己三个问题：

| 问题                                     | 答案 | 存放位置                      |
| :--------------------------------------- | :--- | :---------------------------- |
| **Q1: 这个数据其他页面会用到吗？**       | 是   | **Pinia**                     |
| **Q2: 刷新页面后，这个数据需要保留吗？** | 是   | **Pinia + 持久化插件**        |
| **Q3: 离开这个页面，数据还需要保留吗？** | 否   | **组件内部 (`ref/reactive`)** |

### 🟢 随堂测试 (场景判断)

请判断以下场景的数据应该放在 **Pinia** 还是 **组件内部**？

1.  **场景 A**：一个“修改密码”的弹窗，里面的 `oldPassword` 和 `newPassword` 输入框的值。
2.  **场景 B**：电商网站的“左侧侧边栏菜单”收起/展开的状态（用户习惯，希望刷新后保持）。
3.  **场景 C**：文章详情页的内容（Article Detail）。
4.  **场景 D**：当前登录用户的头像 URL。

---
---

**参考答案：**

1.  **组件内部**。修改完密码弹窗就关了，数据销毁，不需要共享。
2.  **Pinia**（通常配合 `pinia-plugin-persistedstate`）。因为 Header 和 Sidebar 是兄弟组件，Layout 布局需要共享这个状态。
3.  **组件内部**。除非你要做“最近浏览记录”，否则没必要存 Store。
4.  **Pinia**。Header 要用，个人中心要用，评论区也要用。
