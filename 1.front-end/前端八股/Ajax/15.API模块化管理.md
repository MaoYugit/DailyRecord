这一章是**“码农”**和**“工程师”**的分水岭。

*   **码农**：图省事，直接在 `.vue` 组件里写 `axios.get('/api/user')`。项目小的时候没问题，项目一大，接口一变，几百个文件都要改，直接跑路。
*   **工程师**：懂得**分层架构**。把所有的网络请求抽离出去，组件只负责“调用”，不负责“实现”。

我们将这种管理方式称为 **Service Layer (服务层)**。

---

### 第一部分：为什么要这样做？（面试必答）

如果面试官问：“为什么不能在组件里直接写请求？”
你要回答这三点：

1.  **解耦 (Decoupling)**：View 层（组件）不应该知道底层是用 Axios 还是 Fetch，也不应该知道 URL 是 `/user` 还是 `/v1/user`。
2.  **复用 (Reusability)**：一个“获取用户信息”的接口，可能在“个人中心”、“头部导航”、“支付页”都要用。抽离出来后，写一遍，处处用。
3.  **易维护 (Maintainability)**：后端突然要把所有接口加个前缀 `/api/v2`。
    *   **不管**：你要打开 50 个 `.vue` 文件一个个改。
    *   **管了**：你只需要改 `src/api` 下的一个文件。

---

### 第二部分：标准的目录结构

这是目前 Vue 3 企业级项目（如 vue-element-admin, soybean-admin）通用的结构：

```text
src/
├── utils/
│   └── request.js    # 核心：Axios 实例与拦截器封装 (上一章写的)
├── api/              # 核心：API 接口定义层
│   ├── user.js       # 用户模块 (登录、注册、详情)
│   ├── order.js      # 订单模块 (列表、下单、取消)
│   └── common.js     # 公共模块 (上传、字典、地区)
└── views/
    └── login/
        └── index.vue # 组件：只负责调用 api/user.js
```

### 第三部分：手把手实现

#### 1. 编写 API 文件 (`src/api/user.js`)

这里有两个关键点：
*   **只引入封装好的 request**，不要引入 axios。
*   **使用命名导出 (Named Export)**，每个接口一个函数。

```javascript
// src/api/user.js
import request from '@/utils/request';

// 1. 登录
export function login(data) {
  return request({
    url: '/user/login',
    method: 'post',
    data // post 请求放 data
  });
}

// 2. 获取用户信息
export function getUserInfo() {
  return request({
    url: '/user/info',
    method: 'get'
    // get 请求不需要传参时，可以不写 params
  });
}

// 3. 修改密码
export function changePassword(data) {
  return request({
    url: '/user/password',
    method: 'put',
    data
  });
}
```

#### 2. 在组件中调用 (`src/views/login/index.vue`)

你会发现组件的代码变得极其**干净**。没有 URL，没有 Method，只有业务逻辑。

```vue
<script setup>
import { ref } from 'vue';
// 关键点：从 api 模块引入，而不是从 axios 引入
import { login } from '@/api/user'; 
import { useRouter } from 'vue-router';

const router = useRouter();
const username = ref('');
const password = ref('');

const handleLogin = async () => {
  // 表单校验...
  
  try {
    // 🚀 调用接口
    // 组件根本不知道 url 是什么，它只知道我要 login
    const res = await login({ 
      username: username.value, 
      password: password.value 
    });
    
    // 登录成功逻辑
    console.log('Token:', res.token);
    router.push('/');
    
  } catch (error) {
    console.error('登录失败', error);
  }
};
</script>
```

### 第四部分：进阶技巧 —— 命名空间管理 (Namespace)

当接口非常多时（比如几百个），每个都 `export function` 可能会导致命名冲突（比如 `user.js` 有 `getList`，`order.js` 也有 `getList`）。

虽然 `import { getList as getUserList }` 可以解决，但更优雅的方式是**对象导出**。

**写法升级 (`src/api/order.js`):**

```javascript
import request from '@/utils/request';

export default {
  // 获取列表
  getList(params) {
    return request.get('/orders', { params });
  },
  
  // 获取详情
  getDetail(id) {
    return request.get(`/orders/${id}`);
  },
  
  // 删除
  delete(id) {
    return request.delete(`/orders/${id}`);
  }
}
```

**组件调用:**

```javascript
import orderApi from '@/api/order'; // 导入整个对象

const loadData = async () => {
    // 语义化非常强：orderApi.getList
    const res = await orderApi.getList({ page: 1 });
}
```

*注：Vue 3 社区目前两种写法都流行。如果结合 TypeScript，第一种（命名导出）做类型推断会稍微方便一点点，但第二种（对象导出）代码组织更整洁。面试时说哪种都行。*

### 🟢 随堂测试 (架构思维)

**场景题**：
后端开发跟你说：“兄弟，接口规范改了。以前查询参数叫 `pageNo`，现在全部改成 `currentPage`。”

**如果你没有做 API 模块化**，你需要怎么改？
**如果你做了 API 模块化**，你需要怎么改？

---
---

**参考答案：**

*   **没做模块化**：
    你需要全局搜索 `pageNo`，然后一个个确认是不是这个接口的参数（万一其他地方也用了这个变量名就改错了），可能涉及几十个文件，**风险极大**。

*   **做了模块化**：
    你只需要打开 `src/api/` 下的文件，找到对应的函数，做一个简单的映射：
    ```javascript
    export function getUserList(params) {
      return request({
        url: '/users',
        method: 'get',
        params: {
            // 在这里做一层转换，组件里依然传 pageNo，不用动组件代码！
            currentPage: params.pageNo, 
            pageSize: params.pageSize
        }
      });
    }
    ```
    **改动范围：1 个文件。风险：0。**

### 总结

到现在为止，你已经搭建好了一套**企业级的网络请求层**：
1.  **底层**：`request.js` (Axios 实例 + 拦截器)。
2.  **中间层**：`api/*.js` (接口定义)。
3.  **顶层**：Vue 组件 (调用)。

这套架构是目前前端行业的主流标准。

下一章，我们要把这套架构和 Vue 全家桶的另一个核心结合起来：
**结合 Composition API (useRequest Hook)**。
这是 Vue 3 的精髓，我们要尝试自己封装一个类似于 `VueUse` 的 Hook，让请求逻辑更“丝滑”。
