### 面试题 1：ECharts 的渲染原理是什么？

**❌ 初级回答**：它是用 Canvas 画的。
**✅ 高级回答（包含关键词：ZRender、MVC、Diff）**：

> “ECharts 的底层依赖于一个轻量级的 2D 图形库，叫做 **ZRender**（也是百度团队开源的）。
>
> 1.  **分层架构**：ECharts 本身是一个数据可视化的业务层，负责处理组件模型（Model）、数据处理和视图逻辑；而 ZRender 是渲染引擎层，负责把图形画到浏览器上。
> 2.  **渲染抽象**：ZRender 封装了底层的 Canvas API，并提供了一个类似 DOM 的事件模型（Eventful），让我们能像操作 DOM 一样监听 Canvas 中图形的点击事件。
> 3.  **绘制流程**：当我们调用 `setOption` 时，ECharts 会进行数据解析，计算出布局，然后创建对应的 ZRender 图形元素（Shape）。它内部有一套 **Diff 算法**，会对比新旧 Option，只更新发生变化的图形，从而保证渲染性能。
> 4.  **多渲染器支持**：正因为基于 ZRender 的抽象，ECharts 5.0 才能流畅地支持 **Canvas** 和 **SVG** 两种渲染模式的切换，因为 ZRender 屏蔽了底层的差异。”

### 面试题 2：如何解决 ECharts 内存泄漏问题？

**❌ 初级回答**：组件销毁的时候把图表删了。
**✅ 高级回答（包含关键词：SPA机制、dispose、引用切断）**：

> “在 Vue 这种单页应用（SPA）中，页面路由切换时，旧组件的 DOM 虽被移除，但 JS 闭包中可能还存有对 ECharts 实例的引用，导致内存无法释放。
>
> 我的标准处理流程是：
> 1.  **显式销毁**：在 Vue 组件的 `onUnmounted`（Vue 3）或 `beforeDestroy`（Vue 2）生命周期中，必须调用 `chartInstance.dispose()`。这会释放实例持有的 Canvas 上下文、定时器和事件监听器。
> 2.  **解绑外部事件**：如果我手动绑定了 `window.addEventListener('resize', handler)`，必须在销毁钩子中同步 `removeEventListener`，或者使用 `ResizeObserver` 并及时 `disconnect`。
> 3.  **切断引用**：销毁后，将保存实例的变量置为 `null`（如 `this.myChart = null`），帮助垃圾回收机制（GC）更快回收内存。”

### 面试题 3：Vue 中数据变了，为什么图表没更新？

**❌ 初级回答**：可能没调用 setOption 吧。
**✅ 高级回答（包含关键词：命令式 vs 声明式、深度监听、Proxy代理）**：

> “这通常是两个原因造成的：
>
> **原因一：未手动触发更新**。
> Vue 是数据驱动（声明式）的，而 ECharts 是指令式（Imperative）的。修改 Vue 的 `data` 并不会自动通知 ECharts。我们需要使用 `watch` 监听数据变化，并在回调中显式调用 `chartInstance.setOption(newVal)`。
>
> **原因二：监听失效或对象引用未变**。
> 1.  如果监听的是一个对象（Option），需要开启 `{ deep: true }` 深度监听，否则对象内部属性变化 Vue 捕捉不到。
> 2.  **性能陷阱**：在 Vue 3 中，如果直接用 `ref` 包裹 ECharts 实例，Vue 的 Proxy 会深度代理这个庞大的对象，不仅造成严重的性能损耗，甚至可能导致 ECharts 内部逻辑异常（无法更新）。**解决方案是使用 `shallowRef` 来存储 chart 实例**，或者使用 `markRaw` 标记，这样 Vue 就不会对其进行响应式代理，只保留纯 JS 对象的引用。”

### 面试题 4：如何实现自定义复杂的 Tooltip？

**❌ 初级回答**：用 formatter 改一下字符串。
**✅ 高级回答（包含关键词：HTML注入、CSS样式、marker）**：

> “当业务需求超出默认样式（例如需要显示缩略图、多列布局、带颜色的状态点）时，我会使用 `tooltip.formatter` 回调函数。
>
> 1.  **结构构建**：在 `formatter(params)` 中，根据 params 数组拿到当前触发的数据，拼接一段完整的 HTML 字符串（String Template）。
> 2.  **样式控制**：为了保证样式不被污染且足够灵活，我会直接在 HTML 字符串中写行内样式（Inline Style），或者在全局 CSS 中定义特殊的 class。
> 3.  **小技巧**：ECharts 在 params 里提供了一个 `marker` 字段（就是一个带颜色的 HTML 圆点字符串），直接拼接到 HTML 里，能保持 Tooltip 的颜色与图表系列颜色一致，省去了自己写 CSS 画圆点的麻烦。”
>
> *代码口述示例*：
> ```javascript
> formatter: (params) => {
>   // 这是一个 HTML 字符串
>   return `<div class="my-tip">
>             <h3>${params[0].name}</h3>
>             <img src="${params[0].data.imgUrl}" style="width:50px"/>
>             <div>${params[0].marker} 销量：${params[0].value}</div>
>           </div>`;
> }
> ```

### 面试题 5：ECharts 3D 了解吗？

**❌ 初级回答**：没用过 / 用过一点。
**✅ 高级回答（包含关键词：GL模块、WebGL、性能瓶颈）**：

> “我了解并使用过。ECharts 的 3D 功能并不在核心包里，需要引入扩展库 **`echarts-gl`**。
>
> 1.  **技术底层**：标准 ECharts 基于 Canvas/SVG，而 `echarts-gl` 基于 **WebGL**，利用 GPU 加速，可以渲染几十万级的散点图、3D 地球（Globe）、3D 柱状图（Bar3D）和曲面图（Surface）。
> 2.  **应用场景**：我通常在需要展示**地理空间数据**（如全球航线、城市建筑群）或者**三维复杂数学模型**时使用它。
> 3.  **注意事项**：3D 渲染非常消耗显卡资源。在使用时，我会特别注意控制光照、阴影和纹理的分辨率，避免在低性能设备上导致浏览器崩溃。”
