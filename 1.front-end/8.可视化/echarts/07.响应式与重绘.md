这一节看似简单，实则是**新手和老手的照妖镜**。

很多初级开发者做出来的页面，一缩放浏览器，图表就变形、拉伸或者干脆不动，必须刷新页面才能恢复。而在企业级后台管理系统（Admin Dashboard）中，侧边栏折叠/展开是标配功能，这会导致图表容器宽度变化，但**浏览器窗口大小（window size）其实没变**。

这时候，如果你只监听了 `window.resize`，图表是不会自适应的。

我们分三步走：基础方案、进阶方案、以及性能优化。

---

### 一、 基础方案：监听 Window Resize

这是最简单的方案，适用于**全屏大屏**或者**布局固定**的页面。

#### 原理
浏览器提供了全局事件 `resize`。当用户拖动浏览器边框时触发。

#### 代码实现
在 `ChartComponent.vue` 的 `onMounted` 中添加：

```javascript
onMounted(() => {
  initChart();
  
  // 监听窗口变动
  window.addEventListener('resize', handleResize);
});

onUnmounted(() => {
  if (chartInstance.value) {
    chartInstance.value.dispose();
  }
  // ⚠️ 必做：移除监听器，防止内存泄漏
  window.removeEventListener('resize', handleResize);
});

const handleResize = () => {
  // 调用 ECharts 实例自带的 resize 方法
  // 它会重新计算容器宽度，然后重绘 Canvas
  chartInstance.value?.resize();
};
```

---

### 二、 进阶方案：ResizeObserver（企业级标准）

#### 痛点场景
你在做一个后台系统，左边是侧边栏，右边是图表。当你点击“收起侧边栏”按钮时：
1.  右边的内容区域变宽了。
2.  但是！**浏览器窗口本身的大小（window.innerWidth）并没有变**。
3.  因此，`window.resize` 事件**根本不会触发**。
4.  结果：图表还是原来的宽度，右边留出一大片空白。

#### 解决方案：ResizeObserver
`ResizeObserver` 是现代浏览器原生 API，它可以**专门监听某个 DOM 元素（DIV）的尺寸变化**。无论是因为 CSS 变了、侧边栏收起了、还是浏览器缩放了，只要这个 DIV 变了，它就触发。

---

### 三、 性能优化：防抖 (Debounce)

`resize` 事件触发频率极高（一秒钟可能触发几十次）。ECharts 的 `resize()` 涉及 Canvas 的重绘，是非常消耗 CPU 的计算。如果每动一下鼠标都重绘，页面会掉帧、卡顿。

**解决方法**：加防抖。意思是“等你拖完窗口停下来 100ms 后，我再重绘”。

---

### 四、 终极代码：集成了 ResizeObserver + 防抖的组件

请更新你的 `ChartComponent.vue`。这是可以直接贴到生产环境的代码。

```vue
<script setup>
import { ref, onMounted, onUnmounted, shallowRef, watch } from 'vue';
import * as echarts from 'echarts';
// 如果项目中没有 lodash，可以使用自定义防抖函数，或者 npm install lodash
import { debounce } from 'lodash-es'; 

const props = defineProps({
  option: { type: Object, required: true }
});

const chartRef = ref(null);
const chartInstance = shallowRef(null);
let resizeObserver = null; // 保存观察器实例

// 1. 定义 Resize 逻辑
// 使用防抖，避免频繁重绘导致卡顿
const handleResize = debounce(() => {
  if (chartInstance.value) {
    chartInstance.value.resize();
    // 技巧：可以在这里打印日志，观察防抖是否生效
    // console.log('Chart Resized'); 
  }
}, 100);

const initChart = () => {
  if (chartRef.value) {
    chartInstance.value = echarts.init(chartRef.value);
    chartInstance.value.setOption(props.option);
    
    // 2. 启动 ResizeObserver
    // 创建观察器，一旦 chartRef 这个 DIV 大小变了，就执行 handleResize
    resizeObserver = new ResizeObserver(() => {
      handleResize();
    });
    // 开始观察
    resizeObserver.observe(chartRef.value);
  }
};

// 监听数据变化
watch(() => props.option, (newVal) => {
  chartInstance.value?.setOption(newVal);
}, { deep: true });

onMounted(() => {
  initChart();
});

onUnmounted(() => {
  // 3. 销毁逻辑（非常重要）
  // 销毁 ECharts 实例
  chartInstance.value?.dispose();
  // 停止观察 DOM，防止内存泄漏
  resizeObserver?.disconnect();
  // 取消还未执行的防抖函数
  handleResize.cancel?.(); 
});
</script>

<template>
  <div ref="chartRef" class="chart-box"></div>
</template>

<style scoped>
.chart-box {
  width: 100%;
  height: 100%;
}
</style>
```

#### 如果你不想引入 lodash，这里有个手写防抖函数供参考：
```javascript
function debounce(fn, delay) {
  let timer = null;
  return function(...args) {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => {
      fn.apply(this, args);
    }, delay);
  };
}
```

### 五、 课后作业（实战验证）

为了验证 `ResizeObserver` 的威力，请在父组件做一个模拟场景：

1.  **布局**：页面分为左右两栏。左栏宽度 200px，右栏自适应（flex: 1）。
2.  **功能**：在左栏放一个按钮“折叠/展开”。点击后，左栏宽度变为 0px。
3.  **观察**：
    *   如果你用的是 `window.resize`，折叠左栏时，右边的图表**不会**自动变宽。
    *   如果你用的是 `ResizeObserver`，折叠左栏时，右边的图表会**丝滑地**充满剩余空间。

完成这个实验，你就攻克了 ECharts 集成中最容易出 Bug 的环节。
