这一阶段是**从“会写 Demo”到“由企业级开发”的分水岭**。在真实的业务场景中，我们很少直接在 HTML 里写 ECharts，而是将其封装为 Vue 组件。

关于集成方案，业界主要分两派：**原生集成** 和 **第三方库（Vue-ECharts）**。作为立志成为高级开发者的你，**我强烈建议掌握原生集成**。

---

### 一、 为什么要用原生集成？（面试必答）

在面试中，如果问你“为什么不直接用 `vue-echarts` 这种现成的库？”，你可以这样回答：

1.  **控制力更强**：原生 API (`echarts.init`, `setOption`) 是最底层的，没有中间层干扰。遇到复杂交互（如地图下钻、图表联动、自定义事件）时，原生集成更容易调试。
2.  **版本无依赖**：第三方封装库通常更新滞后。ECharts 出了新特性（比如 5.0 的新动画），原生集成能立刻用，封装库可能要等作者更新。
3.  **包体积更小**：少引入一个依赖库，减少项目体积。
4.  **避免黑盒 Bug**：第三方库可能存在未知的 Bug，排查起来非常困难。

---

### 二、 原生集成核心模式（Vue 3 版）

在 Vue 3 中，集成 ECharts 有一个**巨大的坑**，如果不注意，会导致页面极其卡顿甚至浏览器崩溃。这个坑叫：**响应式代理（Proxy）**。

#### 1. 核心流程
1.  **DOM 挂载**：使用 `ref` 获取 DOM 元素。
2.  **生命周期**：必须在 `onMounted` 中初始化，因为此时 DOM 才存在。
3.  **实例保存（关键点）**：使用 `shallowRef` 保存 chart 实例，而不是 `ref`。

#### 2. 为什么用 `shallowRef` 而不是 `ref`？（高频面试题）
*   **Vue 3 的机制**：`ref` 会把对象用 `Proxy` 包裹，进行**深层响应式监听**。
*   **ECharts 的实例**：是一个非常庞大且复杂的对象，内部包含成千上万个属性和状态。
*   **冲突**：如果用 `ref` 包裹 ECharts 实例，Vue 会试图监听这个庞大对象的所有属性变化。这会消耗巨大的性能，甚至导致 ECharts 内部逻辑出错（比如 tooltip 闪烁、动画卡顿）。
*   **解决**：使用 `shallowRef`。它只监听 `.value` 的变化，而不监听 `.value` 内部属性的变化。这正是我们想要的——**ECharts 实例本身不需要响应式，我们只需要持有它的引用。**

### 三、 企业级通用封装代码

下面是一个可以直接在企业项目中使用的标准模版。

新建 `src/components/ChartComponent.vue`：

```vue
<template>
  <!-- 容器必须指定宽高，通常由父组件通过 CSS 控制，或者这里给默认值 -->
  <div ref="chartRef" class="chart-box"></div>
</template>

<script setup>
import { ref, onMounted, onUnmounted, shallowRef, watch } from 'vue';
import * as echarts from 'echarts';

// 接收父组件传来的 option
const props = defineProps({
  option: {
    type: Object,
    required: true,
    default: () => ({})
  }
});

const chartRef = ref(null);
// ⚠️ 重点：使用 shallowRef 而不是 ref，避免 Vue 深度代理导致性能问题
const chartInstance = shallowRef(null);

// 初始化图表
const initChart = () => {
  if (chartRef.value) {
    // 1. 初始化
    chartInstance.value = echarts.init(chartRef.value);
    
    // 2. 渲染
    chartInstance.value.setOption(props.option);
    
    // 3. 监听点击事件（示例：企业级通常需要交互）
    chartInstance.value.on('click', (params) => {
      console.log('图表被点击：', params);
    });
  }
};

// 监听 props.option 的变化，实现数据驱动视图
// 场景：父组件请求接口获取新数据，更新了 option，图表自动刷新
watch(
  () => props.option,
  (newOption) => {
    if (chartInstance.value) {
      // notMerge: true 表示不合并，完全替换（常用于数据完全刷新的场景）
      // 也可以设为 false 实现增量更新动画
      chartInstance.value.setOption(newOption);
    }
  },
  { deep: true } // 深度监听 option 对象内部属性变化
);

onMounted(() => {
  initChart();
});

onUnmounted(() => {
  // 销毁实例，释放内存
  if (chartInstance.value) {
    chartInstance.value.dispose();
    chartInstance.value = null;
  }
});
</script>

<style scoped>
.chart-box {
  width: 100%;
  height: 100%; /* 依赖父容器高度 */
  min-height: 300px; /* 防止父容器高度坍塌 */
}
</style>
```

### 四、 如何使用这个组件？

在你的页面文件（如 `Dashboard.vue`）中引入：

```vue
<template>
  <div class="dashboard">
    <!-- 图表容器 -->
    <div class="chart-wrapper">
      <ChartComponent :option="salesOption" />
    </div>
    
    <button @click="updateData">模拟更新数据</button>
  </div>
</template>

<script setup>
import { ref } from 'vue';
import ChartComponent from './components/ChartComponent.vue';

// 定义数据配置
const salesOption = ref({
  title: { text: '实时销量' },
  xAxis: { type: 'category', data: ['A', 'B', 'C'] },
  yAxis: { type: 'value' },
  series: [{ type: 'bar', data: [10, 20, 30] }]
});

// 模拟接口数据更新
const updateData = () => {
  // 只需要修改响应式数据，组件内的 watch 会自动触发 setOption
  salesOption.value.series[0].data = [
    Math.random() * 100,
    Math.random() * 100,
    Math.random() * 100
  ];
};
</script>

<style>
.chart-wrapper {
  width: 600px;
  height: 400px;
  border: 1px solid #ddd;
}
</style>
```
