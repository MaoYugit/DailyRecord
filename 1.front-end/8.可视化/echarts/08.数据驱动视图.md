欢迎来到第二阶段的第三课。这一节是将 ECharts 真正融入业务逻辑的核心。

在真实工作中，图表数据永远不是写死的，而是从后端 API 请求来的。你需要处理**数据加载状态**、**数据更新**，以及一个极其隐蔽但致命的坑——**数据合并策略**。

---

### 一、 数据驱动的核心逻辑

Vue 是**数据驱动视图**（Data-Driven），而 ECharts 是**指令式**（Imperative）的。
我们需要用 Vue 的 `watch` 或 `computed` 做桥梁，当数据变化时，命令 ECharts 去画画。

#### 最佳实践流程：
1.  **Parent Component**: 请求 API $\rightarrow$ 获取原始数据 `rawDara`。
2.  **Computed**: 将 `rawData` 转换为 ECharts 需要的 `option` 格式。
3.  **Watcher**: 监听 `option` 变化 $\rightarrow$ 调用 `chartInstance.setOption(val)`。

---

### 二、 核心难点：增量更新 vs 完全替换 (`notMerge`)

这是面试中常问的细节，也是导致图表显示“幽灵数据”的原因。

#### 1. `setOption` 的默认行为：合并 (Merge)
*   **语法**：`chart.setOption(newOption, false)` (第二个参数默认是 false)。
*   **行为**：ECharts 会把新的配置和旧的配置**合并**。
*   **优点**：性能好，适合做实时数据更新（比如股票走势，只更新 `series.data`）。
*   **缺点（坑）**：
    *   **场景**：旧图表有 3 条折线。新数据只有 2 条折线。
    *   **结果**：新数据更新了前 2 条，但**第 3 条旧线依然留在图上！** 这就是“幽灵数据”。

#### 2. `setOption` 的暴力模式：不合并 (Not Merge)
*   **语法**：`chart.setOption(newOption, true)`。
*   **行为**：先清空当前图表的所有组件，然后根据新配置重新绘制。
*   **场景**：切换图表类型（柱状变饼图）、数据系列数量不固定、或者彻底刷新报表。

### 三、 实战代码：Loading 状态与更新策略

我们将升级之前的 `ChartComponent.vue`，增加 `loading` 控制和 `notMerge` 选项。

#### 1. 升级子组件 (`ChartComponent.vue`)

```vue
<script setup>
import { ref, onMounted, onUnmounted, shallowRef, watch } from 'vue';
import * as echarts from 'echarts';
// 引入防抖逻辑（沿用上一节）
import { debounce } from 'lodash-es';

const props = defineProps({
  option: { type: Object, required: true },
  // 新增：控制 loading 状态
  loading: { type: Boolean, default: false },
  // 新增：控制是否强制重新渲染（默认为 false，即走合并模式）
  notMerge: { type: Boolean, default: false }
});

const chartRef = ref(null);
const chartInstance = shallowRef(null);

// 初始化
const initChart = () => {
  if (chartRef.value) {
    chartInstance.value = echarts.init(chartRef.value);
    // 初始渲染
    chartInstance.value.setOption(props.option);
  }
};

// 核心 1：监听 Option 变化，驱动视图更新
watch(
  () => props.option,
  (newOption) => {
    if (chartInstance.value) {
      // ⚠️ 重点：第二个参数传入 props.notMerge
      chartInstance.value.setOption(newOption, props.notMerge);
    }
  },
  { deep: true }
);

// 核心 2：监听 Loading 变化
watch(
  () => props.loading,
  (isLoading) => {
    if (!chartInstance.value) return;
    if (isLoading) {
      chartInstance.value.showLoading({
        text: '数据加载中...',
        color: '#409EFF',
        textColor: '#000',
        maskColor: 'rgba(255, 255, 255, 0.8)',
      });
    } else {
      chartInstance.value.hideLoading();
    }
  }
);

// Resize 逻辑（沿用上一节）
const handleResize = debounce(() => chartInstance.value?.resize(), 100);
let resizeObserver = null;

onMounted(() => {
  initChart();
  resizeObserver = new ResizeObserver(handleResize);
  resizeObserver.observe(chartRef.value);
});

onUnmounted(() => {
  chartInstance.value?.dispose();
  resizeObserver?.disconnect();
});
</script>

<template>
  <div ref="chartRef" class="chart-box"></div>
</template>

<style scoped>
.chart-box { width: 100%; height: 100%; }
</style>
```

#### 2. 父组件实战场景 (`Dashboard.vue`)

这里模拟一个真实的业务场景：点击按钮请求数据，数据返回前显示 Loading，返回后更新图表。

```vue
<template>
  <div class="dashboard">
    <div class="controls">
      <button @click="fetchData(2)">加载2条数据 (合并模式)</button>
      <button @click="fetchData(1)">加载1条数据 (会有幽灵数据)</button>
      <button @click="fetchFullReset">强制重置 (无幽灵数据)</button>
    </div>

    <div class="chart-wrapper">
      <ChartComponent 
        :option="chartOption" 
        :loading="isLoading" 
        :not-merge="isForceRefresh"
      />
    </div>
  </div>
</template>

<script setup>
import { ref, computed } from 'vue';
import ChartComponent from './ChartComponent.vue';

const isLoading = ref(false);
const isForceRefresh = ref(false);
const apiData = ref([]); // 模拟后端返回的原始数据

// 核心 3：使用 computed 生成 option
// 好处：逻辑分离，option 永远是根据最新数据自动计算出来的
const chartOption = computed(() => {
  return {
    tooltip: { trigger: 'axis' },
    xAxis: { type: 'category', data: ['Mon', 'Tue', 'Wed'] },
    yAxis: { type: 'value' },
    series: apiData.value.map(item => ({
      name: item.name,
      type: 'line',
      data: item.values
    }))
  };
});

// 模拟 API 请求
const fetchData = (count) => {
  isLoading.value = true;
  isForceRefresh.value = false; // 使用默认合并模式
  
  setTimeout(() => {
    // 模拟生成不同数量的 Series
    const newData = [];
    for(let i=0; i<count; i++) {
      newData.push({
        name: `系列 ${i+1}`,
        values: [Math.random()*100, Math.random()*100, Math.random()*100]
      });
    }
    apiData.value = newData;
    isLoading.value = false;
  }, 1000);
};

// 强制重置模式
const fetchFullReset = () => {
  isLoading.value = true;
  isForceRefresh.value = true; // ⚠️ 开启 notMerge: true
  
  setTimeout(() => {
    // 即使这里只有 1 条数据，也不会保留之前的旧线
    apiData.value = [{
      name: '全新系列',
      values: [50, 50, 50]
    }];
    isLoading.value = false;
  }, 500);
};
</script>

<style>
.chart-wrapper { height: 400px; border: 1px solid #eee; margin-top: 20px; }
.controls button { margin-right: 10px; padding: 8px 15px; cursor: pointer; }
</style>
```

### 四、 课后实验（必做）

1.  **复现“幽灵数据”**：
    *   先点击“加载2条数据”。图上会有两条线。
    *   再点击“加载1条数据”。
    *   **观察**：你会发现图上依然有 2 条线！其中一条是上一次遗留的，这就是合并模式的副作用。
2.  **解决问题**：
    *   点击“强制重置”。
    *   **观察**：图表会先清空，然后只显示 1 条线。这就验证了 `notMerge: true` 的作用。

### 面试官追问预警
**Q: 如果我的数据量非常大（例如动态波形图，每秒更新10次），每次都用 `notMerge: true` 会怎么样？**
**A:** 会卡死。因为 `notMerge: true` 会销毁并重建所有组件，开销极大。
**Correct Strategy:** 这种场景必须用 `merge` 模式（默认），甚至只更新 `series.data` 部分。为了避免“幽灵数据”，在数据量减少时，显式地把多余的 series 设置为 `data: []` 或者在 option 里把多余的 series 对象删掉（并保证 series 数组长度一致，用 null 占位）。
