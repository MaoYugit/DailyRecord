### 一、 按需引入 (Tree Shaking)

**痛点**：默认的 `import * as echarts` 会把 ECharts 的所有图表（地图、热力图、K线图...）和所有组件全打包进去，体积高达 **1MB+**。
**解决**：使用 ECharts 5 提供的模块化引入方式，将体积压缩到 **300KB** 左右。

#### 实战：构建自己的 ECharts 核心文件

建议在项目中新建 `src/utils/echarts-core.js`，专门管理按需引入。

```javascript
// 1. 引入核心模块
import * as echarts from 'echarts/core';

// 2. 引入渲染器 (必须二选一：Canvas 或 SVG)
import { CanvasRenderer } from 'echarts/renderers';

// 3. 引入你需要的图表 (用什么引什么)
import { 
  BarChart, 
  LineChart, 
  PieChart 
} from 'echarts/charts';

// 4. 引入你需要的组件 (Tooltip, Legend, Grid 是最常用的)
import {
  TitleComponent,
  TooltipComponent,
  GridComponent,
  LegendComponent,
  DataZoomComponent // 如果用了缩放，必须引入
} from 'echarts/components';

// 5. 注册模块
echarts.use([
  CanvasRenderer,
  BarChart,
  LineChart,
  PieChart,
  TitleComponent,
  TooltipComponent,
  GridComponent,
  LegendComponent,
  DataZoomComponent
]);

// 6. 导出
export default echarts;
```

**使用方法**：
以后在组件里，**不再引入官方包**，而是引入你自己封装的文件：

```javascript
// import * as echarts from 'echarts'; // ❌ 不要这样写
import echarts from '@/utils/echarts-core'; // ✅ 这样写
```

### 二、 海量数据渲染（10万+ 数据点）

当 Series 里的 `data` 长度超过 1 万时，页面可能会掉帧；超过 10 万时，浏览器可能会假死。ECharts 提供了三大神器来解决这个问题。

#### 1. 开启 `large` 模式（Canvas 专属）

ECharts 会检测数据量。对于 `scatter`（散点图）和 `line`（折线图），你可以手动开启优化。

*   **原理**：当数据量超过阈值，ECharts 不再绘制具体图形的细节（如圆角、阴影），而是把它们合并成一张静态图片绘制，并**关闭鼠标交互**（Hover 高亮失效），从而极大提升速度。

```javascript
series: [{
  type: 'bar',
  data: bigData, // 假设有 50,000 条
  large: true,   // 开启大数据优化
  largeThreshold: 2000 // 数据超过 2000 就自动开启
}]
```

#### 2. 降采样算法 (`sampling`)

**场景**：显示一年的分钟级数据（约 50 万个点），但在 1920px 的屏幕上，X 轴只有 1920 个像素。
**问题**：在一个像素宽度的区域内挤了 200 个点，绘制它们毫无意义，只会增加 CPU 负担。
**解决**：用算法筛选出一个代表点。

*   `'lttb'`: **推荐**。Largest-Triangle-Three-Buckets 算法。能最大程度保留数据的视觉波峰波谷结构（不会把尖峰磨平）。
*   `'average'`: 取平均值（会把波峰削平，不建议用于监控数据）。
*   `'max'`: 取最大值。

```javascript
series: [{
  type: 'line',
  data: hugeData,
  sampling: 'lttb' // 核心代码
}]
```

#### 3. 分片加载 (`appendData`)

**场景**：数据不是一次性拿到的，或者是流式数据（WebSocket）。如果不分片，每次 `setOption` 都会全量重绘整个图表。

```javascript
// 1. 初始化一个空的 series
chart.setOption({
  series: [{ type: 'scatter' }]
});

// 2. 模拟分批加载（假设总共 100万，每次加 2万）
const appendDataFunc = (dataChunk) => {
  // appendData 是 ECharts 实例的方法，不是 option 配置
  // 注意：appendData 只支持 scatter 和 line，且此时无法进行某些交互
  chart.appendData({
    seriesIndex: 0,
    data: dataChunk
  });
}
```

### 三、 Canvas vs SVG（面试必考题）

ECharts 默认使用 Canvas 渲染，但它也支持 SVG。面试官非常喜欢问：“**什么情况下你会把 renderer 设为 SVG？**”

#### 1. 对比表 (背诵)

| 特性         | Canvas (画布)                                                | SVG (矢量图)                                                 |
| :----------- | :----------------------------------------------------------- | :----------------------------------------------------------- |
| **底层原理** | 一个 `<canvas>` 标签，基于像素绘制（位图）。                 | 一堆 `<path>`, `<rect>` 标签，基于 DOM 节点。                |
| **内存占用** | 只跟画布面积有关。画 10 万个点内存也不变（除了 JS 数据本身）。 | 跟节点数量有关。画 10 万个点会生成 10 万个 DOM 节点，**内存爆炸**。 |
| **渲染性能** | **大数据量无敌**。适合动画、特效。                           | **数据量少时（<1000）性能更好**。                            |
| **清晰度**   | 放大浏览会模糊（锯齿）。                                     | **无损放大**，永远清晰。                                     |
| **适用场景** | 折线图、热力图、地图、炫酷大屏。                             | 移动端报表、PDF导出、简单的饼图/柱状图。                     |

#### 2. 如何切换？

```javascript
// 在 init 时指定
const chart = echarts.init(domRef.value, null, { 
  renderer: 'svg' // 默认是 'canvas'
});
```

### 四、 面试突击 Q&A

这里模拟几个真实的高频面试题，你可以直接背诵答案关键词。

**Q1: ECharts 图表数据量很大，页面卡顿，你怎么优化的？**

> **A (标准回答):**
>
> 1.  **渲染层面**：我会开启 `large: true` 模式，让 ECharts 对超过阈值的数据进行合并渲染。对于折线图，我会配置 `sampling: 'lttb'` 降采样算法，只渲染屏幕像素能承载的数据量。
> 2.  **代码层面**：使用 `dataset` 管理数据。如果是流式数据，使用 `appendData` 分片渲染，避免一次性阻塞主线程。
> 3.  **打包层面**：使用 `echarts/core` 进行按需引入，只打包用到的图表组件，减小体积。

**Q2: 你的大屏项目中，为什么选择 Canvas 而不是 SVG？**

> **A:** 因为大屏项目通常涉及大量的动画效果（如飞线、动态波纹）和较高的数据密度（如热力图）。Canvas 是基于像素的单一节点，渲染大量图形时不会导致 DOM 节点过多而造成内存泄漏或回流（Reflow），性能表现远优于 SVG。SVG 更适合低端移动设备或者对清晰度要求极高的静态报表。

**Q3: ECharts 的渲染原理是什么？**

> **A:** ECharts 底层依赖一个轻量级的 Canvas 类库叫 **ZRender**（也是百度开源的）。
> 我们写的 `option` 只是配置对象，ECharts 会将其解析为 ZRender 的图形（Shape），通过 MVC 架构将数据模型映射为视图。
> 当调用 `setOption` 时，Diff 算法会计算出需要更新的图形元素，进行增量绘制。
