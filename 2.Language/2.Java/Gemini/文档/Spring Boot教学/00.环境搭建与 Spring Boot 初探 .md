# Java Spring Boot 入门详解：从环境搭建到第一个 Web 接口

## 1. 前置准备：夯实地基

在正式进入 Spring Boot 之前，我们需要准备好 Java 开发的两大基石：构建工具 (Maven) 和 开发环境 (IDEA)。

### 1.1 Maven：Java 世界的“智能管家”
很多新手只会照抄配置，我们需要理解 Maven 到底做了什么。

*   **它是什么？** 一个项目管理和构建自动化工具。
*   **它解决了什么痛点？**
    *   **自动下载**：告别手动去网上搜索、下载、复制 `jar` 包的痛苦时代。
    *   **依赖管理**：自动解决依赖传递问题（A 依赖 B，B 依赖 C，Maven 会自动把 C 也下载下来）。
*   **核心概念：坐标 (G.A.V)**
    Maven 仓库中每个 Jar 包都有唯一的“身份证”，由三部分组成：
    *   **GroupId**: 组织ID（通常是域名倒写，如 `com.google`）。
    *   **ArtifactId**: 项目名/模块名（如 `guava`）。
    *   **Version**: 版本号（如 `31.0-jre`）。

### 1.2 IDEA：工欲善其事
IntelliJ IDEA 是目前最强大的 Java IDE。对于 Spring Boot 开发，它提供了极致的智能提示。

*   **关键设置建议**：
    *   **Maven 配置**：确保 IDEA 使用正确的 Maven 路径，并配置阿里云镜像源（极大提升下载速度）。
    *   **JDK 设置**：
        *   **Spring Boot 3.0+**：强制要求 **JDK 17** 或更高。
        *   **Spring Boot 2.7.x**：支持 JDK 8 或 11（建议初学者跟随主流，逐渐过渡到 JDK 17）。

## 2. Spring Boot 简介：为什么我们需要它？

### 2.1 传统 Spring 开发的噩梦 (SSM 时代)
在 Spring Boot 诞生前，搭建一个 Web 项目（Spring + SpringMVC + MyBatis）非常痛苦：
1.  **配置地狱 (XML Hell)**：需要编写海量的 XML 配置文件，错一个字母就无法启动。
2.  **依赖冲突 (Dependency Hell)**：需要手动管理 Jar 包版本，容易出现版本不兼容导致的 `ClassNotFoundException`。
3.  **部署繁琐**：必须安装 Tomcat，打成 `war` 包并手动部署。

### 2.2 Spring Boot 的解决方案
Spring Boot 不是新框架，而是一个**“工具集”**，核心目的是**简化 Spring 应用的初始搭建和开发过程**。

1.  **起步依赖 (Starters)**：将常用的依赖打包在一起。例如引入 `spring-boot-starter-web`，它会自动引入 Spring MVC、Tomcat、Jackson 等几十个兼容的包。
2.  **自动配置 (Auto Configuration)**：根据引入的依赖，自动配置 Bean（后续详解）。
3.  **内嵌服务器**：直接把 Tomcat 塞进 Jar 包，运行 `main` 方法即可启动。

> **🎓 面试金句**：
> Spring Boot 的核心价值在于 **“约定大于配置”**。它通过 **起步依赖** 解决了版本管理问题，通过 **自动配置** 解决了繁琐的 XML 配置问题，通过 **内嵌容器** 简化了部署流程。

## 3. 实战：搭建博客后端脚手架

我们将从零创建一个项目，并在浏览器上打印出 "Hello, My Blog!"。

### 3.1 使用 Spring Initializr 创建项目

1.  **打开向导**：IDEA 中点击 `File` -> `New` -> `Project` -> 选择左侧 **Spring Initializr**。
2.  **填写基础信息**：
    *   **Name**: `blog-backend`
    *   **Language**: `Java`
    *   **Type**: `Maven`
    *   **Group**: `com.example`
    *   **Artifact**: `blog-backend`
    *   **Package name**: `com.example.blog` (保持默认)
    *   **JDK**: 建议 `17` (与 Spring Boot 版本匹配)
3.  **选择依赖 (Dependencies) —— 关键！**
    *   **Spring Boot Version**: 选择 **3.x.x** (若用JDK 17) 或 **2.7.x** (若用JDK 8)。避免选择 SNAPSHOT 版本。
    *   **搜索并勾选**: `Spring Web` (这是开发 Web 接口的核心)。
4.  **等待加载**：点击 Create，等待右下角 Maven 进度条跑完，直到 `pom.xml` 无报错。

### 3.2 项目结构解析
项目创建后，标准结构如下：

```text
blog-backend
├── src
│   ├── main
│   │   ├── java
│   │   │   └── com.example.blog
│   │   │       ├── BlogApplication.java  <-- [1] 启动类 (必须在根包下)
│   │   │       ├── controller            <-- [2] 我们稍后创建，放 Web 接口
│   │   │       ├── service               <-- [3] 业务逻辑层
│   │   │       └── entity                <-- [4] 数据库实体
│   │   ├── resources
│   │   │   ├── static                    <-- [5] 存放静态文件(js/css，前后端分离通常不用)
│   │   │   ├── templates                 <-- [6] 存放模板文件
│   │   │   └── application.properties    <-- [7] 全局配置文件 (修改端口等)
│   └── test                              <-- 测试代码
└── pom.xml                               <-- [8] Maven 依赖管理
```

**重点提示**：
*   **启动类位置**：`BlogApplication.java` 必须位于所有子包的**最上层**。因为 `@SpringBootApplication` 默认只扫描当前包及其子包。如果把它移到子文件夹，会导致 Controller 扫描不到，报 404 错误。

## 4. 编码：RESTful 接口初体验

我们要写一个最简单的 RESTful 接口。
*   **RESTful**：目前主流的风格，将网络一切视为“资源”，通过 HTTP 动词（GET/POST/DELETE等）操作资源。

### 4.1 编写 Controller 代码
1.  在 `com.example.blog` 下新建包 `controller`。
2.  在 `controller` 包下新建类 `HelloController`。

```java
package com.example.blog.controller;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

/**
 * @RestController 是一个组合注解。
 * 等同于 @Controller + @ResponseBody。
 * 意味着这个类的方法返回的数据直接写入 HTTP 响应体（JSON/字符串），而不是跳转页面。
 */
@RestController
public class HelloController {

    /**
     * @GetMapping("/hello")
     * 路由映射：当浏览器发送 GET 请求访问 /hello 路径时，触发此方法。
     */
    @GetMapping("/hello")
    public String sayHello() {
        return "Hello, My Blog! 这是一个个人博客的开始。";
    }
}
```

## 5. 运行与验证

### 5.1 启动
1.  回到 `BlogApplication.java`。
2.  点击 `main` 方法旁的绿色三角形运行。
3.  观察控制台日志，看到 `Tomcat started on port(s): 8080` 即为成功。

### 5.2 测试
打开浏览器访问：`http://localhost:8080/hello`
**预期结果**：页面显示 “Hello, My Blog! 这是一个个人博客的开始。”

### 5.3 常见问题排查 (Debug)
*   **端口被占用 (Port 8080 was already in use)**：
    *   原因：已经有一个项目在运行了。
    *   解决：关闭所有 Java 进程，或者在 `application.properties` 中添加 `server.port=8081` 修改端口。
*   **404 Not Found (Whitelabel Error Page)**：
    *   原因1：URL 拼写错误（检查是否是 `/hello`）。
    *   原因2：**包结构错误**。请检查 `HelloController` 是否在启动类的子包中。

## 6. 核心原理：约定大于配置 (Convention over Configuration)

这是 Spring Boot 的灵魂。Spring Boot 预先定义了一套“最佳实践”。

*   **含义**：如果你遵守规范，就不需要写配置；只有想打破规范时，才需要配置。
*   **案例**：
    *   **约定**：引入 `spring-boot-starter-web`，Spring Boot 就默认你需要 Tomcat，并自动配置端口 8080。
    *   **配置**：如果你不想用 8080，想用 9999，才需要在 `application.properties` 写 `server.port=9999`（这是在覆盖约定）。

## 7. 面试突击：必考题

### 题 1：Spring Boot 和 Spring MVC 的区别是什么？
*   **Spring MVC** 是一个 **Web 框架**，负责处理 HTTP 请求（Controller, ViewResolver 等）。就像汽车的**发动机**。
*   **Spring Boot** 是一个 **脚手架/工具**，负责简化配置和构建。它包含了 Spring MVC。就像**汽车组装厂**，把发动机（Spring MVC）、底盘、轮子组装好给你。
*   **结论**：Spring Boot 包含 Spring MVC，旨在让你开箱即用，免去繁琐配置。

### 题 2：`@SpringBootApplication` 包含哪三个核心注解？
这是一个组合注解，点开源码可以看到：
1.  **`@SpringBootConfiguration`**：标记当前类为配置类（等同于 `@Configuration`）。
2.  **`@EnableAutoConfiguration` (核心)**：开启自动配置，让 Spring Boot 根据 classpath 下的 jar 包自动配置 Bean。
3.  **`@ComponentScan`**：开启组件扫描，自动扫描当前包及子包下的 Controller/Service 等组件。

## Controller 是什么

### 1. 生活中的比喻：Controller 是什么？

想象你去一家餐厅吃饭：

1.  **你 (Client/Browser)**：看着菜单点了一份“宫保鸡丁”（发起 **Request**）。
2.  **服务员 (Controller)**：
    *   他站在门口或桌边接收你的需求。
    *   他**不负责**炒菜（不处理复杂的业务逻辑）。
    *   他把你的单子递给**后厨 (Service层)**。
3.  **后厨 (Service)**：切菜、炒菜、放盐（处理业务逻辑）。
4.  **服务员 (Controller)**：菜做好后，他端出来给你（返回 **Response**）。

**结论**：
在 Spring Boot 中，Controller 就是这个**服务员**。它的核心作用只有两个：
1.  **接收请求**（你想要什么？）。
2.  **返回响应**（把结果给你）。
*至于怎么做出来的（业务逻辑），它通常交给 Service 层去处理。*

---

### 2. 核心注解：`@RestController` vs `@Controller`

在代码中，你最常看到这两个注解，区别非常关键：

#### 2.1 `@Controller` (传统派)
*   **作用**：主要用于返回 **HTML 页面** (JSP, Thymeleaf)。
*   **行为**：如果你方法返回字符串 `"index"`，它会去寻找一个叫 `index.html` 的文件显示给用户。
*   **场景**：老式网站开发（前后端不分离）。

#### 2.2 `@RestController` (现代派 / 我们的重点)
*   **作用**：专门用于写 **API 接口**（给前端 React/Vue 或 手机 App 用的）。
*   **行为**：如果你方法返回 `"Hello"` 或一个 `User` 对象，它会直接把数据转换成 **JSON 格式** 给浏览器。
*   **公式**：
    > `@RestController` = `@Controller` + `@ResponseBody`

---

### 3. Controller 是怎么工作的？（五脏六腑详解）

让我们把之前的 `HelloController` 拆解开来看，一个标准的 Controller 包含以下要素：

```java
@RestController // 1. 告诉 Spring：我是服务员，我负责通过 JSON 回复客人
@RequestMapping("/users") // 2. (可选) 类级别的路径。表示在这个类里的所有接口，都要加上前缀 /users
public class UserController {

    /**
     * 场景：获取用户信息
     * 请求：GET /users/info
     */
    @GetMapping("/info") // 3. 方法级别的路径。组合起来就是 /users/info
    public String getUser() {
        return "张三"; // 4. 返回数据
    }
}
```

#### 四大请求动作 (HTTP Verbs)
Controller 通过不同的注解来区分你“想做什么”：

*   **`@GetMapping`**：查。用于获取数据（比如：加载文章列表）。
*   **`@PostMapping`**：增。用于提交数据（比如：发布一篇新博客）。
*   **`@PutMapping`**：改。用于更新数据（比如：修改密码）。
*   **`@DeleteMapping`**：删。用于删除数据（比如：删除评论）。

### 4. 进阶：Controller 如何接收参数？（重点！）

前端传参数的方式有三种，Controller 也有三种对应的“接招”方式。

#### 方式 A：路径参数 (`@PathVariable`)
*   **场景**：URL 像这样 `http://localhost:8080/users/5` (那个 5 是 ID)。
*   **代码**：
```java
@GetMapping("/users/{id}") // 注意大括号，表示这是个变量
public String getUserById(@PathVariable Integer id) {
    return "你查询的用户ID是：" + id;
}
```

#### 方式 B：查询参数 (`@RequestParam`)
*   **场景**：URL 像这样 `http://localhost:8080/users?key=MacBook&page=1` (问号后面的)。
*   **代码**：
```java
@GetMapping("/search")
// Spring 会自动把 URL 里的 key 赋值给 keyword
public String search(@RequestParam String key, @RequestParam int page) { 
    return "你在搜索：" + key + ", 第 " + page + " 页";
}
```

#### 方式 C：请求体 JSON (`@RequestBody`)
*   **场景**：用户注册、发布文章。数据量大，放在包里（Body）发过来，而不是挂在 URL 上。
*   **代码**：
```java
// 假设有一个 User 类（包含 name, age）
@PostMapping("/register")
public String register(@RequestBody User user) {
    // Spring 自动把 JSON { "name": "Jack", "age": 20 } 转成了 User 对象
    return "注册成功，用户名：" + user.getName();
}
```

### 5. 架构规范：Controller 应该写什么代码？

初学者最容易犯的错误：**把所有逻辑都写在 Controller 里。**

**❌ 错误示范 (胖 Controller)：**
```java
@GetMapping("/buy")
public String buy(int id) {
    // 1. 连接数据库查询商品 (不该在这做)
    // 2. 判断库存够不够 (不该在这做)
    // 3. 计算价格打折 (不该在这做)
    // 4. 扣减库存 (不该在这做)
    return "购买成功";
}
```

**✅ 正确示范 (瘦 Controller)：**
Controller 只负责**指挥**，具体干活交给 **Service**。
```java
@Autowired
private OrderService orderService; // 注入 Service

@GetMapping("/buy")
public String buy(int id) {
    // Controller 只做一件事：调用 Service
    boolean success = orderService.createOrder(id);
    
    if(success) return "购买成功";
    else return "库存不足";
}
```

---

### 总结

1.  **角色**：Controller 是**交通指挥官**（接收请求 -> 调用 Service -> 返回结果）。
2.  **核心注解**：用 **`@RestController`** 做 API 开发。
3.  **接参三剑客**：
    *   URL 里的 `/users/1` 用 **`@PathVariable`**。
    *   URL 里的 `?id=1` 用 **`@RequestParam`**。
    *   表单/JSON 提交的数据用 **`@RequestBody`**。
4.  **原则**：Controller 里的代码越少越好，复杂的逻辑丢给 Service 层。

理解了 Controller，你就掌握了 Web 开发的“入口”。接下来通常就是学习 Service（业务逻辑）和 DAO（数据库交互）了。
